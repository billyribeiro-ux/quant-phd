Computational Reproducibility & The Replication Package

A published theorem without a proof is mere assertion; an empirical paper without an executable replication package is mere rumor. In modern doctoral quantitative finance, scientific legitimacy requires computational reproducibility: an independent scholar given raw data and code must reproduce every published number bit-for-bit. Mastering replication architecture protects the literature against unverified artifacts and establishes durable research integrity.

1The Reproducibility Crisis in Empirical Economics and Finance

Scientific integrity requires that an empirical claim be computationally verifiable. In pioneering investigations of academic reproducibility, Dewald, Thursby & Anderson (1986) attempted to replicate empirical papers published in the Journal of Money, Credit and Banking, discovering that fewer than one-third of authors could supply runnable code and data, and only a small fraction produced results conforming to published tables. Subsequent audits by McCullough & Vinod (2003) revealed widespread computational errors, manual copy-paste discrepancies, and unresolved data discrepancies across major economic journals.

In cross-sectional asset pricing, computational opacity exacerbates the reproducibility deficit. Because empirical pipelines require thousands of lines of data processing across WRDS, CRSP, Compustat, and OptionMetrics, subtle coding variations produce vastly different test statistics. Chen & Zimmermann (2022) demonstrate that providing open-source, standardized code implementations for over 200 cross-sectional anomalies restores high baseline replication fidelity (median return correlation of 0.95 with original papers during identical sample periods), proving that code transparency resolves apparent empirical discrepancies.

2Institutional Standards: AEA and Journal of Finance Policies

To eliminate computational irreproducibility, premier scientific bodies have enacted mandatory verification protocols. Under the leadership of the AEA Data Editor, the American Economic Association adopted its comprehensive Data and Code Availability Policy. The Journal of Finance, Journal of Financial Economics, and Review of Financial Studies followed by establishing formal reproducibility directorates.

These policies enforce four non-negotiable operational requirements:

  • Mandatory Code Deposit: Authors must provide all code used to clean raw data, generate variables, execute regressions, and produce all tables and figures appearing in the manuscript and online appendices.
  • Data Provenance and Manifests: Where raw data can be legally redistributed, it must be deposited in trusted repositories (e.g. Zenodo, openICPSR) with persistent Digital Object Identifiers (DOIs). Where data is proprietary (such as CRSP or Compustat), authors must deposit exact data retrieval scripts, detailed schema specifications, and cryptographic hashes of the raw input files.
  • Deterministic Single-Command Execution: The replication package must include a master execution script (e.g. run.sh or main.py) that compiles all data, executes the econometric pipeline, and outputs final publication artifacts without manual user intervention.
  • Environment Specification: The package must specify the operating system, language runtime version (e.g. Python 3.14), pinned package dependencies (e.g. requirements.txt or lockfile), and random seeds.

3The Architecture of a Gold-Standard Replication Package

Definition 3.1 (Replication Package)

A replication package is an autonomous, deterministic computational repository containing the complete raw data manifests, pipeline source code, software environment specifications, cryptographic checksums, and master execution scripts necessary for an independent party to regenerate every empirical figure and table of a scientific publication bit-for-bit without manual intervention.

A production-grade doctoral replication package conforms to a modular five-directory structure:

  1. data/: Contains raw data dictionaries, fetch scripts, licensing documentation, and SHA-256 verification manifests. Raw inputs are treated as read-only.
  2. src/: Contains numbered, sequentially staged execution scripts:
    • 01_clean_universe.py: Ingests raw data, applies CRSP share code and exchange filtering, compounds delisting returns, and formats timestamps.
    • 02_construct_signals.py: Constructs predictive signals, applies monthly cross-sectional winsorization, and validates non-lookahead alignment.
    • 03_portfolio_sorts.py: Generates quintile/decile portfolios under equal-weighting and value-weighting, outputting spread time series.
    • 04_factor_regressions.py: Executes asset pricing factor regressions with White, Newey-West, and clustered standard errors.
    • 05_generate_tables.py: Formats regression outputs into standalone CSV/LaTeX tables identical to published exhibits.
  3. config/: Contains pinned dependency manifests (e.g. pyproject.toml, environment.lock) and container definitions (Docker / Nix).
  4. output/: The destination directory where all tables, logs, and figures are automatically written.
  5. master_run.sh: The single entry-point script that executes all steps from clean workspace to final verified output.
Theorem 3.1 (Cryptographic Determinism and Manifest Invariance)

Let a computational pipeline be represented as a deterministic mapping \(\Phi: \mathcal{X} \times \Theta \to \mathcal{Y}\), where \(\mathcal{X}\) is the input dataset, \(\Theta\) is the software environment parameter vector (including runtime, dependencies, and random seed), and \(\mathcal{Y}\) is the set of generated publication tables. Let \(H: \{0, 1\}^* \to \{0, 1\}^L\) be a cryptographic hash function (SHA-256) satisfying collision resistance: \[ \Prob(H(y_1) = H(y_2) \mid y_1 \neq y_2) < 2^{-L/2} \] If two computational runs produce outputs \(y_a, y_b \in \mathcal{Y}\) such that \(H(y_a) = H(y_b)\), then with probability exceeding \(1 - 2^{-128}\), \(y_a = y_b\) byte-for-byte, guaranteeing bit-for-bit reproducibility.

Proof

The proposition follows from the collision resistance of cryptographic hash functions. For SHA-256, the digest length is \(L = 256\) bits. By the birthday paradox bound, the probability that two distinct byte strings \(y_1 \neq y_2\) map to the identical hash digest is bounded above by \(2^{-L/2} = 2^{-128} \approx 2.94 \times 10^{-39}\). If the verified hash matches the published manifest digest, the probability of an undetected numerical difference or data corruption is strictly less than \(2^{-128}\), which establishes byte-level identity for all practical scientific purposes.

Lab 1 · Automated replication package validator and hash auditor

This lab audits an empirical research replication package, validating sequential pipeline completion, detecting missing files, and verifying SHA-256 cryptographic digests of generated publication tables against certified publication hashes.

"""Lab 3: Replication package manifest verification and bit-for-bit audit."""

from __future__ import annotations

import hashlib


def audit_replication_package(
    manifest: dict[str, str],
    file_contents: dict[str, bytes],
) -> tuple[bool, list[str]]:
    logs: list[str] = []
    all_ok = True

    # Check completeness
    for filename, expected_digest in manifest.items():
        if filename not in file_contents:
            logs.append(f"MISSING: {filename} listed in manifest but not produced.")
            all_ok = False
            continue

        actual_digest = hashlib.sha256(file_contents[filename]).hexdigest()
        if actual_digest.lower() == expected_digest.lower():
            logs.append(f"VERIFIED: {filename} SHA-256 {actual_digest[:12]}... matches.")
        else:
            logs.append(
                f"CORRUPT: {filename} digest mismatch: expected {expected_digest[:12]}..., got {actual_digest[:12]}..."
            )
            all_ok = False

    return all_ok, logs


def main() -> None:
    data_clean = b"date,permno,ret\n199001,10001,0.045\n199001,10002,-0.012\n"
    table_1 = b"Factor,Alpha,Beta_Mkt,t_stat\nMOM,0.0078,0.12,3.14\n"
    table_2 = b"Decile,VW_Ret,EW_Ret\n1,-0.002,0.001\n10,0.012,0.018\n"

    manifest = {
        "data/cleaned_panel.csv": hashlib.sha256(data_clean).hexdigest(),
        "tables/table1_baseline.csv": hashlib.sha256(table_1).hexdigest(),
        "tables/table2_deciles.csv": hashlib.sha256(table_2).hexdigest(),
    }

    test_bundle = {
        "data/cleaned_panel.csv": data_clean,
        "tables/table1_baseline.csv": table_1,
        "tables/table2_deciles.csv": table_2,
    }

    success, report = audit_replication_package(manifest, test_bundle)
    print("Replication Package Audit Report:")
    print(f"Status: {'PASS' if success else 'FAIL'}")
    for line in report:
        print(f"  {line}")


main()

  VERIFIED: tables/table1_baseline.csv SHA-256 c4f014e839bf... matches.

The audit verifies that all required output files exist and match their expected cryptographic digests byte-for-byte. If any table is corrupted or modified by even a single digit, the SHA-256 digest fails completely, alerting the referee to an irreproducible output.

4Where the Canon Breaks

Even when authors deliver a complete code repository with pinned dependencies, bit-for-bit reproducibility can break down across heterogeneous hardware and compiler architectures:

  • Floating-Point Non-Associativity: In computer arithmetic conforming to IEEE 754, floating-point addition is not associative: \((a + b) + c \neq a + (b + c)\). When operations are vectorized using multi-threaded SIMD instructions (e.g. Intel AVX-512 vs Apple Silicon NEON), summation orders vary dynamically across CPU cores, altering the least significant bits of matrix inversions.
  • Operating System BLAS/LAPACK Implementations: Differences between Apple Accelerate, Intel MKL, and OpenBLAS introduce slight numerical variations in singular value decompositions and eigenvalue calculations, producing divergent standard errors in collinear panels.
  • Database Revision Drift: Commercial data vendors like CRSP and Compustat periodically restate historical earnings, update share codes retroactively, or revise corporate action adjustment factors. Running code against a 2026 CRSP snapshot will not reproduce numbers computed against a 2014 snapshot unless the exact vintage is frozen.

5Misconceptions

  1. “Providing a folder containing raw Jupyter notebooks satisfies modern journal replication standards.”

    Jupyter notebooks often execute out of order, conceal hidden global state, and fail to record execution environments. Top-tier journal policies require clean, standalone script pipelines executed via a master terminal command.

  2. “If an empirical paper uses proprietary WRDS/CRSP data, it is legally exempt from reproducibility requirements.”

    Proprietary licensing prevents redistributing raw CRSP files, but does not exempt authors from computational verification. Authors must provide exact data extraction code, transformation pipelines, and cryptographic checksums so that any subscriber can verify reproduction.

  3. “Setting random.seed(42) in Python guarantees identical results across all computer hardware.”

    A random seed guarantees repeatability only within the identical language runtime, OS architecture, and NumPy version. Cross-platform determinism requires containerized virtualization (e.g. Docker or Nix).

6Problem Set

Mechanics

M1 · SHA-256 Collision Probability

Suppose an automated replication archive verifies \(N = 10^6\) published data tables. Using the birthday paradox approximation \(\Prob(\text{collision}) \approx \frac{N^2}{2 \times 2^L}\), compute the upper bound on the probability of a hash collision under SHA-256 (\(L = 256\)).

Solution

For \(N = 10^6\), \(N^2 = 10^{12} \approx 2^{40}\). The collision probability is: \[ \Prob(\text{collision}) \approx \frac{2^{40}}{2 \times 2^{256}} = 2^{39 - 256} = 2^{-217} \approx 3.4 \times 10^{-66} \] The probability of a false match due to hash collision is unimaginably small, effectively zero across all empirical science.

M2 · Designing a Pipeline Execution Sequence

An author submits a replication folder containing four un-numbered scripts: make_table1.py, download_crsp.py, winsorize_signals.py, and merge_compustat.py. Order these scripts into a proper execution manifest.

Solution

The correct dependency pipeline order is: (1) 01_download_crsp.py (data extraction), (2) 02_merge_compustat.py (linking databases by PERMNO/GVKEY with disclosure lags), (3) 03_winsorize_signals.py (cross-sectional signal processing and outlier handling), (4) 04_make_table1.py (portfolio sorting, factor regression, and table generation). A master script run.sh must invoke them in this sequential order.

M3 · Floating-Point Non-Associativity Demonstration

In floating-point arithmetic with limited precision, consider \(a = 1.0\), \(b = 10^{-16}\), and \(c = -1.0\). Show how \((a + b) + c\) differs from \((a + c) + b\) under standard double precision (where machine epsilon \(\epsilon_{\text{mach}} \approx 2.22 \times 10^{-16}\)).

Solution

In IEEE 754 64-bit float: 1. Compute \((a + b) + c\): since \(b = 10^{-16} < \epsilon_{\text{mach}} / 2\), the floating-point addition \(1.0 + 10^{-16}\) rounds down to \(1.0\). Then \(1.0 + (-1.0) = 0.0\). 2. Compute \((a + c) + b\): first \(1.0 + (-1.0) = 0.0\). Then \(0.0 + 10^{-16} = 10^{-16}\). The results differ: \(0.0 \neq 10^{-16}\). This demonstrates that reordering summations across parallel threads alters the final computed digits.

Proof

P1 · Idempotence of Data Cleaning Pipelines

Let a data cleaning function \(f: \mathcal{D} \to \mathcal{D}\) perform cross-sectional winsorization at quantiles \([q_{\text{low}}, q_{\text{high}}]\). Prove that \(f\) is idempotent, i.e., \(f(f(D)) = f(D)\) for any data vector \(D\).

Solution

Let \(D\) be a real-valued vector, and let \(c_{\text{low}} = \text{quantile}(D, q_{\text{low}})\) and \(c_{\text{high}} = \text{quantile}(D, q_{\text{high}})\). The winsorization operator maps each element \(x \in D\) to: \[ f(x) = \min(\max(x, c_{\text{low}}), c_{\text{high}}) \] All elements of \(f(D)\) lie strictly in the closed interval \([c_{\text{low}}, c_{\text{high}}]\). When \(f\) is applied again to \(f(D)\), the quantiles of \(f(D)\) are identical to the thresholds: \(\text{quantile}(f(D), q_{\text{low}}) = c_{\text{low}}\) and \(\text{quantile}(f(D), q_{\text{high}}) = c_{\text{high}}\). For any \(y \in f(D)\), since \(c_{\text{low}} \le y \le c_{\text{high}}\), \(\min(\max(y, c_{\text{low}}), c_{\text{high}}) = y\). Therefore, \(f(f(D)) = f(D)\), proving idempotence.

P2 · Consistency of Sample Breakpoints

Let \(F(x)\) be the continuous cumulative distribution function of firm characteristic \(X\), strictly increasing on its support. Prove that the empirical quantile \(\hat{q}_p\) converges almost surely to the true population quantile \(q_p = F^{-1}(p)\) as sample size \(N \to \infty\).

Solution

Let \(F_N(x) = \frac{1}{N} \sum_{i=1}^N \indic_{\{X_i \le x\}}\) be the empirical distribution function. By the Glivenko-Cantelli theorem, \(\sup_{x \in \R} |F_N(x) - F(x)| \xrightarrow{\text{a.s.}} 0\) as \(N \to \infty\). Fix \(\epsilon > 0\). Since \(F\) is continuous and strictly increasing, \(F(q_p - \epsilon) < p < F(q_p + \epsilon)\). Almost sure uniform convergence implies that for large \(N\), \(F_N(q_p - \epsilon) < p < F_N(q_p + \epsilon)\) with probability 1. By definition of the empirical quantile \(\hat{q}_p = \inf \{x : F_N(x) \ge p\}\), this implies \(q_p - \epsilon \le \hat{q}_p \le q_p + \epsilon\). Since \(\epsilon > 0\) is arbitrary, \(\hat{q}_p \xrightarrow{\text{a.s.}} q_p\).

P3 · Linear Factor Spanning Identity

Let \(R_t\) be an \(N \times 1\) vector of asset returns and let \(F_t\) be a \(K \times 1\) vector of factor returns. Prove that the residual vector \(u_t\) from projecting \(R_t\) onto \(F_t\) has zero sample covariance with \(F_t\), regardless of whether the true economic model is correctly specified.

Solution

The OLS projection expresses \(R_t = \hat{\alpha} + \hat{\beta} F_t + \hat{u}_t\), where the coefficient matrix is \(\hat{\beta} = \widehat{\Cov}(R_t, F_t) [\widehat{\Var}(F_t)]^{-1}\). The sample covariance between \(\hat{u}_t\) and \(F_t\) is: \[ \widehat{\Cov}(\hat{u}_t, F_t) = \widehat{\Cov}(R_t - \hat{\alpha} - \hat{\beta} F_t, F_t) = \widehat{\Cov}(R_t, F_t) - \hat{\beta} \widehat{\Var}(F_t) \] Substitute the definition of \(\hat{\beta}\): \[ \widehat{\Cov}(\hat{u}_t, F_t) = \widehat{\Cov}(R_t, F_t) - \widehat{\Cov}(R_t, F_t) [\widehat{\Var}(F_t)]^{-1} \widehat{\Var}(F_t) = \widehat{\Cov}(R_t, F_t) - \widehat{\Cov}(R_t, F_t) = 0 \] Sample residual orthogonality holds algebraically by construction as a consequence of the OLS normal equations, independent of the true underlying data-generating process.

Empirical

E1 · Auditing a Non-Reproducible Anomaly Package

You download a published replication package and run python main.py. The script crashes with ModuleNotFoundError: No module named 'statsmodels'. After manually installing statsmodels, the script completes but Table 1 reports a t-statistic of 1.88 instead of the published 2.45. What failure modes occurred?

Solution

Two distinct failure modes occurred: (1) Environment specification failure: the author failed to provide a pinned dependencies manifest (such as a requirements.txt or lockfile), violating the environment specification standard. (2) Non-reproducibility / code drift: the code executed produces a different numerical result (\(t = 1.88\)) than the published exhibit (\(t = 2.45\)), indicating that the code deposited was either an earlier version, was run on a revised dataset without version freezing, or was modified after table generation.

E2 · Evaluating Database Snapshot Revisions

An author claims that their paper's replication discrepancy with an earlier 2012 study is entirely due to "Compustat database restatements." How should an independent referee verify or refute this claim?

Solution

The referee should request point-in-time Compustat snapshots or query the Compustat Unrestated / Snapshot archive available on WRDS. By comparing the 2012 historical database vintage against the modern revised vintage, the referee can isolate the exact changes in fundamental variables. If the restatements affect less than 1% of the sample's book equity values, but the anomaly return difference is 40 basis points, the author's claim is refuted.

E3 · Cryptographic Verification of Large Data Bundles

A research project processes 50 GB of intraday order-book data from NASDAQ ITCH. The university cluster administrator cannot store redundant copies. How does a replication manifest allow third-party verification without storing duplicate datasets?

Solution

The replication manifest records the raw file names, byte sizes, and SHA-256 cryptographic digests of every raw ITCH file, along with the automated parsing script. A third party possessing access to the raw ITCH archive computes local SHA-256 hashes to verify that their inputs match the author's inputs identically, then executes the pipeline to verify output tables. The manifest establishes cryptographic provenance without requiring redundant multi-gigabyte data transfers.

Research

R1 · Designing an Automated Verification Bot for Journals

Propose the architecture for an automated continuous-integration (CI) bot deployed by a top finance journal to pre-screen submitted replication packages prior to referee assignment.

Solution

The journal CI bot operates as follows: (1) Spins up an isolated, sandboxed container (Linux x86_64) with pinned base runtimes. (2) Parses the repository manifest and verifies SHA-256 digests of deposited data files. (3) Executes master_run.sh under a strict execution timeout (e.g. 2 hours) and memory limit. (4) Compares newly generated tables against submitted PDF/LaTeX exhibit tables using automated text-parsing diff tools. (5) Generates an automated verification badge: PASS (100% numerical match), WARNING (numerical differences in least significant digits due to BLAS variations), or FAIL (execution crash or table discrepancy), attaching the log directly to the editor's dashboard.

R2 · Code Transparency vs Intellectual Property in Proprietary Trading

Analyze the trade-offs between academic open-source replication standards and proprietary quantitative hedge fund operations. Can an institutional asset manager maintain scientific reproducibility internally while protecting trading alpha?

Solution

Yes. Institutional quantitative funds implement internal replication platforms (such as the Atlas platform in this doctoral curriculum) that enforce strict code review, deterministic containers, automated regression testing, and cryptographic manifests behind firewalls. Every production alpha model must replicate bit-for-bit on clean historical data before capital allocation. This enforces full internal scientific reproducibility while preventing public intellectual property leakage.

R3 · The Role of Replication Studies in Academic Career Incentives

Why have academic finance journals historically disincentivized pure replication papers, and how are open-science initiatives (e.g. Critical Finance Review, replication registries) altering the equilibrium?

Solution

Historically, journals prioritized novel theoretical claims and surprising empirical discoveries to maximize citations and journal impact factors, treating replications as derivative. This created an adverse equilibrium where false discoveries proliferated uncorrected. Specialized outlets like the Critical Finance Review and formal data editor policies now grant publication credit for rigorous replications, reducing the reputational stigma and aligning academic incentives with scientific truth.
