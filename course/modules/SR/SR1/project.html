Run Dynamics Model: Solvency Thresholds & Buffer Calibration

Extend the classical Diamond–Dybvig framework to incorporate uninsured commercial depositors and mark-to-market securities valuation shocks. You will develop a quantitative solver that calculates the fundamental solvency run threshold, calibrate the minimal prudential liquid reserve buffer required to eliminate run incentives for a target safety standard, and author an executive policy memo evaluating balance sheet vulnerabilities from the 2023 regional banking panic.

  • Deliverables: Python solver (solver.py) and executive policy memo (memo.md)
  • Grading: Graded by both autograder (test suite on solver) and rubric (5-criterion qualitative assessment of memo)
  • Data: Model parameters and calibration targets are SIMULATED.

def solve_model(uninsured_share: float, liquidation_value: float, liquid_buffer: float) -> dict[str, float]:
    """Calculate the run threshold theta* and run fraction for given bank balance sheet parameters."""
    if not (0.0 <= uninsured_share <= 1.0):
        raise ValueError("uninsured share must lie in [0, 1]")
    if not (0.0 < liquidation_value <= 1.0):
        raise ValueError("liquidation value must lie in (0, 1]")
    if not (0.0 < liquid_buffer < 1.0):
        raise ValueError("liquid buffer must lie in (0, 1)")

    if uninsured_share == 0.0 or uninsured_share <= liquid_buffer:
        return {"run_threshold": 0.0, "run_fraction": 0.0}

    raw_threshold = (uninsured_share - liquid_buffer) / (liquidation_value * (1.0 - liquid_buffer))
    run_threshold = min(1.0, max(0.0, raw_threshold))
    run_fraction = 1.0 if run_threshold > 0.0 else 0.0
    return {"run_threshold": run_threshold, "run_fraction": run_fraction}


def calibrate_buffer(target_threshold: float, uninsured_share: float, liquidation_value: float) -> float:
    """Calibrate the required liquid buffer ell to achieve target_threshold."""
    if not (0.0 <= uninsured_share <= 1.0):
        raise ValueError("uninsured share must lie in [0, 1]")
    if not (0.0 < liquidation_value <= 1.0):
        raise ValueError("liquidation value must lie in (0, 1]")
    if uninsured_share == 0.0:
        raise ValueError("target threshold is not attainable")

    max_attainable = min(1.0, uninsured_share / liquidation_value)
    if not (0.0 < target_threshold < max_attainable):
        raise ValueError("target threshold is not attainable")

    # Analytical closed-form: ell = (mu - kappa * theta) / (1 - kappa * theta)
    denom = 1.0 - liquidation_value * target_threshold
    buffer_val = (uninsured_share - liquidation_value * target_threshold) / denom
    return buffer_val

    print(f"Inputs: mu = {uninsured_share:.2f}, kappa = {liquidation_value:.2f}, ell = {liquid_buffer:.2f}")

    # Step 1: Solve model threshold
    sol = solve_model(uninsured_share, liquidation_value, liquid_buffer)
    theta_star = sol["run_threshold"]
    run_frac = sol["run_fraction"]
    print(f"Step 1: Computed Run Threshold theta* = {theta_star:.6f}, Run Fraction = {run_frac:.2f}")

    # Step 2: Calibrate buffer for target threshold
    calibrated_ell = calibrate_buffer(target_threshold, uninsured_share, liquidation_value)
    print(f"Step 2: Calibrated Buffer for Target theta*={target_threshold:.2f} ==> ell* = {calibrated_ell:.6f}")

    # Step 3: Residual verification
    verification = solve_model(uninsured_share, liquidation_value, calibrated_ell)
    residual = abs(verification["run_threshold"] - target_threshold)
    print(f"Step 3: Verification Run Threshold = {verification['run_threshold']:.6f}")
    print(f"Step 4: Calibration Residual = {residual:.2e} (Passed tolerance 1e-8)")

Specification

Context
In March 2023, regional banking institutions with heavy concentrations of uninsured deposits experienced rapid deposit flight following mark-to-market securities losses. This project tasks you with constructing a quantitative model of uninsured depositor run dynamics, analyzing the solvency run threshold \(\theta^*\), and calibrating the required regulatory liquidity buffer to prevent run contagion.
Inputs
The model consumes three primary balance sheet parameters:
  • uninsured_share (\(\mu \in [0.0, 1.0]\)): The fraction of total deposits that are uninsured.
  • liquidation_value (\(\kappa \in (0.0, 1.0]\)): The fire-sale recovery rate per unit of book value upon early asset liquidation.
  • liquid_buffer (\(\ell \in (0.0, 1.0)\)): The fraction of total deposits held in cash reserves and liquid short-term assets.
  • target_threshold (\(\theta_{\text{target}} \in (0.0, \min(1.0, \mu/\kappa))\)): The prudential target run threshold for buffer calibration.
Required outputs
You must submit two deliverables:
  1. A Python module solver.py implementing the frozen interface:
    • solve_model(uninsured_share: float, liquidation_value: float, liquid_buffer: float) -> dict[str, float]: Returns a dictionary with keys "run_threshold" (the critical fundamental threshold \(\theta^* \in [0.0, 1.0]\)) and "run_fraction" (the fraction of uninsured deposits that run at the threshold, 1.0 if \(\theta^* > 0\) else 0.0). By convention, returns {"run_threshold": 0.0, "run_fraction": 0.0} when uninsured_share == 0.0 or when uninsured_share <= liquid_buffer.
    • calibrate_buffer(target_threshold: float, uninsured_share: float, liquidation_value: float) -> float: Solves for and returns the unique liquid buffer \(\ell^* \in (0.0, 1.0)\) such that solve_model(...)["run_threshold"] equals target_threshold to within tolerance 1e-8.
  2. An executive policy memorandum memo.md (1,200–1,800 words) presenting the mathematical derivation of the model, numerical calibration findings for the 2023 regional bank episode, comparative statics analysis, and policy recommendations for liquidity regulation.
Constraints
  • Standard library only: math, fractions, random. No NumPy or SciPy dependencies inside solver.py.
  • Calculations must be performed at full double-precision floating-point precision.
  • The implementation must strictly enforce the following three exception conditions:
    • Raise ValueError("uninsured share must lie in [0, 1]") if uninsured_share < 0.0 or uninsured_share > 1.0.
    • Raise ValueError("liquidation value must lie in (0, 1]") if liquidation_value <= 0.0 or liquidation_value > 1.0.
    • Raise ValueError("target threshold is not attainable") if target_threshold lies outside the attainable open interval \((0.0, \min(1.0, \mu/\kappa))\) or if uninsured_share == 0.0.

1. Mathematical Model Formulation

We formalize the Run Dynamics Model across three dates \(t \in \{0, 1, 2\}\). Total deposits are normalized to 1, partitioned into an insured retail share \(1 - \mu\) and an uninsured commercial share \(\mu \in [0, 1]\). Assets comprise a liquid reserve buffer \(\ell \in (0, 1)\) and illiquid productive assets \(1 - \ell\). Illiquid assets yield fundamental return \(\theta \in [0, 1]\) at date 2, but recover only fraction \(\kappa \in (0, 1]\) if liquidated at date 1 under fire-sale distress.

Under sequential service, if uninsured depositors withdraw, the bank satisfies claims up to available cash \(\ell + \kappa \theta (1 - \ell)\). Setting available liquidity equal to total uninsured demand \(\mu\) yields the unique fundamental solvency threshold:

\[ \theta^* = \min\left(1.0, \max\left(0.0, \frac{\mu - \ell}{\kappa (1 - \ell)}\right)\right) \]

For any \(\theta < \theta^*\), available liquidation proceeds fall strictly short of \(\mu\), rendering running a strictly dominant best response for uninsured creditors.

2. Empirical Calibration to the 2023 Regional Bank Episode

We calibrate our solver to the balance sheet configuration of Silicon Valley Bank immediately prior to its failure in March 2023 . Based on regulatory reports, SVB exhibited an uninsured deposit share \(\mu = 0.88\), a liquid cash buffer \(\ell = 0.15\), and an estimated liquidation recovery rate \(\kappa = 0.70\) under forced asset sales . Evaluating solve_model(0.88, 0.70, 0.15) yields a baseline run threshold of \(\theta^* = 1.000000\). Because \(\mu - \ell = 0.73\) exceeds \(\kappa (1 - \ell) = 0.70 \times 0.85 = 0.595\), the bank was structurally insolvent under a full run even under perfect asset quality (\(\theta = 1.0\)).

To eliminate run vulnerability and achieve a conservative prudential target threshold of \(\theta_{\text{target}} = 0.35\), we calibrate the required liquid buffer using our closed-form inverse mapping:

\[ \ell^* = \frac{\mu - \kappa \theta_{\text{target}}}{1 - \kappa \theta_{\text{target}}} = \frac{0.88 - 0.70 \times 0.35}{1.0 - 0.70 \times 0.35} = \frac{0.6350}{0.7550} = 0.841060 \]

Verification via solve_model(0.88, 0.70, 0.841060) returns \(\theta^* = 0.350000\) with a numerical residual of \(3.33 \times 10^{-16} \le 10^{-8}\). This demonstrates that preventing runs at SVB without deposit insurance would have required holding 84.11% of deposits in cash reserves.

Exemplar B · Low Pass (Level 2)

Model Overview

The bank has deposits, some of which are uninsured (\(\mu\)), and holds cash (\(\ell\)) and loans. When people run, the bank sells loans at a discount (\(\kappa\)). The run condition happens when cash plus loan sales cannot pay the depositors. The formula is \(\theta^* = (\mu - \ell) / (\kappa(1 - \ell))\).

SVB Run

At Silicon Valley Bank, uninsured deposits were around 90%, and cash was small, maybe 15%. When rates went up, bond prices fell. People saw this on Twitter and withdrew their money. Our code gives a run threshold of 1.0, which means everyone ran. If the regulator wants a safer threshold like 0.35, the bank needs more cash, about 84%. The bank failed because depositors panicked.
