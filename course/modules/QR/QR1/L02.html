Data Vintages & Bitemporal Data Models

Macroeconomic indicators and corporate accounting metrics are not static historical facts; they are evolving estimates subject to successive revisions, benchmark adjustments, and restatements over decades. When a quantitative backtest consumes the modern, fully revised series from a traditional database, it tests strategies on economic signals that no living trader could have observed. Bitemporal data models and immutable data vintages preserve the exact historical state of knowledge, eliminating revision look-ahead bias.

1. The Nature of Economic Revisions

Government statistical agencies (such as the US Bureau of Economic Analysis and Bureau of Labor Statistics) operate under a trade-off between timeliness and accuracy. Initial releases (often designated advance or preliminary estimates) rely on incomplete survey returns, statistical sampling, and seasonal projection models.

As comprehensive administrative records, tax filings, and trade surveys arrive over subsequent months, agencies publish second, third, and annual benchmark revisions. In a foundational paper on real-time macroeconomic datasets, Croushore & Stark (2001) demonstrated that macroeconomic forecasting models and policy rules produce substantially different empirical findings when tested on real-time data vintages rather than post-revision series.

Example 2.1 · Real-Time GDP Growth Revisions

Consider real annualized quarterly GDP growth for 2025-Q3. The initial advance estimate released in October 2025 was 2.8%. In November 2025, additional corporate inventory data adjusted the figure to 3.1% (second estimate). In December 2025, revised trade balance figures brought the final quarterly estimate to 2.9%. In July 2026, the annual comprehensive benchmark revision restated 2025-Q3 GDP growth to 3.4%. A macro trend-following strategy operating on November 15, 2025, had access only to the 2.8% figure. Feeding 3.4% into the strategy's historical feature pipeline assumes foresight of statistical revisions published nine months in the future.

2. Data Vintages and Historical Snapshotting

To eliminate revision look-ahead bias, financial data stores must record time series not as one-dimensional vectors \(x(t)\), but as two-dimensional surfaces indexed by observation time and publication instant.

Data Vintage

Let \(t \in \mathcal{T}_{\mathrm{obs}}\) denote an observation period or date (such as a calendar day, month, or quarter). A data vintage \(\mathcal{V}_\tau\) at publication timestamp \(\tau \in \mathbb{T}\) is the complete sequence of observed values for all historical periods \(t \le \tau\) as published and accessible at instant \(\tau\):

\[ \mathcal{V}_\tau = \left\{ (t, v) \in \mathcal{T}_{\mathrm{obs}} \times \mathbb{R} : \text{value of observation } t \text{ known at instant } \tau \text{ was } v \right\} \]

A sequence of vintages \(\{\mathcal{V}_{\tau_1}, \mathcal{V}_{\tau_2}, \dots\}\) indexed by strictly increasing publication timestamps \(\tau_1 < \tau_2 < \dots\) forms a historical vintage matrix. Each row represents a fixed observation date \(t\), while each column represents a publication instant \(\tau\). When an economic agency restates historical values, it generates a new column without modifying prior columns.

3. The Bitemporal Data Model

Relational databases that overwrite rows in place discard past data vintages. The bitemporal data model provides the formal database architecture required to store evolving historical knowledge immutably.

Bitemporal Data Model

A bitemporal data model is a database schema where every recorded state fact \(x\) is indexed along two independent, orthogonal temporal dimensions:

  1. Valid Time (\(T_V\)): The real-world calendar instant or interval \([t_{\mathrm{start}}, t_{\mathrm{end}})\) during which the fact was true in the real economy.
  2. Transaction Time (\(T_X\)): The system instant or interval \([\tau_{\mathrm{start}}, \tau_{\mathrm{end}})\) during which the fact was current in the database and visible to external queries.

A bitemporal table is append-only: when a revision is received at instant \(\tau_{\mathrm{new}}\), the existing active record has its transaction interval closed (\(\tau_{\mathrm{end}} \leftarrow \tau_{\mathrm{new}}\)), and a new record is appended with transaction interval \([\tau_{\mathrm{new}}, \infty)\).

Proposition 2.1 · Point-in-Time Visibility Invariance

Let \(\mathcal{V} = \{(t_i, \tau_i, v_i, s_i)\}_{i=1}^n\) be a collection of stored vintages for a fixed series, where \(t_i\) is the observation date, \(\tau_i\) is the publication timestamp, \(v_i\) is the published value, and \(s_i\) is an internal monotonic ingestion sequence counter. Assume:

  • A1 (Publication Timestamping): \(\tau_i\) is recorded accurately for every vintage.
  • A2 (Visibility Query Function): For any cut-off instant \(T\), the visible value \(v^*(t, T)\) is the value of the record maximizing \((\tau_i, s_i)\) subject to \(\tau_i \le T\): \[ i^*(t, T) = \arg\max_{i: t_i = t, \tau_i \le T} (\tau_i, s_i), \quad v^*(t, T) = v_{i^*(t, T)} \] with \(v^*(t, T) = \mathrm{None}\) if \(\{i: t_i = t, \tau_i \le T\} = \emptyset\).
  • A3 (Non-Causal Isolation): Records with \(\tau_i > T\) are strictly excluded from \(i^*(t, T)\).

Then for any cut-off instant \(T\), the visible value \(v^*(t, T)\) is invariant under the subsequent recording of any future vintage \((t, \tau_{\mathrm{new}}, v_{\mathrm{new}}, s_{\mathrm{new}})\) satisfying \(\tau_{\mathrm{new}} > T\).

Proof

Let \(\mathcal{S}_T = \{i \in \{1, \dots, n\} : t_i = t \land \tau_i \le T\}\) be the candidate index set at cut-off \(T\). By A2, the visible index is \(i^* = \arg\max_{i \in \mathcal{S}_T} (\tau_i, s_i)\), which is completely determined by \(\mathcal{S}_T\).

Suppose a new vintage is appended to the store: \(\mathcal{V}' = \mathcal{V} \cup \{(t, \tau_{\mathrm{new}}, v_{\mathrm{new}}, s_{\mathrm{new}})\}\) with \(\tau_{\mathrm{new}} > T\). The new candidate set evaluated at cut-off \(T\) is:

\[ \begin{aligned} \mathcal{S}'_T &= \{j \in \mathcal{V}' : t_j = t \land \tau_j \le T\} \\ &= \mathcal{S}_T \cup \left(\{n+1\} \cap \{j : \tau_{n+1} \le T\}\right) \end{aligned} \]

Because \(\tau_{n+1} = \tau_{\mathrm{new}} > T\), the condition \(\tau_{n+1} \le T\) is false, and \(\{n+1\} \cap \{j : \tau_{n+1} \le T\} = \emptyset\). Thus \(\mathcal{S}'_T = \mathcal{S}_T\). Because the candidate index set is identical, \(\arg\max_{j \in \mathcal{S}'_T} (\tau_j, s_j) = i^*\), and the visible query output is unchanged: \(v^*(t, T)' = v^*(t, T)\). This proves point-in-time visibility invariance.

Lab 1 · Macroeconomic Revision Trajectory and Proposition 2.1 Verification

Simulates the multi-stage revision history of a GDP growth estimate, computes point-in-time revision gaps against final benchmark numbers, and numerically confirms Proposition 2.1 invariance.

"""QR1 Lesson 2 Inline Lab 1: Data vintages and bitemporal point-in-time visibility.

Demonstrates tracking macroeconomic data revisions across historical publication vintages,
computes real-time revision gaps, and numerically verifies Proposition 2.1
(point-in-time visibility invariance).
Data: SIMULATED GDP revision trajectory.
"""

from __future__ import annotations

from typing import NamedTuple


class Vintage(NamedTuple):
    obs_date: str
    published: str  # YYYY-MM-DDTHH:MM:SSZ
    value: float
    description: str


def query_visible_vintage(vintages: list[Vintage], cutoff: str) -> Vintage | None:
    """Return the vintage with the latest publication timestamp at or before cutoff."""
    eligible = [v for v in vintages if v.published <= cutoff]
    if not eligible:
        return None
    return max(eligible, key=lambda v: v.published)


def main() -> None:
    # SIMULATED revision sequence for 2025-Q3 real annualized GDP growth rate (%)
    obs_date = "2025-Q3"
    revision_history: list[Vintage] = [
        Vintage(obs_date, "2025-10-30T12:30:00Z", 2.8, "Advance estimate"),
        Vintage(obs_date, "2025-11-26T13:30:00Z", 3.1, "Second estimate"),
        Vintage(obs_date, "2025-12-23T13:30:00Z", 2.9, "Third estimate"),
        Vintage(obs_date, "2026-07-30T12:30:00Z", 3.4, "Annual benchmark revision"),
    ]

    final_revised_value = revision_history[-1].value
    print(f"Tracking revision trajectory for {obs_date} GDP growth:")
    for v in revision_history:
        print(f"  Published {v.published}: {v.value:4.1f}% ({v.description})")

    # Evaluation decision cut-offs
    cutoffs = [
        ("2025-11-15T00:00:00Z", "Post-Advance (pre-Second)"),
        ("2025-12-01T00:00:00Z", "Post-Second (pre-Third)"),
        ("2026-01-15T00:00:00Z", "Post-Third (pre-Benchmark)"),
        ("2026-08-15T00:00:00Z", "Post-Benchmark"),
    ]

    print("\nPoint-in-time queries and revision gaps against final figure (3.4%):")
    for cutoff_ts, label in cutoffs:
        v_vis = query_visible_vintage(revision_history, cutoff_ts)
        assert v_vis is not None
        gap = v_vis.value - final_revised_value
        print(f"  Cut-off {cutoff_ts} [{label}]: visible={v_vis.value:.1f}% gap={gap:+.1f}%")

    # Proposition 2.1 Numerical Verification:
    # Visible value at cutoff T must be invariant under addition of vintages published after T.
    cutoff_t1 = "2025-11-15T00:00:00Z"
    sub_history_t1 = [v for v in revision_history if v.published <= cutoff_t1]
    val_before_add = query_visible_vintage(sub_history_t1, cutoff_t1)
    val_after_add = query_visible_vintage(revision_history, cutoff_t1)

    assert val_before_add is not None and val_after_add is not None
    invariance_holds = val_before_add.value == val_after_add.value
    print(f"\nProposition 2.1 Invariance Test at {cutoff_t1}:")
    print(f"  Value visible using only contemporaneous history: {val_before_add.value:.1f}%")
    print(f"  Value visible after appending subsequent revisions: {val_after_add.value:.1f}%")
    print(f"  Invariance property verified: {invariance_holds}")


main()

4. Where the Canon Breaks

Traditional database architectures and standard econometric workflows routinely fail when managing data vintages:

  • Overwriting Historical Records in Place: Relational schemas using UPDATE macro_series SET value = ? WHERE date = ? destroy historical vintages. Once an update runs, previous observations vanish, making it impossible to reconstruct the state of knowledge available on any historical trading date.
  • Omission of Publication Timestamps: Vendors who distribute "point-in-time" databases often provide an effective observation date and an ingestion date, but fail to capture the exact minute when the statistical press release crossed public news feeds.
  • Non-Stationarity of Macro Revisions: Econometric models frequently assume revisions are white noise (zero mean and uncorrelated). Empirical studies demonstrate that initial macroeconomic estimates carry predictable directional revision drift (for example, underestimating growth during business cycle turning points), meaning post-revision data introduces severe structural look-ahead bias.

5. Common Misconceptions

  1. "Using the latest fully revised macroeconomic data produces a superior backtest because it reflects the most accurate economic truth."

    Trading strategies cannot trade economic truth that was unknown at the decision instant. Conditioning trades on benchmark revisions published years later produces phantom alpha that collapses in live execution.

  2. "A bitemporal model requires duplicating the entire database table on every revision."

    Bitemporal schemas are delta-compressed: only modified observations generate new rows. Immutable append-only tables indexed by valid date and transaction timestamp store millions of vintages with minimal storage overhead.

  3. "Financial statements (10-K and 10-Q) become publicly available on the final day of the fiscal quarter."

    SEC filing regulations grant companies 40 to 90 days after quarter-end to file official statements. Operating on quarter-end dates assumes quarterly earnings were known months before they were filed on EDGAR.

6. Problem Set

Tier 1 · Mechanics

An economic series for observation date 2025-01-01 has three recorded vintages: \((\tau_1 = \text{2025-02-01T12:00:00Z}, v_1 = 100.0)\), \((\tau_2 = \text{2025-03-01T12:00:00Z}, v_2 = 102.5)\), and \((\tau_3 = \text{2025-04-01T12:00:00Z}, v_3 = 101.8)\). Determine the visible value at cut-offs \(T_A = \text{2025-01-15T00:00:00Z}\), \(T_B = \text{2025-02-15T00:00:00Z}\), and \(T_C = \text{2025-03-15T00:00:00Z}\).

Solution

At \(T_A\), no vintage has \(\tau_i \le T_A\); hence the visible value is None. At \(T_B\), only \(\tau_1 \le T_B\); the visible value is \(v_1 = 100.0\). At \(T_C\), both \(\tau_1\) and \(\tau_2\) satisfy \(\tau_i \le T_C\); the maximum timestamp is \(\tau_2\), yielding visible value \(v_2 = 102.5\).

Calculate the revision gap \(\Delta v = v_{\mathrm{prelim}} - v_{\mathrm{final}}\) for a non-farm payrolls observation where the initial advance release reported \(+180\text{k}\) jobs and the final benchmark revision restated the figure to \(+135\text{k}\) jobs.

Solution

The revision gap is \(\Delta v = 180 - 135 = +45\text{k}\). The preliminary report overestimated job growth by 45,000 jobs. A strategy backtested on the final 135k figure would assume a weaker macro signal than was actually observed by market participants at release.

Write an SQL query to retrieve the prevailing visible value for series 'GDP' and observation date '2025-Q1' as of cut-off timestamp '2025-05-01T00:00:00Z' from an append-only bitemporal table vintages(series, obs_date, value, published, seq).

Solution

The standard point-in-time SQL query is: SELECT value FROM vintages WHERE series = 'GDP' AND obs_date = '2025-Q1' AND published <= '2025-05-01T00:00:00Z' ORDER BY published DESC, seq DESC LIMIT 1;. This enforces non-strict inequality and breaks timestamp ties using the monotonic insertion sequence counter.

Tier 2 · Proof

Prove that if publication timestamps \(\tau_i\) are strictly increasing with insertion sequence counter \(s_i\) for a given observation date, the relation \(\preceq\) defined by \(i \preceq j \iff \tau_i \le \tau_j\) defines a total preorder on vintages.

Solution

Reflexivity: For any vintage \(i\), \(\tau_i \le \tau_i\), so \(i \preceq i\). Transitivity: If \(i \preceq j\) and \(j \preceq k\), then \(\tau_i \le \tau_j \le \tau_k\), which implies \(\tau_i \le \tau_k\), so \(i \preceq k\). Completeness: For any two vintages \(i\) and \(j\), by totality of real numbers, either \(\tau_i \le \tau_j\) or \(\tau_j \le \tau_i\), hence either \(i \preceq j\) or \(j \preceq i\). This proves \(\preceq\) is a total preorder. Furthermore, tie-breaking with strict sequence \(s_i\) promotes the preorder to a strict total order.

Prove that an append-only bitemporal store is idempotent under re-ingestion of an identical vintage tuple \((t, \tau, v)\).

Solution

Let \(\mathcal{V}\) be the set of stored vintages. An ingestion operator \(\Phi((t, \tau, v), \mathcal{V})\) is idempotent if \(\Phi((t, \tau, v), \Phi((t, \tau, v), \mathcal{V})) = \Phi((t, \tau, v), \mathcal{V})\). By the contract rule, if a tuple with key \((t, \tau)\) already exists in \(\mathcal{V}\) with identical value \(v\), the operator performs a no-op: \(\Phi((t, \tau, v), \mathcal{V}) = \mathcal{V}\). Applying \(\Phi\) a second time encounters the existing record, returning \(\mathcal{V}\) again. Thus \(\Phi \circ \Phi = \Phi\), establishing idempotence.

Prove that any point-in-time visibility query function satisfying Proposition 2.1 is a monotonic step function with respect to cut-off time \(T\).

Solution

Let \(v^*(T)\) be the visible value for fixed observation date \(t\) as a function of cut-off \(T\). Let \(\{\tau_1 < \tau_2 < \dots < \tau_m\}\) be the distinct publication timestamps of vintages for \(t\). For \(T < \tau_1\), \(v^*(T) = \mathrm{None}\). For \(T \in [\tau_k, \tau_{k+1})\), the candidate set \(\{i : \tau_i \le T\}\) equals \(\{i : \tau_i \le \tau_k\}\), which is constant. Therefore, \(v^*(T)\) is piecewise constant on each half-open interval \([\tau_k, \tau_{k+1})\) with potential discontinuities only at publication instants \(\tau_k\), which defines a step function.

Tier 3 · Empirical

In an empirical study of quarterly corporate earnings announcements, 12% of preliminary revenue releases are restated in annual 10-K filings. If the average restatement reduces reported revenue by 3.2%, calculate the expected percentage bias in preliminary price-to-sales ratios.

Solution

Let true final revenue be \(S_{\mathrm{final}}\). Preliminary revenue is \(S_{\mathrm{prelim}} = S_{\mathrm{final}} / (1 - 0.032) \approx 1.033 \times S_{\mathrm{final}}\) for the 12% of restated firms. The expected preliminary revenue across the population is \(E[S_{\mathrm{prelim}}] = 0.88 \times S_{\mathrm{final}} + 0.12 \times 1.033 \times S_{\mathrm{final}} = 1.004 \times S_{\mathrm{final}}\). Because the price-to-sales ratio is \(P/S\), an overstatement of sales by 0.4% causes reported \(P/S\) to be understated by approximately 0.4% in preliminary data.

Describe how a research team can measure whether an equity factor's simulated Sharpe ratio is artificially inflated by revision look-ahead bias.

Solution

The team executes dual backtests on identical asset universes and transaction cost models: (1) Backtest A using real-time publication vintages (\(\mathcal{V}_\tau\)); (2) Backtest B using the modern fully revised historical series. The look-ahead alpha distortion is \(\Delta \mathrm{SR} = \mathrm{SR}_B - \mathrm{SR}_A\). If \(\Delta \mathrm{SR} > 0.3\), the strategy's apparent backtest profitability is predominantly driven by post-hoc revisions that were unobservable in live trading.

During macroeconomic regime shifts (such as the onset of a recession), initial employment figures frequently underestimate job losses. Explain how this systematic revision error impacts trend-following CTA strategies.

Solution

If preliminary data underestimates economic deterioration, a trend-following model using contemporaneous vintages reacts more slowly to the downturn, taking short positions later. Backtesting on post-revision data shows sharp, immediate economic collapses, leading the model to initiate short positions prematurely in the simulation. The backtest appears to catch turning points with zero lag, creating unrealistic expectations for live drawdown mitigation.

Tier 4 · Research

Evaluate the architectural trade-offs between storing full snapshot tables versus delta event-sourcing in an enterprise bitemporal quantitative data store.

Solution

Full snapshot tables store the complete time series state for every publication vintage \(\tau\). This optimizes query latency (simple index seek on \(\tau\)) but incurs \(O(N \cdot M)\) storage amplification where \(N\) is history length and \(M\) is vintage count. Delta event-sourcing stores only modified cells with valid intervals \([t_{\mathrm{start}}, t_{\mathrm{end}}) \times [\tau_{\mathrm{start}}, \tau_{\mathrm{end}})\), achieving minimal \(O(N + K)\) storage where \(K\) is total revisions. However, point-in-time reconstruction requires temporal range filtering and window aggregation, increasing query compute cost.

How does the bitemporal data model interact with machine learning feature stores (such as Feast or Hopsworks) that compute rolling feature aggregations?

Solution

Feature stores compute aggregations like 90-day rolling mean volatility. In a bitemporal engine, the feature store must evaluate features as-of cut-off timestamp \(T\): all raw input observations entering the rolling window \([T - 90\,\text{days}, T]\) must satisfy transaction time \(\tau \le T\). If the feature store computes rolling features using modern database rows, revisions to data within the 90-day window contaminate the model training set with future restatements, causing catastrophic test-set leakage.

Analyze how Croushore & Stark's (2001) real-time dataset revolutionized the empirical validation of the Taylor rule in monetary economics.

Solution

The Taylor rule posits that central banks set policy rates in response to inflation and the output gap. Early empirical tests using modern revised data found high \(R^2\) fits and concluded central banks closely tracked the rule. Croushore & Stark demonstrated that real-time output gap estimates available to the Federal Reserve were dramatically different from revised figures (often differing by several percentage points and even changing sign). When evaluated on real-time vintages, the Taylor rule fit deteriorated significantly, proving that apparent historical policy adherence was an artifact of hindsight revision bias.
