Rung 1 · Worked example

In quantitative asset management, machine learning models frequently display stellar backtested Sharpe ratios yet fail catastrophically upon live deployment. This failure stems from three subtle forms of information leakage: lookahead in feature observation timestamps, overlapping holding-period label contamination across validation folds, and uncalibrated black-box feature interactions. The following worked workflow demonstrates how an institutional ML pipeline isolates and audits each stage.

Step 1: Point-in-Time Feature Registration

Suppose an earnings-to-price ratio is announced after market close on bar \(t=10\). A query executed at decision time \(t_{\text{query}} = 10\) must receive only the prior value from \(t=5\), because the new accounting figure was not physically accessible prior to market close. The feature store strictly enforces:

\[ v^*(e, f, t_{\text{query}}) = v(e, f, t^*), \quad t^* = \max \{ t_{\text{obs}} \le t_{\text{query}} \} \]

Step 2: Purged Validation Partitioning

When predicting forward 5-day cumulative excess returns \(y_t = (P_{t+5} - P_t) / P_t\), evaluating a test fold spanning \([j_{\text{start}}, j_{\text{end}}] = [50, 99]\) requires removing training observations near the boundaries. Any training observation \(i\) whose label window \([i, i + 4]\) touches \([50, 99]\) leaks future return information. Left-purging drops training observations in \([46, 99]\), while a 2% embargo drops observations in \([100, 105]\), eliminating autoregressive feature memory.

Step 3: Sparse Factor Shrinkage and TreeSHAP Audit

Fitting an \(L_1\)-regularized LASSO estimator via cyclical coordinate descent drives coefficients of collinear noise factors to zero using soft-thresholding:

\[ \beta_j \leftarrow \frac{\mathcal{S}\left(\frac{1}{N} X_{:,j}^\top (y - \hat{y}^{(-j)}), \alpha\right)}{\frac{1}{N} X_{:,j}^\top X_{:,j}} \]

For nonlinear tree architectures, exact TreeSHAP verifies that every individual prediction decomposes additively into a base expected market return \(\phi_0\) plus explicit feature contributions \(\phi_j(x)\), satisfying local accuracy without heuristics.

Rung 3 · Independent project deliverable (Atlas Milestone A17)

Implement the complete Atlas milestone A17 contract in atlas/ml.py conforming exactly to atlas/A17.contract.md.

Specification

Context
In production systematic investing, predictive statistical models frequently encounter severe out-of-sample breakdown due to feature lookahead bias, label window overlap, and unconstrained model variance in low signal-to-noise ratio regimes. This milestone provides an institutional-grade, causality-enforcing machine learning framework that isolates validation boundaries, regularizes linear and nonlinear predictors, explains model decisions via Shapley attributions, and governs deployment lifecycle states.
Inputs
  • X / x_mat: 2D NumPy array of shape \((N, P)\) representing historical asset characteristics or macroeconomic time series.
  • y / y_vec: 1D NumPy array of shape \((N,)\) representing target future asset returns or excess benchmark returns.
  • store_events: Sequence of entity-timestamped feature observations \((t_{\text{obs}}, f, v)\) for point-in-time state reconstruction.
  • query_keys: List of \((e, t_{\text{query}})\) tuples requesting as-of feature values at historical decision timestamps.
Required outputs
A single Python module atlas/ml.py exporting:
  • FeatureStore: Point-in-time feature store with register_entity, add_feature_record, get_point_in_time, and as_of_join.
  • PurgedKFold(n_splits, label_lookahead, embargo_pct): Cross-validation split generator with exact left-purging and post-test embargo.
  • CombinatorialPurgedCV(n_groups, k_test_groups, label_lookahead, embargo_pct): Combinatorial split generator.
  • Estimators: RidgeRegressor, LassoRegressor, DecisionTreeRegressor, RandomForestRegressor, GradientBoostingRegressor, NeuralNetworkRegressor.
  • TreeSHAPExplainer(model): Feature attribution engine computing exact Shapley values satisfying local additivity.
  • ModelRegistry & ModelLifecycleState: Model governance tracking DRAFT → VALIDATED → DEPLOYED → RETIRED.
  • evaluate_ml_strategy(predictions, forward_returns, lag): Strategy evaluation engine enforcing strictly positive execution lag \(\tau_{\text{lag}} \ge 1\).
Constraints
  • All functions and classes must validate inputs, raising ValueError on invalid configurations.
  • Point-in-time queries at \(t_{\text{query}}\) must never access observations with \(t_{\text{obs}} > t_{\text{query}}\).
  • Execution lag in strategy evaluation must be strictly positive: \(\tau_{\text{lag}} \ge 1\).
  • Code must be fully typed, warning-free, and clean under mypy --strict and ruff.
Grading
The module is evaluated by an automated autograder test suite across 50 consecutive pseudo-random market seeds (seeds 0–49). To pass, all tests must succeed within 60 seconds.
