Data, Databases & SQL

Quantitative finance demands absolute rigor in data engineering: historical models cannot tolerate look-ahead contamination, key multiplicity explosion, or unverified data revisions. CS3 establishes the computational and relational foundations of modern financial databases. It covers Codd's relational model and algebra, SQL joins and duplicate-key cardinality identities, window frame aggregations, temporal ASOF joins between trades and quotes, bitemporal point-in-time data discipline, database index performance, columnar storage and projection pruning in DuckDB and Parquet, and cryptographic data manifests. The module culminates in Atlas Milestone A2: building the core research data layer store with point-in-time schemas and bit-for-bit SHA-256 tamper verification.

  • Prerequisites: CS1 Programming in Python from Zero.
  • Project: Atlas A2: data layer, graded by autograder.
  • Milestone: Atlas A2 (research data layer store and manifest).

64 h lessons · 16 h project (20%)

Objectives

By the end of CS3 you can:

  1. Formalize relational schemas and algebra operations to prove relational closure and data integrity invariants (Lesson 1).
  2. Construct SQL inner, outer, and cross joins, and verify duplicate-key cardinality expansion identities on financial tables (Lesson 2).
  3. Apply SQL window functions and frame specifications to calculate rolling time-series metrics without collapsing relation cardinality (Lesson 3).
  4. Execute deterministic ASOF joins aligning asynchronous trade executions with prevailing quotes while enforcing strict no-look-ahead invariants (Lesson 4).
  5. Implement point-in-time data ingestion and bitemporal querying to prevent look-ahead bias from macroeconomic and financial restatements (Lesson 5).
  6. Analyze database indexing mechanisms and query execution plans to minimize page I/O and row comparisons (Lesson 6).
  7. Differentiate columnar storage from row-oriented storage layouts and quantify I/O bandwidth reduction from projection pruning (Lesson 7).
  8. Build an immutable data layer manifest with SHA-256 cryptographic digests to ensure bit-for-bit research reproducibility and tamper detection (Lesson 8).

Placement diagnostic

Ten questions: eight on prerequisite CS1 and P0.1 foundations, and two skill checks testing what rungs 1 and 2 of the project teach. The mastery threshold is 80 percent (at least eight of ten correct). To place out of rungs 1 and 2, you must achieve the mastery threshold and answer both skill checks correctly.

  1. In an ASOF join between a trade at timestamp \(t_{\text{trade}} = \text{10:00:05.100}\) and quote updates at \(t_1 = \text{10:00:04.900}\), \(t_2 = \text{10:00:05.100}\), and \(t_3 = \text{10:00:05.150}\), which quote is selected?

    Options

    An ASOF join admits all observations satisfying \(t_{\text{quote}} \le t_{\text{trade}}\) and takes the maximal candidate. Because \(t_2 = t_{\text{trade}}\), it qualifies and dominates \(t_1\). Rung 1 skill check.

  2. Under the Atlas A2 data layer contract, what must open_store do if called with an empty path string ""?

    Options

    The Atlas A2 contract explicitly requires open_store to validate its path argument and raise ValueError naming the condition if the path is empty. Rung 2 skill check.

  3. What does Codd's principle of relational closure state?

    Options

    Relational closure guarantees that operators take relations as inputs and return relations as outputs, enabling unlimited mathematical composition.

  4. If symbol AAPL appears 3 times in relation L and 4 times in relation R, how many rows will AAPL produce in an inner equi-join \(L \bowtie R\)?

    By the duplicate-key multiplication identity, the inner join produces \(n_L \times n_R = 3 \times 4 = 12\) rows.

  5. Which SQL window function clause ensures that peer rows with identical ordering values are treated as distinct physical offsets?

    Options

    ROWS counts physical row offsets regardless of duplicate values, whereas RANGE groups peer rows sharing the same ordering value.

  6. What is point-in-time data discipline designed to prevent in backtesting?

    Options

    Point-in-time discipline ensures that the backtest at simulated time \(t\) can only access observations published and known at or prior to \(t\).

  7. What is the primary I/O advantage of columnar storage over row-oriented storage in analytical queries?

    Options

    Columnar storage allows the storage engine to read only the contiguous disk blocks for queried columns, avoiding scanning unneeded fields.

  8. What does a B-tree database index reduce search time complexity to for key lookups?

    Options

    Balanced search tree indexes provide logarithmic lookup time \(O(\log N)\) compared to \(O(N)\) linear table scans.

  9. Why does a research data manifest record the SHA-256 cryptographic hash of raw data payloads?

    Options

    Cryptographic hashes provide an immutable fingerprint: if even a single byte in the raw dataset changes, the SHA-256 digest changes completely.

  10. In Python static type annotations, which typing construct specifies a tuple of arbitrary length containing strings?

    Options

    In Python 3.9+, tuple[str, ...] represents a homogeneous tuple of variable length containing string elements.

Lessons

L01 · 8 h The Relational Model Relations as sets of n-tuples, domains, schemas, relational algebra operations (selection, projection, Cartesian product, union, difference, join), and relational closure. L02 · 8 h SQL Joins Equi-joins, inner joins, left outer joins, right outer joins, full outer joins, cross joins, NULL semantics, and the duplicate-key cardinality multiplication identity. L03 · 8 h SQL Window Functions The OVER clause, PARTITION BY, ORDER BY, framing rules (ROWS vs RANGE BETWEEN), running totals, moving averages, and ranking functions without collapsing cardinality. L04 · 8 h ASOF Joins Temporal matching of asynchronous market event streams, joining trades to prevailing quotes, deterministic tie-breaking on ingestion sequence, and no-look-ahead invariants. L05 · 8 h Point-in-Time Data Bitemporal data architecture, distinguishing valid event time from publication knowledge time, handling restatements from macroeconomic and corporate filings, and eliminating look-ahead bias. L06 · 8 h Database Indexes Index structures, B-trees, sorted primary keys, secondary indexes, covering indexes, query plans, search complexity (O(N) scan vs O(log N) lookup), and write amplification. L07 · 8 h Columnar Storage & Parquet Row-oriented (NSM) vs columnar (DSM) layouts, projection pruning, vectorized query execution, DuckDB embeddable analytics, and Apache Parquet row groups and pages. L08 · 8 h The Data Manifest Research reproducibility, immutable data provenance, SHA-256 cryptographic hashing of payload bytes, bit-for-bit tamper detection, and idempotence vs conflict detection.

Project ladder

The four-rung project ladder bridges conceptual relational database theory with production-grade quantitative research data architecture.

  1. Rung 1 · Worked example A fully implemented instance of the point-in-time store, demonstrating CSV ingestion, manifest generation, and as-of lookup querying on simulated macroeconomic tables.
  2. Rung 2 · Completion problem The core data layer implementation with key components removed: fill the missing timestamp validation, cryptographic hashing, and as-of SQL querying logic with instant feedback.
  3. Rung 3 · Independent project deliverable Atlas Milestone A2: build the complete research data layer package (atlas.dataset) implementing the SQLite point-in-time store, ingestion for FRED, French, Shiller, Treasury, and EDGAR, and cryptographic manifest verification.
  4. Rung 4 · Stretch goal Extend the data layer with partitioned columnar snapshots or develop a high-throughput parallel ingestion pipeline with asynchronous batch hashing.
