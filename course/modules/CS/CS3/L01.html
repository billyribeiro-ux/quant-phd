The Relational Model

Financial data integrity requires mathematical precision. Ad-hoc spreadsheets and hierarchical tree stores suffer from update anomalies, unconstrained data redundancy, and silent schema drift. Edgar F. Codd formulated the relational model to separate the logical mathematical structure of data from its physical hardware layout. Grounding financial records in first-order predicate logic and set theory guarantees algebraic closure, unambiguous query semantics, and verifiable consistency constraints across trade ledgers and market feeds.

1Mathematical Foundations of Relations

Codd introduced the relational model to eliminate dependency on tree-structured and network pointer navigation in large data banks.

Definition 1.1 (Relational Model, Domain, and Relation)

The relational model represents all data as mathematical relations over sets of atomic domains. Given \(n\) sets \(D_1, D_2, \dots, D_n\) (not necessarily distinct) termed domains, an \(n\)-ary relation \(R\) is a subset of the Cartesian product \(D_1 \times D_2 \times \dots \times D_n\): \[ R \subseteq D_1 \times D_2 \times \dots \times D_n = \{(d_1, d_2, \dots, d_n) : d_i \in D_i \text{ for each } i = 1, \dots, n\}. \] The elements of \(R\) are called \(n\)-tuples. The number of attributes \(n\) is the degree of \(R\), and the number of tuples \(|R|\) is the cardinality of \(R\).

Remark 1.1 (Properties of Relations)

By set-theoretic definition, a relation possesses four fundamental properties (Codd, 1970, Section 1.3): (1) all tuples are distinct (no duplicate rows); (2) the ordering of tuples is mathematically insignificant; (3) attributes are identified by names rather than positional indices; and (4) every attribute value is atomic (indivisible in the domain).

2Relational Algebra and Closure

Relational algebra consists of a formal collection of operators that take one or more relations as operands and evaluate to a new relation.

Definition 1.2 (Primitive Relational Operators)

Let \(R\) and \(S\) be relations with schema \(\operatorname{attr}(R)\) and \(\operatorname{attr}(S)\):

  1. Selection (\(\sigma_\theta\)): Filters tuples satisfying propositional condition \(\theta\): \[ \sigma_\theta(R) = \{t \in R : \theta(t) = \text{true}\}. \]
  2. Projection (\(\pi_A\)): Restricts tuples to attribute subset \(A \subseteq \operatorname{attr}(R)\) and eliminates duplicate projected tuples: \[ \pi_A(R) = \{t[A] : t \in R\}. \]
  3. Cartesian Product (\(\times\)): Pairs every tuple of \(R\) with every tuple of \(S\): \[ R \times S = \{(t_r, t_s) : t_r \in R, t_s \in S\}. \]
  4. Set Difference (\(\setminus\)): Returns tuples present in \(R\) and absent in union-compatible \(S\): \[ R \setminus S = \{t \in R : t \notin S\}. \]
  5. Set Union (\(\cup\)): Returns tuples present in union-compatible \(R\) or \(S\): \[ R \cup S = \{t : t \in R \lor t \in S\}. \]

Theorem 1.1 (Relational Closure Invariant)

Let \(\mathcal{U}\) denote the universe of all well-formed relations over atomic domains. For any relations \(R, S \in \mathcal{U}\) and valid relational operators \(\omega \in \{\sigma, \pi, \times, \cup, \setminus, \bowtie\}\), the evaluated result \(\omega(R, S)\) is strictly a member of \(\mathcal{U}\).

Proof

By Definition 1.1, an object \(R'\) is a relation if and only if it is a set of \(k\)-tuples over atomic domains \(D'_1, \dots, D'_k\). Selection \(\sigma_\theta(R)\) produces a subset of \(R\); since every subset of a finite set of tuples is a set of tuples over the same domains, \(\sigma_\theta(R) \in \mathcal{U}\). Projection \(\pi_A(R)\) applies set comprehension over sub-tuples \(t[A]\); by the axiom of specification and standard set semantics, duplicate elements collapse into unique set members, yielding a valid relation of degree \(|A|\). Cartesian product \(R \times S\) produces a set of concatenated tuples of degree \(n + m\) over product domains \(D_1 \times \dots \times D_n \times D'_1 \times \dots \times D'_m\). Because union, set difference, and natural join are defined via composition of these primitive set operations, their outputs are relations. Hence \(\mathcal{U}\) is closed under all relational operators.

Example 1.1 (Natural Join as Derived Operator)

Natural join \(R \bowtie S\) on shared attribute set \(K = \operatorname{attr}(R) \cap \operatorname{attr}(S)\) is derived from primitive operators: \[ R \bowtie S = \pi_{\operatorname{attr}(R) \cup \operatorname{attr}(S)}\left(\sigma_{\bigwedge_{k \in K} R.k = S.k}(R \times S)\right). \] Natural join is commutative (\(R \bowtie S = S \bowtie R\)) and associative (\((R \bowtie S) \bowtie T = R \bowtie (S \bowtie T)\)).

Lab 1 · Relational Algebra Closure and Operations

Verifies that selection, projection, and natural join on simulated market records strictly preserve relational set closure (no duplicate tuples, valid mathematical relation output).

"""CS3 Lesson 1 Inline Lab 1: Relational algebra closure and operations.

Demonstrates relations as sets of named tuples, selection, projection,
natural join, and verifies closure under relational operations.
Data: SIMULATED market orders and instruments.
"""

from __future__ import annotations

from typing import NamedTuple


class Instrument(NamedTuple):
    symbol: str
    asset_class: str
    currency: str


class Order(NamedTuple):
    order_id: int
    symbol: str
    quantity: int
    price: float


def select_orders_by_symbol(orders: set[Order], symbol: str) -> set[Order]:
    """Relational selection: sigma_{symbol = sym}(Orders)."""
    return {o for o in orders if o.symbol == symbol}


def project_order_symbols(orders: set[Order]) -> set[str]:
    """Relational projection: pi_{symbol}(Orders)."""
    return {o.symbol for o in orders}


class EnrichedOrder(NamedTuple):
    order_id: int
    symbol: str
    quantity: int
    price: float
    asset_class: str
    currency: str


def natural_join(orders: set[Order], instruments: set[Instrument]) -> set[EnrichedOrder]:
    """Relational natural join: Orders bowtie Instruments on symbol."""
    inst_map = {inst.symbol: inst for inst in instruments}
    joined: set[EnrichedOrder] = set()
    for o in orders:
        if o.symbol in inst_map:
            inst = inst_map[o.symbol]
            joined.add(
                EnrichedOrder(
                    order_id=o.order_id,
                    symbol=o.symbol,
                    quantity=o.quantity,
                    price=o.price,
                    asset_class=inst.asset_class,
                    currency=inst.currency,
                )
            )
    return joined


def main() -> None:
    # SIMULATED relations
    instruments: set[Instrument] = {
        Instrument("AAPL", "EQUITY", "USD"),
        Instrument("MSFT", "EQUITY", "USD"),
        Instrument("EURUSD", "FX", "USD"),
        Instrument("UST10Y", "BOND", "USD"),
    }

    orders: set[Order] = {
        Order(101, "AAPL", 100, 150.25),
        Order(102, "AAPL", 200, 150.50),
        Order(103, "MSFT", 50, 310.00),
        Order(104, "EURUSD", 100000, 1.0850),
        Order(105, "UNKNOWN", 10, 99.00),
    }

    print(f"Total initial orders: {len(orders)}")
    print(f"Total instruments: {len(instruments)}")

    # 1. Selection
    aapl_orders = select_orders_by_symbol(orders, "AAPL")
    print(f"Selection sigma_(symbol='AAPL') count: {len(aapl_orders)}")
    for o in sorted(aapl_orders, key=lambda x: x.order_id):
        print(f"  Order {o.order_id}: {o.symbol} qty={o.quantity} px={o.price:.2f}")

    # 2. Projection
    distinct_symbols = project_order_symbols(orders)
    print(f"Projection pi_(symbol) distinct count: {len(distinct_symbols)}")
    print(f"  Distinct symbols: {sorted(distinct_symbols)}")

    # 3. Natural Join
    enriched = natural_join(orders, instruments)
    print(f"Natural join count: {len(enriched)}")
    for eo in sorted(enriched, key=lambda x: x.order_id):
        print(f"  Enriched {eo.order_id}: {eo.symbol} class={eo.asset_class} ccy={eo.currency}")

    # 4. Relational closure check
    # The output of natural join is itself a set of tuples with no duplicate rows.
    is_relation = isinstance(enriched, set) and all(isinstance(x, tuple) for x in enriched)
    print(f"Relational closure verified: {is_relation}")

3Where the Canon Breaks

Codd's theoretical relational model assumes that all relations are pure mathematical sets. In commercial database implementations (SQL engines), the relational model departs from theory in three fundamental ways:

  • Multisets (Bags) vs Sets: Standard SQL tables permit duplicate rows unless an explicit PRIMARY KEY or UNIQUE constraint is declared. SQL queries default to SELECT ALL (multiset semantics), violating set idempotence.
  • Three-Valued Logic (3VL): SQL introduces NULL to represent missing information. In 3VL, comparisons like NULL = NULL evaluate to UNKNOWN rather than TRUE, breaking classical boolean algebraic identities such as the Law of the Excluded Middle (\(p \lor \neg p \equiv \text{True}\)).
  • Physical Tuple Ordering: While theoretical relations have no row ordering, storage engines rely on physical disk layout (clustered indexes, append-only logs) to achieve acceptable scan latency.

4Misconceptions

  1. A SQL table is identical to a mathematical relation.

    A mathematical relation is strictly a set of unique tuples. A SQL table is a multiset (bag) that can hold duplicate rows. In a SQL table without a primary key, duplicate rows inflate cardinality and distort aggregation queries.

  2. Projection \(\pi_A(R)\) in relational algebra simply selects columns like SELECT col FROM tbl.

    Relational projection \(\pi_A(R)\) maps the relation to a smaller tuple space and mathematically eliminates duplicate tuples. In SQL, SELECT col FROM tbl retains all duplicates; matching mathematical projection requires SELECT DISTINCT col FROM tbl.

  3. The result of evaluating val = NULL in SQL is boolean False.

    In SQL's three-valued logic, any comparison with NULL evaluates to UNKNOWN. In a WHERE clause, UNKNOWN filters out the row, but in truth tables NOT UNKNOWN remains UNKNOWN, not True.

5Problem Set

Tier 1 · Mechanics

Given relation \(R\) with degree 4 and cardinality 100, and relation \(S\) with degree 3 and cardinality 50, calculate the degree and cardinality of the Cartesian product \(R \times S\).

Solution

The degree of the Cartesian product \(R \times S\) is the sum of the degrees: \(\operatorname{deg}(R \times S) = \operatorname{deg}(R) + \operatorname{deg}(S) = 4 + 3 = 7\). The cardinality of the Cartesian product is the product of the cardinalities: \(|R \times S| = |R| \times |S| = 100 \times 50 = 5000\).

Let relation \(R(A, B)\) contain 5 tuples: \(\{(1, 10), (1, 20), (2, 10), (3, 30), (3, 10)\}\). Compute the cardinality of the relational projection \(\pi_A(R)\) and \(\pi_B(R)\).

Solution

Relational projection eliminates duplicate values. For \(\pi_A(R)\), projecting attribute \(A\) yields the set \(\{1, 2, 3\}\), so \(|\pi_A(R)| = 3\). For \(\pi_B(R)\), projecting attribute \(B\) yields the set \(\{10, 20, 30\}\), so \(|\pi_B(R)| = 3\).

Given relation \(T(\text{symbol}, \text{price})\) with tuples \(\{(\text{AAPL}, 150)\), \((\text{MSFT}, 300)\), \((\text{GOOG}, 100)\}\), evaluate the selection \(\sigma_{\text{price} \ge 150 \land \text{symbol} \ne \text{MSFT}}(T)\).

Solution

Evaluating the predicate on each tuple: AAPL has price 150 (\(\ge 150\)) and symbol != MSFT (True); MSFT has price 300 but fails \(\text{symbol} \ne \text{MSFT}\) (False); GOOG has price 100 which fails \(\text{price} \ge 150\) (False). The resulting relation is \(\{(\text{AAPL}, 150)\}\) with cardinality 1.

Tier 2 · Proof

Prove that relational selection distributes over union: \(\sigma_\theta(R \cup S) = \sigma_\theta(R) \cup \sigma_\theta(S)\).

Solution

Let \(t \in \sigma_\theta(R \cup S)\). By definition, \(t \in (R \cup S)\) and \(\theta(t) = \text{true}\). Since \(t \in R \lor t \in S\), we have \((t \in R \land \theta(t)) \lor (t \in S \land \theta(t))\). This is equivalent to \(t \in \sigma_\theta(R) \lor t \in \sigma_\theta(S)\), which means \(t \in \sigma_\theta(R) \cup \sigma_\theta(S)\). Since each step is an iff logical equivalence, \(\sigma_\theta(R \cup S) = \sigma_\theta(R) \cup \sigma_\theta(S)\).

Prove that selection distributes over set difference: \(\sigma_\theta(R \setminus S) = \sigma_\theta(R) \setminus \sigma_\theta(S)\).

Solution

By definition, \(t \in \sigma_\theta(R \setminus S) \iff t \in (R \setminus S) \land \theta(t) \iff (t \in R \land t \notin S) \land \theta(t)\). Rewriting by associativity and commutativity of conjunction: \((t \in R \land \theta(t)) \land \neg(t \in S)\). For \(t\) where \(\theta(t)\) holds, \(t \notin S \iff t \notin \sigma_\theta(S)\). Therefore, \(t \in \sigma_\theta(R) \land t \notin \sigma_\theta(S) \iff t \in \sigma_\theta(R) \setminus \sigma_\theta(S)\).

Prove that projection does not generally distribute over set intersection: \(\pi_A(R \cap S) \subseteq \pi_A(R) \cap \pi_A(S)\), and provide a counterexample showing equality can fail.

Solution

If \(x \in \pi_A(R \cap S)\), there exists tuple \(t \in R \cap S\) such that \(t[A] = x\). Since \(t \in R\), \(x \in \pi_A(R)\); since \(t \in S\), \(x \in \pi_A(S)\). Thus \(x \in \pi_A(R) \cap \pi_A(S)\), proving the subset inclusion. To show equality fails, let \(R = \{(1, \text{a})\}\) and \(S = \{(1, \text{b})\}\) over attributes \((A, B)\). Then \(R \cap S = \emptyset\), so \(\pi_A(R \cap S) = \emptyset\). But \(\pi_A(R) = \{1\}\) and \(\pi_A(S) = \{1\}\), giving \(\pi_A(R) \cap \pi_A(S) = \{1\} \ne \emptyset\).

Tier 3 · Empirical

A trade reconciliation job compares internal executions \(R\) with broker clearing records \(S\). If \(|R| = 10{,}000\) and \(|S| = 10{,}000\), and the set difference \(R \setminus S\) contains 15 records while \(S \setminus R\) contains 12 records, calculate the number of perfectly reconciled trade tuples.

Solution

By set arithmetic, the perfectly reconciled trades correspond to the set intersection \(R \cap S\). We know that \(|R \setminus S| = |R| - |R \cap S|\). Substituting the known numbers: \(15 = 10{,}000 - |R \cap S| \implies |R \cap S| = 9{,}985\). Verifying on the broker side: \(|S| - |R \cap S| = 10{,}000 - 9{,}985 = 15\), but \(S \setminus R\) had 12 records, implying \(S\) contains duplicate or distinct records if treating as sets. For exact set identity: \(9{,}985\) trades match bit for bit.

In a tick database with 50 million records, a naive query runs without projection pruning: SELECT * FROM trades over a table with 20 columns of 8 bytes each. Calculate the total byte transfer and compare it to projected query SELECT price FROM trades.

Solution

Row width for 20 columns is \(20 \times 8 = 160\) bytes. Total transfer for SELECT * is \(50 \times 10^6 \times 160 \text{ bytes} = 8.0 \times 10^9 \text{ bytes} = 8.0 \text{ GB}\). For SELECT price, only 1 column of 8 bytes is transferred: \(50 \times 10^6 \times 8 \text{ bytes} = 0.4 \text{ GB}\) (400 MB). Projection eliminates 7.6 GB of I/O transfer, achieving an exact 20x bandwidth reduction factor.

A financial ledger table holds transactions with possible duplicate order IDs. Writing SELECT DISTINCT order_id FROM transactions versus SELECT order_id FROM transactions yields 450,000 and 500,000 rows respectively. Quantify the duplicate row contamination rate.

Solution

Total recorded rows is 500,000, while distinct order identifiers is 450,000. The number of redundant duplicate rows is \(500{,}000 - 450{,}000 = 50{,}000\). The duplicate row contamination rate is \(50{,}000 / 500{,}000 = 0.10\) or 10.0%. If an analyst aggregated order volume without DISTINCT, total volume would be inflated by the duplicate multiset entries.

Tier 4 · Research

Evaluate the trade-offs between physical data independence in Codd's relational model and low-latency mechanical sympathy in modern high-frequency trading (HFT) memory stores.

Solution

Codd's physical data independence insulates the conceptual query interface from physical storage structures, allowing indexing and layout optimizations without rewriting business logic. However, ultra-low-latency HFT systems require cache-line alignment, hardware prefetching, and zero-allocation memory layouts (mechanical sympathy). Pure relational abstractions introduce pointer indirection and query interpretation overhead that high-frequency engines bypass using static memory-mapped structs.

How does the relational model's inability to express transitive closure (recursive reachability) in first-order relational algebra impact supply-chain counterparty credit risk modeling?

Solution

First-order relational algebra cannot compute the transitive closure of an arbitrary graph (proved via the Compactness Theorem and Ehrenfeucht-Fraïssé games). Modeling counterparty network contagion where entity A defaults on B, impacting C through N degrees of counterparty exposure, requires recursive relational algebra extensions (SQL:1999 WITH RECURSIVE) or dedicated graph engines to iterate to a fixed point.

Analyze why Edgar F. Codd insisted that domains must be atomic, and assess how modern JSON/semi-structured columns in SQL databases impact normalization theory.

Solution

Codd required domain atomicity (First Normal Form) so that relational algebra operations could address every individual data item through the uniform coordinates of relation name, attribute name, and primary key value. Embedding semi-structured JSON documents reintroduces hierarchical pointer navigation within cell values, bypassing relational algebra optimizers, invalidating standard functional dependency checks, and shifting schema validation from database compile time to application runtime.

7Retrieval quiz

  1. What is an n-ary relation mathematically in Codd's relational model?

    Options

    An n-ary relation is formally defined as a subset of the Cartesian product \(D_1 \times \dots \times D_n\).

  2. What does the principle of relational closure guarantee?

    Options

    Relational closure means the operator domain and codomain are identical: operators take relations and output relations.

  3. Which relational operator changes the degree (number of attributes) of a relation?

    Options

    Projection selects a subset of attributes, reducing or preserving degree. Selection filters rows without altering degree.

  4. If relation R has cardinality 7 and relation S has cardinality 5, what is the cardinality of the Cartesian product \(R \times S\)?

    \(|R \times S| = |R| \times |S| = 7 \times 5 = 35\).

  5. How does SQL's default query output differ from pure relational algebra projection?

    Options

    SQL operates on multisets (bags) by default; relational projection is a set operation that eliminates duplicates.

  6. What does Codd's first normal form require of attribute values?

    Options

    Domain atomicity means values cannot be repeating groups, arrays, or nested tables.

  7. What truth value does the expression NULL = NULL yield in SQL three-valued logic?

    Options

    In SQL 3VL, comparing NULL to any value (including NULL) yields UNKNOWN.

  8. Which relational algebra operation expresses natural join when combined with selection and projection?

    Options

    Natural join is formally defined as the projection of a selection over the Cartesian product: \(\pi(\sigma(R \times S))\).
