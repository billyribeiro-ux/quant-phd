Streaming statistics library

A monitoring team receives one number at a time and needs three things from each stream: the online mean and variance without a second pass, the minimum and maximum of the last few values in constant amortized time per value, and an estimate of a quantile from a quantile sketch with a stated rank guarantee (defined under Conventions below). You write streamstats.py to the specification below, prove the update formula that Welford's method rests on, and write a design note for the sketch. The autograder runs your library on a stream generated from your workspace seed, so the numbers are yours to compute. Such a stream is SIMULATED: it is generated by code and is not market data.

Lab 1 · Worked example: a rolling minimum and maximum with a monotonic deque

The code runs a rolling minimum and maximum with a window of four over twelve SIMULATED integers from a seeded generator, and it checks every step against a brute-force scan of its window. Before running it, predict the minimum and the maximum at step 12. The window at step 12 holds the last four values of the series. The code also counts the deque operations, and the lab states the bound 4n on that count.

"""CS2 project lab 1 (rung 1, worked example): a rolling minimum and maximum with a monotonic deque.

SIMULATED: twelve integers drawn from random.Random(12) in [0, 99]. They are generated here and are not market data.
Standard library only, no randomness after the seed, no network. The window holds the last four values. For every
value the code prints the window and its minimum and maximum. At the end it prints whether every step agrees with a
brute-force scan of its window, then the count of deque pushes and pops over both deques and the bound 4n on that count.
"""

from __future__ import annotations

import random
from collections import deque

WINDOW = 4
_RNG = random.Random(12)
SERIES: list[int] = [_RNG.randint(0, 99) for _ in range(12)]


class RollingMinMax:
    """Minimum and maximum of the last WINDOW values. Each deque holds (index, value) pairs."""

    def __init__(self, window: int) -> None:
        self.window = window
        self.index = -1  # index of the latest value pushed
        # Why: the minimum deque keeps values in increasing order, so its front is the window's minimum.
        self.mins: deque[tuple[int, int]] = deque()
        # Why: the maximum deque keeps values in decreasing order, so its front is the window's maximum.
        self.maxs: deque[tuple[int, int]] = deque()
        self.ops = 0  # pushes and pops on both deques, counted to measure the work

    def push(self, x: int) -> None:
        self.index += 1
        # Why: an older value at least as large as x can never be the minimum again while x is in the window.
        while self.mins and self.mins[-1][1] >= x:
            self.mins.pop()
            self.ops += 1
        self.mins.append((self.index, x))
        self.ops += 1
        # Why: an older value at most as large as x can never be the maximum again while x is in the window.
        while self.maxs and self.maxs[-1][1] <= x:
            self.maxs.pop()
            self.ops += 1
        self.maxs.append((self.index, x))
        self.ops += 1
        # Why: an index at or before index - window has left the window, and it can only be at the front.
        while self.mins[0][0] <= self.index - self.window:
            self.mins.popleft()
            self.ops += 1
        while self.maxs[0][0] <= self.index - self.window:
            self.maxs.popleft()
            self.ops += 1

    def minimum(self) -> int:
        return self.mins[0][1]

    def maximum(self) -> int:
        return self.maxs[0][1]


def main() -> None:
    rolling = RollingMinMax(WINDOW)
    print("series:", SERIES)
    all_agree = True
    for t, x in enumerate(SERIES, start=1):
        rolling.push(x)
        window = SERIES[max(0, t - WINDOW) : t]
        agree = rolling.minimum() == min(window) and rolling.maximum() == max(window)
        all_agree = all_agree and agree
        print(f"step {t:2d} value {x:2d} window {window} min {rolling.minimum()} max {rolling.maximum()}")
    print("every step agrees with brute force:", all_agree)
    print(f"deque operations: {rolling.ops} for n = {len(SERIES)} values, bound 4n = {4 * len(SERIES)}")

Each step's minimum and maximum are the least and greatest of that step's window, and the last line says the brute-force check agreed at every step. At step 9 the minimum is 1, and the value 1 is still in the window at step 12, so it is reported there too; it leaves the window at the next push. The count of 44 deque operations is at most the bound 4n = 48. Each value is appended once to each deque, and an element is popped at most once from each deque, so the count is at most 4n. A count bounded by a multiple of n gives constant amortized work per value, which is the argument of Lesson 10. This lab shows the count on one seeded series; it does not measure time.

Rung 3 · Specification

Context
A monitoring team receives a stream of real numbers one at a time. For each stream it needs the mean and the variance of everything seen so far, the minimum and maximum of the last few values, and an estimate of a quantile without a second pass over the data. You implement a small library that does these three things and that a later analysis can call. The streams in the labs and the autograder are SIMULATED. The autograder's stream is generated from the workspace seed by grader/instance.py. The labs' streams are written out in their code, except Lab 1, whose twelve integers are drawn in the code from a fixed seed.
Inputs
A value is a real number, given as a Python float. The autograder's stream has between 20 and 400 values, each a finite float with one or six decimal places, around a common offset of 0, 10,000 or 1,000,000. The window is an integer from 2 to 30. The quantile sketch's epsilon is 0.05, 0.1 or 0.2. The autograder checks the rank guarantee of Conventions at ten probe quantiles, which are ten values of q in the closed interval from 0 to 1. A student does not call make_instance; the grader decodes the instance. Every instance is labelled SIMULATED: it is generated, it is not market data, and nothing in it is a measurement of anything real.
Required outputs
  • A file streamstats.py that defines three classes, with these methods and signatures. WelfordAccumulator() has update(x: float) -> None, a read-only property count that returns an int, mean() -> float, and variance(ddof: int = 1) -> float, where ddof 0 gives the population variance and ddof 1 the sample variance (both defined under Conventions below). RollingMinMax(window: int) has push(x: float) -> None, minimum() -> float and maximum() -> float. QuantileSketch(epsilon: float) has add(x: float) -> None and quantile(q: float) -> float.
  • A file proof.md: the proof of Welford's update, with its hypotheses, as described in the write-up section.
  • A file design.md: the design note for the quantile sketch, of about 500 to 800 words, as described in the write-up section.
Start from the starter file. Every method in it raises NotImplementedError until you replace it, and the checks that call them fail on the starter.
Constraints
The standard library and nothing else. The module does not import any file from the grader, so it runs on its own. The three classes never print or warn, and no method changes its arguments. No method changes the value it is given, and each class holds its state in the object only. The conventions below define the numbers the library returns. The following conditions are named, and each raises ValueError: (1) mean(), or variance() with either ddof, before any value has been added; (2) variance(1) when fewer than two values have been added; (3) update(x) with NaN; (4) RollingMinMax(window) with a window below 1, the boolean False (which is 0) included; (5) push(x) with NaN; (6) minimum() or maximum() before any value has been pushed; (7) QuantileSketch(epsilon) with an epsilon that is not strictly between 0 and 1, NaN, both infinities and the booleans False and True included; (8) add(x) with NaN; (9) quantile(q) with a q outside the closed interval from 0 to 1, NaN and both infinities included; (10) quantile(q) on an empty sketch. The autograder checks the exception type for these ten and not the wording of a message. The conditions the specification does not name have no exception type required of them. For variance(ddof) with a ddof other than 0 or 1, the call raises an exception of any type, and it returns nothing. For a value that is not a real number, such as a string or None, the call raises an exception of any type, or it accepts the value and gives the answer for the number that the value denotes; a string such as "2.5" denotes 2.5. A None denotes no number, so for None, whether it is a value, a window or a ddof, the call must raise. For an infinite value passed to WelfordAccumulator.update, the call raises, or the mean and the sample variance that follow are not finite numbers. For an infinite value passed to RollingMinMax.push or QuantileSketch.add, the specification states no outcome, and the autograder does not test one. For a window given as a string or a float that denotes a whole number, such as "3" or 3.0, the call raises an exception of any type, or it gives the minimum of the last window values that the number denotes. For a window that denotes no whole number, such as the float 2.5, the call raises an exception of any type.
Grading mode
Grading: both. The autograder is grader/test_project.py, which collects 171 checks, counted with pytest --collect-only on the reference solution. The count is 171 for each of the seeds 0 to 49. The suite runs with warnings as errors. It covers the named conditions, each in both directions where the condition is a boundary (a window of 0 and of 1, an epsilon of 0, of 1e-6, of 0.999999 and of −1e-6, a q of 1.1 and of 1.0, a q just outside each end of [0, 1] and just inside it); the named conditions on an empty object, a first value that is NaN, and an infinite epsilon or q; the Welford mean and variance against an exact Fraction reference to a relative tolerance of 1e-9 with an absolute floor of 1e-9, on every prefix of 2 to 20 values and on the whole stream; the scaling of the variance by a factor of four when every value is doubled; the rolling minimum and maximum against brute force for every position, for eight window widths, and for a stream with repeated values; the rank guarantee of the sketch (defined under Conventions below) at each of the ten probes, on short streams, on sorted streams, on a stream with repeated values, and on a fixed twenty-value stream where a rank target (defined under Conventions below) computed in floating point is one short of the exact one, and at a q with seven decimal places (0.2500004) on that stream, where a q rounded to six places gives a different target; the constant-stream and single-value checks; the monotonicity of the quantile in q on 101 evenly spaced values of q and the ten probes; a count that is an int and is not changed by an assignment; the three classes printing nothing and holding their own state; the standard-library imports; and the value and window rules of Constraints for a boolean, a padded string, a string, None, a whole float window and a float window such as 2.5 that is not whole, for the value passed to update, push and add (a boolean, a padded string, a string and None), and for ddof given as a string or a float, both the values that denote 0 or 1 and the values that denote another number (each is refused, or answered as the number it denotes, as Constraints says; None must raise). A failing check names the property it tests and never prints the expected value. The rubric grades the proof write-up and the design note against the six criteria in the write-up section, with two annotated exemplars.

Conventions, defined once

  • Welford. After n values \(x_1, \dots, x_n\) the mean is mean(), and variance(0) is the population variance: the sum of squared deviations from the mean divided by n. variance(1) is the sample variance: the same sum divided by n − 1. Both describe every value added so far, not a window: the window belongs to minimum() and maximum(), and the Welford statistics are cumulative.
  • Rolling window. minimum() and maximum() describe the last window values pushed. Before the window is full they describe every value pushed so far. A value that has left the window is never reported.
  • The rank guarantee. For a sketch that has been given n values, and a probe q, where ε is the epsilon of the sketch, as in Inputs and Constraints, the answer v returned by quantile(q) satisfies two inequalities, with the counts taken over the stream as it was given. The first is that the number of values strictly below v is at most qn + εn. The second is that the number of values at or below v is at least qn − εn. The specification requires that quantile(q) never decrease as q increases. The specification does not bound the memory of the sketch, and the autograder does not test memory.
  • Exact counts. The autograder computes the mean, the variance and the rank counts with exact rational arithmetic on the floats that it passes to your code. The mean and the variance are checked to the relative tolerance of 1e-9 with the absolute floor of 1e-9 given above. The two rank inequalities have no tolerance: a stored value passes only if each inequality holds exactly, with qn and εn taken as exact rationals of the q and the epsilon that the autograder passes. The rank target is the smallest integer at or above qn − εn, and at least 1. A rank target computed in floating point can fall one rank short of the exact target, so compute it exactly, for example with fractions.Fraction. For example, with q = 0.1, n = 20 and epsilon 0.05, the exact target is 2, and the same expression computed in 64-bit floats gives 1. The exact value uses the exact rationals of the floats 0.1 and 0.05 (0.1 is stored slightly above one tenth), so qn − εn is slightly above 1 and its ceiling is 2.
  • Infinite values. An infinite value is outside the domain of the specification. Constraints states an outcome for WelfordAccumulator only, and the autograder does not test an infinite value for RollingMinMax or QuantileSketch. An infinite epsilon or q is outside the named ranges, and it raises ValueError.

Named errors, in brief

The ten named conditions in Constraints are the only conditions that the autograder requires to raise ValueError. Each of them has at least one test in the suite. The tests for an empty object or sketch start from a fresh one, and the others change one argument or one value to the boundary. A value just inside a bound is valid: a window of 1, an epsilon of 0.000001, a q of 0 and a q of 1, and a variance with ddof 0 on a single value each return an answer.

Lab 3 · Reference numbers: an eleven-value SIMULATED stream, checked against exact arithmetic

The code prints reference numbers for an eleven-value SIMULATED stream with a common offset of 10,000. It prints the exact mean and sample variance from exact rational arithmetic, the same two numbers from Welford's update in floats, whether the float mean lies within 1e-9 of the exact mean, the minimum and maximum of the last four values, and the exact rank target and answer for the median with epsilon 0.1. Before running it, predict whether the Welford mean agrees with the exact mean to within 1e-9.

"""CS2 project lab 3 (rung 3, reference numbers): an eleven-value SIMULATED stream, checked against exact arithmetic.

SIMULATED: the eleven values are written out here, one decimal each, with a common offset of 10,000 (dimensionless).
They are not market data. Standard library only, no randomness, no network. The code computes the exact mean and
sample variance with Fraction, the same values by Welford's update in floats, the minimum and maximum of the last
four values, and the exact rank target and answer for the median with epsilon 0.1. Exact values are printed to six
decimals, rounded from the unrounded Fraction.
"""

from __future__ import annotations

import math
from fractions import Fraction

STREAM: list[str] = [
    "10003.2",
    "10001.7",
    "10007.5",
    "10000.4",
    "10004.9",
    "10002.1",
    "10009.6",
    "10001.0",
    "10006.3",
    "10003.8",
    "10005.5",
]
WINDOW = 4
EPSILON = Fraction("0.1")


def welford(values: list[float]) -> tuple[float, float]:
    """Return the mean and the sample variance by Welford's update."""
    count, mean, m2 = 0, 0.0, 0.0
    for x in values:
        count += 1
        delta = x - mean
        mean += delta / count
        m2 += delta * (x - mean)
    return mean, m2 / (count - 1)


def main() -> None:
    exact = [Fraction(s) for s in STREAM]
    n = len(exact)
    mean_exact = sum(exact) / n
    var_exact = sum((x - mean_exact) ** 2 for x in exact) / (n - 1)
    print(f"count {n}")
    print(f"exact mean {float(mean_exact):.6f}")
    print(f"exact sample variance {float(var_exact):.6f}")
    mean_w, var_w = welford([float(s) for s in STREAM])
    print(f"welford mean {mean_w:.6f}")
    print(f"welford sample variance {var_w:.6f}")
    print("welford mean within 1e-9 of exact:", abs(mean_w - float(mean_exact)) <= 1e-9)
    last = [float(s) for s in STREAM[-WINDOW:]]
    print(f"last {WINDOW} values minimum {min(last):.1f} maximum {max(last):.1f}")
    q = Fraction(1, 2)
    target = max(1, math.ceil(q * n - EPSILON * n))
    ordered = sorted(exact)
    print(f"median target rank k = {target} of {n} with epsilon 0.1")
    print(f"the {target}th smallest value is {float(ordered[target - 1]):.1f}")

Exemplar A

Official scoring: C1 1 · C2 1 · C3 2 · C4 1 · C5 1 · C6 1.

proof.md: Welford's update

Let the mean be m and the sum of squared deviations be S. When a value x arrives, the mean moves by the deviation divided by the new count, and S moves by the deviation times the new deviation. Induction on the count gives this. The base case is clear. For the inductive step the algebra works out, so the update holds for every count.

C1, level 1: no hypotheses are listed; the count, the values and the arithmetic are never stated, so the induction has no declared domain. C2, level 1: the base case is asserted as clear and not shown, and the inductive step asserts that the algebra works out, with no line of the algebra shown. C3, level 2: S is named but not tied to a sum of squared deviations after each count.

proof.md: Welford's update

Hypotheses. (H1) n is a positive integer. (H2) The values \(x_1, \dots, x_n\) are real numbers. (H3) Arithmetic is exact, over the real numbers. Definitions. \(\bar x_n = \frac{1}{n}\sum_{i=1}^{n} x_i\) and \(S_n = \sum_{i=1}^{n}(x_i - \bar x_n)^2\). Statement. Under H1 to H3, for \(\delta = x_{n+1} - \bar x_n\), we have \(\bar x_{n+1} = \bar x_n + \delta/(n+1)\) and \(S_{n+1} = S_n + \delta\,(x_{n+1} - \bar x_{n+1})\). Also \(\sum_{i=1}^{n}(x_i - \bar x_n) = 0\) by the definition of \(\bar x_n\).

Proof. By induction on n. Base case, n = 1: \(\bar x_1 = x_1\) and \(S_1 = 0\), since the only deviation is zero. Inductive step: assume the definitions hold for n. By H2, \(x_{n+1}\) and \(\bar x_n\) are real numbers, so \(\delta\) and each deviation \(x_i - \bar x_n\) are real. Since \(\bar x_{n+1} = (n\,\bar x_n + x_{n+1})/(n+1)\), we get \(\bar x_{n+1} = \bar x_n + (x_{n+1} - \bar x_n)/(n+1)\), which is the mean update. Write \(a = \bar x_n - \bar x_{n+1} = -\delta/(n+1)\). Then \(\sum_{i \le n}(x_i - \bar x_{n+1})^2 = \sum_{i \le n}(x_i - \bar x_n)^2 + 2a\sum_{i \le n}(x_i - \bar x_n) + n a^2\). The middle sum is zero by the definition of \(\bar x_n\), so this equals \(S_n + n a^2 = S_n + n\delta^2/(n+1)^2\). The new value deviates by \(x_{n+1} - \bar x_{n+1} = \delta - \delta/(n+1) = n\delta/(n+1)\), so its squared deviation is \(n^2\delta^2/(n+1)^2\). Adding the two parts gives \(S_{n+1} = S_n + (n + n^2)\delta^2/(n+1)^2 = S_n + n\delta^2/(n+1)\). Finally \(\delta\,(x_{n+1} - \bar x_{n+1}) = \delta \cdot n\delta/(n+1) = n\delta^2/(n+1)\), which is the increment just found, so \(S_{n+1} = S_n + \delta\,(x_{n+1} - \bar x_{n+1})\). Each step used H1 (the count is positive, so the division is defined), H2 (the deviations are real numbers), or H3 (exact algebra). ∎

C1, level 4: the three hypotheses are listed before the statement, and each is cited where it is used (H1 for the division, H2 for δ and the deviations, H3 for the algebra). C2, level 4: the base case is shown, and each algebra line of the inductive step is justified by the definition of the mean or by the cancellation shown. C3, level 4: S is stated as the sum of squared deviations from the current mean, and the invariant is carried through the step.

The sample variance after n values is \(S_n/(n-1)\) for n at least 2. Lab 3 gives the exact sample variance 8.313636 for its eleven values, and the Welford output in the same lab agrees to six digits. The proof is over the real numbers; the code computes in 64-bit floats, so the claim that the two agree is a measured claim, not a consequence of the proof.

C4, level 4: the real-number assumption is named, the floating-point difference is named, and the agreement is tied to Lab 3's printed value of the Welford mean within 1e-9 of the exact mean, True.

design.md: the sketch

For n values added and a probe q, the answer v satisfies two inequalities: at most \(qn + \varepsilon n\) of the values lie strictly below v, and at least \(qn - \varepsilon n\) of them lie at or below v. The sketch I implemented answers with a stored value whose rank, among the values seen so far, is within the slack of the target rank. The rank target is the ceiling of \(qn - \varepsilon n\), and at least 1. The rank guarantee is checked at the ten probes of the instance (0, 0.01, 0.1, 0.25, 0.5, 0.75, 0.9, 0.99, 1, and one seeded value), on streams of one to eight values with epsilon 0.05, 0.1 and 0.2, and on sorted streams; a constant stream is checked to return its value.

The note does not claim a memory bound, and it does not claim a guarantee for an adversarial order of the input beyond the sorted cases checked. The domain excludes infinite and non-real values, as the specification states.

C5, level 4: both inequalities are stated with the slack; the ten probes and the streams are named; the limits (memory, adversarial order, the domain) are stated.

Lab 1 prints 44 deque operations for twelve values, below the bound 4n = 48 that the lab prints. The bound follows from the deque's structure: each value is appended once to each deque and popped at most once from each, so the count is at most 4n. The lab measures the count on one series; it does not time anything. Lab 3's printed agreement of the Welford mean within 1e-9 is the stability evidence here, for the one eleven-value stream at offset 10,000. No claim here cites a timing.

C6, level 4: the speed claim cites Lab 1's printed count and its bound; the stability claim cites Lab 3's printed agreement; no timing is quoted.
