A search tree answers a search by comparing the key with a node and going left or right, so the number of comparisons is at most the height of the tree. An unbalanced tree can grow as tall as the number of its keys: inserted in sorted order, keys form a path. A balanced search tree prevents this by restructuring itself after each insertion. This lesson uses the AVL rule, which keeps the two subtrees of every node within one level of each other, and it proves that an AVL tree with \(n\) keys has height at most \(\log_{\varphi}(n+1)\). The insertion step that keeps the rule is checked by Lab 1 on 500 seeded keys and is not proved here.

1Binary search trees and why height matters

A binary search tree stores one key in each node. Every key in the left subtree of a node is smaller than the node's key, and every key in the right subtree is larger. A search starts at the root and compares the key with the node, then goes to the left or right subtree, or stops. The height of a tree is the number of nodes on its longest path from the root down to a leaf, so the empty tree has height 0 and a single node has height 1. The in-order sequence of a tree lists the keys of its left subtree, then its own key, then the keys of its right subtree; in a binary search tree it is the keys in increasing order. A search that ends at a node compares the key with the nodes on one path, so it makes at most as many comparisons as the height. The comparisons are the comparisons of L04's model.

Remark 1.1 (sorted insertion makes a path)

Insert the keys \(1, 2, \ldots, n\) in that order into an unbalanced binary search tree. The first key is the root. Each later key is larger than every key present, so it goes to the right of its predecessor, and the tree is a path of \(n\) nodes. Its height is \(n\). The argument is an induction on the number of keys: after \(k\) insertions the tree is a path of \(k\) nodes, and the next key extends the path. Lab 1, Part B, prints height 64 for the keys 1 to 64.

2The AVL rule and the height bound

Definition 2.1 (balanced search tree, AVL variant)

The balanced search tree is a binary search tree that restructures itself after each change, so that its height stays logarithmic in the number of its keys. This unit uses the AVL variant. For a node, the balance factor is the height of its left subtree minus the height of its right subtree, with the height of an empty subtree equal to 0. An AVL tree is a binary search tree in which every node has balance factor \(-1\), \(0\) or \(1\).

Definition 2.2 (the recurrence for N(h))

For an integer \(h \ge 0\), let \(N(h)\) be defined by \(N(0) = 0\), \(N(1) = 1\), and \(N(h) = 1 + N(h-1) + N(h-2)\) for \(h \ge 2\). These are recurrence values. Lemma 2.3 shows that every AVL tree of height \(h\) has at least \(N(h)\) nodes; this page does not show that an AVL tree with exactly \(N(h)\) nodes exists for each \(h\). The first values are \(N(0), \ldots, N(7) = 0, 1, 2, 4, 7, 12, 20, 33\), and Lab 1, Part C, computes them.

Lemma 2.3 (the recurrence bounds every AVL tree)

Let \(h \ge 0\) and let \(T\) be an AVL tree of height \(h\). Then \(T\) has at least \(N(h)\) nodes. Also \(N(h)\) is nondecreasing in \(h\).

Proof

First, \(N\) is nondecreasing. For \(h \ge 2\), \(N(h) - N(h-1) = 1 + N(h-2) \ge 1 > 0\), and \(N(1) = 1 > 0 = N(0)\). Now the bound, by strong induction on \(h\). For \(h = 0\) the tree is empty and has \(0 = N(0)\) nodes. For \(h = 1\) the tree is a single node, which has \(1 = N(1)\) node. Let \(h \ge 2\), and assume the bound for every height below \(h\). Let the root of \(T\) have subtrees \(L\) and \(R\) with heights \(h_L\) and \(h_R\). The height of the root is \(1 + \max(h_L, h_R) = h\), so one subtree has height \(h - 1\), and the other has height \(h_2\) with \(h - 2 \le h_2 \le h - 1\), because the balance rule gives \(|h_L - h_R| \le 1\). Both subtrees are AVL trees, since each node of a subtree has the same balance factor as in \(T\). Both heights are below \(h\), so by induction the subtree of height \(h - 1\) has at least \(N(h-1)\) nodes, and the other has at least \(N(h_2) \ge N(h-2)\) nodes, using that \(N\) is nondecreasing. Adding the root gives at least \(1 + N(h-1) + N(h-2) = N(h)\) nodes.

Proposition 2.4 (the height bound)

Assume the following. (1) \(T\) is an AVL tree with \(n \ge 0\) nodes and height \(h\). (2) The symbol \(\varphi = (1 + \sqrt{5})/2\) denotes the golden ratio. Then \(\varphi^{h} \le n + 1\), and so \(h \le \log_{\varphi}(n+1) = \log_2(n+1) / \log_2 \varphi\).

Proof

Let \(M(h) = N(h) + 1\). Then \(M(0) = 1\), \(M(1) = 2\), and for \(h \ge 2\), \(M(h) = M(h-1) + M(h-2)\), because \(N(h) + 1 = 1 + N(h-1) + N(h-2) + 1\). We show \(M(h) \ge \varphi^{h}\) for every \(h \ge 0\). For \(h = 0\) both sides are 1. For \(h = 1\), \(\varphi < 2\) because \(\sqrt{5} < 3\), so \(M(1) = 2 \ge \varphi\). For \(h \ge 2\), assume \(M(h-1) \ge \varphi^{h-1}\) and \(M(h-2) \ge \varphi^{h-2}\). Then \(M(h) \ge \varphi^{h-1} + \varphi^{h-2} = \varphi^{h-2}(\varphi + 1)\). Since \(\varphi^{2} = \varphi + 1\), which follows from \((1 + \sqrt{5})^{2}/4 = (6 + 2\sqrt{5})/4 = (3 + \sqrt{5})/2 = \varphi + 1\), this equals \(\varphi^{h}\). By Lemma 2.3, \(n \ge N(h)\), so \(n + 1 \ge M(h) \ge \varphi^{h}\). Taking \(\log_2\) and dividing by \(\log_2 \varphi > 0\) gives the second form.

Remark 2.5 (the constant is not 1)

The bound is \(\log_{\varphi}(n+1)\), and \(1 / \log_2 \varphi\) equals 1.440420 to six decimal places, as Lab 1, Part C prints. So the height of an AVL tree can exceed \(\log_2 n\). With two nodes, the tree with root 2 and left child 1 has height 2, and \(\log_2 2 = 1\). Proposition 2.4 gives \(\log_{\varphi} 3 = \ln 3 / \ln \varphi = 2.28\), which is at least 2, so the example is consistent with the bound. Lab 1, Part C, prints this two-node height.

3Insertion and rotations

Insertion into an AVL tree has two stages. First the key is inserted as in a plain binary search tree, at a leaf. Then the heights are updated on the path from the new leaf back to the root. The first node on that path whose balance factor is \(2\) or \(-2\) is the lowest unbalanced node. A rotation re-links a node and one of its children so that the child takes the parent's place; Proposition 3.1 shows that it keeps the search order. The heavy child of a node with balance factor \(2\) is its left child, and of a node with balance factor \(-2\) it is its right child. A child leans the way its own balance factor points: a balance factor of \(1\) leans left, \(-1\) leans right, and \(0\) leans neither. If the heavy child's balance factor is \(0\) or has the same sign as the unbalanced node's, one single rotation at the unbalanced node is made. If it has the opposite sign, a double rotation is made: first a rotation at the child, then a rotation at the node. Remark 3.2 says what is and is not proved about this repair.

Proposition 3.1 (a rotation keeps the keys in order)

Let \(y\) be a node with left child \(x\), and let \(A\), \(B\) and \(C\) be the subtrees with keys in that order: \(A\) under \(x\)'s left side, \(B\) under \(x\)'s right side, and \(C\) under \(y\)'s right side. The right rotation makes \(x\) the root with left subtree \(A\) and right subtree \(y\), where \(y\) has left subtree \(B\) and right subtree \(C\). The in-order sequence of keys is the same before and after the rotation.

Proof

Before the rotation the in-order sequence of the subtree at \(y\) is the in-order sequence of \(A\), then \(x\), then \(B\), then \(y\), then \(C\). After the rotation, the in-order sequence of the subtree at \(x\) is the in-order sequence of \(A\), then \(x\), then the in-order sequence of the subtree at \(y\), which is \(B\), then \(y\), then \(C\). The two sequences are the same. The left rotation is the mirror image of this argument.

Remark 3.2 (what this page proves about insertion)

Proposition 3.1 shows that a rotation keeps the search order. This page does not prove that one single rotation or one double rotation restores the AVL rule after every insertion. That claim is checked, not proved: Lab 1, Part A, checks it after each of 500 seeded insertions, and only that check is stated here.

Lab 1 · AVL insertion, the balance rule and the height bound

The keys are SIMULATED: 500 distinct integers drawn from a generator seeded with 20261028, and the sorted keys 1 to 64. Part A inserts the 500 keys into an AVL tree and checks after every insertion that every balance factor is \(-1\), \(0\) or \(1\), that every stored height is correct, that the keys in order are the keys inserted, and that the height is at most \(\log_{\varphi}(n+1)\) for the \(n\) keys so far. It counts rotation calls by kind. Part B inserts 1 to 64 in increasing order into a plain binary search tree and into an AVL tree. Part C prints \(N(h)\) for \(h = 1\) to 12, beside \(\varphi^{h}\), and prints the height of a two-node AVL tree. The code measures no time.

"""CS2 lab L05: AVL insertion on seeded keys, the balance invariant, and the height bound.

SIMULATED keys: 500 distinct integers drawn from a seeded generator (seed 20261028). No market data, no
network, standard library only. Height is the number of nodes on the longest root-to-leaf path, so an empty
tree has height 0 and a single node has height 1. Every count is a count of nodes or rotations; no time is
measured, so every run prints the same lines.

Part A: insert 500 seeded keys into an AVL tree. After every insert the code checks the balance invariant
(every balance factor is -1, 0 or 1, and every stored height is correct), the in-order sequence, and the
height bound h <= log_phi(n + 1) with phi = (1 + sqrt 5) / 2. It counts single and double rotations.
Part B: the same kind of tree on the sorted keys 1..64, with a plain binary search tree beside it.
Part C: the recurrence values N(h) = 1 + N(h-1) + N(h-2) for h = 1 to 12, beside phi^h.
"""

from __future__ import annotations

import math
import random
from dataclasses import dataclass

SEED = 20261028
PHI = (1 + math.sqrt(5)) / 2


@dataclass
class Node:
    """A tree node. height counts the nodes on the longest path from this node down to a leaf."""

    key: int
    left: Node | None = None
    right: Node | None = None
    height: int = 1


@dataclass
class Counts:
    """Rotation calls by kind: a single rotation is one call, a double rotation is two calls."""

    single_left_left: int = 0
    single_right_right: int = 0
    double_left_right: int = 0
    double_right_left: int = 0
    rotation_calls: int = 0
    rebalances_that_rotated: int = 0


def node_height(node: Node | None) -> int:
    """The height of a subtree; the empty tree has height 0."""
    return 0 if node is None else node.height


def balance_factor(node: Node) -> int:
    """Left height minus right height. An AVL tree keeps it in {-1, 0, 1}."""
    return node_height(node.left) - node_height(node.right)


def update_height(node: Node) -> None:
    """Recompute the stored height of node from its children."""
    node.height = 1 + max(node_height(node.left), node_height(node.right))


def rotate_right(y: Node, counts: Counts) -> Node:
    """Single right rotation around y, whose left child x becomes the subtree root. Returns the new root."""
    x = y.left
    if x is None:
        raise ValueError("rotate_right needs a left child")
    y.left = x.right
    x.right = y
    update_height(y)
    update_height(x)
    counts.rotation_calls += 1
    return x


def rotate_left(x: Node, counts: Counts) -> Node:
    """Single left rotation around x, whose right child y becomes the subtree root. Returns the new root."""
    y = x.right
    if y is None:
        raise ValueError("rotate_left needs a right child")
    x.right = y.left
    y.left = x
    update_height(x)
    update_height(y)
    counts.rotation_calls += 1
    return y


def rebalance(node: Node, counts: Counts) -> Node:
    """Restore the balance factor of node to {-1, 0, 1}, using one single rotation or one double rotation."""
    update_height(node)
    factor = balance_factor(node)
    if factor > 1:
        left = node.left
        if left is None:
            raise ValueError("a left-heavy node has a left child")
        if balance_factor(left) < 0:
            node.left = rotate_left(left, counts)
            counts.double_left_right += 1
        else:
            counts.single_left_left += 1
        counts.rebalances_that_rotated += 1
        return rotate_right(node, counts)
    if factor < -1:
        right = node.right
        if right is None:
            raise ValueError("a right-heavy node has a right child")
        if balance_factor(right) > 0:
            node.right = rotate_right(right, counts)
            counts.double_right_left += 1
        else:
            counts.single_right_right += 1
        counts.rebalances_that_rotated += 1
        return rotate_left(node, counts)
    return node


def avl_insert(node: Node | None, key: int, counts: Counts) -> Node:
    """Insert a key that is not yet present, and rebalance on the way up. Raises ValueError on a duplicate."""
    if node is None:
        return Node(key)
    if key < node.key:
        node.left = avl_insert(node.left, key, counts)
    elif key > node.key:
        node.right = avl_insert(node.right, key, counts)
    else:
        raise ValueError(f"key {key} is already present")
    return rebalance(node, counts)


def check_invariant(node: Node | None) -> tuple[bool, int]:
    """Return (ok, height). ok is True when every balance factor is in {-1, 0, 1} and every stored height is right."""
    if node is None:
        return True, 0
    ok_left, height_left = check_invariant(node.left)
    ok_right, height_right = check_invariant(node.right)
    height = 1 + max(height_left, height_right)
    factor = height_left - height_right
    ok = ok_left and ok_right and factor in (-1, 0, 1) and node.height == height
    return ok, height


def in_order(node: Node | None, out: list[int]) -> list[int]:
    """Append the keys of the subtree in increasing order and return the list."""
    if node is not None:
        in_order(node.left, out)
        out.append(node.key)
        in_order(node.right, out)
    return out


def plain_insert(node: Node | None, key: int) -> Node:
    """Insert key into an unbalanced binary search tree. No rotations are made."""
    if node is None:
        return Node(key)
    if key < node.key:
        node.left = plain_insert(node.left, key)
    elif key > node.key:
        node.right = plain_insert(node.right, key)
    return node


def plain_height(node: Node | None) -> int:
    """The height of an unbalanced binary search tree, by a full traversal."""
    if node is None:
        return 0
    return 1 + max(plain_height(node.left), plain_height(node.right))


def height_bound(size: int) -> float:
    """log_phi(size + 1): an AVL tree with size nodes has height at most this value."""
    return math.log(size + 1) / math.log(PHI)


def min_nodes(max_height: int) -> list[int]:
    """N(h), the recurrence values N(h) = 1 + N(h-1) + N(h-2) for h = 0 to max_height."""
    values = [0, 1]
    for h in range(2, max_height + 1):
        values.append(1 + values[h - 1] + values[h - 2])
    return values[: max_height + 1]


def part_a() -> None:
    print("Part A: AVL insertion of 500 seeded distinct keys")
    rng = random.Random(SEED)
    keys = rng.sample(range(1, 1_000_000), 500)
    root: Node | None = None
    counts = Counts()
    inserts_without_rotation = 0
    max_rotations_in_one_insert = 0
    invariant_every_insert = True
    bound_every_insert = True
    order_every_insert = True
    inserted: list[int] = []
    for key in keys:
        calls_before = counts.rotation_calls
        root = avl_insert(root, key, counts)
        inserted.append(key)
        this_insert = counts.rotation_calls - calls_before
        if this_insert == 0:
            inserts_without_rotation += 1
        max_rotations_in_one_insert = max(max_rotations_in_one_insert, this_insert)
        ok, height = check_invariant(root)
        invariant_every_insert = invariant_every_insert and ok
        bound_every_insert = bound_every_insert and height <= height_bound(len(inserted))
        order_every_insert = order_every_insert and in_order(root, []) == sorted(inserted)
    print(f"invariant_after_every_insert {invariant_every_insert}")
    print(f"height_within_log_phi_n_plus_1_after_every_insert {bound_every_insert}")
    print(f"in_order_sorted_and_complete_after_every_insert {order_every_insert}")
    print(f"final_size {len(inserted)} final_height {node_height(root)}")
    print(f"log_phi_501 {height_bound(len(inserted)):.4f}")
    print(f"rotation_calls_total {counts.rotation_calls}")
    print(
        f"rotation_kinds single_left_left {counts.single_left_left} "
        f"single_right_right {counts.single_right_right} "
        f"double_left_right {counts.double_left_right} double_right_left {counts.double_right_left}"
    )
    print(f"inserts_without_rotation {inserts_without_rotation} of {len(keys)}")
    print(f"max_rotation_calls_in_one_insert {max_rotations_in_one_insert}")


def part_b() -> None:
    print("Part B: sorted keys 1..64 in a plain binary search tree and in an AVL tree")
    plain: Node | None = None
    avl: Node | None = None
    counts = Counts()
    for key in range(1, 65):
        plain = plain_insert(plain, key)
        avl = avl_insert(avl, key, counts)
    print(f"plain_bst_height {plain_height(plain)} for 64 keys inserted in increasing order")
    print(f"avl_height {node_height(avl)} for the same keys")
    print(f"avl_bound_log_phi_65 {height_bound(64):.4f}")
    ok, _ = check_invariant(avl)
    print(f"avl_invariant_holds {ok}")


def part_c() -> None:
    print("Part C: recurrence values N(h) = 1 + N(h-1) + N(h-2), beside phi^h")
    values = min_nodes(12)
    all_hold = True
    for h in range(1, 13):
        n_h = values[h]
        all_hold = all_hold and n_h + 1 >= PHI**h
        print(f"h {h} N_h {n_h} N_h_plus_1 {n_h + 1} phi_h {PHI**h:.4f}")
    print(f"N_h_plus_1_at_least_phi_h_for_h_1_to_12 {all_hold}")
    two: Node | None = None
    two_counts = Counts()
    two = avl_insert(two, 2, two_counts)
    two = avl_insert(two, 1, two_counts)
    print(f"two_node_avl_height {node_height(two)} nodes {len(in_order(two, []))} log2_2 {math.log2(2):.4f}")
    print(f"bound_constant_1_over_log2_phi {1 / math.log2(PHI):.6f}")


def main() -> None:
    part_a()
    part_b()
    part_c()

4Where the canon breaks

  • Deletion is not covered. This lesson proves a height bound for trees built by insertion and checks the insertion rule. Removing a key needs its own rotations and its own check, and the page makes no claim about them.
  • The insertion rule is checked, not proved. Remark 3.2 states the gap. The lab's 500 insertions are one seeded run, so they show the rule held on that run and do not show that it holds for every sequence of insertions.
  • The bound is a worst case. Proposition 2.4 bounds the height from above. The lab's AVL tree on keys 1 to 64 has height 7, and the bound is 8.6747. The bound does not say that the average height has any particular value.
  • Comparisons are not time. A search in a tree of height \(h\) makes at most \(h\) comparisons, by the argument of §1. The lab counts rotation calls and checks shapes. It measures no time, and it says nothing about memory layout or disk access.

5Misconceptions

  1. “Keys inserted in sorted order leave a binary search tree balanced.”

    Sorted insertion makes a path (Remark 1.1). For the keys 1 to 64 in increasing order, the plain tree has height 64, and the AVL tree on the same keys has height 7 (Lab 1, Part B). Balance is a property of the shape, and the insertion order can destroy it.

  2. “An AVL tree rotates on every insertion.”

    Most insertions need no rotation. In the run of Lab 1, Part A, 272 of 500 insertions needed none, and the lab made 340 rotation calls in total for the 500 insertions. A rotation is made only at a node whose balance factor has reached 2 or \(-2\).

  3. “The height of an AVL tree is at most \(\log_2 n\).”

    The bound is \(\log_{\varphi}(n+1)\), which is about 1.44 times \(\log_2(n+1)\) (Remark 2.5). The two-node AVL tree has height 2, and \(\log_2 2 = 1\). Lab 1, Part C, prints that height.

Mechanics

M1 · Balance factors of a small tree

A tree has root 5, whose left child is 3 and right child is 7. The node 3 has left child 2 and no right child. The node 7 is a leaf. Compute the height and balance factor of every node, and say whether the tree is AVL.

Solution

The leaves 2 and 7 have height 1 and balance factor 0. The node 3 has left subtree height 1 and empty right subtree height 0, so its height is 2 and its balance factor is \(1 - 0 = 1\). The root has left subtree height 2 and right subtree height 1, so its height is 3 and its balance factor is \(2 - 1 = 1\). Every balance factor is in \(\{-1, 0, 1\}\), so the tree is AVL.

M2 · Inserting 1, 2, 3 into an empty tree

Insert 1, 2 and 3 in that order into an empty AVL tree. Which rotation is made, and what is the root afterwards?

Solution

After 1 and 2, the root 1 has a right child 2, so its balance factor is \(0 - 1 = -1\). Inserting 3 makes the right child 2 have right child 3, and the root 1 gets balance factor \(0 - 2 = -2\). The heavy child 2 leans right, the same way as the root, so one single left rotation at 1 is made. The new root is 2, with left child 1 and right child 3. The height is 2, and every balance factor is 0.

M3 · The recurrence N(h)

Compute \(N(5)\) from Definition 2.2, and check the value against Lab 1, Part C.

Solution

From the definition, \(N(2) = 1 + N(1) + N(0) = 2\), \(N(3) = 1 + N(2) + N(1) = 4\), \(N(4) = 1 + N(3) + N(2) = 7\), and \(N(5) = 1 + N(4) + N(3) = 12\). Lab 1, Part C, prints \(N_h = 12\) for \(h = 5\).

Proof

P1 · A left rotation keeps the order

State the left rotation and prove that it keeps the in-order sequence of keys, by the argument of Proposition 3.1 with left and right exchanged.

Solution

A left rotation at \(x\) with right child \(y\) makes \(y\) the root, with \(x\) as its left child. The subtree \(B\) that was the left subtree of \(y\) becomes the right subtree of \(x\). Before the rotation the in-order sequence is \(A\), \(x\), \(B\), \(y\), \(C\), where \(A\) is the left subtree of \(x\) and \(C\) is the right subtree of \(y\). After the rotation the in-order sequence of the subtree at \(y\) is that of \(x\) with \(A\) and \(B\), which is \(A\), \(x\), \(B\), followed by \(y\) and \(C\). The two sequences agree.

P2 · The recurrence N(h) is nondecreasing

Show that \(N(h) - N(h-1) \ge 1\) for every \(h \ge 2\), and that \(N(1) \ge N(0)\).

Solution

For \(h \ge 2\), \(N(h) - N(h-1) = (1 + N(h-1) + N(h-2)) - N(h-1) = 1 + N(h-2)\). Since \(N(h-2) \ge 0\) (each term is a count of nodes), this is at least 1. Also \(N(1) = 1\) and \(N(0) = 0\), so \(N(1) - N(0) = 1\).

P3 · The golden ratio identity

Let \(\varphi = (1 + \sqrt{5})/2\). Show that \(\varphi^{2} = \varphi + 1\) and that \(\varphi < 2\).

Solution

Squaring, \(\varphi^{2} = (1 + 2\sqrt{5} + 5)/4 = (3 + \sqrt{5})/2\). Also \(\varphi + 1 = (1 + \sqrt{5})/2 + 1 = (3 + \sqrt{5})/2\), so the two are equal. Since \(\sqrt{5} < 3\), \(\varphi = (1 + \sqrt{5})/2 < 2\). With \(\varphi^{2} = \varphi + 1\), this is the identity used in the proof of Proposition 2.4.

E2 · The height against the logarithm at 64 keys

Read Lab 1, Part B. The AVL height on 64 sorted keys is 7. How does it compare with \(\log_2 64\)?

Solution

\(\log_2 64 = 6\) exactly, since \(64 = 2^{6}\). The AVL height is 7, which is one more than \(\log_2 64\). The bound of Proposition 2.4 is \(\log_{\varphi} 65\), which Part B prints as 8.6747, so 7 satisfies it.

E3 · How tall a 376-node AVL tree can be

Read Lab 1, Part C, at \(h = 12\). By Proposition 2.4, what upper bound on the height does an AVL tree with 376 keys have, and what integer height does that bound allow?

Solution

Part C prints \(N_{12} = 376\), and Lemma 2.3 gives that a tree of height 12 has at least 376 nodes, so the count does not rule out height 12. The bound is \(\log_{\varphi}(377)\). Computed as \(\ln 377 / \ln \varphi\), with \(\ln 377 = 5.932\) and \(\ln \varphi = 0.4812\), this is \(12.33\). So the height is at most 12.33, and an integer height of at most 12 is allowed. This page does not show that a tree with 376 nodes and height 12 exists.

Research

R1 · A double rotation

Insert 3, then 1, then 2 into an empty AVL tree. Identify the case of the rebalancing step and give the tree after it.

Solution

After 3 and 1, the root 3 has left child 1. Inserting 2 puts it as the right child of 1, so the root 3 has balance factor \(2 - 0 = 2\). Its heavy child 1 leans right, the other way from the root, so this is the left-right case and a double rotation is made. A left rotation at 1 makes 2 the left child of 3, with 2 having left child 1. Then a right rotation at 3 makes 2 the root, with left child 1 and right child 3. The tree has height 2 and every balance factor is 0.

R2 · An AVL tree of height 4 with 7 nodes

Describe an AVL tree of height 4 with exactly 7 nodes, and explain why no AVL tree of height 4 has fewer nodes.

Solution

Take a root \(R\) whose left subtree is the tree of Problem M1 (root 5, left child 3 with left child 2, right child 7), which has 4 nodes and height 3, and whose right subtree is a node \(s\) with one left child \(t\), which has 2 nodes and height 2. Every balance factor is listed: \(R\) has \(3 - 2 = 1\), 5 has \(2 - 1 = 1\), 3 has \(1 - 0 = 1\), 2 and 7 have 0, \(s\) has \(1 - 0 = 1\), and \(t\) has 0. All lie in \(\{-1, 0, 1\}\), so the tree is an AVL tree with root height \(1 + 3 = 4\) and \(1 + 4 + 2 = 7\) nodes. By Lemma 2.3 every AVL tree of height 4 has at least \(N(4) = 7\) nodes.

R3 · No AVL tree of height 5 with 7 nodes

Show that no AVL tree with 7 nodes has height 5, using Proposition 2.4 or Lemma 2.3.

Solution

Lemma 2.3 gives \(N(5) = 12\), so an AVL tree of height 5 has at least 12 nodes, and no AVL tree of height 5 has 7 nodes. Proposition 2.4 gives the same conclusion: with \(n = 7\), \(\log_{\varphi} 8 = \ln 8 / \ln \varphi = 4.32\), so the height is at most 4. Both arguments agree, and R2 shows that height 4 is attained with 7 nodes.
