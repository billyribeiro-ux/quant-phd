Some questions about a network reduce to one step: starting from one point, find every point that can be reached, and the order in which they are reached. Which accounts are linked to a given account, and how many links separate two of them, are questions of this form. Two search methods answer them. One finds the fewest links from the starting point to each point that can be reached. The other returns a nested record of when each point is first reached and when its search of that point is finished. This lesson proves both properties. Lab 1 checks the first against exhaustive search, and the second on seeded networks.

1Graphs, adjacency lists and the two orders

A graph here is a finite set of vertices with a set of edges, each edge joining two different vertices. The graph is undirected: an edge joins its two ends in both directions. A path is a sequence of vertices in which each consecutive pair is an edge, and a simple path has no repeated vertex. A walk allows repeated vertices, and its length is its number of edges. The number of edges on a path is its hop count. A graph is stored as adjacency lists: for each vertex, the list of its neighbours. A hash map from vertex labels to these lists stores the graph (L02), and a vertex is looked up by its label. An adjacency matrix is the other storage used here: an \(n \times n\) table, for \(n\) vertices, whose entry in row \(u\) and column \(v\) is 1 when \(u\) and \(v\) are joined by an edge and 0 otherwise. Reading the neighbours of a vertex from a matrix means reading its full row of \(n\) entries.

Definition 1.1 (graph traversal)

A graph traversal starts at a source vertex \(s\) and visits the vertices reachable from \(s\), each once, by moving along edges from vertices already visited. Breadth-first search (BFS) keeps the discovered vertices in a first-in, first-out queue. It starts with \(s\) in the queue, and repeats: remove the front vertex \(u\) (a dequeue), and for each neighbour \(v\) of \(u\) that has not been discovered, mark \(v\) discovered, give it distance \(\mathrm{dist}(u) + 1\), record \(u\) as its parent, and add it to the back of the queue (an enqueue). Depth-first search (DFS) is defined in §3 (Definition 3.1).

2Breadth-first search finds fewest hops

Let \(\delta(v)\) be the fewest edges on a path from \(s\) to \(v\), when \(v\) is reachable from \(s\). BFS is run as in Definition 1.1, with \(\mathrm{dist}(s) = 0\).

Lemma 2.1 (the queue is ordered by distance)

Assume the following. (1) The graph is finite and undirected. (2) BFS runs as in Definition 1.1, and each discovered vertex has distance equal to its parent's distance plus 1. Then at every moment the distances of the queued vertices are nondecreasing from front to back, and they differ by at most 1. Hence the vertices are removed from the queue in nondecreasing order of distance.

Proof

Induct on the number of queue operations. At the start the queue holds \(s\) alone. Suppose the queue holds distances in \(\{\ell, \ell+1\}\), nondecreasing from front to back, with front distance \(\ell\). A removal takes out a vertex with distance \(\ell\), so the remaining distances still lie in \(\{\ell, \ell+1\}\) and remain nondecreasing. The vertices added during this step have distance \(\ell + 1\), and they are added at the back, so the sequence stays nondecreasing. Every distance now lies in \(\{\ell', \ell'+1\}\), where \(\ell'\) is the distance of the new front: if a vertex of distance \(\ell\) remains, then \(\ell' = \ell\); otherwise every remaining distance is \(\ell+1\) and \(\ell' = \ell+1\), and the added vertices also have distance \(\ell+1\). In both cases the invariant holds.

Proposition 2.2 (BFS gives fewest hops)

Assume the hypotheses of Lemma 2.1 and a source \(s\). Then BFS discovers exactly the vertices reachable from \(s\), and for each of them \(\mathrm{dist}(v) = \delta(v)\).

Proof

Every discovered vertex is reachable, because it is discovered from a discovered vertex by an edge, starting from \(s\). Conversely, a reachable vertex is discovered: induct on \(\delta(v)\). If \(\delta(v) = 0\), then \(v = s\). If \(\delta(v) = k \ge 1\), a shortest path to \(v\) has a vertex \(u\) before \(v\) with \(\delta(u) = k - 1\), which is discovered by induction. BFS removes every discovered vertex, so \(u\) is removed, and when it is, \(v\) is either undiscovered, and becomes discovered, or already discovered. Next, \(\mathrm{dist}(v) \ge \delta(v)\) for every discovered \(v\). The distance of \(v\) is the length of the tree path from \(s\) to \(v\) through parents, which is a walk of that length, so the walk has length at least \(\delta(v)\). Finally, \(\mathrm{dist}(v) \le \delta(v)\), by induction on \(k = \delta(v)\). For \(k = 0\), \(\mathrm{dist}(s) = 0\). For \(k \ge 1\), take \(u\) as above, with \(\mathrm{dist}(u) = \delta(u) = k - 1\) by induction. If \(v\) was discovered before \(u\) was removed, by a vertex \(w\) removed no later than \(u\), then \(\mathrm{dist}(w) \le \mathrm{dist}(u) = k - 1\) by Lemma 2.1, so \(\mathrm{dist}(v) = \mathrm{dist}(w) + 1 \le k\). Otherwise \(v\) is discovered when \(u\) is removed, and \(\mathrm{dist}(v) = k\). Either way \(\mathrm{dist}(v) \le k\).

Proposition 2.3 (the operation count of BFS)

Assume an undirected graph with \(|V|\) vertices and \(|E|\) edges, stored as adjacency lists. BFS from \(s\) makes at most \(|V|\) enqueue operations, and it inspects at most \(2|E|\) adjacency entries. In the count of Remark 2.4, each enqueue and each adjacency-entry inspection costs one operation.

Proof

A vertex is enqueued only when it is first discovered, so it is enqueued at most once, which gives at most \(|V|\) enqueues. A vertex is removed once, and when it is removed its adjacency list is scanned once, so the entries inspected are the degrees of the removed vertices. The sum of all degrees is \(2|E|\), since each edge contributes one entry to each of its two ends, so the inspections are at most \(2|E|\).

Remark 2.4 (what the count is)

Proposition 2.3 counts the operations of one search: enqueues and adjacency-entry inspections. It is a count, not a measured time, and it gives \(O(|V| + |E|)\) in the sense of L01. Lab 1, Part D, prints the count for one graph on 200 vertices, together with the row reads that the same search would make on an adjacency matrix.

3Depth-first search and the parenthesis property

Definition 3.1 (depth-first search)

Depth-first search keeps one clock. When a vertex \(v\) is first visited, the clock ticks, and the tick is the discovery time \(d(v)\). Then, for each neighbour \(u\) of \(v\) that has not been discovered, the search visits \(u\) recursively. When every neighbour has been handled, the clock ticks again, and the tick is the finish time \(f(v)\). The whole search runs this procedure from every vertex that has not been discovered, in turn.

Proposition 3.2 (the parenthesis property)

Assume the following. (1) The graph is finite and undirected. (2) The search is that of Definition 3.1, with one clock that ticks once at each discovery and once at each finish. Then for any two distinct vertices \(u\) and \(v\), the intervals \([d(u), f(u)]\) and \([d(v), f(v)]\) are disjoint, or one lies inside the other.

Proof

Each vertex is visited by exactly one recursive call, so the calls correspond one to one to the vertices, and the call for \(v\) runs from the tick \(d(v)\) to the tick \(f(v)\). Let the calls form the recursion forest, with one tree for each vertex that the outer loop of Definition 3.1 starts, and in which the call for \(u\) is the child of the call that discovered it. A child call starts after its parent's discovery tick, and it finishes before its parent's finish tick. So each child interval lies strictly inside its parent's interval, and by transitivity each descendant's interval lies inside that of every ancestor. Take two distinct vertices \(u\) and \(v\). If one call is an ancestor of the other, their intervals are nested. Otherwise, either \(u\) and \(v\) lie in the same tree, and then they have a lowest common ancestor \(a\) and lie in different children's subtrees of \(a\), or they lie in different trees. In the first case, within the call of \(a\), the children are visited one after another, and the first child's call finishes before the second begins, because the search is recursive, so the two intervals are disjoint. In the second case, the search finishes the tree of the earlier root before it starts the later root, so their intervals are disjoint.

Lab 1 · BFS against exhaustive search, the parenthesis property, and operation counts

The graphs are SIMULATED: seeded random undirected graphs on 3 to 7 vertices, drawn from a generator seeded with 20261028, and one seeded graph on 200 vertices. Part A checks that the BFS distances from every source equal the fewest hops over all simple paths, found by exhaustive search, on 40 graphs. Part B checks Proposition 3.2 for every pair of vertices in 40 further graphs drawn the same way. Part C runs BFS and the lightest path search on one weighted graph of 4 vertices. Part D counts the operations of one BFS on the 200-vertex graph and computes, by formula, the row reads that the same search would make on an adjacency matrix. The code measures no time.

"""CS2 lab L06: BFS hop counts against brute force, the DFS parenthesis property, and operation counts.

SIMULATED graphs: every graph is a seeded random undirected graph (seed 20261028 and offsets from it). No market
data, no network, standard library only. Vertices are 0..n-1. Adjacency lists are sorted, so every run prints
the same lines.

Part A: 40 seeded graphs with 3 to 7 vertices. For every source, the BFS hop counts equal the fewest edges over
all simple paths, found by exhaustive search. Mismatches are counted.
Part B: DFS discovery and finish times on 40 further graphs, drawn the same way. For every pair of vertices the two
intervals [discovery, finish] are nested or disjoint (the parenthesis property). Violations are counted.
Part C: a 4-vertex graph with edge weights. The BFS path is the fewest hops; the lightest path is found by
exhaustive search. The two paths differ for a and c; for b they coincide.
Part D: BFS operation counts on a seeded graph with 200 vertices: vertices enqueued, adjacency entries inspected,
and the cost of the same search on an adjacency matrix, which reads one full row per dequeued vertex.
"""

from __future__ import annotations

import itertools
import random
from collections import deque

SEED = 20261028
Graph = dict[int, list[int]]


def random_graph(rng: random.Random, n: int, p: float) -> Graph:
    """An undirected graph on 0..n-1: each pair is an edge with probability p. Adjacency lists are sorted."""
    adj: Graph = {v: [] for v in range(n)}
    for u in range(n):
        for v in range(u + 1, n):
            if rng.random() < p:
                adj[u].append(v)
                adj[v].append(u)
    for v in adj:
        adj[v].sort()
    return adj


def bfs(adj: Graph, source: int) -> tuple[dict[int, int], dict[int, int], list[int], int]:
    """Breadth-first search from source. Returns hop distances, parents, the dequeue order, and the number of
    adjacency entries inspected. A FIFO queue holds the discovered vertices not yet dequeued."""
    dist: dict[int, int] = {source: 0}
    parent: dict[int, int] = {}
    order: list[int] = []
    queue: deque[int] = deque([source])
    inspections = 0
    while queue:
        v = queue.popleft()
        order.append(v)
        for u in adj[v]:
            inspections += 1
            if u not in dist:
                dist[u] = dist[v] + 1
                parent[u] = v
                queue.append(u)
    return dist, parent, order, inspections


def brute_min_hops(adj: Graph, source: int) -> dict[int, int]:
    """The fewest edges over all simple paths from source to each reachable vertex, by exhaustive search."""
    best: dict[int, int] = {source: 0}
    on_path = {source}

    def extend(v: int, length: int) -> None:
        for u in adj[v]:
            if u in on_path:
                continue
            if length + 1 < best.get(u, 10**9):
                best[u] = length + 1
            on_path.add(u)
            extend(u, length + 1)
            on_path.remove(u)

    extend(source, 0)
    return best


def dfs_times(adj: Graph) -> tuple[dict[int, int], dict[int, int]]:
    """Recursive depth-first search over all vertices. Returns discovery and finish times on one clock.

    The clock ticks once when a vertex is discovered and once when it finishes, so the times are 1..2n."""
    discover: dict[int, int] = {}
    finish: dict[int, int] = {}
    clock = [0]

    def visit(v: int) -> None:
        clock[0] += 1
        discover[v] = clock[0]
        for u in adj[v]:
            if u not in discover:
                visit(u)
        clock[0] += 1
        finish[v] = clock[0]

    for v in sorted(adj):
        if v not in discover:
            visit(v)
    return discover, finish


def nested_or_disjoint(d: dict[int, int], f: dict[int, int], u: int, v: int) -> bool:
    """True when the intervals [d[u], f[u]] and [d[v], f[v]] are disjoint or one contains the other."""
    if f[u] < d[v] or f[v] < d[u]:
        return True
    return (d[u] < d[v] and f[v] < f[u]) or (d[v] < d[u] and f[u] < f[v])


def weighted_paths(adj: Graph, weight: dict[tuple[int, int], int], source: int) -> dict[int, tuple[int, list[int]]]:
    """For each reachable vertex, the lightest simple path from source: (total weight, path), by exhaustive search."""
    best: dict[int, tuple[int, list[int]]] = {source: (0, [source])}
    on_path = [source]

    def extend(v: int, total: int) -> None:
        for u in adj[v]:
            if u in on_path:
                continue
            step = total + weight[(min(v, u), max(v, u))]
            if u not in best or step < best[u][0]:
                best[u] = (step, [*on_path, u])
            on_path.append(u)
            extend(u, step)
            on_path.pop()

    extend(source, 0)
    return best


def part_a(rng: random.Random) -> None:
    print("Part A: BFS hop counts against exhaustive search over simple paths")
    graphs = 0
    pairs = 0
    mismatches = 0
    unreachable = 0
    sources = 0
    for k in range(40):
        n = 3 + k % 5
        p = 0.2 + 0.1 * (k % 4)
        adj = random_graph(rng, n, p)
        graphs += 1
        for source in range(n):
            sources += 1
            dist, _, _, _ = bfs(adj, source)
            brute = brute_min_hops(adj, source)
            pairs += len(dist)
            unreachable += n - len(dist)
            if dist != brute:
                mismatches += 1
    print(f"graphs {graphs} sources_checked {sources}")
    print(f"reachable_pairs_checked {pairs} unreachable_pairs {unreachable}")
    print(f"bfs_mismatches_against_brute_force {mismatches}")


def part_b(rng: random.Random) -> None:
    print("Part B: DFS parenthesis property on the same kind of graphs")
    graphs = 0
    pairs = 0
    violations = 0
    for k in range(40):
        n = 3 + k % 5
        p = 0.2 + 0.1 * (k % 4)
        adj = random_graph(rng, n, p)
        graphs += 1
        d, f = dfs_times(adj)
        for u in range(n):
            for v in range(u + 1, n):
                pairs += 1
                if not nested_or_disjoint(d, f, u, v):
                    violations += 1
    print(f"graphs {graphs} vertex_pairs_checked {pairs}")
    print(f"parenthesis_violations {violations}")


def part_c() -> None:
    print("Part C: fewest hops against lightest path on a weighted 4-vertex graph")
    names = ["s", "a", "b", "c"]
    adj: Graph = {0: [1, 2], 1: [0, 2, 3], 2: [0, 1], 3: [1]}
    weight = {(0, 1): 10, (0, 2): 1, (1, 2): 1, (1, 3): 1}
    dist, parent, _, _ = bfs(adj, 0)
    light = weighted_paths(adj, weight, 0)
    for v in (1, 2, 3):
        path: list[int] = [v]
        while path[-1] != 0:
            path.append(parent[path[-1]])
        hop_path = "-".join(names[x] for x in reversed(path))
        weight_hop = sum(weight[(min(a, b), max(a, b))] for a, b in itertools.pairwise(path))
        total, light_path = light[v]
        light_text = "-".join(names[x] for x in light_path)
        print(
            f"to {names[v]}: bfs_path {hop_path} hops {dist[v]} weight {weight_hop} | "
            f"lightest_path {light_text} hops {len(light_path) - 1} weight {total}"
        )


def part_d() -> None:
    print("Part D: BFS operation counts on a seeded graph with 200 vertices")
    rng = random.Random(SEED + 1000)
    n = 200
    adj = random_graph(rng, n, 0.03)
    edges = sum(len(adj[v]) for v in adj) // 2
    dist, _, order, inspections = bfs(adj, 0)
    reached = len(dist)
    degree_sum = sum(len(adj[v]) for v in order)
    print(f"vertices {n} edges {edges} reached_from_0 {reached}")
    print(f"enqueues {reached} dequeues {len(order)} each_vertex_enqueued_once {len(set(order)) == len(order)}")
    print(f"adjacency_entries_inspected {inspections} equals_sum_of_degrees_of_reached {inspections == degree_sum}")
    print(f"matrix_row_reads_for_same_search {len(order) * n}")
    print(f"list_work_enqueues_plus_inspections {reached + inspections}")


def main() -> None:
    rng = random.Random(SEED)
    part_a(rng)
    part_b(rng)
    part_c()
    part_d()


main()

Part A: over 40 graphs, the BFS distances from 200 sources equal the exhaustive minimum in every case, so there are no mismatches. The count of 772 reachable pairs includes each source with itself at distance 0, which is 200 pairs. Excluding those, 572 pairs have a positive distance, and the 308 unreachable pairs are not discovered by the search. Part B: the 440 vertex pairs satisfy the parenthesis property, with 0 violations. 4Where the canon breaks

  • Hops are not weights. Proposition 2.2 is about edges, each counted as one. With edge weights, the fewest-hop path can be the heavier of the two simple paths to vertex c in Part C (weight 11, against weight 3 for the path with 3 hops). This lesson gives no method for weighted shortest paths.
  • DFS paths are not shortest. The path to a vertex through the recursion forest of the proof of Proposition 3.2 can be longer than its hop distance (Misconception 2). The parenthesis property is a statement about nesting of times, not about distances.
  • Directed graphs. The statements above assume undirected edges (hypothesis 1). Their proofs use symmetry only in the degree-sum step of Proposition 2.3, where each edge is counted at both ends. Lemma 2.1, Proposition 2.2 and Proposition 3.2 do not use it. The labs use undirected graphs, and this page does not cover directed graphs, including the edge classification of a directed DFS.
  • Recursion depth. Definition 3.1 is recursive, so one path of recursive calls can be as long as the number of vertices. This page does not measure the stack space that the calls use.

5Misconceptions

  1. “Breadth-first search finds the shortest path when edges have weights.”

    BFS minimizes the number of edges (Proposition 2.2). On the weighted graph of Lab 1, Part C, the path s to a has 1 hop and weight 10, while s to b to a has 2 hops and weight 2. BFS returns the path with the fewest edges, here the direct edge from s to a.

  2. “Depth-first search also finds shortest hop paths, because it reaches every vertex.”

    Reaching a vertex is not the same as reaching it by the fewest edges. Take the triangle a, b, c with edges a to b, b to c and a to c, and let the neighbour list of a be b then c. The depth-first search discovers b from a, then c from b, so the path to c through its recursive calls is a, b, c with 2 hops. But a and c are adjacent, so the hop distance is 1, which BFS returns.

  3. “A traversal costs the same whether the graph is stored as adjacency lists or as an adjacency matrix.”

    Proposition 2.3 gives at most \(|V| + 2|E|\) operations with lists. With an adjacency matrix, a dequeued vertex reads its full row of \(|V|\) entries, so the row reads are \(|V|\) times the number of dequeued vertices, which is at most \(|V|^{2}\). Lab 1, Part D, prints 1438 operations for lists and 40000 row reads for the matrix on the same 200-vertex graph.

6Problem set

Every problem has a full worked solution. Attempt each one before opening it.

Mechanics

M1 · BFS distances on a five-vertex graph

The undirected edges are 1 to 2, 1 to 3, 2 to 4, 3 to 4 and 4 to 5. Run BFS from 1, with neighbours taken in increasing order. Give the distances and the order in which the vertices are removed from the queue.

Solution

Start with queue \([1]\), distance 0. Remove 1, and discover its neighbours 2 and 3 with distance 1, so the queue is \([2, 3]\). Remove 2, whose neighbours are 1 (discovered) and 4, which gets distance 2. The queue is \([3, 4]\). Remove 3, whose neighbours 1 and 4 are discovered. Remove 4, which discovers 5 with distance 3. Remove 5. The distances are 1 to 0, 2 and 3 to 1, 4 to 2, and 5 to 3. The removal order is 1, 2, 3, 4, 5.

M2 · DFS times on a path

The undirected path 1 to 2 to 3 is searched by Definition 3.1 from vertex 1. Give the discovery and finish times of every vertex.

Solution

The clock starts at 0. Vertex 1 is discovered at tick 1, and the search moves to 2, discovered at tick 2. From 2 it moves to 3, discovered at tick 3. Vertex 3 has no undiscovered neighbour, so it finishes at tick 4. Vertex 2 finishes at tick 5 and vertex 1 at tick 6. So \(d = (1, 2, 3)\) and \(f = (6, 5, 4)\) for vertices 1, 2 and 3. The intervals \([1, 6]\), \([2, 5]\) and \([3, 4]\) are nested, as Proposition 3.2 states.

M3 · Adjacency scans on a triangle

The triangle on vertices 1, 2 and 3 has three edges. Count the adjacency entries BFS inspects from vertex 1.

Solution

Each of the three vertices is dequeued once, and each has two neighbours, so the scans are the sum of the degrees, which is \(2 + 2 + 2 = 6\). Proposition 2.3 gives at most \(2|E| = 2 \cdot 3 = 6\). Equality holds here because all three vertices are dequeued, so every adjacency entry is inspected.

Proof

P1 · One queue step keeps the invariant

Let the queue hold distances in \(\{\ell, \ell+1\}\), nondecreasing from front to back. Show that after removing the front vertex and adding its undiscovered neighbours with distance \(\ell+1\), the queue still has distances in \(\{\ell', \ell'+1\}\), where \(\ell'\) is the new front distance.

Solution

The removed vertex has distance \(\ell\), so the remaining vertices have distances in \(\{\ell, \ell+1\}\). The new vertices have distance \(\ell+1\). If a vertex of distance \(\ell\) remains, the new front is \(\ell' = \ell\), and every distance is in \(\{\ell, \ell+1\}\). If none remains, the new front is \(\ell' = \ell + 1\), and every distance is \(\ell+1\), which lies in \(\{\ell', \ell'+1\}\). The order stays nondecreasing, because the new vertices are added at the back with the largest distance present.

P2 · Children nest inside their parent

In the recursion forest of Definition 3.1, show that the interval of a child call lies strictly inside the interval of its parent.

Solution

The child is discovered during the parent's call, when the parent has been discovered and not yet finished, so its discovery tick is after \(d(\text{parent})\). The child finishes before the parent's loop over neighbours ends, which is before the parent's finish tick \(f(\text{parent})\). So \(d(\text{parent}) < d(\text{child}) < f(\text{child}) < f(\text{parent})\).

P3 · Each vertex is enqueued once

Explain why BFS enqueues each vertex at most once, and deduce the bound \(|V|\) on enqueues.

Solution

A vertex is enqueued only at the moment it is discovered, and discovery marks it as discovered. Any later neighbour check finds it discovered and does not enqueue it again. So each vertex is enqueued at most once, and the number of enqueues is at most the number of vertices, \(|V|\).

Part D prints 40000 row reads and 1438 list operations. The ratio is \(40000 / 1438\). Since \(1438 \cdot 27 = 38826\) and \(40000 - 38826 = 1174\), the ratio is \(27 + 1174/1438 = 27.8164\), which is 27.82 to two decimal places.

Research

R1 · Edges in an undirected recursion forest

Let the graph be undirected and searched by Definition 3.1. Prove that for every edge \(\{u, v\}\), one end is an ancestor of the other in the recursion forest.

Solution

Let \(d(u) < d(v)\). When \(u\) is discovered, \(v\) is either undiscovered or discovered already. If \(v\) is already discovered at \(d(u)\), then \(d(v) < d(u)\), a contradiction. So \(v\) is undiscovered at \(d(u)\). If \(v\) were not discovered before \(f(u)\), the loop over the neighbours of \(u\) would reach \(v\) and discover it during \(u\)'s call, so \(v\) would be a descendant of \(u\). If \(v\) were discovered after \(f(u)\), the edge \(\{u, v\}\) would be scanned from \(u\) before \(f(u)\), which would discover \(v\) during \(u\)'s call. Either way \(v\) is a descendant of \(u\).

R2 · BFS reaches exactly the vertices reachable from the source

State what Proposition 2.2 gives for the set of discovered vertices, and identify the set of vertices reachable from \(s\) in the graph.

Solution

Proposition 2.2 gives that the discovered vertices are exactly the vertices reachable from \(s\). These are the vertices joined to \(s\) by a path. Since the graph is undirected, this set is the connected component of \(s\), the part of the graph that contains \(s\). So a traversal from \(s\) discovers that component and no other vertex.

R3 · The complete graph

For the complete graph on \(n\) vertices, count the BFS scans from one source and compare the count with \(|V| + 2|E|\).

Solution

The complete graph has \(|E| = n(n-1)/2\) edges, and every vertex has degree \(n - 1\). BFS dequeues all \(n\) vertices, so the scans are \(n(n-1) = 2|E|\). The count \(|V| + 2|E|\) of Proposition 2.3 is \(n + n(n-1) = n^{2}\). So the scans are \(n(n-1)\) and the total operations are \(n^{2}\), which is of order \(n^{2}\), the same order as the adjacency-matrix cost of the same search, which reads \(n\) entries for each of the \(n\) dequeued vertices.
