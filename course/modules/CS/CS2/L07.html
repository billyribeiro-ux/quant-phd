Some problems ask for the best of exponentially many choices: the fewest coins that make an amount, the longest sequence two strings share, the cheapest way to cut a sequence. The method answers each by writing the answer in terms of answers to smaller questions, and computing each of those smaller answers once. The method is as good as its rule, and two traps come up. A rule that looks optimal can be wrong, as Example 2.4 shows, and a table can be far larger than the input's size suggests. This lesson proves that the rule is correct for two problems, counts the smaller computations in a lab, and shows where the method stops being efficient.

1Subproblems, recurrences and the two evaluation strategies

A subproblem is a smaller instance of the same question, identified by a short key such as a pair of integers. A recurrence expresses the answer to an instance as a formula in the answers to its subproblems, together with base values that need no further reduction. A recursive call is a call of a function on a smaller instance, made from inside that function.

Definition 1.1 (dynamic programming)

Dynamic programming solves a problem in three steps. It writes the answer as a recurrence over subproblems. It evaluates each distinct subproblem once and stores its value. It reads the answer from the stored values. There are two standard forms. In memoized recursion, a function calls itself on subproblems, and every call after the first for a given subproblem returns the stored value. In table fill, the values are written into a table in an order where each entry depends only on entries already written.

Both forms are meant to store the value of the recurrence at each subproblem they compute. The memoized form is not proved here to do so. Lab 1 checks that the answers of the memoized form agree with the table fill on 60 seeded instances (parts A and B), a grade C result in the key-results table. The two forms can touch different subproblems: on the pair ACGTACG and TGCATGC of Lab 1, Part C (the longest-common-subsequence problem of Section 3), the memoized recursion stores 28 of the 49 cells that the table fills. They can also touch the same ones: for the coin set \(\{1\}\) (denominations, Definition 2.1) and amount 3, both touch the amounts 0 to 3. The memoized form makes recursive calls, which the table fill does not make. Section 4 counts these differences. Sections 2 and 3 fix the notion of a correct recurrence by proving one for each of two problems.

2Coin change: the recurrence and the largest-coin-first trap

Definition 2.1 (representations and the fewest-coin count)

Let \(D\) be a finite nonempty set of positive integers, the denominations. A multiset is a collection in which an element may appear several times and order is ignored. A representation of a nonnegative integer \(a\) is a multiset of elements of \(D\), each usable any number of times, whose sum is \(a\). Let \(f(a)\) be the fewest elements in a representation of \(a\), with \(f(a) = \infty\) when no representation exists.

Theorem 2.2 (coin-change recurrence)

Hypotheses.

  1. \(D\) is a finite nonempty set of positive integers.
  2. \(a\) is a nonnegative integer, and \(f\) is as in Definition 2.1.
  3. The minimum over an empty set is \(\infty\), and \(\infty + 1 = \infty\).

Then \(f(0) = 0\), and for every \(a \ge 1\), \[ f(a) = \min\{\, 1 + f(a - c) : c \in D,\ c \le a \,\}. \]

Proof

Base case. The only multiset of positive integers with sum \(0\) is the empty one, so \(f(0) = 0\).

Upper bound. Let \(a \ge 1\), and let \(g(a)\) be the right-hand side. Take any \(c \in D\) with \(c \le a\) and \(f(a - c) < \infty\). A fewest-element representation of \(a - c\) has \(f(a - c)\) elements; adding one element \(c\) gives a representation of \(a\) with \(1 + f(a - c)\) elements. So \(f(a) \le 1 + f(a - c)\) for each such \(c\), and \(f(a) \le g(a)\). If no such \(c\) exists, \(g(a) = \infty\) and the inequality holds.

Lower bound. Suppose \(f(a) < \infty\), and let \(S\) be a representation of \(a\) with \(f(a)\) elements. Since \(a \ge 1\), \(S\) is nonempty. Pick any element \(c\) of \(S\). Then \(c \le a\), and \(S\) without that element represents \(a - c\) with \(f(a) - 1\) elements. So \(f(a - c) \le f(a) - 1\), that is \(1 + f(a - c) \le f(a)\), and \(g(a) \le f(a)\).

Infinite case. If \(f(a) = \infty\) and \(g(a) < \infty\), some \(c \le a\) has \(f(a - c) < \infty\). Adding \(c\) to a representation of \(a - c\) represents \(a\), so \(f(a) < \infty\), a contradiction. Hence \(f(a) = g(a)\) in every case.

The proof uses no induction. Induction enters when the recurrence is turned into a table, which the next corollary states.

Corollary 2.3 (table fill computes the fewest-coin counts)

Hypotheses.

  1. The hypotheses of Theorem 2.2 hold.
  2. \(A \ge 0\) is an integer.

Write \(\mathrm{dp}[0] = 0\), and for \(a = 1, \ldots, A\) let \(\mathrm{dp}[a] = \min\{1 + \mathrm{dp}[a - c] : c \in D,\ c \le a,\ \mathrm{dp}[a - c] < \infty\}\), with the minimum over an empty set taken as \(\infty\). Then \(\mathrm{dp}[a] = f(a)\) for every \(0 \le a \le A\).

Proof

By strong induction on \(a\). For \(a = 0\), \(\mathrm{dp}[0] = 0 = f(0)\) by Theorem 2.2. For \(a \ge 1\), assume \(\mathrm{dp}[b] = f(b)\) for all \(b < a\). Each entry \(\mathrm{dp}[a - c]\) that the formula reads has \(a - c < a\), so \(\mathrm{dp}[a - c] = f(a - c)\) by hypothesis. The formula for \(\mathrm{dp}[a]\) is then the right-hand side of Theorem 2.2, so \(\mathrm{dp}[a] = f(a)\).

Example 2.4 (denominations 1, 3 and 4)

Take \(D = \{1, 3, 4\}\). Theorem 2.2 gives \(f(0), \ldots, f(6) = 0, 1, 2, 1, 1, 2, 2\). For \(a = 6\), the three candidates are \(1 + f(5) = 3\), \(1 + f(3) = 2\) and \(1 + f(2) = 3\), so \(f(6) = 2\), realized by \(3 + 3\). The largest-coin-first rule (the greedy rule), which at each step takes the largest denomination that does not exceed the amount left, takes \(4\), then \(1\), then \(1\), which is three coins. The rule is not optimal here.

3Longest common subsequence (LCS)

Definition 3.1 (common subsequence and the prefix length)

Let \(x = x_1 x_2 \cdots x_m\) and \(y = y_1 y_2 \cdots y_n\) be finite sequences of symbols. A common subsequence of length \(k\) is given by indices \(p_1 < \cdots < p_k\) in \(x\) and \(q_1 < \cdots < q_k\) in \(y\) with \(x_{p_t} = y_{q_t}\) for every \(t\). Symbols are equal exactly when they are the same symbol. For \(0 \le i \le m\) and \(0 \le j \le n\), let \(\lambda(i, j)\) be the largest length of a common subsequence of the prefixes \(x_1 \cdots x_i\) and \(y_1 \cdots y_j\), with \(\lambda(0, j) = \lambda(i, 0) = 0\) for the empty prefix.

Lemma 3.2 (monotonicity, and at most one more per symbol)

Hypotheses.

  1. \(x\) and \(y\) are finite sequences.
  2. \(\lambda\) is as in Definition 3.1.
  3. Symbols are compared by exact equality.

Under these hypotheses:

  1. for \(1 \le i \le m\) and \(0 \le j \le n\), \(\lambda(i - 1, j) \le \lambda(i, j) \le \lambda(i - 1, j) + 1\);
  2. for \(0 \le i \le m\) and \(1 \le j \le n\), \(\lambda(i, j - 1) \le \lambda(i, j) \le \lambda(i, j - 1) + 1\).
Proof

The left inequalities hold because a common subsequence of shorter prefixes is also one of longer prefixes, with the same indices. For the right inequality in (1), let \(Z\) be a longest common subsequence of \(x_1 \cdots x_i\) and \(y_1 \cdots y_j\), with length \(k\). If \(k = 0\) there is nothing to show. If \(p_k < i\), every index of \(Z\) in \(x\) lies in \(1, \ldots, i - 1\), so \(k \le \lambda(i - 1, j)\). If \(p_k = i\), the first \(k - 1\) pairs are a common subsequence of \(x_1 \cdots x_{i-1}\) and \(y_1 \cdots y_j\), so \(k - 1 \le \lambda(i - 1, j)\). In both cases \(k \le \lambda(i - 1, j) + 1\). Part (2) follows by exchanging the roles of \(x\) and \(y\).

Theorem 3.3 (longest-common-subsequence recurrence)

Hypotheses.

  1. \(x\) and \(y\) are finite sequences.
  2. Symbols are compared by exact equality.
  3. \(\lambda\) is as in Definition 3.1.

Let \(1 \le i \le m\) and \(1 \le j \le n\). (a) If \(x_i = y_j\), then \(\lambda(i, j) = \lambda(i - 1, j - 1) + 1\). (b) If \(x_i \ne y_j\), then \(\lambda(i, j) = \max\{\lambda(i - 1, j), \lambda(i, j - 1)\}\).

Proof

Part (a). Let \(W\) be a longest common subsequence of \(x_1 \cdots x_{i-1}\) and \(y_1 \cdots y_{j-1}\). Since \(x_i = y_j\), adding the pair \(i, j\) after the indices of \(W\) gives a common subsequence of \(x_1 \cdots x_i\) and \(y_1 \cdots y_j\) of length \(\lambda(i - 1, j - 1) + 1\). So \(\lambda(i, j) \ge \lambda(i - 1, j - 1) + 1\). For the converse, let \(Z\) be a longest common subsequence of \(x_1 \cdots x_i\) and \(y_1 \cdots y_j\), with length \(k\) and indices \(p, q\). If \(k = 0\) the claim is clear. Otherwise there are three exhaustive cases. (i) \(p_k = i\) and \(q_k = j\). The first \(k - 1\) pairs form a common subsequence of the prefixes of length \(i - 1\) and \(j - 1\), so \(k - 1 \le \lambda(i - 1, j - 1)\). (ii) \(p_k < i\). Then \(Z\) is a common subsequence of \(x_1 \cdots x_{i-1}\) and \(y_1 \cdots y_j\), so \(k \le \lambda(i - 1, j)\), and Lemma 3.2(2) gives \(\lambda(i - 1, j) \le \lambda(i - 1, j - 1) + 1\). (iii) \(q_k < j\). Symmetrically, \(k \le \lambda(i, j - 1) \le \lambda(i - 1, j - 1) + 1\) by Lemma 3.2(1). In all three cases \(k \le \lambda(i - 1, j - 1) + 1\).

Part (b). The inequality \(\lambda(i, j) \ge\) each term of the maximum holds by Lemma 3.2 (left inequalities). Let \(Z\) be a longest common subsequence, with length \(k \ge 1\) (the case \(k = 0\) is clear). If \(p_k = i\) and \(q_k = j\), then \(x_i = z_k = y_j\), which contradicts \(x_i \ne y_j\). So either \(p_k < i\), and \(k \le \lambda(i - 1, j)\), or \(q_k < j\), and \(k \le \lambda(i, j - 1)\). Hence \(\lambda(i, j) \le \max\{\lambda(i - 1, j), \lambda(i, j - 1)\}\).

Corollary 3.4 (row-by-row table fill is correct)

Hypotheses. The hypotheses of Theorem 3.3 hold.

Let \(\mathrm{dp}[i][j] = 0\) when \(i = 0\) or \(j = 0\). For \(1 \le i \le m\) and \(1 \le j \le n\), let \(\mathrm{dp}[i][j] = \mathrm{dp}[i - 1][j - 1] + 1\) if \(x_i = y_j\), and \(\mathrm{dp}[i][j] = \max\{\mathrm{dp}[i - 1][j], \mathrm{dp}[i][j - 1]\}\) otherwise, with the table filled row by row. Then \(\mathrm{dp}[i][j] = \lambda(i, j)\) for all \(0 \le i \le m\) and \(0 \le j \le n\).

Proof

By induction on \(i + j\), with the hypotheses of Theorem 3.3. Boundary entries are zero, which equals \(\lambda\) by Definition 3.1. Let \(i, j \ge 1\) and assume the claim for all pairs with a smaller sum. The three entries \((i - 1, j - 1)\), \((i - 1, j)\) and \((i, j - 1)\) have smaller sums, so they equal \(\lambda\) there. Theorem 3.3 then gives \(\lambda(i, j) = \mathrm{dp}[i][j]\) in both cases. The row-by-row order writes each of the three entries before \((i, j)\).

Proposition 3.5 (cost of the LCS table)

Hypotheses.

  1. \(m\) and \(n\) are the lengths of the finite sequences \(x\) and \(y\).
  2. The table is filled as in Corollary 3.4.

Then the table fill of Corollary 3.4 computes exactly \(mn\) entries, uses \((m + 1)(n + 1)\) stored entries, and performs at most \(K\,mn\) elementary operations for a fixed constant \(K\). Its operation count is therefore \(O(mn)\) in the sense of Lesson 1.

Proof

The entries with \(1 \le i \le m\) and \(1 \le j \le n\) are the \(mn\) pairs, and each is computed once. Each computation reads at most three stored entries, makes one equality test, and does at most one addition or one comparison of two values, so it costs at most a fixed number \(K\) of elementary operations. Summing over \(mn\) entries gives at most \(K\,mn\) operations. The boundary entries are stored but not computed.

4Counting subproblems

The cost of a dynamic program has two parts, the number of distinct subproblems and the work per subproblem. Memoized recursion touches only the subproblems reached from the answer's subproblem. A table fill touches every entry in its range. Without a memo table, the same recursion recomputes a subproblem each time it is reached, so its number of calls can be far larger than the number of distinct subproblems. Memoized recursion stores its values in a dictionary, a hash map (Lesson 2), keyed by the subproblem.

Proposition 4.2 (size of the coin table in the bits of the amount)

Hypotheses.

  1. \(A \ge 1\) is an integer.
  2. \(b\) is the number of binary digits of \(A\), so that \(b = \lfloor \log_2 A \rfloor + 1\).

Then the table of Corollary 2.3 has \(A + 1\) entries, and \(2^{b-1} < A + 1 \le 2^{b}\). In particular, \(A = 2^{40}\) has \(41\) bits in binary and a table with more than \(10^{12}\) entries.

Proof

The table has entries for \(0, 1, \ldots, A\), which is \(A + 1\) entries. Since \(b - 1 = \lfloor \log_2 A \rfloor \le \log_2 A\), we have \(2^{b-1} \le A\), so \(A + 1 > 2^{b-1}\). Since \(b = \lfloor \log_2 A \rfloor + 1 > \log_2 A\), we have \(A < 2^{b}\), so \(A + 1 \le 2^{b}\). For \(A = 2^{40}\), the binary form is a one followed by forty zeros, so \(b = 41\), and \(A + 1 = 2^{40} + 1 > 10^{12}\) because \(2^{40} = 1\,099\,511\,627\,776\).

Lab 1 · Memoized recursion, table fill and exhaustive search

Expected result: for 30 seeded LCS pairs and 30 seeded coin instances, the memoized recursion, the table fill and an exhaustive search return the same answer. For every LCS pair the table has exactly \(mn\) computed cells. For denominations (1, 3, 4) and amount 6, largest-coin-first uses 3 coins and the optimum uses 2. For the LCS pair ACGTACG and TGCATGC, the table has 49 computed cells, the memoized recursion stores 28 subproblems and makes 47 calls, and the same recursion with no memo table makes 183 calls.

"""CS2 L07 lab 1: longest common subsequence and minimum-count coin change, three ways.

SIMULATED: every instance is generated from a fixed seed by an integer generator; none is market data.
Part A: the longest common subsequence (LCS) of 30 seeded string pairs, by memoized recursion, by table fill
and by exhaustive search over all subsequences of the first string. Part B: the fewest coins summing to a
seeded amount, for 30 seeded coin sets, by the same three methods (exhaustive search over all coin-count
vectors), plus the largest-coin-first rule on the coin set (1, 3, 4). Part C: subproblem counts. Each method's
recursive calls and stored subproblems are counted, and the table cells filled are counted. The lab counts
operations only; it does not time anything. Standard library only, no network access, no randomness other
than the seeded generator.
"""

from __future__ import annotations

LCG_MULT = 1103515245
LCG_INC = 12345
LCG_MOD = 2**31
SEED = 20261028
ALPHABET = "ACGT"
LCS_INSTANCES = 30
COIN_INSTANCES = 30
FIXED_X = "ACGTACG"
FIXED_Y = "TGCATGC"
FIXED_COINS = (1, 3, 4)
FIXED_AMOUNT = 6
PART_C_AMOUNT = 20


class Lcg:
    """A linear congruential generator on integers, so every run draws the same numbers."""

    def __init__(self, seed: int) -> None:
        self.state = seed % LCG_MOD

    def below(self, n: int) -> int:
        """Return an integer k with 0 <= k < n."""
        if n < 1:
            raise ValueError("below needs n >= 1")
        self.state = (LCG_MULT * self.state + LCG_INC) % LCG_MOD
        return (self.state >> 16) % n


def lcs_memo(x: str, y: str) -> tuple[int, int, int]:
    """LCS length by memoized recursion. Returns (length, distinct subproblems stored, recursive calls)."""
    cache: dict[tuple[int, int], int] = {}
    calls = 0

    def go(i: int, j: int) -> int:
        nonlocal calls
        calls += 1
        if i == 0 or j == 0:
            return 0
        if (i, j) in cache:
            return cache[(i, j)]
        value = go(i - 1, j - 1) + 1 if x[i - 1] == y[j - 1] else max(go(i - 1, j), go(i, j - 1))
        cache[(i, j)] = value
        return value

    length = go(len(x), len(y))
    return length, len(cache), calls


def lcs_naive_calls(x: str, y: str) -> int:
    """Recursive calls of the same recursion with no memo table: every call recomputes its subproblem."""
    calls = 0

    def go(i: int, j: int) -> int:
        nonlocal calls
        calls += 1
        if i == 0 or j == 0:
            return 0
        if x[i - 1] == y[j - 1]:
            return go(i - 1, j - 1) + 1
        return max(go(i - 1, j), go(i, j - 1))

    go(len(x), len(y))
    return calls


def lcs_table(x: str, y: str) -> tuple[int, int]:
    """LCS length by filling the (m+1) by (n+1) table row by row. Returns (length, cells filled)."""
    m, n = len(x), len(y)
    table = [[0] * (n + 1) for _ in range(m + 1)]
    cells = 0
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            cells += 1
            if x[i - 1] == y[j - 1]:
                table[i][j] = table[i - 1][j - 1] + 1
            else:
                table[i][j] = max(table[i - 1][j], table[i][j - 1])
    return table[m][n], cells


def is_subsequence(s: str, t: str) -> bool:
    """True when s can be read off t in order, by deleting symbols of t."""
    remaining = iter(t)
    return all(ch in remaining for ch in s)


def lcs_exhaustive(x: str, y: str) -> int:
    """LCS length by trying every subset of positions of x, which gives every subsequence of x."""
    best = 0
    for mask in range(1 << len(x)):
        s = "".join(x[k] for k in range(len(x)) if (mask >> k) & 1)
        if len(s) > best and is_subsequence(s, y):
            best = len(s)
    return best


def coins_memo(denoms: tuple[int, ...], amount: int) -> tuple[int | None, int, int]:
    """Fewest coins summing to amount, by memoized recursion.

    Returns (fewest coins or None when no combination exists, distinct amounts stored, recursive calls).
    """
    cache: dict[int, int | None] = {}
    calls = 0

    def best(a: int) -> int | None:
        nonlocal calls
        calls += 1
        if a == 0:
            return 0
        if a in cache:
            return cache[a]
        found: list[int] = []
        for c in denoms:
            if c <= a:
                sub = best(a - c)
                if sub is not None:
                    found.append(1 + sub)
        value = min(found) if found else None
        cache[a] = value
        return value

    answer = best(amount)
    return answer, len(cache), calls


def coins_naive_calls(denoms: tuple[int, ...], amount: int) -> int:
    """Recursive calls of the same recursion with no memo table."""
    calls = 0

    def best(a: int) -> int | None:
        nonlocal calls
        calls += 1
        if a == 0:
            return 0
        found: list[int] = []
        for c in denoms:
            if c <= a:
                sub = best(a - c)
                if sub is not None:
                    found.append(1 + sub)
        return min(found) if found else None

    best(amount)
    return calls


def coins_table(denoms: tuple[int, ...], amount: int) -> tuple[int | None, int]:
    """Fewest coins by filling the table entry for each amount 0..amount. Returns (answer, entries filled)."""
    table: list[int | None] = [0] + [None] * amount
    for a in range(1, amount + 1):
        found: list[int] = []
        for c in denoms:
            sub = table[a - c] if c <= a else None
            if sub is not None:
                found.append(1 + sub)
        table[a] = min(found) if found else None
    return table[amount], amount


def coins_exhaustive(denoms: tuple[int, ...], amount: int) -> int | None:
    """Fewest coins by trying every vector of coin counts (k_1, ..., k_d) with sum k_i * d_i = amount."""
    best: int | None = None

    def search(k: int, remaining: int, used: int) -> None:
        nonlocal best
        if k == len(denoms):
            if remaining == 0 and (best is None or used < best):
                best = used
            return
        c = denoms[k]
        for count in range(remaining // c + 1):
            search(k + 1, remaining - count * c, used + count)

    search(0, amount, 0)
    return best


def greedy_count(denoms: tuple[int, ...], amount: int) -> int | None:
    """Largest-coin-first: repeatedly take the largest coin that fits. Returns the number of coins used."""
    remaining, used = amount, 0
    while remaining > 0:
        fits = [c for c in denoms if c <= remaining]
        if not fits:
            return None
        remaining -= max(fits)
        used += 1
    return used


def make_lcs_instances(gen: Lcg) -> list[tuple[str, str]]:
    pairs: list[tuple[str, str]] = []
    for _ in range(LCS_INSTANCES):
        m = 1 + gen.below(7)
        n = 1 + gen.below(7)
        x = "".join(ALPHABET[gen.below(len(ALPHABET))] for _ in range(m))
        y = "".join(ALPHABET[gen.below(len(ALPHABET))] for _ in range(n))
        pairs.append((x, y))
    return pairs


def make_coin_instances(gen: Lcg) -> list[tuple[tuple[int, ...], int]]:
    cases: list[tuple[tuple[int, ...], int]] = []
    for _ in range(COIN_INSTANCES):
        size = 2 + gen.below(3)
        chosen: set[int] = set()
        while len(chosen) < size:
            chosen.add(1 + gen.below(9))
        amount = gen.below(13)
        cases.append((tuple(sorted(chosen)), amount))
    return cases


def part_a(pairs: list[tuple[str, str]]) -> None:
    for x, y in pairs:
        memo, _, _ = lcs_memo(x, y)
        table, cells = lcs_table(x, y)
        exact = lcs_exhaustive(x, y)
        if not memo == table == exact:
            raise AssertionError(f"LCS methods disagree on {x!r}, {y!r}: {memo}, {table}, {exact}")
        if cells != len(x) * len(y):
            raise AssertionError(f"table fill did not fill m * n cells for {x!r}, {y!r}")
    print(f"part A: LCS instances checked: {len(pairs)}; memo, table and exhaustive agree on all of them")
    x, y = pairs[0]
    print(f"part A: first instance x = {x}, y = {y}, LCS length = {lcs_table(x, y)[0]}")


def part_b(cases: list[tuple[tuple[int, ...], int]]) -> None:
    for denoms, amount in cases:
        memo, _, _ = coins_memo(denoms, amount)
        table, _ = coins_table(denoms, amount)
        exact = coins_exhaustive(denoms, amount)
        if not memo == table == exact:
            raise AssertionError(f"coin methods disagree on {denoms}, {amount}: {memo}, {table}, {exact}")
    impossible = sum(1 for denoms, amount in cases if coins_table(denoms, amount)[0] is None)
    print(f"part B: coin instances checked: {len(cases)}; memo, table and exhaustive agree on all of them")
    print(f"part B: instances with no combination (answer None): {impossible} of {len(cases)}")
    greedy = greedy_count(FIXED_COINS, FIXED_AMOUNT)
    optimum = coins_table(FIXED_COINS, FIXED_AMOUNT)[0]
    print(
        f"part B: coins {FIXED_COINS}, amount {FIXED_AMOUNT}: "
        f"largest-coin-first uses {greedy} coins, optimum uses {optimum}"
    )


def part_c() -> None:
    memo, stored, calls = lcs_memo(FIXED_X, FIXED_Y)
    _, cells = lcs_table(FIXED_X, FIXED_Y)
    naive = lcs_naive_calls(FIXED_X, FIXED_Y)
    if stored > len(FIXED_X) * len(FIXED_Y):
        raise AssertionError("more stored subproblems than table cells")
    print(f"part C: LCS x = {FIXED_X}, y = {FIXED_Y}, LCS length = {memo}")
    print(f"part C: table cells filled = {cells}; memo subproblems stored = {stored}; memo calls = {calls}")
    print(f"part C: recursion with no memo table makes {naive} calls")

5Where the canon breaks

  • The greedy rule is not an algorithm for every coin set. Example 2.4 and Lab 1, part B show that largest-coin-first uses 3 coins for amount 6 with denominations (1, 3, 4), while the recurrence gives 2. The rule is optimal for denominations \(\{1, c\}\) (Problem R2), so optimality depends on the set, and the recurrence is the tool that settles which case holds.
  • A table over the amount is not polynomial in the input's size. Corollary 2.3 fills a table with one entry per amount. Proposition 4.2 shows that the number of entries grows exponentially in the number of bits that write the amount, which is the input size for the amount. The coin table is linear in the value of the amount and, by Proposition 4.2, exponential in the length of its binary encoding.
  • Memory is part of the cost. The LCS table has \((m + 1)(n + 1)\) entries (Proposition 3.5). Each row depends only on the row above it and on the entries already written to its left, so Problem R3 keeps two rows.

6Misconceptions

  1. “Taking the largest coin first is optimal for any set of denominations.”

    It is not. For \(D = \{1, 3, 4\}\) and amount 6, the rule uses \(4 + 1 + 1\), three coins, while \(3 + 3\) uses two (Example 2.4). The smallest amount where the rule fails for this set is 6 (Problem P3). Lab 1, part B prints the same pair: 3 coins against 2.

  2. “Dynamic programming is polynomial in the size of the input, so the coin table is always cheap.”

    Polynomial in the value of the amount is not polynomial in its encoding. Proposition 4.2 shows that \(A + 1\) entries is exponential in the \(b\) bits that write \(A\). An amount of \(2^{40}\) needs 41 bits and more than \(10^{12}\) entries.

  3. “A recursion makes one call for each subproblem, so the number of calls equals the number of subproblems.”

    The lab shows 47 calls and 28 stored subproblems for the memoized LCS recursion on the same pair. Calls to a stored subproblem are lookups, and calls with an empty prefix are base cases that are not stored. Without a memo table the same pair makes 183 calls, because subproblems are recomputed.

7Problem set

Every problem has a full worked solution. Attempt each one before opening it.

Mechanics

M1 · Coin change by the recurrence

Find \(f(9)\) for denominations \(\{2, 5\}\), using Theorem 2.2.

Solution

Theorem 2.2 gives \(f(9) = \min\{1 + f(7), 1 + f(4)\}\), since \(c = 2\) and \(c = 5\) both fit. Next, \(f(4) = 1 + f(2) = 2\) with \(f(2) = 1\). For \(f(7)\), the candidates are \(1 + f(5)\) and \(1 + f(2)\). Here \(f(5) = 1\) and \(f(2) = 1\), so \(f(7) = 2\). Then \(f(9) = \min\{3, 3\} = 3\), realized by \(2 + 2 + 5\).

M2 · An LCS table by hand

Fill the table \(\lambda(i, j)\) for \(x = \mathrm{AB}\) and \(y = \mathrm{BA}\), and state the answer.

Solution

Boundary entries are zero. \(\lambda(1,1)\): \(x_1 = \mathrm{A} \ne \mathrm{B} = y_1\), so the maximum of \(\lambda(0,1)\) and \(\lambda(1,0)\) is 0. \(\lambda(1,2)\): \(x_1 = y_2 = \mathrm{A}\), so \(\lambda(1,2) = \lambda(0,1) + 1 = 1\). \(\lambda(2,1)\): \(x_2 = y_1 = \mathrm{B}\), so \(\lambda(2,1) = \lambda(1,0) + 1 = 1\). \(\lambda(2,2)\): \(x_2 = \mathrm{B} \ne \mathrm{A} = y_2\), so the value is \(\max\{\lambda(1,2), \lambda(2,1)\} = 1\). The answer is 1, since \(\mathrm{AB}\) is not a subsequence of \(\mathrm{BA}\).

M3 · Cells of an LCS table

For \(m = 5\) and \(n = 8\), how many entries does the table have in total, how many are computed, and how many are boundary entries?

Solution

The table has \((m + 1)(n + 1) = 6 \times 9 = 54\) entries. The computed entries are \(mn = 5 \times 8 = 40\). The boundary entries are \(54 - 40 = 14\): the row \(i = 0\) has 9 entries, the column \(j = 0\) has 6, and the corner \((0, 0)\) is counted in both, so \(9 + 6 - 1 = 14\).

Proof

P1 · A single denomination

Let \(D = \{c\}\) with \(c \ge 1\). Prove that \(f(a) = a/c\) when \(c\) divides \(a\), and \(f(a) = \infty\) otherwise, using Theorem 2.2 and induction on \(a\).

Solution

Base. For \(a = 0\), \(f(0) = 0 = 0/c\). For \(1 \le a < c\), no element of \(D\) fits, so the minimum over an empty set gives \(f(a) = \infty\), and \(c\) does not divide \(a\). Step. Let \(a \ge c\), and assume the claim for smaller amounts. Theorem 2.2 gives \(f(a) = 1 + f(a - c)\). If \(c\) divides \(a\), then \(c\) divides \(a - c\), and the hypothesis gives \(f(a - c) = (a - c)/c\), so \(f(a) = 1 + (a - c)/c = a/c\). If \(c\) does not divide \(a\), then it does not divide \(a - c\), so \(f(a - c) = \infty\) and \(f(a) = \infty\).

P2 · Column-major fill also works

Show that Corollary 3.4 remains true if the table is filled column by column, with \(j\) as the outer index, instead of row by row.

Solution

The induction in the proof of Corollary 3.4 needs only that each entry is written after the three entries it reads. Column-major order writes \((i, j)\) after every entry of column \(j - 1\) and after \((i - 1, j)\) in column \(j\). The entry \((i - 1, j - 1)\) lies in column \(j - 1\), the entry \((i, j - 1)\) lies in column \(j - 1\), and \((i - 1, j)\) comes earlier in column \(j\). So all three are written first, and the same induction on \(i + j\) gives \(\mathrm{dp}[i][j] = \lambda(i, j)\).

P3 · The smallest failing amount

For \(D = \{1, 3, 4\}\), find the smallest amount \(a \ge 1\) at which largest-coin-first does not use \(f(a)\) coins.

Solution

For \(a = 1, 2, 3, 4\), the greedy rule takes \(1\), \(1 + 1\), \(3\) and \(4\), which are \(1, 2, 1, 1\) coins, and these equal \(f(a)\) (Example 2.4). For \(a = 5\), the rule takes \(4 + 1\), two coins, and \(f(5) = 2\) by Theorem 2.2. For \(a = 6\), the rule takes \(4 + 1 + 1\), three coins, while \(f(6) = 2\). So the smallest failing amount is 6.

Empirical

E1 · Stored amounts for the coin recursion

Lab 1, part C, reports 20 stored amounts for denominations (1, 3, 4) and amount 20. Explain why the count is exactly 20.

Solution

The denomination 1 is in \(D\). From amount \(a\), the recursion calls amount \(a - 1\), so starting at 20 it reaches every amount \(19, 18, \ldots, 1\). Each amount from 1 to 20 is stored once, and amount 0 is a base case that is not stored, so 20 amounts are stored. Every stored amount has a representation, so none is an infinite value.

E2 · Stored subproblems for the LCS pair

For \(x = \mathrm{ACGTACG}\) and \(y = \mathrm{TGCATGC}\), the table has 49 computed cells and the memoized recursion stores 28 subproblems. Explain the difference without rerunning the lab.

Solution

A table fill computes every pair \((i, j)\) with \(1 \le i \le 7\) and \(1 \le j \le 7\). The memoized recursion computes only the pairs reached from \((7, 7)\), by the rule that a matching pair moves to \((i - 1, j - 1)\) and a mismatch moves to \((i - 1, j)\) and to \((i, j - 1)\). The lab reports that 28 of the 49 pairs are reached, so the recursion stores 28. The table computes all 49, and the lab's output is consistent with both counts.

E3 · Calls and stored subproblems

For the same LCS pair, the memoized recursion makes 47 calls. Account for the difference between 47 calls and 28 stored subproblems.

Solution

Each stored subproblem is computed once, and each call that finds a stored value returns it without further recursion. A subproblem can be reached from several parents, so it is called more than once. The calls also include base calls with an empty prefix, where \(i = 0\) or \(j = 0\), which return 0 at once and are not stored. The 47 calls therefore count both repeated lookups and base calls, and the 28 stored subproblems count only the non-base pairs computed once.

Research

R1 · The coin table for a power of two

For denominations \(\{1, 2\}\) and amount \(A = 2^{20}\), show that the table has more than a million entries while the amount has 21 bits.

Solution

By Proposition 4.2 the table has \(A + 1 = 2^{20} + 1 = 1\,048\,577\) entries. The binary form of \(2^{20}\) is a one followed by twenty zeros, which has 21 bits. The count \(1\,048\,577\) exceeds \(10^6\). The table has one entry per amount, so its size is the value of the amount plus one. By Proposition 4.2 that size lies between \(2^{b-1} + 1\) and \(2^{b}\) for an amount of \(b\) bits: the bound \(2^{b}\) is reached only when \(A = 2^{b} - 1\), and the lower bound only when \(A = 2^{b-1}\).

R2 · Largest-coin-first is optimal for \(\{1, c\}\)

Let \(D = \{1, c\}\) with an integer \(c \ge 2\). Prove that largest-coin-first uses \(f(a)\) coins for every \(a \ge 0\).

Solution

Any representation of \(a\) uses \(k\) coins of value \(c\) and \(a - kc\) coins of value 1, with \(0 \le k \le \lfloor a/c \rfloor\). Its number of coins is \(k + (a - kc) = a - k(c - 1)\). Since \(c \ge 2\), this decreases as \(k\) increases, so the fewest coins come from the largest \(k\), which is \(\lfloor a/c \rfloor\). Largest-coin-first takes \(\lfloor a/c \rfloor\) coins of \(c\) (the rule takes \(c\) while it fits, and \(c\) fits exactly \(\lfloor a/c \rfloor\) times), then \(a - c\lfloor a/c \rfloor\) coins of 1. So it is optimal. The hypothesis \(D = \{1, c\}\) is what makes the argument work: \(\{1, 3, 4\}\) has two denominations above 1, and Example 2.4 shows the argument does not extend.

R3 · Two rows instead of a table

Show that the LCS length can be computed with two rows of \(n + 1\) entries, and state the memory used.

Solution

Row \(i\) of the table reads only row \(i - 1\) and the entry just left of the current cell in row \(i\) (Corollary 3.4). So a program can keep the previous row and the current row, and write row \(i\) over row \(i - 2\) after it is no longer needed. The memory is \(2(n + 1)\) entries, not \((m + 1)(n + 1)\). The final entry in row \(m\) is \(\lambda(m, n)\), because each row is computed by the same recurrence in the same order.
