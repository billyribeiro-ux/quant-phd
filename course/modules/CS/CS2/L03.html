Binary Heaps and the Event Queue

  • Uses: big-O notation and the operation counts of Lesson 1, built-in lists and tuples (CS1), and the logarithm (M1), used as \(\lfloor \log_2 n \rfloor\)
  • Introduces: binary heap and priority queue; event queue for discrete-event simulation

  • Areplicated
  • Bpublished, not settled
  • Csingle study or lab result
  • Dlore

A simulation of arrivals, departures and timeouts runs by repeatedly taking the earliest scheduled event and scheduling later ones. This lesson defines an array structure with the heap order, in which the minimum sits at the front, bounds the comparisons of one push and one pop, and defines the event queue with a tie-break that makes its order total. Lab 3 runs, at each size N from 16 to 4096, one seeded event stream (SIMULATED, seed 2026) through the array structure and through a sorted list (kept in descending order, so its minimum is last), and it counts comparisons and moves, where a move is one assignment of a key into a slot. It measures no time.

1The binary heap in an array

Definition 1.1 (binary min-heap)

A binary heap of \(n\) keys is an array \(a[0], \dots, a[n-1]\) of distinct keys with the heap order: for every index \(i \ge 1\), the key of its parent \(a[\lfloor (i - 1)/2 \rfloor]\) is smaller than \(a[i]\). The children of index \(i\) are the indices \(2i + 1\) and \(2i + 2\) when they are less than \(n\). The minimum is \(a[0]\). A priority queue offers two operations on such a structure: push a key, and pop the minimum.

Proposition 1.2 (the levels and the height)

Assume \(n \ge 1\) and the array shape of Definition 1.1. Level \(d\) consists of the indices \(2^d - 1\) through \(2^{d+1} - 2\), so index \(i\) lies at depth \(d = \lfloor \log_2(i + 1) \rfloor\). The deepest node is at depth \(\lfloor \log_2 n \rfloor\), which is the height of the heap. Here \(\lfloor \log_2 n \rfloor\) denotes the integer \(d\) with \(2^d \le n < 2^{d+1}\).

Proof (by induction on the level \(d\))

Level 0 is the index 0, which is \(2^0 - 1\) through \(2^1 - 2 = 0\). Assume level \(d\) is the indices \(2^d - 1\) through \(2^{d+1} - 2\). The children of these indices are \(2i + 1\) and \(2i + 2\), and as \(i\) runs over this range the smallest child is \(2(2^d - 1) + 1 = 2^{d+1} - 1\) and the largest is \(2(2^{d+1} - 2) + 2 = 2^{d+2} - 2\). Every index in that range has a parent in level \(d\), because its parent \(\lfloor (j - 1)/2 \rfloor\) lies between \(2^d - 1\) and \(2^{d+1} - 2\). So level \(d + 1\) is the indices \(2^{d+1} - 1\) through \(2^{d+2} - 2\). For the deepest node, index \(n - 1\) lies at depth \(d\) exactly when \[2^d - 1 \le n - 1 \le 2^{d+1} - 2\], which is \[2^d \le n \le 2^{d+1} - 1\], that is, \(d = \lfloor \log_2 n \rfloor\). \(\blacksquare\)

Proposition 1.3 (operation bounds on the heap)

Assume a binary min-heap of distinct keys in the array shape of Definition 1.1, with \(s\) keys. (a) A push that leaves \(s\) keys makes at most \(\lfloor \log_2 s \rfloor\) comparisons. (b) A pop from a heap of \(s \ge 1\) keys makes at most \(2 \lfloor \log_2 s \rfloor\) comparisons. Here a comparison is one test of two keys.

Proof

(a) The push appends the key at index \(s - 1\), which lies at depth \(\lfloor \log_2 s \rfloor\) by Proposition 1.2. The sift-up loop (the step that moves a new key toward the root while it is smaller than its parent) compares the moving key with its parent, one comparison per iteration, and each iteration that continues moves it to the parent's depth, one level up. So the loop makes at most \(\lfloor \log_2 s \rfloor\) comparisons. (b) The pop removes the last key, places it at the root, and sifts it down (moves it toward the leaves, swapping it with its smaller child while that child is smaller). At a node with no children the loop makes no comparison. A node with at least one child lies at depth less than the height \(h\) of the heap that remains, which holds \(s - 1\) keys. At such a node the loop makes at most two comparisons, and the nodes visited at depths \(0, \dots, h - 1\) are at most \(h\) in number. So the pop makes at most \(2h\) comparisons. Since \[h = \lfloor \log_2 (s - 1) \rfloor \le \lfloor \log_2 s \rfloor\] when \(s \ge 2\), and the pop of a single key makes no comparison, the bound \(2 \lfloor \log_2 s \rfloor\) holds. \(\blacksquare\)

Definition 1.4 (event queue)

An event queue is a priority queue whose keys are pairs (time, sequence number). The sequence number is the order of insertion, so no two keys are equal and the order is total: an earlier time comes first, and two events at the same time come out in insertion order. A discrete-event simulation repeatedly pops the earliest event and may push new events at times not earlier than the current time.

Remark 1.5 (why the tie-break is part of the key)

Without the sequence number two events at the same time have equal keys, and a heap may return them in either order. The result of a simulation would then depend on how the heap happened to arrange them. With the number in the key, Definition 1.4 fixes the pop order, and that order is the one Lab 3 compares between the two structures.

Lab 3 · Heap-based event queue against a sorted list, at sizes 16 to 4096

Predicted before running. The stream is SIMULATED: it is seeded with 2026. For \(N = 2^k\) with \(k = 4, \dots, 12\), the lab runs the same seeded stream through both structures: \(N\) pushes, then \(N\) hold steps, each a pop followed by a push of one later event, then \(N\) drain pops. The two pop sequences should be equal. Each heap operation should meet its bound of Proposition 1.3, and the heap total of comparisons should not exceed \(6 N \lfloor \log_2 N \rfloor\), the bound of Proposition 1.5 stated in §2 below. Because each sorted-list insertion shifts a tail of the list, the sorted list should make many more moves than the heap as \(N\) grows, and its moves should grow by about 4 when \(N\) doubles (the printed ratios are 3.5282 to 4.5050 from \(N = 64\) to \(N = 4096\)). The heap's counts should grow by about 2 per doubling, since \(N \log N\) grows that way (the printed heap comparison ratios are 2.0850 to 2.1206 from \(N = 512\) to \(N = 4096\)).

"""CS2 lab L03: a binary-heap event queue against a sorted list, on one seeded event stream.

Standard library only. No wall-clock time is measured. Both structures are counted in the same model:
a comparison is one test of two event keys, and a move is one assignment of an event key into a slot of
the array that holds the structure. An event key is a pair (time, sequence number), so all keys are distinct
and the order is total. The sorted list keeps its keys in descending order, so its minimum is the last element.

For each N the stream is the same for both structures: N events are inserted with seeded random times, then N
hold steps each pop the earliest event and insert one new event at its time plus a seeded delay, then the
remaining N events are popped. The popped sequences of the two structures are compared element by element.
The lab checks two bounds: each heap operation stays within its comparison bound, and the heap total stays
within 6 * N * floor(log2 N), which is proved on the page.
"""

from __future__ import annotations

import random

Key = tuple[int, int]


class CountingHeap:
    """An array-based binary min-heap of event keys that counts comparisons and moves."""

    def __init__(self) -> None:
        self.items: list[Key] = []
        self.comparisons = 0
        self.moves = 0
        self.bound_violations = 0

    def __len__(self) -> int:
        return len(self.items)

    def push(self, key: Key) -> None:
        before = self.comparisons
        self.items.append(key)
        self.moves += 1
        i = len(self.items) - 1
        while i > 0:
            parent = (i - 1) // 2
            self.comparisons += 1
            if self.items[i] < self.items[parent]:
                self.items[i], self.items[parent] = self.items[parent], self.items[i]
                self.moves += 2
                i = parent
            else:
                break
        if self.comparisons - before > (len(self.items)).bit_length() - 1:
            self.bound_violations += 1

    def pop(self) -> Key:
        if not self.items:
            raise IndexError("pop from an empty event queue")
        before = self.comparisons
        size_before = len(self.items)
        top = self.items[0]
        last = self.items.pop()
        if self.items:
            self.items[0] = last
            self.moves += 1
            i = 0
            n = len(self.items)
            while True:
                left, right = 2 * i + 1, 2 * i + 2
                smallest = i
                if left < n:
                    self.comparisons += 1
                    if self.items[left] < self.items[smallest]:
                        smallest = left
                if right < n:
                    self.comparisons += 1
                    if self.items[right] < self.items[smallest]:
                        smallest = right
                if smallest == i:
                    break
                self.items[i], self.items[smallest] = self.items[smallest], self.items[i]
                self.moves += 2
                i = smallest
        if self.comparisons - before > 2 * (size_before.bit_length() - 1):
            self.bound_violations += 1
        return top


class CountingSortedList:
    """A list of event keys in descending order, so the minimum is last. Insertion finds the place by binary search."""

    def __init__(self) -> None:
        self.items: list[Key] = []
        self.comparisons = 0
        self.moves = 0

    def __len__(self) -> int:
        return len(self.items)

    def push(self, key: Key) -> None:
        lo, hi = 0, len(self.items)
        while lo < hi:
            mid = (lo + hi) // 2
            self.comparisons += 1
            if self.items[mid] > key:
                lo = mid + 1
            else:
                hi = mid
        self.moves += len(self.items) - lo + 1
        self.items.insert(lo, key)

    def pop(self) -> Key:
        if not self.items:
            raise IndexError("pop from an empty event queue")
        return self.items.pop()


def run_hold(queue: CountingHeap | CountingSortedList, n: int, seed: int) -> list[Key]:
    """Insert n seeded events, run n hold steps, then drain. Return the popped keys in order."""
    rng = random.Random(seed)
    for seq in range(n):
        queue.push((rng.randrange(1_000_000), seq))
    delays = [rng.randint(1, 1000) for _ in range(n)]
    popped: list[Key] = []
    for step in range(n):
        time, _ = event = queue.pop()
        popped.append(event)
        queue.push((time + delays[step], n + step))
    while len(queue) > 0:
        popped.append(queue.pop())
    return popped


def main() -> None:
    print("hold model: N events, N hold steps (pop, then push one later event), then N drain pops")
    previous: tuple[int, int, int, int] | None = None
    all_equal = True
    bounds_ok = True
    for k in range(4, 13):
        n = 2**k
        heap = CountingHeap()
        heap_popped = run_hold(heap, n, 2026)
        sorted_list = CountingSortedList()
        sorted_popped = run_hold(sorted_list, n, 2026)
        equal = heap_popped == sorted_popped
        nondecreasing = all(heap_popped[i] <= heap_popped[i + 1] for i in range(len(heap_popped) - 1))
        within = heap.comparisons <= 6 * n * (n.bit_length() - 1)
        all_equal = all_equal and equal
        bounds_ok = bounds_ok and heap.bound_violations == 0 and within
        print(
            f"N={n:5d} operations={4 * n:6d} heap comparisons={heap.comparisons:7d} heap moves={heap.moves:7d} "
            f"sorted-list comparisons={sorted_list.comparisons:7d} sorted-list moves={sorted_list.moves:9d}"
        )
        print(
            f"  pop orders equal: {equal}; popped times nondecreasing: {nondecreasing}; "
            f"heap comparisons within 6*N*floor(log2 N): {within}"
        )
        current = (heap.comparisons, heap.moves, sorted_list.comparisons, sorted_list.moves)
        if previous is not None:
            print(
                f"  N doubled from the row above: heap comparison ratio {current[0] / previous[0]:.4f}, "
                f"heap move ratio {current[1] / previous[1]:.4f}, "
                f"sorted-list move ratio {current[3] / previous[3]:.4f}"
            )
        previous = current
    print(f"pop orders equal for every N: {all_equal}")
    print(f"every heap operation within its comparison bound, and every total within its bound: {bounds_ok}")

2Totals of the event queue run

Proposition 1.5 (the heap total in the hold run)

Assume \(N \ge 1\), the hold run of Lab 3 with \(N\) initial pushes, \(N\) hold steps and \(N\) drain pops, and that the heap never holds more than \(N\) keys. Then the heap makes at most \(6 N \lfloor \log_2 N \rfloor\) comparisons in total.

Proof

The hold run never holds more than \(N\) keys: the initial pushes leave \(N\) keys, each hold step pops one key and then pushes one, and the drain only pops. So the size hypothesis holds for this run. The run makes \(N\) initial pushes and \(N\) hold pushes, so \(2N\) pushes. Each push leaves at most \(N\) keys, so by Proposition 1.3(a) it makes at most \(\lfloor \log_2 N \rfloor\) comparisons. The run makes \(N\) hold pops and \(N\) drain pops, so \(2N\) pops. Each pop starts from at most \(N\) keys, so by Proposition 1.3(b) it makes at most \(2 \lfloor \log_2 N \rfloor\) comparisons. The total is at most \[2N \lfloor \log_2 N \rfloor + 2N \cdot 2 \lfloor \log_2 N \rfloor = 6 N \lfloor \log_2 N \rfloor\]. \(\blacksquare\)

Proposition 1.6 (the sorted-list total in the hold run)

Assume the same hold run as Proposition 1.5. The sorted list makes at most \(2N(N + 1)\) moves in total.

Proof

A push into a list of length \(L\) at position \(p\) moves the \(L - p\) entries after \(p\) and places the new key, which is \(L - p + 1\) moves, and this is at most \(L + 1\). A pop from the end moves nothing. The list holds the same keys as the heap in the same run, so it never holds more than \(N\) keys, and each push makes at most \(N + 1\) moves. The run makes \(2N\) pushes, so the total is at most \(2N(N + 1)\). \(\blacksquare\)

Remark 1.7 (what the two bounds do and do not compare)

Propositions 1.5 and 1.6 are upper bounds of different orders, \(N \log N\) for the heap comparisons and \(N^2\) for the list moves. They do not say which structure is faster on a machine. A move in the model is an assignment of a key into a slot, and its time depends on the machine, which the lab does not measure. Upper bounds do not order the two counts, so the growth rates are read from the printed ratios, which come from one stream per size: the sorted-list move ratios are between 3.5282 and 4.5050 per doubling, and the heap comparison ratios are between 2.0850 and 2.5077 over the same rows (the printed rows for N = 64 to 4096, each against the row above; the rows for N = 512 to 4096 have ratios 2.0850 to 2.1206).

3Where the canon breaks

The lab compares structures in one counting model, and the model has four limits.

  • A move is not a unit of time. A list shift and a heap swap may take different times per move on a real machine, and the counts cannot rank them there.
  • One stream is one sample. Each size is one seeded stream, and the ratios in the lab come from that stream only. Proposition 1.5 bounds the heap total for every stream of this shape, but the printed ratios are a single realization.
  • The hold model is one workload. The stream inserts later events and pops the earliest. A workload that inserts events in decreasing time order, or one that never pops, may give different counts. The lab does not test those.
  • Small sizes reverse the ranking. At \(N = 16\) the sorted list has 205 counted operations against 602 for the heap, so the heap's advantage in this model starts at a larger size, which the printed rows place between \(N = 128\) and \(N = 256\) for moves.

4Misconceptions

  1. “A heap keeps all its keys in sorted order.”

    A heap guarantees the heap order of Definition 1.1 and nothing more: each parent is smaller than its children. The array \([1, 3, 2]\) is a valid min-heap, since \(1 < 3\) and \(1 < 2\), and it is not sorted. The heap gives the minimum at \(a[0]\) and nothing more about the order of the other keys.

  2. “A pop is \(O(1)\) because it removes only one key.”

    A pop removes one key and then restores the heap order by a sift-down, which can make up to \(2 \lfloor \log_2 s \rfloor\) comparisons by Proposition 1.3(b). So the bound on a pop grows with the number of keys \(n\), as \(O(\log n)\), and this page does not prove a constant bound on a pop; the upper bound \(2 \lfloor \log_2 s \rfloor\) is all it states. Lab 3 counts 166912 heap comparisons over 16384 operations at \(N = 4096\), and Proposition 1.5 bounds that total by 294912.

  3. “The sorted list is always the slower structure.”

    In the counting model the sorted list is cheaper at small sizes. At \(N = 16\) it makes 107 comparisons and 98 moves, a total of 205, against 241 comparisons and 361 moves for the heap, a total of 602. At \(N = 128\) the sorted list still has the smaller total, 6131 against 8735. At \(N = 256\) the heap has the smaller total, 19140 against 21405, and its moves are fewer than the list's, 10623 against 17663.

Mechanics

M1 · Children and parent of an index

In a binary heap array, give the parent and the two children of index 5, and the depth of index 5.

Solution

The parent of 5 is \(\lfloor (5 - 1)/2 \rfloor = 2\). The children are \(2 \cdot 5 + 1 = 11\) and \(2 \cdot 5 + 2 = 12\). Index 5 lies at depth \(\lfloor \log_2 6 \rfloor = 2\), since \(2^2 = 4 \le 6 < 8\).

M2 · Height of a heap with 10 keys

What is the height of a binary heap with 10 keys?

Solution

By Proposition 1.2 the height is \(\lfloor \log_2 10 \rfloor\). Since \(2^3 = 8 \le 10 < 16 = 2^4\), the height is 3.

M3 · The heap order of an array

Decide whether the array \([2, 5, 3, 7, 6, 4]\) satisfies the heap order of Definition 1.1, and name every violated parent-child pair.

Solution

The parent of index 1 is index 0, and \(2 < 5\). The parent of index 2 is index 0, and \(2 < 3\). The parent of index 3 is index 1, and \(5 < 7\). The parent of index 4 is index 1, and \(5 < 6\). The parent of index 5 is index 2, and \(3 < 4\). Every pair satisfies the order, so the array is a valid min-heap.

Proof

P1 · The depth of a last index

Prove that the index \(n - 1\) of an \(n\)-key heap lies at depth \(\lfloor \log_2 n \rfloor\), using only Proposition 1.2.

Solution

By Proposition 1.2 index \(i\) lies at depth \(d\) when \(2^d - 1 \le i \le 2^{d+1} - 2\). Put \(i = n - 1\). The condition becomes \[2^d \le n \le 2^{d+1} - 1\], which is the definition of \(d = \lfloor \log_2 n \rfloor\) in Proposition 1.2.

P2 · Heap order after a push

Show that if the heap order held before a push, then the sift-up loop of the push restores it, and state the invariant of the loop.

Solution

Let \(H\) be the array before the push, a heap of \(s - 1\) keys, and let the push place the key \(x\) at index \(i = s - 1\). A pass of the sift-up loop runs while \(i \ge 1\) and \(x\) is smaller than the key \(y = a[p]\) at its parent \(p\). The pass swaps \(a[i]\) and \(a[p]\), so \(y\) moves to \(i\) and \(x\) moves to \(p\), and then sets \(i = p\). The loop stops at \(i = 0\), or when \(a[p] < x\). At the start of each pass the invariant has three parts, with \(x\) at index \(i\):

  • (a) every parent-child pair \((q, c)\) with \(c \ne i\) satisfies \(a[q] < a[c]\);
  • (b) if \(i \ge 1\), the key \(a[\mathrm{parent}(i)]\) is smaller than every child \(c\) of \(i\);
  • (c) \(x\) is smaller than every child \(c\) of \(i\).

Base. At the start \(i = s - 1\) has no children, so (b) and (c) are vacuous. Every pair with \(c \ne s - 1\) is a pair of \(H\), so (a) holds.

Step. Suppose the pass runs, so \(x < y\). The displaced key \(y\) now sits at \(i\), and the moving index is \(p\). Let \(\sigma\) be the sibling of \(i\), a child of \(p\). If \(i\) has no sibling, as for \(i = 1\) in a heap of two keys, whose parent \(p = 0\) has the single child \(i\), then \(\sigma\) does not exist, every claim below that mentions \(\sigma\) is vacuous, and the step for \(p\) uses (b) and (c) alone. Use the three parts at the start of the pass. By (a), \(y = a[p] < a[\sigma]\). By (b), \(y\) is smaller than every child of \(i\), so the pairs \((i, c)\) hold after the swap. The pair \((p, i)\) holds because \(x < y\). Hence (a) holds for the new array at every pair with \(c \ne p\). For (b) at \(p\): the children of \(p\) are \(i\) and \(\sigma\), and, when \(p \ge 1\), by (a) on the pair \((\mathrm{parent}(p), p)\), \(a[\mathrm{parent}(p)] < a[p] = y\), and by (a) on the pair \((p, \sigma)\), \(y < a[\sigma]\); chaining the two gives \(a[\mathrm{parent}(p)] < a[\sigma]\). For (c) at \(p\): \(x < y = a[i]\), and \(x < y < a[\sigma]\).

Stop. If \(i = 0\), (a) covers every pair, so the array is a heap. Otherwise \(a[p] < x\), so the pair \((p, i)\) holds. Part (a) covers every pair with \(c \ne i\), and (c) gives \(a[i] = x < a[c]\) for every child \(c\) of \(i\). So every pair satisfies the heap order, and the loop restores it. \(\blacksquare\)

P3 · The count of hold pops

In the hold run of Lab 3 with \(N\) events, state how many pops are made in total and how many keys remain in the heap after the hold steps.

Solution

There are \(N\) hold pops and \(N\) drain pops, so \(2N\) pops in total. Each hold step pops one key and pushes one, so after \(N\) hold steps the heap still holds \(N\) keys, and the drain pops remove them.

Empirical

E1 · The sorted-list total at \(N = 16\)

Lab 3 prints 107 sorted-list comparisons and 98 sorted-list moves at \(N = 16\). Add them, and state the same sum for the heap from the printed counts.

Solution

The sorted list makes \(107 + 98 = 205\) counted operations. The heap makes \(241 + 361 = 602\), from its printed 241 comparisons and 361 moves. These are the totals used in Misconception 3.

E2 · The bound of Proposition 1.5 at \(N = 4096\)

Lab 3 prints 166912 heap comparisons at \(N = 4096\). Compute the bound of Proposition 1.5 and state the margin.

Solution

\(\lfloor \log_2 4096 \rfloor = 12\), so the bound is \[6 \cdot 4096 \cdot 12 = 294912\]. The margin is \[294912 - 166912 = 128000\] comparisons.

E3 · The sorted-list moves against the bound

Lab 3 prints 4378444 sorted-list moves at \(N = 4096\). Compute the bound of Proposition 1.6 and say whether the printed value is below it.

Solution

\(2N(N + 1) = 2 \cdot 4096 \cdot 4097 = 33562624\). The printed value 4378444 is below it, so the bound holds at this size. The bound is not tight here: the printed value is about 13 percent of it, which is \(4378444 / 33562624\), about 0.1305.

R1 · The first size where the heap moves less

Solution

At \(N = 128\) the heap makes 4933 moves and the list 4514, so the list has fewer. At \(N = 256\) the heap makes 10623 and the list 17663, so the heap has fewer. The first printed size with fewer heap moves is 256. The rows do not show the crossing for sizes between 128 and 256, and a finer table would be needed to locate it.

R2 · A stream that inserts in decreasing time

Explain how the sorted list's move count changes if every new event in the hold run had an earlier time than all events present, and why the heap bound of Proposition 1.5 still holds.

Solution

A new key that is smaller than all present keys is placed at the end of the descending list, which is the position of the minimum, so the list shifts nothing and the push makes 1 move. Each of the \(2N\) pushes then makes 1 move, so the list's total is \(2N\), which is at most the bound \(2N(N + 1)\) of Proposition 1.6. The proof of Proposition 1.5 counts the pushes and pops and uses the size bound of at most \(N\) keys; it does not use the order of the keys, so the heap bound still holds.

R3 · Two structures with one pop order

State what the equality of pop orders in Lab 3 would need in order to be a theorem about these two structures, and what the printed check alone does not give.

Solution

The argument needs three facts. The keys are distinct, because the sequence number is part of each key. Both structures hold the same set of keys at every step, because they receive the same operations. And each pop returns the minimum of the current keys, for both structures. Given the third fact, induction on the number of pops gives equal pop orders on every stream with distinct keys. This page does not prove the third fact for either structure: Proposition 1.3 bounds counts and states no correctness claim, and no proposition here shows that the sift-down or the last element of the sorted list is the minimum. So the equality of pop orders stays graded C, from the printed check on one stream per size.
