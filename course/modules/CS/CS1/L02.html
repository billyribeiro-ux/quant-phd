Every trading system, risk engine, and backtester organizes financial entities in memory: price series in sequences, order books in key-value maps, and unique identifiers in sets. Selecting an inappropriate data structure causes catastrophic latency or memory bloat. Understanding the memory layout, mutability semantics, hashing requirements, and asymptotic operation counts of Python's fundamental containers prevents algorithmic bottlenecks in production analytics.

1Memory Layout, Mutability, and Container Semantics

Python's standard library provides four primary built-in data structures: list, tuple, dict, and set. These containers store references (pointers) to Python objects rather than raw byte buffers.

Definition 1.1 (Built-In Data Structures and Mutability)

The built-in data structures comprise: (1) list, a mutable, variable-length array of object references indexed by consecutive integers; (2) tuple, an immutable sequence of fixed length; (3) dict, a mutable associative mapping of unique hashable keys to arbitrary values; and (4) set, a mutable collection of unique hashable elements. An object is mutable if its internal state or contents can be modified after creation without changing its memory identity (id()); it is immutable if its state is fixed at instantiation.

Theorem 1.1 (Hash Invariance and Mapping Key Requirement)

An object is hashable if and only if it possesses a hash value that never changes during its lifetime (evaluated via __hash__()) and can be compared to other objects for equality (via __eq__()). All atomic immutable built-in types (int, float, str, bytes) are hashable. A collection is hashable if and only if it is immutable and all of its contained elements are recursively hashable. A mutable container cannot serve as a dictionary key or set element.

Proof

By the Python data model specification (PSF Language Reference, Section 3.1), dictionaries and sets are implemented as open-addressing hash tables. The hash table indexes slots using the integer hash code \(h = \text{hash}(\text{key})\). If a key object could mutate after insertion such that its equality or hash value changed, subsequent lookups for that key would compute a different hash or fail the equality check, making the entry inaccessible and corrupting table invariants. Hence, Python explicitly unbinds __hash__ on mutable built-in types (setting it to None), raising TypeError: unhashable type on insertion.

Example 1.1 (Tuple Hashability Under Nested Mutability)

Consider two tuples representing security identifiers and attributes:

t1 = ("AAPL", 150.0, (2026, 1, 15))
t2 = ("AAPL", 150.0, [2026, 1, 15])

Evaluating hash(t1) succeeds because all elements (string, float, tuple of ints) are immutable and hashable. Evaluating hash(t2) raises TypeError: unhashable type: 'list' because t2[2] is a mutable list. Immutability of the outer container is necessary but not sufficient for hashability.

Remark 1.1 (Amortized Dynamic Array Resizing)

Ramalho (2021) details how Python lists allocate spare buffer capacity to achieve \(O(1)\) amortized append complexity. When a list outgrows its allocated buffer, CPython allocates a new contiguous memory chunk following the growth pattern \(N_{\text{new}} \approx N + (N \gg 3) + 6\), copies the existing pointers, and frees the old buffer.

Lab 1 · Built-in Containers, Mutability, and Operation Counts

Verifies that list mutation updates sequences in place, that sets eliminate duplicate elements, that dictionaries provide key-value associations, and that membership search requires \(O(N)\) linear comparisons in an unsorted list versus \(O(1)\) average lookups in a hash set.

"""CS1 lab L02: Built-in data structures (list, tuple, dict, set).

Standard library only. Tests mutability, sequence slicing, hashability invariants,
and operation counts for membership lookup.
SIMULATED synthetic market order identifiers.
"""

from __future__ import annotations


def count_list_scans(items: list[str], target: str) -> int:
    """Count comparisons required in a linear scan of a list."""
    steps = 0
    for item in items:
        steps += 1
        if item == target:
            break
    return steps


def main() -> None:
    # 1. Tuples: immutable sequences
    fixed_pair: tuple[str, float] = ("EURUSD", 1.0850)
    print(f"tuple pair: symbol={fixed_pair[0]}, quote={fixed_pair[1]:.4f}")

    # 2. Lists: mutable dynamic arrays
    order_queue: list[str] = ["ord_001", "ord_002", "ord_003"]
    order_queue.append("ord_004")
    popped = order_queue.pop(0)
    print(f"popped order: {popped}")
    print(f"remaining queue length: {len(order_queue)}")

    # 3. Sets: unique, unordered collections with O(1) average hash lookup
    seen_ids: set[str] = {"ord_002", "ord_003", "ord_004"}
    seen_ids.add("ord_002")  # duplicate insertion has no effect
    print(f"set size after duplicate addition: {len(seen_ids)}")
    print(f"ord_003 in set: {'ord_003' in seen_ids}")

    # 4. Dicts: key-value mapping with unique hashable keys
    book_depth: dict[str, float] = {
        "ord_002": 100.0,
        "ord_003": 250.0,
        "ord_004": 75.0,
    }
    book_depth["ord_005"] = 300.0
    print(f"dict entry ord_003 quantity: {book_depth['ord_003']:.1f}")
    print(f"total depth across keys: {sum(book_depth.values()):.1f}")

    # 5. Comparing search steps: linear scan vs hash lookup
    symbols = [f"SYM_{i:04d}" for i in range(1000)]
    symbol_set = set(symbols)
    target = "SYM_0750"

    list_steps = count_list_scans(symbols, target)
    set_has = target in symbol_set
    print(f"linear scan steps to find target at index 750: {list_steps}")
    print(f"set membership found target: {set_has}")
    print(f"tuple is hashable: {isinstance(hash(fixed_pair), int)}")


main()
tuple pair: symbol=EURUSD, quote=1.0850
popped order: ord_001
remaining queue length: 3
set size after duplicate addition: 3
ord_003 in set: True
dict entry ord_003 quantity: 250.0
total depth across keys: 725.0
linear scan steps to find target at index 750: 751
set membership found target: True
tuple is hashable: True

The lab confirms that list operations preserve order and allow dynamic growth, sets enforce uniqueness by rejecting duplicate insertions, and finding a target at index 750 in a 1000-element list takes 751 sequential equality checks, whereas set membership checks the hash slot directly.

2Where the canon breaks

In high-level scripting, beginners often assume that dictionaries and lists can be used interchangeably for lookups, or that tuples are simply "constant lists." In quantitative finance, using a list of 100,000 tick identifiers to perform repeated membership checks (\(\text{id} \in \text{list}\)) causes an \(O(N^2)\) performance collapse, turning a sub-second process into a multi-hour bottleneck. Furthermore, tuples provide fixed memory overhead and can serve as composite dictionary keys (such as (ticker, date)), whereas lists cannot.

3Misconceptions

  1. “All tuples are hashable because tuples are immutable.”

    A tuple is only hashable if every single element it contains is also hashable. A tuple containing a mutable object (such as (1, [2, 3])) is immutable in structure but unhashable, raising a TypeError if used as a dictionary key or set element.

  2. “Assigning a list to a new variable creates a copy of the list.”

    Variable assignment in Python binds a new reference to the identical underlying object. Executing b = a does not duplicate the list; modifying b.append(1) directly alters a. Creating an independent copy requires b = a.copy() or b = list(a).

  3. “Checking membership using 'item in container' has the same speed across lists, sets, and dictionaries.”

    Membership testing in a list performs a linear scan through the items from left to right, taking \(O(N)\) time. In a set or dictionary, membership testing uses hash-table indexing, taking \(O(1)\) average time regardless of container size.

4Problem set

Mechanics

M1 · Dictionary Key Collision Handling

What is the final state of the dictionary d = {} after executing d[1] = "integer"; d[1.0] = "float", and why?

Solution

The dictionary contains {1: "float"}. In Python, hash(1) == hash(1.0) and 1 == 1.0 evaluates to True. Because the keys have identical hash codes and are equal, the second assignment updates the value associated with the existing key slot rather than creating a new entry.

M2 · Shallow vs. Deep Copying

Given a = [[1, 2], [3, 4]] and b = a.copy(), explain the result of executing b[0].append(5) followed by checking a[0].

Solution

The shallow copy a.copy() creates a new outer list containing references to the original inner list objects. Appending 5 to b[0] mutates the shared inner list in place, so a[0] now evaluates to [1, 2, 5]. Full isolation requires copy.deepcopy().

M3 · Set Difference for Universe Filtering

Given an asset universe all_assets = {"AAPL", "MSFT", "GOOG", "AMZN"} and halted assets halted = {"MSFT", "TSLA"}, what expression produces the tradeable assets, and what is its value?

Solution

The set difference expression all_assets - halted evaluates to {"AAPL", "GOOG", "AMZN"}. The halted asset "TSLA" is ignored because it was not in all_assets. Set difference runs in \(O(\text{len}(all\_assets))\) average time.

Proof

P1 · Linear Scan Complexity of Unsorted List Search

Prove that searching for an element in an unsorted list of length \(N\) requires exactly \(N\) comparisons in the worst case and \((N + 1)/2\) comparisons on average assuming uniform distribution.

Solution

In an unsorted list, the target element may reside at any position \(i \in \{1, \dots, N\}\) with equal probability \(P(i) = 1/N\), or be absent. If the element is absent or at index \(N - 1\), the algorithm must inspect every element from index 0 to \(N - 1\), establishing the worst-case bound of \(N\) comparisons. Assuming the target is present with uniform probability, the expected comparison count is \(\sum_{i=1}^N i \cdot \frac{1}{N} = \frac{1}{N} \frac{N(N + 1)}{2} = \frac{N + 1}{2}\).

P2 · Set Uniqueness Invariant

Prove that inserting an element \(x\) into a set \(S\) containing \(N\) elements results in a set of size \(N\) if \(x \in S\) and \(N + 1\) if \(x \notin S\).

Solution

A set maintains the mathematical set invariant where each equivalence class under == appears at most once. Insertion evaluates \(h = \text{hash}(x)\) and probes the table. If an entry \(y\) is found with \(\text{hash}(y) == h\) and \(y == x\), the insertion is a no-op, preserving cardinality \(|S| = N\). If no equal element is found, a new entry is written, incrementing the cardinality to \(N + 1\).

P3 · Immutability of Tuple Reference Pointers

Prove that while the object references stored in a tuple cannot change, the internal state of those referenced objects can change if they are mutable.

Solution

A tuple of length \(k\) is allocated as a fixed C array of \(k\) object pointers: PyObject* ob_item[k]. The tuple object provides no C API or Python methods to modify any pointer in ob_item after creation. However, if pointer ob_item[i] addresses a mutable heap object (such as a list), that target object's own internal buffer can be modified through its own mutating methods. The tuple's pointer array remains unaltered.

Empirical

E1 · Memory Sizing of Built-In Containers

Using sys.getsizeof(), measure the baseline memory overhead of an empty list, empty tuple, empty dict, and empty set in Python 64-bit.

Solution

In standard 64-bit CPython, an empty tuple consumes 40 bytes (fixed header and length), an empty list consumes 56 bytes (header, length, and buffer pointer), an empty set consumes 216 bytes (table allocation), and an empty dict consumes 64 bytes (compact dictionary layout). Tuples provide the most compact memory footprint.

E2 · Dictionary Insertion Order Preservation

Verify that Python dictionaries preserve insertion order across sequential insertions and deletions.

Solution

Insert keys in a non-sorted order: d = {'c': 1, 'a': 2, 'b': 3}. Iterating over list(d.keys()) yields exactly ['c', 'a', 'b']. Deleting 'a' and re-inserting d['a'] = 4 places 'a' at the end: ['c', 'b', 'a']. Since Python 3.7, compact hash table ordering is a guaranteed language specification.

E3 · Hash Collision Generation

Construct two distinct integer objects that have identical hash values and observe how dictionary lookup handles them.

Solution

In Python, integers hash to themselves modulo \(2^{61} - 1\) (on 64-bit systems), with -1 reserved for errors (hash(-1) returns -2). Thus hash(-1) == hash(-2) == -2. Placing both -1 and -2 in a dictionary demonstrates that even with a hash collision, the dictionary uses the equality check key1 == key2 to store and retrieve both entries correctly.

Research

R1 · Cache Locality of Pointer Arrays vs. Contiguous Structs

Analyze why a Python list of floats incurs higher cache miss penalties than a contiguous C or NumPy array during sequential numerical traversals.

Solution

A Python list is an array of 64-bit pointers pointing to boxed PyFloatObject structures scattered across the heap. Traversing the list requires dereferencing each pointer, causing pointer chasing and cache misses when accessing non-contiguous memory. A contiguous buffer (like a NumPy array) packs raw 64-bit IEEE floats contiguously, allowing CPU prefetchers to stream cache lines directly into L1/L2 cache.

R2 · Compact Dict Memory Layout

Explain how the compact dictionary architecture introduced in Python 3.6 reduces memory usage while preserving insertion order.

Solution

Traditional hash tables stored sparse arrays of 24-byte entries (hash, key_ptr, val_ptr). The compact dict separates this into a sparse hash index table of small integers (1-byte or 2-byte indices) and a dense array of entries appended in order of insertion. This eliminates unused padding in entry structs, reducing memory usage by 20 to 25 percent and naturally maintaining insertion order.

R3 · Set Operations in Multi-Asset Order Routing

Design an order validation filter for a multi-exchange router using bitwise set operations and quantify its computational advantages.

Solution

By representing eligible asset symbols, approved market makers, and regulatory restricted lists as Python set objects, intersection (&) and difference (-) operations determine permissible routes in \(O(\min(|A|, |B|))\) time. This replaces nested sequential conditional loops with hash table lookups, ensuring deterministic microsecond routing decisions.

6Retrieval quiz

  1. Which of the following built-in Python containers is immutable?

    Options

    Tuples are immutable sequences whose length and element pointers cannot be modified after instantiation.

  2. What exception is raised when attempting to use a mutable list as a dictionary key?

    Options

    Python raises TypeError: unhashable type: 'list' because lists are mutable and do not implement __hash__.

  3. What is the average time complexity of checking membership (x in s) for a set with \(N\) elements?

    Options

    Sets are implemented as hash tables, providing \(O(1)\) average-time membership lookup.

  4. If t = (1, 2, [3, 4]), can t be added as an element of a Python set?

    Options

    A tuple is only hashable if all of its constituent elements are recursively hashable. Because [3, 4] is an unhashable list, t is unhashable.

  5. What is len(set(["AAPL", "GOOG", "AAPL", "MSFT", "GOOG"]))?

    Sets enforce uniqueness; duplicate entries ("AAPL", "GOOG") are discarded, leaving 3 unique elements.

  6. What does b = a[:] perform when a is a list?

    Options

    Slice syntax a[:] creates a shallow copy of the list containing the same element references.

  7. Which statement accurately describes dictionary ordering in Python 3.7+?

    Options

    Since Python 3.7, dictionaries are guaranteed by the language specification to maintain insertion order.

  8. What happens when evaluating d = {1: 'a', 1.0: 'b'}?

    Options

    Because 1 == 1.0 and both keys share the same hash value, the second assignment overwrites the value for key 1.
