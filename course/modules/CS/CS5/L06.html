Modern CPU cores execute arithmetic operations in sub-nanosecond clock cycles, but retrieving data from main memory (DRAM) requires 50 to 100 nanoseconds—hundreds of wasted execution cycles. Low-latency financial algorithms are fundamentally bounded by memory subsystem throughput. Understanding cache lines, spatial and temporal locality, and avoiding multi-core false sharing transforms latency-sensitive matching engines and Monte Carlo kernels into cache-optimal systems.

1The Hardware Memory Hierarchy and Cache Latency

CPUs bridge the massive speed disparity between core registers and main memory by deploying tiered SRAM hardware caches:

Definition 6.1 (Memory Hierarchy)

The memory hierarchy and cache effects govern the tiered architecture of computer storage, organized in ascending capacity and descending speed: CPU registers (\(\sim 0.5\) ns, 1 cycle), Level 1 (L1) data cache (\(\sim 1\) ns, 4-5 cycles, 32-48 KB per core), Level 2 (L2) cache (\(\sim 3\text{--}4\) ns, 12-14 cycles, 512 KB to 1 MB per core), Level 3 (L3) shared cache (\(\sim 10\text{--}20\) ns, 40-60 cycles, 16-64 MB shared), and main memory DRAM (\(\sim 60\text{--}100\) ns, 200+ cycles). Data transfers between DRAM and caches occur strictly in fixed-size blocks termed cache lines, standardized at 64 bytes under Assumption A1.

Proposition 6.2 (Sequential Cache Line Footprint)

Assumption A1: The hardware cache line size is \(L = 64\) bytes, and arrays are aligned on 64-byte boundaries.
Statement: A sequential traversal reading \(N\) contiguous elements of size \(s\) bytes touches exactly \(\lceil N \cdot s / L \rceil\) distinct cache lines.

Proof

The total contiguous memory span occupied by the array is \(B = N \cdot s\) bytes. Because the starting address \(A_0\) is aligned on a 64-byte boundary (\(A_0 \equiv 0 \pmod L\)), byte offsets span the half-open interval \([0, B)\). The \(k\)-th cache line covers byte interval \([k \cdot L, (k+1) \cdot L)\). The number of distinct intervals required to cover \([0, B)\) is precisely the smallest integer \(k\) such that \(k \cdot L \ge B\), which is \(\lceil B / L \rceil = \lceil N \cdot s / 64 \rceil\). \(\blacksquare\)

2Spatial Locality, Strided Traversal, and Cache Miss Penalty

Locality of reference dictates how effectively algorithms exploit cache lines:

  • Spatial Locality: Accessing a memory address increases the probability that nearby addresses will be accessed soon. Sequential array scans maximize spatial locality.
  • Temporal Locality: Accessing a memory address increases the probability that the identical address will be accessed repeatedly in the near future. Keeping hot loop counters and volatility parameters in L1 cache exploits temporal locality.
Proposition 6.3 (Strided Access Cache Degradation)

Assumption A1: Cache lines are \(L = 64\) bytes, and element size is \(s = 8\) bytes (e.g. double).
Statement: A strided traversal with stride \(K \ge L/s = 8\) incurs a cache miss on every access under a cold cache model, wasting \((1 - s/L) = 87.5\%\) of loaded memory bandwidth.

Proof

With stride \(K \ge 8\), consecutive accessed indices \(i\) and \(i+1\) are separated in memory by \(\Delta \mathrm{addr} = K \cdot s \ge 8 \cdot 8 = 64\) bytes. Because \(\Delta \mathrm{addr} \ge L\), each access lands in a strictly distinct 64-byte cache line. Therefore, every single read of 8 bytes requires loading a full 64-byte cache line from memory, achieving a miss rate of 1.0 (100%). Out of 64 bytes transferred across the memory bus, only 8 bytes are consumed by the algorithm, wasting \(64 - 8 = 56\) bytes (\(56/64 = 87.5\%\)). \(\blacksquare\)

3Multi-Core False Sharing and Cache Invalidation

Multi-core CPU architectures maintain cache coherence across cores using snooping protocols (such as MESI: Modified, Exclusive, Shared, Invalid). Coherence is tracked at the granularity of full 64-byte cache lines, not individual variables.

Definition 6.4 (False Sharing)

False sharing occurs when two or more independent threads executing on separate CPU cores modify distinct variables that reside within the same 64-byte cache line. Even though the variables are logically independent, hardware coherence protocols force the cache line to bounce between core caches in the Modified state, invalidating private L1/L2 caches and causing severe performance degradation.

Preventing false sharing requires memory alignment. In C++17/20, variables can be padded and aligned to the hardware destructive interference size using alignas(std::hardware_destructive_interference_size) (typically 64 bytes).

Lab 1 · Cache line access model and false sharing simulation

Under Assumption A1 (64B cache line), sequential traversal of 1,024 doubles loads 128 cache lines with 100% bandwidth utilization, whereas stride-8 traversal loads 128 lines for only 128 elements (12.5% utilization). Unpadded multi-core writes trigger 100 cache line invalidations, which padding eliminates completely.

"""CS5 Lab L06: Memory hierarchy, cache line utilization, and false sharing model.

Standard library only. Deterministic integer counter under Assumption A1 (64-byte cache line).
Models sequential vs strided traversal cache line misses, byte traffic, and multi-core
cache line invalidations caused by false sharing.
"""

from __future__ import annotations


def run_cache_hierarchy_model() -> None:
    print("CS5 L06: Memory Hierarchy and Cache Line Access Model (Assumption A1: 64B Line)")

    line_size = 64  # bytes per cache line
    element_size = 8  # sizeof(double) = 8 bytes
    elements_per_line = line_size // element_size  # 8 doubles per line
    n_elements = 1024  # 8192 total bytes = 128 cache lines

    # Traversal 1: Sequential access (stride = 1)
    seq_lines_touched = set()
    seq_bytes_transferred = 0
    for i in range(n_elements):
        byte_offset = i * element_size
        line_idx = byte_offset // line_size
        if line_idx not in seq_lines_touched:
            seq_lines_touched.add(line_idx)
            seq_bytes_transferred += line_size

    useful_bytes_seq = n_elements * element_size
    seq_miss_rate = len(seq_lines_touched) / n_elements

    print(f"Sequential Scan (N={n_elements} doubles, stride=1):")
    print(f"  Distinct cache lines loaded: {len(seq_lines_touched)}")
    print(f"  Total memory traffic:        {seq_bytes_transferred} bytes")
    seq_util = useful_bytes_seq / seq_bytes_transferred
    print(f"  Useful payload bytes:        {useful_bytes_seq} bytes (utilization: {seq_util:.1%})")
    print(f"  Cold miss rate:              {seq_miss_rate:.3f} (1 miss per {elements_per_line} accesses)")

    # Traversal 2: Strided access (stride = 8, stepping across cache lines)
    stride = 8
    strided_indices = list(range(0, n_elements, stride))  # 128 reads
    strided_lines_touched = set()
    strided_bytes_transferred = 0
    for idx in strided_indices:
        byte_offset = idx * element_size
        line_idx = byte_offset // line_size
        if line_idx not in strided_lines_touched:
            strided_lines_touched.add(line_idx)
            strided_bytes_transferred += line_size

    useful_bytes_strided = len(strided_indices) * element_size
    strided_miss_rate = len(strided_lines_touched) / len(strided_indices)

    print(f"Strided Scan (N={len(strided_indices)} doubles, stride={stride}):")
    print(f"  Distinct cache lines loaded: {len(strided_lines_touched)}")
    print(f"  Total memory traffic:        {strided_bytes_transferred} bytes")
    strided_util = useful_bytes_strided / strided_bytes_transferred
    print(f"  Useful payload bytes:        {useful_bytes_strided} bytes (utilization: {strided_util:.1%})")
    print(f"  Cold miss rate:              {strided_miss_rate:.3f} (1 miss per access)")

    # Traversal 3: False sharing model
    # Two adjacent int64 variables at offsets 0 and 8 (same 64B cache line)
    # vs padded variables at offsets 0 and 64 (separate cache lines)
    unpadded_line_var1 = 0 // line_size
    unpadded_line_var2 = 8 // line_size
    padded_line_var1 = 0 // line_size
    padded_line_var2 = 64 // line_size

    unpadded_invalidations = 100 if unpadded_line_var1 == unpadded_line_var2 else 0
    padded_invalidations = 100 if padded_line_var1 == padded_line_var2 else 0

    print("Multi-core False Sharing (100 alternating ping-pong writes):")
    print(f"  Unpadded (same 64B line):   {unpadded_invalidations} cache line invalidation transfers")
    print(f"  Padded (alignas(64)):       {padded_invalidations} cache line invalidation transfers")


def main() -> None:
    run_cache_hierarchy_model()


main()

The model confirms that strided memory traversal wastes 87.5% of memory bus bandwidth by loading 64 bytes per 8-byte double read. Furthermore, aligning per-thread counters to 64-byte boundaries with alignas(64) completely prevents cache line bouncing between CPU cores.

4Where the Canon Breaks

Hardware prefetchers attempt to disguise memory latency by detecting regular access strides and speculatively fetching subsequent cache lines before instructions request them. However, prefetchers fail when traversing pointer-based data structures (linked lists, sparse matrices, hash tables with deep collision buckets) or random index permutations. Under random lookups, every read stalls for 60 to 100 nanoseconds, reducing multi-gigahertz processors to the speed of DRAM. In quantitative trading, algorithms that cannot be vectorized or linearly streamed suffer massive latency penalties regardless of algorithmic \(\mathcal{O}(1)\) theoretical bounds.

5Misconceptions

  1. CPUs read and write individual bytes or 64-bit numbers directly from DRAM.

    CPUs never read isolated bytes from main memory. All memory transactions between DRAM and cache occur in atomic blocks of 64 bytes (cache lines). Reading a single 1-byte boolean loads the entire 64-byte surrounding cache line.

  2. Two threads writing to different variables never interfere with each other if they do not share pointers.

    If two distinct variables happen to reside within the same 64-byte cache line, modifying one variable invalidates the other core's cache line via false sharing, degrading multi-threaded throughput by orders of magnitude.

  3. Increasing the clock frequency of a CPU core linearly accelerates memory-bound algorithms.

    When an algorithm is memory-bound (waiting on DRAM latency during cache misses), the CPU core spends most cycles in an idle stall state waiting for the memory bus. Increasing core clock speed provides zero speedup for memory-stalled pipelines.

6Problems

Mechanics

M1 · Cache Line Alignment in C++

Write the C++ declaration for a per-thread trade counter struct that prevents false sharing across cores under Assumption A1.

Solution

struct alignas(64) ThreadTradeCounter { uint64_t trade_count{0}; uint64_t total_volume{0}; };.
The alignas(64) specifier forces the compiler to align the struct to a 64-byte boundary, placing each instance in a separate cache line.

M2 · Cache Miss Rate Computation

Under Assumption A1, compute the cold cache miss rate for a sequential scan over an array of int32_t (4 bytes each).

Solution

In a 64-byte cache line, exactly \(64 / 4 = 16\) integers fit. The first access loads the cache line (1 miss), and the subsequent 15 accesses hit L1 cache. The cold miss rate is \(1/16 = 6.25\%\).

M3 · Software Prefetching Intrinsics

How does the _mm_prefetch compiler intrinsic mitigate memory latency in order book scans?

Solution

_mm_prefetch(addr, _MM_HINT_T0) instructs the CPU memory controller to load the cache line at addr into L1 cache asynchronously before the execution pipeline reaches the read instruction, hiding memory latency.

Proof

P1 · Minimum Alignment for False Sharing Immunity

Prove that aligning two variables to integer multiples of \(L\) guarantees that no single cache line contains bytes from both variables.

Solution

Let variable \(A\) start at address \(k_1 L\) with size \(s_A \le L\) and variable \(B\) start at address \(k_2 L\) with \(k_2 > k_1\). Cache lines partition memory into disjoint sets \(C_k = [k L, (k+1) L)\). Variable \(A\) is fully contained in \(C_{k_1}\). Variable \(B\) is contained in \(C_{k_2}\). Because \(k_1 \ne k_2\), \(C_{k_1} \cap C_{k_2} = \emptyset\). Hence, no cache line contains bytes from both \(A\) and \(B\), eliminating false sharing.

P2 · Latency Bound under Direct-Mapped Cache Thrashing

Prove that traversing two equal-length arrays whose starting addresses differ by an exact multiple of cache capacity \(C\) causes 100% conflict misses in a direct-mapped cache.

Solution

In a direct-mapped cache of size \(C\), memory address \(A\) maps to cache set index \((A / L) \pmod{(C / L)}\). If addresses \(A_1\) and \(A_2\) satisfy \(A_2 = A_1 + m C\), their set indices are identical. Alternating reads between \(A_1[i]\) and \(A_2[i]\) evict each other continuously, yielding a 100% conflict miss rate on every iteration.

P3 · Matrix Transpose Cache Miss Bound

Prove that a naive square matrix transpose of size \(N \times N\) (where \(N \cdot s \gg C_{\mathrm{L1}}\)) incurs \(\mathcal{O}(N^2)\) cache misses without cache blocking.

Solution

Evaluating B[j][i] = A[i][j] reads row \(i\) of \(A\) sequentially but writes column \(i\) of \(B\) with stride \(N \cdot s\). Because \(N \cdot s\) exceeds cache capacity, each write to \(B\) accesses a different cache line that evicts previously loaded lines before row \(j\) is completed. The column write incurs a cache miss on almost every element, generating \(\mathcal{O}(N^2)\) misses.

Empirical

E1 · Interpreting Lab 1 Utilization Rates

In Lab 1, why was sequential scan utilization 100.0% while strided scan utilization was only 12.5%?

Solution

In the sequential scan, every 64-byte line loaded had all 8 of its constituent doubles consumed by the loop (8/8 = 100%). In the stride-8 scan, each 64-byte line loaded had only 1 double read before the loop stepped to the next line (1/8 = 12.5% utilization, wasting 87.5% bandwidth).

E2 · Quantifying False Sharing Invalidation in Lab 1

Why did Lab 1 record 100 invalidation transfers for unpadded variables but 0 for padded variables?

Solution

The unpadded variables sat at offsets 0 and 8, sharing cache line index 0. Alternating writes forced 100 inter-core cache line invalidation cycles. When padded to offset 64, the variables occupied distinct cache lines (indices 0 and 1), allowing independent core caching with zero invalidations.

E3 · Execution Latency of Cache Misses

If an L1 hit takes 1 ns and an L3 miss takes 80 ns, compute the average memory access time (AMAT) for a code path with a 5% L1 miss rate and a 20% L2/L3 miss rate.

Solution

\(\mathrm{AMAT} = t_{\mathrm{L1}} + \mathrm{MissRate}_{\mathrm{L1}} \times (t_{\mathrm{L2}} + \mathrm{MissRate}_{\mathrm{L2}} \times t_{\mathrm{DRAM}}) = 1.0 + 0.05 \times (4.0 + 0.20 \times 80.0) = 1.0 + 0.05 \times (4.0 + 16.0) = 1.0 + 0.05 \times 20.0 = 2.0\) ns.

Research

R1 · Cache-Oblivious Algorithms

Explain the core principle of cache-oblivious algorithms in quantitative matrix factorizations.

Solution

Cache-oblivious algorithms use recursive divide-and-conquer strategies (such as recursive matrix multiplication) without hard-coding specific cache line sizes or cache capacities. When subproblems become small enough to fit into any cache level (L1, L2, or L3), they run at peak cache efficiency automatically across arbitrary hardware architectures.

R2 · NUMA Memory Affinity and Core Pinning

Why do multi-socket trading servers pin execution threads to specific CPU cores and allocate memory on the local NUMA node?

Solution

In Non-Uniform Memory Access (NUMA) systems, accessing memory attached to a remote CPU socket across UPI/QPI interconnects takes 1.5-2x longer than local DRAM. Pinning threads to local cores with pthread_setaffinity_np and binding memory with numactl --membind eliminates cross-socket latency.

R3 · Hardware Transversal Latency Profiling

How do Linux perf hardware performance counters track LLC (Last Level Cache) load misses in production trading systems?

Solution

perf stat -e L1-dcache-load-misses,LLC-load-misses,cache-misses programs on-chip Performance Monitoring Units (PMU) to count exact hardware cache miss events during program execution, isolating memory stalls without source code instrumentation overhead.
