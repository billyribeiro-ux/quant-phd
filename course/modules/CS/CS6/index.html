Parallel & High-Performance Computing

Scale quantitative finance algorithms across modern heterogeneous computing hardware. Master theoretical speedup limits, multithreaded shared memory vs. multiprocess isolation, CPython GIL internals, hardware SIMD vector units, massively parallel GPU kernels, bit-for-bit reproducible parallel RNG streams, hardware counter profiling, and queueing latency optimization.

Course objectives

  1. Derive theoretical strong and weak scaling limits using Amdahl's Law and the Gustafson-Barsis Law to evaluate parallelization viability (Lesson 1).
  2. Architect multi-core financial execution engines navigating memory isolation, cache coherence, and CPython Global Interpreter Lock contention (Lesson 2).
  3. Vectorize quantitative pricing routines to execute on AVX2 and AVX-512 vector execution units via contiguous memory layouts (Lesson 3).
  4. Analyze massively parallel graphics processor architectures, thread warp execution, and memory bandwidth saturation in quantitative simulation kernels (Lesson 4).
  5. Implement counter-based pseudorandom number generators that guarantee bit-for-bit reproducible simulation paths across arbitrary worker counts (Lesson 5).
  6. Diagnose microarchitectural latency bottlenecks using statistical profiling, CPU flame graphs, and queueing models governed by Little's Law (Lesson 6).

Prerequisites

CS6 assumes comprehensive mastery of CS5 (C++ & Systems for Finance) and M8 (Numerical Methods & Scientific Computing). It directly applies foundational concepts established across the prerequisite closure:

  • From CS5: memory hierarchy, struct-of-arrays, compilation model, and value semantics.

  • From CS2: big-O complexity.
  • From CS4: deterministic computation and bit-for-bit reproducibility.
  • From M1: direct proof.

Placement diagnostic

Test your prerequisite mastery and determine whether you can place out of Rungs 1–2 of the capstone project. Scoring at least 80% with correct answers on marked skill items permits jumping directly to Rung 3.

  1. Under Amdahl's Law, what is the theoretical maximum speedup limit for a program whose serial fraction is \(s = 0.10\) as the processor count \(N \to \infty\)?

    As \(N \to \infty\), Amdahl's Law dictates \(S(\infty) = 1/s = 1 / 0.10 = 10\).

  2. What structural condition causes multithreaded CPython code to achieve zero CPU execution speedup across multiple physical cores?

    Options

    The CPython Global Interpreter Lock ensures only one thread executes Python bytecode at any given moment, neutralizing CPU-bound parallelism within a single interpreter process.

  3. Which CPU register width is utilized by 256-bit AVX2 SIMD instructions to process double-precision floating-point numbers concurrently?

    Options

    A 256-bit YMM register holds exactly \(256 / 64 = 4\) 64-bit IEEE 754 double-precision floating-point values.

  4. In modern NVIDIA GPU architectures, how many contiguous threads constitute a single warp executed in lockstep under SIMT scheduling?

    CUDA GPUs group threads into warps of exactly 32 threads that execute instructions synchronously.

  5. In parallel Monte Carlo simulation, why does counter-based PRNG stream indexing (such as Philox) guarantee bit-for-bit reproducibility across differing worker counts?

    Options

    Counter-based PRNGs generate random numbers by applying a bijection to an explicit integer counter and key, ensuring path \(i\) always generates the exact same numbers regardless of which thread executes it.

  6. When partitioning \(N\) simulation paths across \(P\) parallel workers where \(N\) is not divisible by \(P\), how must the final worker chunk end bound be calculated to prevent missing or duplicated paths?

    Options

    The final worker must take all remaining paths up to \(N\) to ensure that integer division truncation does not omit trailing paths.

The module culminates in an independent capstone project: Parallel Risk Run (36 project study hours). The 4-rung scaffolding ladder transitions students from verified foundations to production-grade implementation:

  1. Rung 1 · Worked example: Tracing counter-based RNG stream indexing in serial and partitioned slices (project.html#worked-example).

  4. Rung 4 · Stretch: Vectorized Black-Scholes SIMD evaluation, dynamic work-stealing, and importance sampling (project.html#stretch).
