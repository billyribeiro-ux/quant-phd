Amdahl's Law and Scaling Limits

Modern quantitative finance operations require parallelizing mission-critical risk runs, portfolio optimizations, and option calibration routines across thousands of compute cores. Before deploying capital to specialized high-performance clusters, quantitative architects must determine the theoretical maximum speedup possible for a given workload. Amdahl's Law establishes the fundamental ceiling imposed by sequential code bottlenecks, preventing costly architectural misallocations when parallelization yields diminishing returns.

1Strong Scaling and Amdahl's Law

High-performance computing categorizes scaling behavior into two distinct regimes: strong scaling, where problem size remains fixed as processors increase, and weak scaling, where problem size grows proportionally with processor count. Gene Amdahl demonstrated that for any fixed-size computation, the speedup achievable by parallel execution is rigorously bounded by the fraction of execution time spent on inherently sequential tasks.

Definition 1.1 (Amdahl's Law and Strong Scaling Speedup)

Let a computation require baseline single-processor execution time \(T(1) = T_{\text{seq}} + T_{\text{par}}\), where \(T_{\text{seq}}\) represents the sequential execution fraction and \(T_{\text{par}}\) represents the portion that can be partitioned across parallel workers without synchronization loss. Defining the serial fraction as \(s = T_{\text{seq}} / T(1) \in [0, 1]\) and the parallelizable fraction as \(p = 1 - s\), Amdahl's law states that the theoretical strong scaling speedup \(S_A(N)\) achieved with \(N \ge 1\) parallel processors is given by:

\[ S_A(N) = \frac{T(1)}{T(N)} = \frac{T(1)}{s T(1) + \frac{1 - s}{N} T(1)} = \frac{1}{s + \frac{1 - s}{N}} \]
Theorem 1.2 (Asymptotic Speedup Limit)

Assumption: A workload with non-zero serial fraction \(s > 0\) executes on \(N\) processors with zero inter-processor communication overhead.
Statement: The strong scaling speedup is strictly monotonically increasing in \(N\) and bounded above by \(1/s\):

\[ \lim_{N \to \infty} S_A(N) = \frac{1}{s} \]
Proof

By Definition 1.1, the denominator of the speedup function is \(D(N) = s + \frac{1 - s}{N}\). Taking the first derivative with respect to \(N\) for \(N \ge 1\):

\[ \frac{d S_A}{d N} = -\frac{1}{D(N)^2} \frac{d D}{d N} = -\frac{1}{D(N)^2} \left(-\frac{1 - s}{N^2}\right) = \frac{1 - s}{N^2 \left(s + \frac{1 - s}{N}\right)^2} \]

Because \(s \in (0, 1)\), the numerator \(1 - s > 0\) and the denominator is strictly positive for all \(N \ge 1\), establishing strict monotonicity. Evaluating the limit as \(N \to \infty\):

\[ \lim_{N \to \infty} S_A(N) = \lim_{N \to \infty} \frac{1}{s + \frac{1 - s}{N}} = \frac{1}{s + 0} = \frac{1}{s} \quad \blacksquare \]
Example 1.3 (VaR Portfolio Aggregation Bottleneck)

Consider a portfolio risk engine where path generation takes 95% of serial runtime (\(p = 0.95\)), while reading market price feeds and sorting portfolio losses to compute the 99% Value-at-Risk quantile consumes the remaining 5% (\(s = 0.05\)). By Theorem 1.2, even if the trading desk deploys an infinite supercomputing cluster (\(N \to \infty\)), the maximum possible speedup is exactly \(1 / 0.05 = 20\times\). On 128 physical CPU cores, the theoretical speedup is:

\[ S_A(128) = \frac{1}{0.05 + \frac{0.95}{128}} = \frac{1}{0.05 + 0.007422} \approx 17.41\times \]

2Weak Scaling and the Gustafson-Barsis Law

Hennessy & Patterson emphasize that Amdahl's Law assumes the problem size is frozen as hardware scales. In institutional quantitative finance, firms do not hold the portfolio size or Monte Carlo path count constant when expanding compute infrastructure; instead, they simulate larger portfolios, more granular market scenarios, or smaller time steps.

Proposition 1.4 (Gustafson-Barsis Weak Scaling Law)

Assumption: The parallel workload scales linearly with the processor count \(N\), such that the parallel execution time on \(N\) processors remains constant while total work completed scales as \(W(N) = s + N(1 - s)\).
Statement: The scaled speedup \(S_G(N)\) expands linearly with processor count:

\[ S_G(N) = s + N(1 - s) = N - s(N - 1) \]
Proof

Let execution time on \(N\) processors be normalized to \(T(N) = s + (1 - s) = 1\), where \(s\) is the sequential time and \(1 - s\) is the parallel execution time per processor. If the same scaled problem were executed serially on a single processor, the sequential component would consume \(s\) while the parallel component would require \(N(1 - s)\). Therefore, the serial time for the scaled workload is \(T(1) = s + N(1 - s)\). The scaled speedup is:

\[ S_G(N) = \frac{T(1)}{T(N)} = \frac{s + N(1 - s)}{1} = N - s(N - 1) \quad \blacksquare \]

3Parallel Efficiency and the Karp-Flatt Metric

In physical hardware implementations, parallel scaling degrades beyond Amdahl's theoretical curve due to inter-processor communication, thread contention, and cache synchronization overheads. Parallel efficiency measures how effectively additional cores are utilized.

Definition 1.5 (Parallel Efficiency and Karp-Flatt Metric)

The parallel efficiency \(E(N)\) of an algorithm executing on \(N\) processors is the ratio of realized speedup to processor count: \(E(N) = S(N) / N\). The Karp-Flatt metric \(e\) extracts the empirically observed serial fraction from measured speedup \(S(N)\) and core count \(N > 1\):

\[ e = \frac{\frac{1}{S(N)} - \frac{1}{N}}{1 - \frac{1}{N}} \]

If \(e\) remains constant as \(N\) increases, scaling loss is strictly caused by sequential code bottlenecks. If \(e\) increases with \(N\), scaling degradation is dominated by communication, synchronization, or algorithmic coordination overheads.

Lab 1 · Amdahl vs Gustafson speedup and Karp-Flatt analysis

Simulating execution across scaling core counts demonstrates that Amdahl's speedup flattens toward its theoretical ceiling 1/s, whereas communication overhead causes the Karp-Flatt metric to rise as core count grows.

"""CS6 Lab L01-1: Amdahl's Law, Gustafson's Law, and Karp-Flatt Metric Evaluation.

Standard library only. Evaluates theoretical vs communication-constrained parallel speedup,
efficiency degradation, and empirical serial fraction extraction.
"""

from __future__ import annotations

import math


def amdahl_speedup(serial_fraction: float, p_cores: int) -> float:
    """Compute theoretical strong scaling speedup via Amdahl's Law."""
    if p_cores < 1:
        raise ValueError("Core count must be at least 1.")
    return 1.0 / (serial_fraction + (1.0 - serial_fraction) / float(p_cores))


def gustafson_speedup(serial_fraction: float, p_cores: int) -> float:
    """Compute theoretical weak scaling speedup via Gustafson-Barsis Law."""
    if p_cores < 1:
        raise ValueError("Core count must be at least 1.")
    return serial_fraction + float(p_cores) * (1.0 - serial_fraction)


def karp_flatt_metric(speedup: float, p_cores: int) -> float:
    """Extract experimental serial fraction from observed speedup."""
    if p_cores <= 1:
        return 0.0
    return (1.0 / speedup - 1.0 / float(p_cores)) / (1.0 - 1.0 / float(p_cores))


def simulate_scaling_run() -> None:
    s = 0.05  # 5% serial fraction
    cores = [1, 2, 4, 8, 16, 32, 64]
    comm_coeff = 0.002  # O(log P) communication overhead

    print("=== CS6 Lab 1: Parallel Scaling & Karp-Flatt Metric Analysis ===")
    print(f"Serial fraction s = {s:.2f}, Asymptotic Amdahl limit S(inf) = {1.0 / s:.2f}x\n")
    header = (
        f"{'Cores':>6} | {'Amdahl':>8} | {'Gustafson':>10} | "
        f"{'Realistic':>10} | {'Efficiency':>10} | {'Karp-Flatt':>10}"
    )
    print(header)
    print("-" * 68)

    for p in cores:
        s_amdahl = amdahl_speedup(s, p)
        s_gustafson = gustafson_speedup(s, p)

        # Realistic runtime: T(p) = s + (1-s)/p + comm_coeff * log2(p)
        comm_overhead = comm_coeff * math.log2(p) if p > 1 else 0.0
        t_p = s + (1.0 - s) / float(p) + comm_overhead
        s_realistic = 1.0 / t_p
        efficiency = s_realistic / float(p)
        e_kf = karp_flatt_metric(s_realistic, p)

        eff_str = f"{efficiency * 100:9.1f}%"
        row = f"{p:6d} | {s_amdahl:8.3f} | {s_gustafson:10.3f} | {s_realistic:10.3f} | {eff_str} | {e_kf:10.4f}"
        print(row)

4Where the Canon Breaks

Classical textbooks assert that parallel speedup can never exceed core count: \(S(N) \le N\). In quantitative systems engineering, this rule breaks in two major regimes:

  • Superlinear Speedup via Cache Expansion: Distributing a dataset across \(N\) independent processors multiplies aggregate L1, L2, and L3 cache capacity by \(N\). If a portfolio problem exceeds the 32 MB L3 cache of a single socket but partitions cleanly into 2 MB chunks per worker on 16 sockets, memory access latencies drop from DRAM (~70 ns) to local L2 cache (~3 ns). The resulting reduction in memory stall cycles yields speedups exceeding \(N\) (\(S(N) > N\)).
  • Memory Bandwidth Saturation: Amdahl's Law assumes that adding cores scales compute capacity linearly without hardware interference. On modern multicore architectures sharing a unified memory controller (e.g., 64-core AMD EPYC or Intel Xeon sockets), memory-intensive streaming workloads saturate DDR5 memory bandwidth long before ALU saturation occurs. Speedup plateaus at 8–16 cores regardless of serial fraction.

5Misconceptions

  • A workload with 99% parallelizable code will achieve approximately 100x speedup when given 1,000 cores.

    Under Amdahl's Law, with serial fraction \(s = 0.01\), the theoretical speedup on 1,000 cores is \(S_A(1000) = 1 / (0.01 + 0.99/1000) \approx 91.0\times\). Even with an infinite number of cores, the asymptotic ceiling is strictly \(1/0.01 = 100\times\). Adding 900 additional cores beyond 100 yields an efficiency collapse from ~50% to under 9.1%.

  • Parallel efficiency loss is always caused by unoptimized serial code in the algorithm.

    The Karp-Flatt metric differentiates algorithmic serial bottlenecks from hardware overheads. If the extracted metric \(e\) rises as core count grows, efficiency loss is driven by communication latency, cacheline bouncing (false sharing), or OS scheduling jitter rather than the algorithmic serial fraction.

  • Gustafson's Law invalidates Amdahl's Law for quantitative applications.

    Gustafson's Law does not contradict Amdahl's Law; it evaluates a different operational question. Amdahl's Law evaluates strong scaling (how fast can we finish a fixed portfolio simulation?), whereas Gustafson's Law evaluates weak scaling (how large a simulation can we run in a fixed batch time window?).

6Problem Set

Mechanics

M1 · Strong Scaling Calculation

A Monte Carlo pricing kernel spends 4% of its single-threaded execution time initializing market data arrays and 96% generating stochastic paths. What is the theoretical speedup on 32 cores?

Solution

Applying Amdahl's Law with serial fraction \(s = 0.04\) and core count \(N = 32\):

\[ S_A(32) = \frac{1}{0.04 + \frac{0.96}{32}} = \frac{1}{0.04 + 0.03} = \frac{1}{0.07} \approx 14.2857\times \]

The theoretical speedup on 32 cores is approximately 14.29x with parallel efficiency \(E(32) = 14.2857 / 32 \approx 44.64\%\).

M2 · Asymptotic Core Ceiling

A quantitative risk manager requires a 50x speedup to complete overnight VaR runs within the market close window. What is the maximum permissible serial fraction \(s\) in the pricing codebase?

Solution

By Theorem 1.2, the asymptotic speedup limit as \(N \to \infty\) is \(S(\infty) = 1/s\). Requiring \(S \ge 50\) establishes the strict inequality \(1/s \ge 50\), which implies \(s \le 1/50 = 0.02\). The codebase must have a sequential fraction of at most 2.0%.

M3 · Karp-Flatt Extraction

An algorithm running on 16 cores achieves an empirical speedup of 10.0x. What is the experimentally determined Karp-Flatt metric \(e\)?

Solution

Applying the Karp-Flatt formula with \(N = 16\) and \(S(16) = 10.0\):

\[ e = \frac{\frac{1}{10.0} - \frac{1}{16}}{1 - \frac{1}{16}} = \frac{0.100 - 0.0625}{0.9375} = \frac{0.0375}{0.9375} = 0.0400 \]

The effective experimental serial fraction of the system is exactly 4.0%.

Proof

P1 · Efficiency Monotonicity Under Amdahl's Law

Prove that for any serial fraction \(s > 0\), the parallel efficiency \(E(N) = S_A(N) / N\) is strictly decreasing for \(N \ge 1\).

Solution

Express parallel efficiency explicitly in terms of \(N\):

\[ E(N) = \frac{S_A(N)}{N} = \frac{1}{N \left(s + \frac{1 - s}{N}\right)} = \frac{1}{s N + (1 - s)} \]

Because \(s > 0\), the denominator \(g(N) = s N + (1 - s)\) is a strictly increasing linear function of \(N\) with derivative \(g'(N) = s > 0\). Therefore, the derivative of \(E(N)\) is:

\[ \frac{d E}{d N} = -\frac{s}{(s N + 1 - s)^2} < 0 \quad \forall N \ge 1 \]

This proves that parallel efficiency monotonically degrades toward zero as processor count grows.

P2 · Gustafson Speedup Equivalence Condition

Prove that Gustafson's scaled speedup \(S_G(N)\) is strictly greater than Amdahl's speedup \(S_A(N)\) for all \(N > 1\) and \(s \in (0, 1)\).

Solution

We compare \(S_G(N) = s + N(1 - s)\) and \(S_A(N) = \frac{1}{s + \frac{1 - s}{N}}\). Multiply both by the positive denominator of \(S_A(N)\):

\[ S_G(N) \cdot \left(s + \frac{1 - s}{N}\right) = (s + N(1 - s)) \left(s + \frac{1 - s}{N}\right) \]

Expanding the product:

\[ s^2 + \frac{s(1 - s)}{N} + N s (1 - s) + (1 - s)^2 = s^2 + (1 - s)^2 + s(1 - s)\left(N + \frac{1}{N}\right) \]

Note that \(s^2 + (1 - s)^2 = 1 - 2s(1 - s)\). Substituting gives:

\[ 1 + s(1 - s)\left(N + \frac{1}{N} - 2\right) = 1 + s(1 - s)\frac{(N - 1)^2}{N} \]

For \(N > 1\) and \(s \in (0, 1)\), \(s(1 - s) > 0\) and \((N - 1)^2 > 0\). Thus the product strictly exceeds 1, proving \(S_G(N) > S_A(N)\).

P3 · Karp-Flatt Invariance Under Pure Amdahl Scaling

Prove that if an execution follows Amdahl's Law with zero communication overhead, the Karp-Flatt metric \(e\) is invariant to processor count \(N\) and equals the serial fraction \(s\).

Solution

Substitute \(S(N) = \frac{1}{s + \frac{1 - s}{N}}\) directly into the definition of the Karp-Flatt metric:

\[ e = \frac{\frac{1}{S(N)} - \frac{1}{N}}{1 - \frac{1}{N}} = \frac{\left(s + \frac{1 - s}{N}\right) - \frac{1}{N}}{1 - \frac{1}{N}} \]

Simplify the numerator:

\[ s + \frac{1 - s - 1}{N} = s - \frac{s}{N} = s \left(1 - \frac{1}{N}\right) \]

Dividing by the denominator \(1 - 1/N\) yields:

\[ e = \frac{s \left(1 - \frac{1}{N}\right)}{1 - \frac{1}{N}} = s \quad \blacksquare \]

Empirical

E1 · Communication Latency Threshold

In Lab 1, on 64 cores, realistic speedup fell from the theoretical Amdahl value of 15.422x to 13.013x. What caused this efficiency loss?

Solution

The simulation introduced logarithmic inter-core coordination overhead \(\kappa(N) = c \log_2(N)\). As core count expanded from 1 to 64, communication latency grew while the parallel compute slice per core shrank from 950 ms to 14.8 ms, causing communication overhead to become a substantial fraction of total execution time.

E2 · Efficiency Halving Point

Under pure Amdahl scaling with serial fraction \(s = 0.05\), at what processor count \(N\) does parallel efficiency drop to exactly 50%?

Solution

Set efficiency \(E(N) = \frac{1}{s N + 1 - s} = 0.50\). Solving for \(N\):

\[ s N + 1 - s = 2 \implies s N = 1 + s \implies N = \frac{1 + s}{s} = \frac{1 + 0.05}{0.05} = 21 \]

At 21 cores, parallel efficiency drops to exactly 50% (achieving 10.5x speedup).

E3 · Diagnosing Network Bottlenecks via Karp-Flatt

A distributed risk cluster observes Karp-Flatt values of \(e(4) = 0.021\), \(e(16) = 0.045\), and \(e(64) = 0.098\). How should the systems architect interpret this trend?

Solution

A rising Karp-Flatt metric indicates that scaling degradation is not caused by algorithmic code serialization (which would keep \(e\) constant at ~0.02), but by network interconnect latency, socket barrier synchronization, or broadcast communication bottlenecks that scale with cluster size.

Research

R1 · Energy-Constrained Heterogeneous Scaling

How do modern asymmetric multi-core processors (e.g., performance cores vs. efficiency cores) extend Amdahl's Law?

Solution

Asymmetric architectures allocate power budgets dynamically: allocating a high-clock-rate single-threaded Performance core to the serial fraction \(s\) reduces \(T_{\text{seq}}\), while dispatching parallel work \(1 - s\) across numerous energy-efficient cores maximizes aggregate throughput per watt, raising the effective Amdahl ceiling.

R2 · Strong vs Weak Scaling in Regulatory Batch Stress Testing

Why do bank risk architectures evaluate both strong and weak scaling for Comprehensive Capital Analysis and Review (CCAR) stress testing?

Solution

Strong scaling dictates whether an existing 100,000-instrument portfolio can be repriced within the overnight regulatory submission deadline. Weak scaling dictates whether the bank can expand the simulation to 10,000 macroeconomic stress scenarios across the entire global book as server nodes are added without execution time expanding beyond the batch window.

R3 · Microarchitectural False Sharing and the Karp-Flatt Metric

How does hardware false sharing manifest in measured speedup and Karp-Flatt metrics?

Solution

When multiple threads write to distinct variables residing on the same 64-byte CPU cacheline, the MESI cache coherence protocol repeatedly invalidates L1/L2 cache lines across sockets. This causes memory stall cycles to spike with core count, triggering a steep rise in the Karp-Flatt metric despite completely parallel application code.

8Retrieval Quiz

  1. Under Amdahl's Law, what is the theoretical maximum speedup limit for a program whose serial fraction is \(s = 0.05\) as \(N \to \infty\)?

    By Theorem 1.2, \(\lim_{N \to \infty} S_A(N) = 1/s = 1 / 0.05 = 20\).

  2. What fundamental distinction separates Amdahl's Law from the Gustafson-Barsis Law?

    Options

    Amdahl's Law models strong scaling where workload is fixed; Gustafson's Law models weak scaling where workload expands with processor count.

  3. A parallel program with serial fraction \(s = 0.05\) runs on \(N = 19\) processors. Under Amdahl's Law, what is the theoretical speedup?

    \(S_A(19) = 1 / (0.05 + 0.95/19) = 1 / (0.05 + 0.05) = 1 / 0.10 = 10.0\).

  4. If the experimentally measured Karp-Flatt metric \(e\) increases significantly as processor count \(N\) grows, what does this indicate?

    Options

    An increasing Karp-Flatt metric indicates that efficiency loss is driven by communication or contention overhead rather than static algorithmic serial code.

  5. What is the parallel efficiency (expressed as a percentage) of an algorithm that achieves 8.0x speedup on 16 cores?

    \(E = S / N = 8.0 / 16 = 0.50 = 50.0\%\).

  6. What physical microarchitectural phenomenon can cause superlinear parallel speedup (\(S(N) > N\)) in memory-intensive quantitative algorithms?

    Options

    When aggregating caches across multiple sockets or cores, the total working set may fit into L2/L3 cache, eliminating slow DRAM memory latency.

  7. Under Gustafson's weak scaling law with serial fraction \(s = 0.05\), what is the scaled speedup on \(N = 64\) cores?

    \(S_G(64) = 64 - 0.05 \times 63 = 64 - 3.15 = 60.85\).

  8. Which regime is described as 'weak scaling'?

    Options

    Weak scaling measures execution performance when the problem size per processor is held constant as processor count scales.
