Deterministic Computation & Seeded Randomness

Quantitative finance relies extensively on stochastic simulation: Monte Carlo option pricing, portfolio stress testing, bootstrap resampling, and randomized factor searches. However, stochastic algorithms must never be confused with non-deterministic software. When research code relies on unseeded entropy, shared module-level state, or non-deterministic hash iteration, consecutive runs yield divergent results, making debugging impossible and invalidating audit trails. Enforcing deterministic computation by isolating pseudo-random generator instances and parameterizing all stochastic draws by explicit seeds guarantees that complex stochastic simulations reproduce bit-for-bit on command.

1Foundations of Deterministic Computation

A computational routine is mathematically deterministic if its output is uniquely determined by its formal inputs without hidden dependencies on physical time, unseeded hardware entropy, or external environmental state.

Definition 6.1 · Deterministic Computation and Seeded Randomness

Deterministic computation and seeded randomness is the programming discipline wherein a system's output is an invariant, reproducible function of its initial parameters and explicit seeds. Any stochastic sequence is produced by a pseudo-random number generator (PRNG) initialized by a known integer seed, encapsulated in an isolated state object, and completely insulated from global mutable side channels.

Theorem 6.1 · Deterministic PRNG State Recurrence

Let a pseudo-random number generator be defined by a finite state space \(\mathcal{S}\), an initial seed mapping \(\iota: \mathbb{Z} \to \mathcal{S}\), a state transition operator \(\psi: \mathcal{S} \to \mathcal{S}\), and an output extraction function \(g: \mathcal{S} \to \mathcal{O}\). For any fixed seed \(s \in \mathbb{Z}\), the resulting sequence of draws \((x_0, x_1, \dots)\) where \(S_0 = \iota(s)\), \(S_{t+1} = \psi(S_t)\), and \(x_t = g(S_t)\) is completely unique and deterministic: identical initial seeds produce identical sequences across arbitrary executions within the same interpreter.

Proof

By mathematical induction on the sequence index \(t\). For base case \(t = 0\), the seed \(s\) uniquely determines the initial state \(S_0 = \iota(s)\) because \(\iota\) is a deterministic function. The initial output \(x_0 = g(S_0)\) is uniquely determined because \(g\) is a deterministic function. For inductive step, assume state \(S_t\) and output \(x_t\) are uniquely determined for index \(t\). The next state is \(S_{t+1} = \psi(S_t)\). Because \(\psi\) is a single-valued mathematical function with no external state inputs, the uniqueness of \(S_t\) implies the uniqueness of \(S_{t+1}\). The output is \(x_{t+1} = g(S_{t+1})\), which is uniquely determined by \(S_{t+1}\). By the principle of mathematical induction, every element of the infinite sequence \((x_t)_{t \ge 0}\) is uniquely determined by \(s\).

Remark 6.1 · Linear Congruential Generators

A classic, transparent example of a deterministic PRNG is the linear congruential generator (LCG) defined by modular recurrence \(X_{i} = (a \cdot s + c \cdot i^2 + d \cdot i) \pmod m\). When modulus \(m\) is prime and parameters \(a, c, d\) are fixed integers, every integer seed \(s\) produces a strictly deterministic sequence of values in \(\{0, \dots, m - 1\}\).

2The Perils of Shared Global Generator State

A primary failure mode in quantitative software is reliance on the global module-level random or numpy.random state.

Example 6.1 · Global State Contamination Anatomy

Consider two functions in an equity market simulator: a factor model simulate_factors() and an order execution router route_orders(). If both call random.random(), they consume draws from a single shared global Mersenne Twister instance. If an analyst inserts an extra diagnostic print statement that calls an external library routine that draws three random numbers, the internal state of the global generator advances by three steps. Subsequent calls to simulate_factors() now receive completely different random numbers despite using the identical initial seed. The simulation's returns diverge, destroying reproducibility.

Wilson et al. (2014) demonstrate that automated computational workflows must eliminate hidden global mutable states to guarantee reproducible results. Encapsulating generator instances inside dedicated classes or passing explicit generator handles (e.g. rng = random.Random(seed)) ensures that sub-routines can never contaminate neighboring simulation streams.

3Order-Dependent Computation: Sets, Dictionaries, and Concurrency

Even in the absence of pseudo-random generators, non-determinism enters quantitative code through non-deterministic iteration and concurrency.

Definition 6.2 · System Sources of Non-Determinism

  • Set and Dictionary Iteration: In Python, string hash randomization (PYTHONHASHSEED) randomizes internal hash bucket placements on each process invocation. Iterating over an un-sorted set (set(symbols)) produces different iteration sequences across interpreter runs.
  • Wall-Clock System Metadata: Functions that query datetime.now() or time.time() inject the physical operating system clock into computational pipelines.
  • Concurrency Race Conditions: Multi-threaded execution without atomic synchronization or deterministic reduction order produces non-deterministic summation due to arbitrary thread scheduling.

Lab 1 · Deterministic Computation and Pseudo-Random Stream Isolation

Evaluates deterministic pseudo-random number generation and state isolation on SIMULATED random streams. Demonstrates that two isolated instances of random.Random seeded with identical keys produce bit-identical streams, whereas global module-level random state is contaminated by intervening third-party calls.

"""CS4 Lesson 6 Inline Lab 1: Deterministic computation and pseudo-random stream isolation.

Demonstrates deterministic pseudo-random number generation and state isolation.
Shows that two independent instances of random.Random seeded with identical keys produce
identical streams of draws bit-for-bit.
Demonstrates how reliance on shared global state (module-level random) introduces silent
non-determinism when intervening functions draw from the global generator.

Data: SIMULATED random streams generated with deterministic pseudo-random seeds.
"""

from __future__ import annotations

import random


def draw_stream_isolated(seed: int, count: int) -> list[int]:
    """Draw a deterministic sequence using an isolated, encapsulated generator instance."""
    rng = random.Random(seed)
    return [rng.randint(1, 1000) for _ in range(count)]


def draw_stream_global(count: int) -> list[int]:
    """Draw a sequence using global module-level random state (unencapsulated)."""
    return [random.randint(1, 1000) for _ in range(count)]


def intervening_third_party_call() -> None:
    """Simulate an external library or routine drawing from the shared global RNG."""
    _ = [random.random() for _ in range(7)]


def main() -> None:
    print("SIMULATED pseudo-random stream isolation evaluation:")

    seed = 42
    n_draws = 5

    # 1. Isolated generator determinism
    stream1 = draw_stream_isolated(seed, n_draws)
    stream2 = draw_stream_isolated(seed, n_draws)

    print(f"Isolated Generator Stream 1 (seed={seed}): {stream1}")
    print(f"Isolated Generator Stream 2 (seed={seed}): {stream2}")
    streams_equal = stream1 == stream2
    print(f"Isolated streams bit-for-bit identical: {streams_equal}")

    # 2. Global state contamination
    print("\nGlobal state contamination demonstration:")
    random.seed(seed)
    global_stream1 = draw_stream_global(n_draws)
    print(f"Global Stream Run 1 (seed={seed}): {global_stream1}")

    # Reset global seed to same value, but simulate intermediate call
    random.seed(seed)
    intervening_third_party_call()
    global_stream2 = draw_stream_global(n_draws)
    print(f"Global Stream Run 2 (after intervening call): {global_stream2}")

    global_equal = global_stream1 == global_stream2
    print(f"Global streams identical despite same seed: {global_equal}")

    print("\nConclusion: Encapsulating PRNG state in dedicated instances guarantees determinism.")


main()

The lab confirms that encapsulating PRNG state guarantees bit-for-bit repeatability. Isolated instances seeded with 42 produce identical integer draws [655, 115, 26, 760, 282] regardless of execution context. In contrast, global random state leaks when intervening functions draw from the generator, causing consecutive runs to diverge.

4Where the Canon Breaks

A widespread assumption among quantitative engineers is that specifying an integer seed guarantees cross-platform determinism across all machines and operating systems. This canon fails across language versions, library updates, and hardware architectures. The internal implementation of Python's random module or NumPy's generator can change across major releases (for example, NumPy's transition from legacy RandomState to modern PCG64 Generator in version 1.17). A seed guarantees determinism only within a pinned, identical software runtime. Cross-platform reproducibility requires pinning the exact runtime engine, operating system environment, and third-party library versions.

5Misconceptions

  1. Calling random.seed(42) once at the top of a script guarantees all functions in the script execute deterministically.

    Top-level seeding initializes the global generator once. If any intervening function, third-party library, or asynchronous thread draws an unpredictable number of random numbers, all subsequent routines receive shifted draws, corrupting reproducibility.

  2. A seeded Monte Carlo simulation will produce identical numbers on Python 3.10, Python 3.14, and C++.

    A seed is merely an initialization parameter for a specific algorithm. Different programming languages, compiler optimizations, and library versions implement different generator algorithms (e.g. Mersenne Twister vs PCG64 vs Xoroshiro) with different state transitions, producing distinct draw sequences from the same seed.

  3. Dictionary iteration order in Python 3.7+ eliminates all iteration-order bugs.

    While Python 3.7+ preserves insertion order in dictionaries, set iteration order (set) remains dependent on process hash seeds. If dictionary insertion order depends on set iteration or asynchronous message delivery, dictionary order remains non-deterministic.

6Problem Set

Tier 1 · Mechanics

Using the linear congruential formula \(x_i = (1103515245 \cdot s + 12345 \cdot i^2 + 7 \cdot i) \pmod{1000003}\), calculate the first two values \(x_1\) and \(x_2\) for seed \(s = 0\).

Solution

For \(s = 0\), the term \(1103515245 \cdot s = 0\). (1) For \(i = 1\): \(x_1 = (0 + 12345 \cdot 1^2 + 7 \cdot 1) \pmod{1000003} = (12345 + 7) \pmod{1000003} = 12352\). (2) For \(i = 2\): \(x_2 = (0 + 12345 \cdot 2^2 + 7 \cdot 2) \pmod{1000003} = (12345 \cdot 4 + 14) \pmod{1000003} = (49380 + 14) \pmod{1000003} = 49394\).

Explain how setting the environment variable PYTHONHASHSEED=0 affects Python string hashing.

Solution

By default, Python generates a random secret salt at interpreter startup to seed its SipHash algorithm, ensuring string hash values differ across process invocations (protecting against hash-collision denial-of-service attacks). Setting PYTHONHASHSEED=0 disables this randomization, forcing the hash salt to a fixed zero seed. Consequently, hash("string") produces identical integer values across all interpreter runs.

Refactor the following unencapsulated function to ensure generator isolation:

import random

def draw_returns(n: int) -> list[float]:
    return [random.normalvariate(0.0, 1.0) for _ in range(n)]
Solution

Refactored version taking an explicit seed and instantiating an isolated generator instance:

import random

def draw_returns(n: int, seed: int) -> list[float]:
    rng = random.Random(seed)
    return [rng.normalvariate(0.0, 1.0) for _ in range(n)]

This guarantees that draws depend only on seed and cannot contaminate or be contaminated by other routines.

Tier 2 · Proof

Prove that any PRNG with finite internal state space \(|\mathcal{S}| = M\) must eventually enter a repeating periodic cycle of length \(L \le M\).

Solution

Let \((S_0, S_1, S_2, \dots)\) be the sequence of internal states generated by \(S_{t+1} = \psi(S_t)\). Consider the first \(M + 1\) states: \((S_0, S_1, \dots, S_M)\). Because \(|\mathcal{S}| = M\), by the Pigeonhole Principle there must exist at least two indices \(j, k\) with \(0 \le j < k \le M\) such that \(S_j = S_k\). Because \(\psi\) is a deterministic function, \(S_{j+1} = \psi(S_j) = \psi(S_k) = S_{k+1}\). By induction, \(S_{j+m} = S_{k+m}\) for all \(m \ge 0\). The sequence enters a strictly periodic cycle of period length \(L = k - j \le M\).

Prove that sorting a finite set of unique strings prior to iteration eliminates hash-seed non-determinism.

Solution

Let \(S\) be a finite set of \(n\) strings. Internal set iteration order is determined by hash values: \(s_i\) precedes \(s_j\) if \(\mathrm{hash}(s_i) < \mathrm{hash}(s_j)\) in the hash table buckets. When PYTHONHASHSEED varies, hash order varies. Calling sorted(S) evaluates the binary lexicographical comparison operator < on character sequences. Lexicographical comparison evaluates character Unicode code points sequentially, which is a pure mathematical function of string content with zero dependence on hash() or memory address. Because lexicographical ordering is a strict total order, sorted(S) yields a unique deterministic sequence regardless of hash table bucket layout.

Prove that a multi-threaded parallel reduction \(\sum_{i=1}^n x_i\) using floating-point arithmetic is non-deterministic unless execution order is fixed.

Solution

By IEEE 754 arithmetic properties, floating-point addition is non-associative: \((a \oplus b) \oplus c \ne a \oplus (b \oplus c)\) in general. In a multi-threaded parallel reduction, worker threads accumulate partial sums concurrently, and intermediate sums are combined dynamically as threads complete. Due to non-deterministic operating system thread scheduling, cache misses, and interrupt latency, the order in which thread results are summed varies across runs. Because different reduction tree orderings produce different intermediate rounding errors, the final floating-point sum is non-deterministic.

Tier 3 · Empirical

A quantitative backtest script yields Sharpe ratio 1.84 on Run 1 and 1.76 on Run 2 under the same nominal seed. An audit reveals that asset weights were stored in a Python set and converted to a list via list(asset_set). Explain the empirical mechanism causing the discrepancy.

Solution

Converting a set directly to a list produces elements in hash bucket order. Because Python randomizes hash seeds across process invocations, the list order of asset tickers changes between runs. When the backtest iterates through the asset list to apply capital allocation caps or trading costs, assets are evaluated in a different sequence. If transaction cost budgets or sector exposure limits bind sequentially, different assets receive allocations on Run 1 versus Run 2, causing the portfolio returns and Sharpe ratio to diverge.

In a distributed cluster running 1,000 parallel Monte Carlo paths, each worker node is initialized with seed = base_seed + worker_id. Why can simple linear seed offsetting introduce severe correlation artifacts across worker streams?

Solution

Many legacy PRNGs (such as 32-bit LCGs) exhibit structural lattice correlations between consecutive seeds: trajectories initialized with seeds \(s\) and \(s + 1\) can overlap or produce highly correlated paths after a short lead-in phase. In parallel Monte Carlo pricing, this cross-stream correlation violates the independence assumption of the sample mean, underestimating estimator standard errors. Modern practice requires jump-ahead generators or cryptographically decoupled streams (such as PCG64 or Philox).

An options pricing engine uses multiprocessing to evaluate 100,000 paths across 8 CPU cores. The main process seeds random.seed(42) before calling fork(). What critical defect occurs on Linux?

Solution

Under Unix fork(), child processes inherit an exact duplicate of the parent process's memory space, including the internal state of the PRNG. If child processes are spawned after seeding without re-seeding, all 8 worker processes execute with identical initial PRNG states. Every worker computes the identical 12,500 paths, reducing effective sample size from 100,000 unique paths to only 12,500 paths repeated 8 times. Workers must be initialized with independent, decorrelated sub-seeds.

Tier 4 · Research

Design an enterprise-grade pseudo-random stream architecture for a multi-asset risk management engine executing 100,000,000 daily Monte Carlo paths across a distributed cloud cluster.

Solution

An enterprise PRNG architecture utilizes counter-based pseudo-random number generators (such as Philox-4x64 or Threefry): (1) Mathematical formulation: Outputs are computed directly from a key and counter using cryptographic block cipher principles: \(x = f(K, c)\). (2) Splittable streams: Set key \(K = \text{base\_seed}\), and split the 128-bit counter into \((\text{risk\_factor\_id}, \text{path\_id}, \text{time\_step})\). (3) Random access: Any worker node can evaluate the exact random variable for path 45,210 at time step 12 in \(O(1)\) time without generating intervening draws. (4) Total isolation: Workers require zero communication or state synchronization, guaranteeing bit-for-bit determinism regardless of node scheduling order.

Formulate a formal proof that deterministic execution is a necessary condition for post-mortem debugging of high-frequency trading execution anomalies.

Solution

Let an execution engine be a state machine \(S_{t+1} = \Phi(S_t, I_t, E_t)\), where \(I_t\) is the market data input and \(E_t\) represents unrecorded environmental state (e.g. wall-clock microseconds, unseeded entropy). An anomaly is a transition \(S_T \in \mathcal{F}\) (a failure state). Post-mortem debugging requires replaying the event to isolate the faulty code path: finding \(\Delta \Phi\) such that \(\Phi'(S_t, I_t, E_t) \notin \mathcal{F}\). If \(E_t\) is non-deterministic and unrecorded, then for identical recorded inputs \(I_t\), re-execution produces state trajectory \(S'_t = \Phi(S_t, I_t, E'_t)\). If \(E'_t \ne E_t\), the failure may not reproduce (a "Heisenbug"), rendering root-cause diagnosis unprovable. Determinism (\(E_t \equiv \emptyset\)) guarantees that \(S_T \in \mathcal{F}\) reproduces with certainty.

Evaluate the trade-offs between Quasi-Monte Carlo (QMC) low-discrepancy sequences (e.g. Sobol, Halton) and pseudo-random Monte Carlo regarding convergence speed and multi-dimensional scalability.

Solution

Pseudo-random Monte Carlo achieves integration error convergence rate \(O(N^{-1/2})\) governed by the Central Limit Theorem, completely independent of dimension \(d\). Quasi-Monte Carlo uses deterministic low-discrepancy sequences that fill space more uniformly, achieving asymptotic integration error \(O(N^{-1} (\log N)^d)\). For low-to-moderate effective dimensions (\(d \le 30\)), QMC provides dramatically faster convergence (approaching \(O(N^{-1})\)), requiring 10 to 100 times fewer paths for option pricing. However, as dimension \(d\) grows large (> 100), the \((\log N)^d\) term dominates until \(N\) is astronomically large, causing standard QMC to degrade unless paired with Brownian bridge path construction or randomized scrambling.
