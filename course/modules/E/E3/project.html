Preference Elicitation

A participant answers a short questionnaire of choices between lotteries. From the answers you estimate how curved the participant's value of money is, how much more a loss weighs than a gain of the same size, and how precisely the participant's choices follow the values. You write the engine that does the estimation, design the questionnaire, and report the estimates with their uncertainty.

Rungs 1 and 2

Both labs use one SIMULATED participant. The participant's parameters are stated inputs: a curvature of 0.40, a loss-aversion coefficient of 2.00 and a choice precision of 1.50. Nothing here is estimated from data, and no file is read. The prospect value of a lottery is defined in Lesson 6, the certainty equivalent in Lesson 2, and the CRRA utility of Lab 1 is the power utility of Lesson 3 without its subtracted constant, which changes no certainty equivalent (Lesson 3, Proposition 2.7). The choice rule is the logit rule, \(P(\text{choose }A)=1/(1+e^{-z})\), which the Choice probability convention of Rung 3 defines.

Lab 1 · Worked example: three answers, step by step

The participant is SIMULATED, with \(\gamma = 0.40\), \(\lambda = 2.00\) and \(\kappa = 1.50\). Expected, stated before running: the CRRA certainty equivalents of pair 1 are 496 cents for A and 500 cents for B, and the prospect certainty equivalents of pair 1 are \(-30\) cents for A and 500 cents for B. The participant chose A in pair 1, so the printed \(P(A) = 0.480149\) gives a log-probability of the chosen answer of \(-0.733658\). The three log-probabilities sum to \(-2.302315\). The money amounts that the printed output shows are in cents, and each certainty equivalent is printed as a whole cent, an exact half going up; the likelihood uses the unrounded values.

"""Rung 1 worked example: one SIMULATED participant, three choice pairs, their certainty equivalents and likelihood.

Standard library only. The participant's parameters are stated values chosen for this example (gamma 0.40,
lambda 2.00, kappa 1.50). They are not estimates, and the participant is not a real person.
"""

import math
from fractions import Fraction

GAMMA = 0.40  # curvature of the value function, in [0, 1) for the prospect model
LAMBDA = 2.00  # loss-aversion coefficient
KAPPA = 1.50  # choice precision: the logit scale, per $100 of certainty-equivalent difference
WEALTH = 100_000  # starting wealth in cents ($1,000.00); used by the CRRA model only


def nearest_cent(amount: float) -> int:
    """The nearest whole cent of a float, with an exact half going up (toward plus infinity)."""
    return math.floor(amount + 0.5)


def crra_certainty_equivalent(prizes: list[int], probs: list[Fraction], gamma: float, wealth: int) -> float:
    """CRRA certainty equivalent as a change from wealth, in cents, unrounded: the sure amount whose utility of final
    wealth equals the lottery's expected utility of final wealth."""
    finals = [wealth + x for x in prizes]
    expected = sum(float(p) * math.pow(w, 1.0 - gamma) for p, w in zip(probs, finals, strict=True))
    return math.pow(expected, 1.0 / (1.0 - gamma)) - wealth


def prospect_value(x: int, gamma: float, lam: float) -> float:
    """Value of a change x from the reference point 0: x^(1-gamma) for a gain, -lambda (-x)^(1-gamma) for a loss."""
    if x >= 0:
        return math.pow(float(x), 1.0 - gamma)
    return -lam * math.pow(float(-x), 1.0 - gamma)


def prospect_certainty_equivalent(prizes: list[int], probs: list[Fraction], gamma: float, lam: float) -> float:
    """The sure change whose value equals the lottery's value (the probability-weighted sum of prospect values), in
    cents, unrounded. The inverse of the value function is taken on each side of zero."""
    total = sum(float(p) * prospect_value(x, gamma, lam) for x, p in zip(prizes, probs, strict=True))
    if total >= 0.0:
        return math.pow(total, 1.0 / (1.0 - gamma))
    return -math.pow(-total / lam, 1.0 / (1.0 - gamma))


def choice_probability_a(ce_a: float, ce_b: float, kappa: float) -> float:
    """P(choose A) = 1 / (1 + exp(-z)), z = kappa (CE_A - CE_B) / 10000: the difference is in units of $100."""
    z = kappa * (ce_a - ce_b) / 10_000.0
    return 1.0 / (1.0 + math.exp(-z))


def main() -> None:
    pairs = [
        ("pair 1", [2000, -1000], [Fraction(1, 2), Fraction(1, 2)], [500], [Fraction(1)], "A"),
        ("pair 2", [3000], [Fraction(1)], [4000, -2000], [Fraction(1, 4), Fraction(3, 4)], "B"),
        ("pair 3", [1500, 2500], [Fraction(1, 3), Fraction(2, 3)], [-500, 3000], [Fraction(1, 2), Fraction(1, 2)], "A"),
    ]
    total = 0.0
    for name, pa, qa, pb, qb, chosen in pairs:
        crra_a = nearest_cent(crra_certainty_equivalent(pa, qa, GAMMA, WEALTH))
        crra_b = nearest_cent(crra_certainty_equivalent(pb, qb, GAMMA, WEALTH))
        ce_a = prospect_certainty_equivalent(pa, qa, GAMMA, LAMBDA)
        ce_b = prospect_certainty_equivalent(pb, qb, GAMMA, LAMBDA)
        print(
            name, "| CRRA cents A, B:", crra_a, crra_b, "| prospect cents A, B:", nearest_cent(ce_a), nearest_cent(ce_b)
        )
        p_a = choice_probability_a(ce_a, ce_b, KAPPA)
        p_chosen = p_a if chosen == "A" else 1.0 - p_a
        total += math.log(p_chosen)
        print(name, "| P(A):", f"{p_a:.6f}", "| chosen:", chosen, "| log P(chosen):", f"{math.log(p_chosen):.6f}")
    print("log-likelihood of the three choices:", f"{total:.6f}")

Rung 3 · Specification

Context
A participant answers a questionnaire in which each question offers a sure amount or a lottery, or two lotteries. Each answer is a noisy signal of the participant's values. You want three numbers from one questionnaire: the curvature of the value of money \(\gamma\), the loss-aversion coefficient \(\lambda\) of a value function that weighs losses against gains, and the precision \(\kappa\) of the choices. The question is how precisely a questionnaire of a given size can estimate each of them, and you answer it with the standard errors.
Inputs
(a) The instrument: a file instrument.json of at least 12 pairs that you write, as a JSON list of objects with the keys pair_id (an integer), prizes_a, probs_a, prizes_b and probs_b, in the form of the responses in (b) but with no choice, because the instrument records no answer. Each lottery gives its prizes in whole cents and its probabilities as exact fractions written "numerator/denominator", and at least one pair in the instrument has a lottery that mixes a gain and a loss, meaning a prize above zero and a prize below zero, each with positive probability. (b) The participant's responses, as a JSON list of objects with the keys pair_id (an integer), choice (the text "A" or "B"), prizes_a and probs_a, prizes_b and probs_b. Each probability is text of the form "numerator/denominator" that Fraction reads exactly. You record the participant's choices with the questionnaire, which exports this file. The autograder's responses come from grader/instance.py for your seed, and they are SIMULATED. Your own responses are personal data. Keep them on your machine: nothing on this page sends them anywhere.
Required outputs
In a repository of your own: elicit.py at its root, with the three functions below; instrument.json; and report/report.md with the sections of the brief, followed by its appendix, and report/self_assessment.md produced by the form in the self-assessment section. The functions of elicit.py are certainty_equivalent_cents(model: str, prizes_cents: list[int], probabilities: list[Fraction], params: dict[str, float], wealth_cents: int) -> int, log_likelihood(responses: list[dict[str, object]], params: dict[str, float]) -> float and estimate(responses: list[dict[str, object]]) -> dict[str, float]. The estimate returns the keys gamma_hat, lambda_hat, kappa_hat, se_gamma, se_lambda, se_kappa and log_likelihood. The params argument is a dict with the keys "gamma", "lambda" and "kappa": certainty_equivalent_cents reads "gamma" alone under the "crra" model and "gamma" and "lambda" under the "prospect" model, and log_likelihood reads all three. Start from the starter file, whose signatures are complete.
Constraints
Standard library only; no network, which the suite checks by reading the imports of elicit.py. Every money output is an int number of cents. Every named invalid input raises the exception that the exception table gives for it, and where the table quotes a message, the message contains that text. No function prints or warns; the suite checks that the functions print nothing and that no warning is raised. The conventions of the next subsection are binding. The engine is graded on the same seeded participant, in your browser and on your machine, so the answers are the same there.
Grading mode
Both modes apply. The engine is autograded by grader/test_project.py, which runs 38 checks with warnings as errors. The checks compare the engine with oracles written for the suite: exact cents where the answer is exact, a stated tolerance elsewhere, and the score, the local maximum and the standard errors of the estimate. The score, the vector of partial derivatives of the log-likelihood, is checked at the estimate: each of its three components, in the coordinates \(\eta\), \(\log\lambda\) and \(\log\kappa\), must be below \(2\times 10^{-5}\) in absolute value, with the components computed by central differences of step \(10^{-5}\) or \(10^{-6}\) in those coordinates, whichever gives the smaller largest component (the log-likelihood has kinks, where a central difference depends on its step). The suite is not secret; its integrity comes from the seeded participant and from a second participant, which a fixed answer for one seed would also have to match. The recovery check requires each estimate to lie within four standard errors of its true value, for every parameter, on at least 47 of the 50 seeds 0 to 49; that count is a threshold of this suite, and the page makes no claim about the coverage of the standard errors. The instrument and the report are graded by rubric, against the five criteria of the report rubric, each with four observable levels. You score yourself with the self-assessment form, calibrated on two annotated exemplars. The report meets the bar at level 3 or above on every criterion.

Conventions

  • Models. model is "crra" or "prospect", with no other spelling accepted. The "crra" model is expected utility of final wealth, \(W^{1-\gamma}/(1-\gamma)\) for \(\gamma \ne 1\) and \(\ln W\) at \(\gamma = 1\), with \(W = \texttt{wealth\_cents} + x\) for each prize \(x\). Its certainty equivalent is the sure change from wealth whose utility equals the lottery's expected utility. The "prospect" model is the loss-averse power value of Lesson 6 (Definition 1.2) with \(\alpha = \delta = 1-\gamma\) and no probability weighting, so the probabilities enter as they are (Definition 1.3):\(v(x)=x^{1-\gamma}\) for \(x \ge 0\) and \(v(x)=-\lambda(-x)^{1-\gamma}\) for \(x<0\), with \(0 \le \gamma < 1\) and \(\lambda > 0\). Its lottery value is \(V=\sum_i p_i v(x_i)\), and its certainty equivalent is the sure change \(c\) with \(v(c)=V\), namely \(c=V^{1/(1-\gamma)}\) when \(V \ge 0\) and \(c=-(-V/\lambda)^{1/(1-\gamma)}\) otherwise. The prospect model does not use wealth.
  • Whole cents. A certainty equivalent is computed in floating point from the exact probabilities, then taken to the nearest whole cent once. An exact half cent goes toward plus infinity: \(\lfloor c + \tfrac12 \rfloor\). So \(2.5\) gives 3 and \(-0.5\) gives 0. No other rounding is applied to a money amount.
  • Choice probability. \(P(\text{choose }A)=1/(1+e^{-z})\) with \(z=\kappa\,(\mathrm{CE}_A-\mathrm{CE}_B)/10\,000\), so the difference is measured in units of $100. The likelihood uses the unrounded certainty equivalents, and \(\kappa > 0\). The likelihood of the responses is the product of the probabilities of the chosen alternatives, so its logarithm is the sum of \(\log P(A)\) for each response that chose A and \(\log(1-P(A))\) for each response that chose B.
  • Identification. A parameter is identified by the answers when two values of it give different likelihoods on them. The certainty equivalent of a lottery whose positive-probability prizes are all gains, or all losses, does not depend on \(\lambda\): \(\lambda\) does not appear in the gain branch of \(v\), and in the loss branch it multiplies the value, which the inverse divides out. So a pair identifies \(\lambda\) only when one of its two lotteries mixes a gain and a loss, each with positive probability.
  • Estimation. estimate uses the prospect model only, with \(\gamma \in (0,1)\), \(\lambda > 0\) and \(\kappa > 0\). The estimates are floats. Its standard errors are the square roots of the diagonal of the inverse of the observed information, the negative Hessian of the log-likelihood at the estimate, in the coordinates \(\eta=\log(\gamma/(1-\gamma))\), \(\log\lambda\) and \(\log\kappa\), carried to the parameters by the delta method: for a parameter \(g(\theta)\) of one coordinate \(\theta\), the standard error is approximately \(|g'(\theta)|\) times the standard error of \(\theta\).
  • Probabilities. Each probability is a Fraction, non-negative, and the probabilities of a lottery sum to exactly 1. A probability of exactly zero is allowed.

"""Rung 3 reference case: the estimates and standard errors for one fixed questionnaire of twelve SIMULATED answers.

negative Hessian of the log-likelihood in the coordinates (eta, log lambda, log kappa), eta = log(gamma / (1 - gamma)),
inverted and carried to the parameters by the delta method.

from fractions import Fraction

]


def value(x: float, gamma: float, lam: float) -> float:
    """Prospect value of a change x from 0: x^(1-gamma) for gains, -lam (-x)^(1-gamma) for losses."""
    if x >= 0.0:
        return math.pow(x, 1.0 - gamma)
    return -lam * math.pow(-x, 1.0 - gamma)


def certainty_equivalent(prizes: list[int], probs: list[str], gamma: float, lam: float) -> float:
    """The sure change whose prospect value equals the lottery's value, in cents, unrounded."""
    total = sum(float(Fraction(p)) * value(x, gamma, lam) for x, p in zip(prizes, probs, strict=True))
    if total >= 0.0:
        return math.pow(total, 1.0 / (1.0 - gamma))
    return -math.pow(-total / lam, 1.0 / (1.0 - gamma))


def log_likelihood(theta: list[float]) -> float:
    """The logit log-likelihood at theta = (eta, log lambda, log kappa); each answer contributes log P(chosen)."""
    gamma = 1.0 / (1.0 + math.exp(-theta[0]))
    lam, kappa = math.exp(theta[1]), math.exp(theta[2])
    total = 0.0
    for _, choice, pa, qa, pb, qb in ANSWERS:
        z = kappa * (certainty_equivalent(pa, qa, gamma, lam) - certainty_equivalent(pb, qb, gamma, lam)) / 10_000.0
        total += -math.log1p(math.exp(-z)) if choice == "A" else -math.log1p(math.exp(z))
    return total


def grid_start() -> list[float]:
    """The best point of a small grid over gamma, lambda and kappa, used to start the search."""
    best = [0.0, 0.0, 0.0]
    best_value = log_likelihood(best)
    for gamma in (0.05, 0.25, 0.45, 0.65, 0.85):
        for lam in (1.0, 2.0, 4.0):
            for kappa in (0.5, 2.0, 5.0):
                start = [math.log(gamma / (1.0 - gamma)), math.log(lam), math.log(kappa)]
                if log_likelihood(start) > best_value:
                    best, best_value = start, log_likelihood(start)
    return best


def newton(theta: list[float]) -> list[float]:
    """Newton's method on the log-likelihood, with central differences of step 1e-6 and step halving."""
    h = 1e-6
    for _ in range(100):
        f0 = log_likelihood(theta)
        grad = [0.0, 0.0, 0.0]
        neg_hess = [[0.0] * 3 for _ in range(3)]
        for i in range(3):
            up = [x + (h if k == i else 0.0) for k, x in enumerate(theta)]
            down = [x - (h if k == i else 0.0) for k, x in enumerate(theta)]
            grad[i] = (log_likelihood(up) - log_likelihood(down)) / (2 * h)
            neg_hess[i][i] = -(log_likelihood(up) - 2 * f0 + log_likelihood(down)) / (h * h)
        for i in range(3):
            for j in range(i + 1, 3):
                pp = [x + (h if k in (i, j) else 0.0) for k, x in enumerate(theta)]
                pm = [x + (h if k == i else 0.0) - (h if k == j else 0.0) for k, x in enumerate(theta)]
                mp = [x - (h if k == i else 0.0) + (h if k == j else 0.0) for k, x in enumerate(theta)]
                mm = [x - (h if k in (i, j) else 0.0) for k, x in enumerate(theta)]
                neg_hess[i][j] = neg_hess[j][i] = -(
                    log_likelihood(pp) - log_likelihood(pm) - log_likelihood(mp) + log_likelihood(mm)
                ) / (4 * h * h)
        step = solve3(neg_hess, grad)
        scale = 1.0
        while scale > 1e-14 and log_likelihood([x + scale * d for x, d in zip(theta, step, strict=True)]) <= f0:
            scale /= 2.0
        if scale <= 1e-14:
            break
        theta = [x + scale * d for x, d in zip(theta, step, strict=True)]
        if max(abs(g) for g in grad) < 1e-7:
            break
    return theta


def solve3(matrix: list[list[float]], rhs: list[float]) -> list[float]:
    """Solves a 3 by 3 linear system by Gaussian elimination with partial pivoting."""
    rows = [[*row, b] for row, b in zip(matrix, rhs, strict=True)]
    n = 3
    for col in range(n):
        pivot = max(range(col, n), key=lambda r: abs(rows[r][col]))
        rows[col], rows[pivot] = rows[pivot], rows[col]
        for r in range(n):
            if r != col:
                factor = rows[r][col] / rows[col][col]
                rows[r] = [a - factor * b for a, b in zip(rows[r], rows[col], strict=True)]
    return [rows[i][n] / rows[i][i] for i in range(n)]


def inverse3(matrix: list[list[float]]) -> list[list[float]]:
    """The inverse of a 3 by 3 matrix, column by column with solve3."""
    columns = [solve3(matrix, [1.0 if k == i else 0.0 for k in range(3)]) for i in range(3)]
    return [[columns[j][i] for j in range(3)] for i in range(3)]


def observed_information(theta: list[float]) -> list[list[float]]:
    """The negative Hessian of the log-likelihood at theta, by central differences of step 1e-5."""
    h = 1e-5
    f0 = log_likelihood(theta)
    info = [[0.0] * 3 for _ in range(3)]
    for i in range(3):
        up = [x + (h if k == i else 0.0) for k, x in enumerate(theta)]
        down = [x - (h if k == i else 0.0) for k, x in enumerate(theta)]
        info[i][i] = -(log_likelihood(up) - 2 * f0 + log_likelihood(down)) / (h * h)
    for i in range(3):
        for j in range(i + 1, 3):
            pp = [x + (h if k in (i, j) else 0.0) for k, x in enumerate(theta)]
            pm = [x + (h if k == i else 0.0) - (h if k == j else 0.0) for k, x in enumerate(theta)]
            mp = [x - (h if k == i else 0.0) + (h if k == j else 0.0) for k, x in enumerate(theta)]
            mm = [x - (h if k in (i, j) else 0.0) for k, x in enumerate(theta)]
            info[i][j] = info[j][i] = -(
                log_likelihood(pp) - log_likelihood(pm) - log_likelihood(mp) + log_likelihood(mm)
            ) / (4 * h * h)
    return info

def largest_score(theta: list[float]) -> float:
    """The largest absolute partial derivative of the log-likelihood at theta, in its three coordinates."""
    h = 1e-5
    values = []
    for i in range(3):
        up = [x + (h if k == i else 0.0) for k, x in enumerate(theta)]
        down = [x - (h if k == i else 0.0) for k, x in enumerate(theta)]
        values.append(abs(log_likelihood(up) - log_likelihood(down)) / (2 * h))
    return max(values)


def mixed_pair(answer: tuple[int, str, list[int], list[str], list[int], list[str]]) -> bool:
    """A question is mixed when one of its two lotteries has a gain and a loss, each with positive probability."""
    _, _, pa, qa, pb, qb = answer
    for prizes, probs in ((pa, qa), (pb, qb)):
        gain = any(x > 0 and Fraction(p) > 0 for x, p in zip(prizes, probs, strict=True))
        loss = any(x < 0 and Fraction(p) > 0 for x, p in zip(prizes, probs, strict=True))
        if gain and loss:
            return True
    return False

Model and likelihood

The value function is \(v(x)=x^{1-\gamma}\) for gains and \(-\lambda(-x)^{1-\gamma}\) for losses, with \(0\le\gamma<1\). Each lottery's certainty equivalent is the sure change whose value equals the lottery's value. The choice probability is \(P(A)=1/(1+e^{-z})\), with \(z=\kappa(\mathrm{CE}_A-\mathrm{CE}_B)/10\,000\). The log-likelihood adds \(\log P(A)\) for each response that chose A and \(\log(1-P(A))\) for each response that chose B. I assume no probability weighting, which is a simplification: a lottery's probabilities enter linearly. The estimate requires at least one mixed pair, and eleven of the twelve pairs contain one (Lab 3 prints the count). I expect, without computing it here, that precision is identified by the spread of the differences in certainty equivalent, and curvature by the pure and mixed pairs together; that is a hypothesis for you to test.
