Market-making game

You write the quoting rule of a market maker for one asset over 20 turns, and the replay of the game log that the rule produces. Some counterparties trade on information the maker does not see. The engine plays the market-making game for your seed, and your replay (specified under Rung 3) turns the log into a decomposition of the P&L into cash flow and inventory, in integer cents; the terms are defined under Conventions. The analysis then says where the result came from and what would change it. Play is by code, not by clicking. Every instance is SIMULATED.

Rungs 1 and 2

Both labs play the same game: seed 0, the fair path and arrivals that grader/instance.py generates for seed 0, and one fixed quoting rule. The rule takes the mid to be the last filled price, or 10000 cents before any fill, and quotes a half-spread of 10 cents (the distance of each quote from the mid), for one unit: a bid 10 cents below the mid and an ask 10 cents above it. A fill is a trade of one unit at the bid or at the ask. The game is SIMULATED: its fair path (the fair value v0 to v20, which the maker does not see) and its arrivals (one per turn: an uninformed buy, an uninformed sell or an informed trader) are generated, and no data file is read. The turn-by-turn rules are those of Lesson 4, and they are restated in the conventions below, where the cash flow, the settlement value, the inventory mark, the P&L and the identity that links them are defined. The labs show the replay that your replay function must reproduce.

Lab 1 · Worked example: one seeded game and its replay

Stated before running. On seed 0 the game has 9 fills in 20 turns. The fills sum to a cash flow of \(-9950\) cents, the maker ends with an inventory of 1 unit, the settlement value is 9980 cents, so the inventory mark is 9980 cents and the P&L is \(30\) cents. The identity P&L = cash flow + inventory \(\times\) settlement holds, and no inventory passes the limit of 10 units.

"""PC3 project, rung 1: a worked example. One seeded game, one fixed quoting rule, and the replay of its log.

SIMULATED. The fair path and the arrivals are generated from random.Random(0), in the order of the project's instance
generator, which is the order of Lesson 4. No data file is read and there is no network access. Standard library only.
Money is an integer number of cents, and every accounting value is an int.

The quoting rule is fixed: bid and ask sit 10 cents either side of the last filled price, or of 10000 cents before any
fill, and each side is for one unit. The log has the fields the project specifies. The replay below computes the cash
flow, the ending inventory, the mark at the settlement value and the P&L from the fills of the log. Then main checks the
identity P&L = cash flow + inventory x settlement, in integer cents. The numbers describe this one seed and this one
rule.
"""

from __future__ import annotations

import random
from typing import Any

HORIZON = 20  # turns
START_CENTS = 10_000  # v_0, in cents
MOVE_CENTS = 5  # the fair value moves by +5 or -5 cents each turn
HALF_SPREAD = 10  # cents either side of the mid
SIZE = 1  # units quoted on each side
LIMIT = 10  # inventory limit: a fill is refused when |inventory| would exceed it
SEED = 0


def draw_game(seed: int) -> tuple[list[int], list[str]]:
    """The fair path v_0 .. v_20 in cents and the 20 arrivals. Turn t draws its move first, then its arrival."""
    rng = random.Random(seed)
    path = [START_CENTS]
    arrivals: list[str] = []
    for _ in range(HORIZON):
        # Step 1a. The fair value moves by +5 cents when the draw is below 0.5, otherwise by -5 cents.
        move = MOVE_CENTS if rng.random() < 0.5 else -MOVE_CENTS
        path.append(path[-1] + move)
        # Step 1b. The arrival: an uninformed buy below 0.25, an uninformed sell below 0.5, else an informed trader.
        draw = rng.random()
        if draw < 0.25:
            arrivals.append("uninformed-buy")
        elif draw < 0.5:
            arrivals.append("uninformed-sell")
        else:
            arrivals.append("informed")
    return path, arrivals


def quote(last_fill: int | None) -> tuple[int, int, int]:
    """The fixed rule: the mid is the last filled price, or 10000 cents before any fill. Returns (bid, ask, size)."""
    # Step 2. Quote HALF_SPREAD cents either side of the mid: the last filled price, or 10000 before any fill.
    mid = START_CENTS if last_fill is None else last_fill
    return mid - HALF_SPREAD, mid + HALF_SPREAD, SIZE


def maker_side(arrival: str, fair: int, bid: int, ask: int) -> int:
    """+1 when the maker buys one unit at the bid, -1 when it sells one at the ask, 0 when there is no trade."""
    if arrival == "uninformed-buy":
        return -1  # the customer buys, so the maker sells at the ask
    if arrival == "uninformed-sell":
        return 1  # the customer sells, so the maker buys at the bid
    if fair > ask:
        return -1  # an informed trader buys when the fair value is strictly above the ask
    if fair < bid:
        return 1  # and sells when the fair value is strictly below the bid
    return 0


def play(seed: int) -> dict[str, Any]:
    """Play the 20 turns and return the log: the seed, the settlement value and the turn records."""
    path, arrivals = draw_game(seed)
    inventory = 0
    cash = 0
    last_fill: int | None = None
    turns: list[dict[str, Any]] = []
    for turn in range(1, HORIZON + 1):
        bid, ask, size = quote(last_fill)
        arrival = arrivals[turn - 1]
        side = maker_side(arrival, path[turn], bid, ask)
        # Step 3. A fill needs a size of at least 1, a trade on the arrival, and |inventory| within the limit after it.
        filled = side != 0 and size >= 1 and abs(inventory + side) <= LIMIT
        price: int | None = None
        if filled:
            price = ask if side < 0 else bid
            inventory += side
            cash += -side * price
            last_fill = price
        turns.append(
            {
                "turn": turn,
                "bid_cents": bid,
                "ask_cents": ask,
                "size": size,
                "arrival": arrival,
                "filled": filled,
                "fill_price_cents": price,
                "inventory_after": inventory,
                "cash_after_cents": cash,
            }
        )
    return {"seed": seed, "settlement_cents": path[HORIZON], "turns": turns}


def replay(log: dict[str, Any]) -> dict[str, int]:
    """Replay the fills of a log: the cash flow, the ending inventory, the mark at settlement and the P&L, in cents."""
    turns: list[dict[str, Any]] = log["turns"]
    # Step 4. A log has exactly 20 turns. Every fill is one unit: a fill at the ask is a sale by the maker, a fill at
    # the bid is a purchase by the maker. The cash flow of a sale is +price, and of a purchase is -price.
    if len(turns) != HORIZON:
        raise ValueError("a log has exactly 20 turns")
    cash_flow = 0
    inventory = 0
    for record in turns:
        if record["filled"] is not True:
            continue
        if record["fill_price_cents"] is None:
            raise ValueError("a filled turn needs a fill price")
        price = int(record["fill_price_cents"])
        side = -1 if price == record["ask_cents"] else 1
        cash_flow += -side * price
        inventory += side
    # Step 5. The inventory is marked at the settlement value, not at the last quote, because the game is settled there.
    mark = inventory * int(log["settlement_cents"])
    return {
        "cash_flow_cents": cash_flow,
        "inventory_end": inventory,
        "inventory_mark_cents": mark,
        "pnl_cents": cash_flow + mark,
    }


def main() -> None:
    print("Rung 1 worked example · seed 0 · SIMULATED · quote 10 cents either side of the last fill, size 1")
    log = play(SEED)
    settlement = log["settlement_cents"]
    print(f"settlement v_{HORIZON} = {settlement} cents")
    print("replay of the fills:")
    for record in log["turns"]:
        if record["filled"]:
            price = int(record["fill_price_cents"])
            side = -1 if price == record["ask_cents"] else 1
            step = -side * price
            print(
                f"  turn {record['turn']:>2}: maker {'sells at the ask' if side < 0 else 'buys at the bid'} "
                f"{price} cents, cash flow {step:+d} cents, inventory {record['inventory_after']:+d}"
            )
    result = replay(log)
    final = log["turns"][-1]
    fills = sum(1 for record in log["turns"] if record["filled"])
    print(f"fills = {fills} of {HORIZON} turns")
    print(f"cash_flow_cents = {result['cash_flow_cents']}")
    print(f"inventory_end = {result['inventory_end']}")
    print(f"inventory_mark_cents = {result['inventory_mark_cents']}")
    print(f"pnl_cents = {result['pnl_cents']}")
    identity = result["pnl_cents"] == result["cash_flow_cents"] + result["inventory_end"] * settlement
    print(f"identity P&L = cash flow + inventory x settlement holds: {identity}")
    print(f"cash flow equals the cash after the last turn: {result['cash_flow_cents'] == final['cash_after_cents']}")
    largest = max(abs(record["inventory_after"]) for record in log["turns"])
    print(f"largest |inventory| over the run = {largest} (limit {LIMIT}): {largest <= LIMIT}")

Step 4 replays the fills, and main then prints one line for each fill: the side (a fill at the ask is a sale by the maker, a fill at the bid a purchase), the price read from the log, the cash flow of that fill (minus the side times the price), and the inventory after it, read from the log. Rung 3 · Specification

Context
Play is by code, not by clicking. You write a quoting rule for a market maker who posts a bid and an ask for one asset over 20 turns, and a replay of the log that the engine writes. Some counterparties trade on information the maker does not see. From the log you must explain the result as its cash flow and its inventory mark (both defined under Conventions), and say what would change the result. The log is the evidence: every number that describes your result is a number of the log or of your replay, and the model's constants are taken from the conventions. The engine that writes the log is described under Inputs.
Inputs
No data file. The game for your workspace seed comes from grader/instance.py, which holds make_instance(seed): a fair path of 21 integers in cents (v0 to v20, starting at 10000) and 20 arrivals. Every instance is SIMULATED, and the seed is derived from your workspace ID. The rules are those of Lesson 4, restated exactly in the conventions. The engine is grader/engine.py, which plays one game for a quoting rule and a seed, and returns the log.
Required outputs
In a folder of your own: market_maker.py at its root. It defines two functions. quote(state: dict[str, object]) -> tuple[int, int, int] returns (bid_cents, ask_cents, size) for the current turn; its state holds exactly the keys turn (1 to 20), inventory, cash_cents, max_size (5), limit (10) and history (the earlier turn records of the log). replay(log: dict[str, object]) -> dict[str, int] returns exactly the keys cash_flow_cents, inventory_end, inventory_mark_cents and pnl_cents, with pnl_cents = cash_flow_cents + inventory_mark_cents and inventory_mark_cents = inventory_end × settlement_cents. Start from the starter file, whose signatures are complete. Also analysis.md, the analysis described in the brief. For the analysis you need a log of your own rule. Run this in the folder that holds engine.py, instance.py and market_maker.py, and it writes game_log.json for the seed shown in the autograder panel: 
python3 -c "import json, engine, market_maker; print(json.dumps(engine.play(market_maker.quote, <your seed>)))" > game_log.json
In the browser a log is not saved as a file. The autograder replays the logs of your rule inside its run. A log is the dict that engine.play(quote, seed) returns. Its keys are seed (an int), settlement_cents (an int, the value \(v_{20}\)) and turns, a list of 20 records. Each record has the keys turn (1 to 20), bid_cents, ask_cents, size, arrival (one of uninformed-buy, uninformed-sell or informed), filled (true or false), fill_price_cents, inventory_after and cash_after_cents. When filled is false, fill_price_cents is None. A fill at the bid is a purchase by the maker, and a fill at the ask is a sale by the maker.
Constraints
Standard library only. Money is an integer number of cents everywhere, and inventory is an integer number of units. A quote must have its bid below its ask, and its size must lie in 0 to 5; the engine refuses a quote that breaks either rule with ValueError, as the named conditions below state. A fill is one unit. A fill needs a size of at least 1 and an inventory within the limit of 10 units after the fill: an order that would take the inventory past the limit is not filled, and its record says filled: false. Neither quote nor replay prints or warns. The analysis does not claim a result for real market makers: the model has one asset, and its arrival probabilities are the ones the rules set. Known limitation. The instance is in grader/instance.py, and a student who reads it can see the fair path. A log shows only the settlement value, at the end, and not the fair path; the autograder cannot check that a rule avoids the fair path. A static site cannot keep its tests secret. Integrity rests on the per-seed instances, on the checks that run on the fixed seeds 0 to 49 and on a second seed (see Grading mode), and on the analysis.
Grading mode
The grade has two parts. The autograder runs 433 checks, with warnings as errors, from grader/test_project.py: 433 for any seed from 0 to 49, and 441 for any other seed. Eight checks run on each distinct seed of the set, which holds the fixed seeds 0 to 49, your seed and your seed plus 7919: 51 seeds when your seed is one of 0 to 49, and 52 otherwise. The eight checks are: the legality of your quote on every turn, the replay against the fills of the log, the agreement of the replay with the engine's final cash and inventory, the P&L identity (defined under Conventions) exact in cents, integer money, the cash change on each turn, the seed and settlement of a log, and the instance. Twenty-four checks run on your seed only: the refusals and boundaries of the quote, the named refusals of the replay, the replay of hand-built logs (its sums, its stale totals, a log with no fill, a fill as one unit, a fill at price 0 and the mark at the settlement value), the fill rules of the engine (the size rule, the inventory limit and the informed-trader rule), and that neither quote nor replay prints or warns. One further check uses no seed of yours: it checks that the fixed seeds 0 to 49 give fifty different fair paths, so it is the same for every learner. The total is therefore 8 × 51 + 24 + 1 = 433 when your seed is one of 0 to 49, and 8 × 52 + 24 + 1 = 441 otherwise. The analysis is scored against the rubric, which has five criteria, each with four observable levels. This page does not collect analysis.md and names no reviewer: you score your analysis yourself with the form in the self-assessment section, calibrated on two annotated exemplars, and you keep the summary the form produces as self_assessment.md. The analysis meets the bar at level 3 or above on every criterion.

Conventions

  • The game. There are \(N = 20\) turns, indexed \(t = 1, \dots, 20\). The fair value starts at \(v_0 = 10000\) cents. Each turn it moves by \(+5\) or \(-5\) cents with probability \(1/2\) each, and the path \(v_0, \dots, v_{20}\) is hidden from the maker. These constants are the model's choices, not facts about any market.
  • The quote. Each turn the maker posts a bid \(b_t\) and an ask \(a_t\) in cents, with \(b_t < a_t\), and a size \(q_t\) in units, with \(0 \le q_t \le 5\). The quote sees the state listed under Required outputs. Its state holds no entry for \(v_t\).
  • The arrival. Each turn one arrival comes. With probability \(1/4\) it is an uninformed buy of one unit, with probability \(1/4\) an uninformed sell of one unit, and with probability \(1/2\) an informed trader. The arrival probabilities are assumptions of the model, not estimates.
  • Trades. An uninformed buy takes one unit from the maker at the ask, so the maker sells. An uninformed sell gives one unit to the maker at the bid, so the maker buys. An informed trader buys one unit at the ask when \(v_t \gt a_t\), sells one unit at the bid when \(v_t \lt b_t\), and otherwise does not trade. A trade fills only when \(q_t \ge 1\) and the inventory after the fill satisfies \(|I| \le 10\), where \(I\) is the inventory in units.
  • Cash and inventory. A maker purchase at the bid \(b\) changes cash by \(-b\) and inventory by \(+1\). A maker sale at the ask \(a\) changes cash by \(+a\) and inventory by \(-1\). Cash starts at zero.
  • The P&L. The settlement value is \(v_{20}\), and the inventory mark is \(I_{20} \times v_{20}\). The P&L of a log is \(\mathrm{pnl} = \mathrm{cash\ flow} + I_{20} \times v_{20}\), in cents, with the cash flow the sum of the fill cash flows. The identity is exact: the cash flow, the inventory and the settlement value are integers, so the product and the sum carry no rounding.

Named invalid inputs

The engine raises ValueError for the first two conditions, and your replay for the last two, each with the message named here.

  • A quote whose bid is not below its ask. The engine refuses it, and the message names “bid must be below ask”.
  • A quote whose size is not in 0 to 5. The engine refuses it, and the message names “size must lie in 0..5”.
  • A log given to replay with a turns list whose length is not 20. The message names “a log has exactly 20 turns”.
  • A turn marked filled with a fill_price_cents of None, given to replay. The message names “a filled turn needs a fill price”.

Any other invalid input may raise any exception or return a value. The autograder requires no exception type for those.

The analysis explains one game of your rule from its log. Its numbers are the ones your replay returns for your log. Lab 3 prints the four numbers of the reference rule on seed 0, so you can check your replay against them before you use it on your own log.

Lab 3 · The rung 3 check: the reference rule, its replay and one counterfactual

Stated before running. For the reference rule on seed 0, the replay gives the four numbers of Lab 1: a cash flow of \(-9950\) cents, an ending inventory of 1 unit, an inventory mark of 9980 cents and a P&L of \(30\) cents, with 9 fills. The counterfactual is the same seed and the same arrivals, with the half-spread widened from 10 cents to 15 cents. It has 9 fills too, and its P&L is 55 cents, which is 25 cents more. Your replay, run on the log of the reference rule for seed 0, must return the same four numbers.

"""PC3 project, rung 3 check: the reference game on seed 0, its replay, and one counterfactual on the same seed.

SIMULATED. The fair path and the arrivals come from random.Random(0), in the order of Lesson 4 and of the project's
instance generator. No data file is read and there is no network access. Standard library only. Money is an integer
number of cents, and every accounting value is an int.

The reference rule quotes around the last filled price, or around 10000 cents before any fill, for one unit. Its
half-spread is 10 cents. The counterfactual is the same game with a half-spread of 15 cents, one change of the rule that
the lab uses to show the rerun. The numbers below describe this one seed. They are not an estimate for any market.
"""

from __future__ import annotations

import random
from typing import Any

HORIZON = 20  # turns
START_CENTS = 10_000  # v_0, in cents
MOVE_CENTS = 5  # the fair value moves by +5 or -5 cents each turn
SIZE = 1  # units quoted on each side
LIMIT = 10  # inventory limit
REFERENCE_HALF_SPREAD = 10  # cents, the reference rule
COUNTERFACTUAL_HALF_SPREAD = 15  # cents, the counterfactual
SEED = 0


def draw_game(seed: int) -> tuple[list[int], list[str]]:
    """The fair path v_0 .. v_20 in cents and the 20 arrivals, drawn in the order of Lesson 4."""
    rng = random.Random(seed)
    path = [START_CENTS]
    arrivals: list[str] = []
    for _ in range(HORIZON):
        move = MOVE_CENTS if rng.random() < 0.5 else -MOVE_CENTS
        path.append(path[-1] + move)
        draw = rng.random()
        if draw < 0.25:
            arrivals.append("uninformed-buy")
        elif draw < 0.5:
            arrivals.append("uninformed-sell")
        else:
            arrivals.append("informed")
    return path, arrivals


def maker_side(arrival: str, fair: int, bid: int, ask: int) -> int:
    """+1 when the maker buys one unit at the bid, -1 when it sells one at the ask, 0 when there is no trade."""
    if arrival == "uninformed-buy":
        return -1
    if arrival == "uninformed-sell":
        return 1
    if fair > ask:
        return -1
    if fair < bid:
        return 1
    return 0


def play(seed: int, half_spread: int) -> dict[str, Any]:
    """Play the 20 turns; quote half_spread cents either side of the last filled price (10000 before any fill)."""
    path, arrivals = draw_game(seed)
    inventory = 0
    cash = 0
    last_fill: int | None = None
    turns: list[dict[str, Any]] = []
    for turn in range(1, HORIZON + 1):
        mid = START_CENTS if last_fill is None else last_fill
        bid, ask, size = mid - half_spread, mid + half_spread, SIZE
        arrival = arrivals[turn - 1]
        side = maker_side(arrival, path[turn], bid, ask)
        filled = side != 0 and size >= 1 and abs(inventory + side) <= LIMIT
        price: int | None = None
        if filled:
            price = ask if side < 0 else bid
            inventory += side
            cash += -side * price
            last_fill = price
        turns.append(
            {
                "turn": turn,
                "bid_cents": bid,
                "ask_cents": ask,
                "size": size,
                "arrival": arrival,
                "filled": filled,
                "fill_price_cents": price,
                "inventory_after": inventory,
                "cash_after_cents": cash,
            }
        )
    return {"seed": seed, "settlement_cents": path[HORIZON], "turns": turns}


def replay(log: dict[str, Any]) -> dict[str, int]:
    """Replay the fills of a log: the cash flow, the ending inventory, the mark at settlement and the P&L, in cents."""
    turns: list[dict[str, Any]] = log["turns"]
    if len(turns) != HORIZON:
        raise ValueError("a log has exactly 20 turns")
    fills: list[tuple[int, int]] = []
    for record in turns:
        if record["filled"] is True:
            if record["fill_price_cents"] is None:
                raise ValueError("a filled turn needs a fill price")
            price = int(record["fill_price_cents"])
            fills.append((1 if price == record["bid_cents"] else -1, price))
    inventory = sum(side for side, _ in fills)
    cash_flow = sum(-side * price for side, price in fills)
    mark = inventory * int(log["settlement_cents"])
    return {
        "cash_flow_cents": cash_flow,
        "inventory_end": inventory,
        "inventory_mark_cents": mark,
        "pnl_cents": cash_flow + mark,
    }


def main() -> None:
    print("Rung 3 check · seed 0 · SIMULATED · reference rule: 10 cents either side of the last fill, size 1")
    log = play(SEED, REFERENCE_HALF_SPREAD)
    result = replay(log)
    fills = sum(1 for record in log["turns"] if record["filled"])
    settlement = int(log["settlement_cents"])
    print(f"settlement v_{HORIZON} = {settlement} cents, fills = {fills} of {HORIZON} turns")
    print(f"cash_flow_cents = {result['cash_flow_cents']}")
    print(f"inventory_end = {result['inventory_end']}")
    print(f"inventory_mark_cents = {result['inventory_mark_cents']}")
    print(f"pnl_cents = {result['pnl_cents']}")
    identity = result["pnl_cents"] == result["cash_flow_cents"] + result["inventory_end"] * settlement
    print(f"identity P&L = cash flow + inventory x settlement holds: {identity}")
    last_cash = log["turns"][-1]["cash_after_cents"]
    print(f"cash flow equals the cash after the last turn: {result['cash_flow_cents'] == last_cash}")
    # The counterfactual: the same seed and arrivals, with the half-spread widened by 5 cents.
    wider = play(SEED, COUNTERFACTUAL_HALF_SPREAD)
    wider_result = replay(wider)
    wider_fills = sum(1 for record in wider["turns"] if record["filled"])
    print(f"counterfactual half-spread {COUNTERFACTUAL_HALF_SPREAD} cents: fills = {wider_fills} of {HORIZON} turns")
    print(f"counterfactual pnl_cents = {wider_result['pnl_cents']}")
    print(f"change in pnl_cents from the wider half-spread = {wider_result['pnl_cents'] - result['pnl_cents']} cents")


main()

Two exemplars

Two analyses of the reference rule on seed 0, at different levels. Each exemplar uses only the numbers that Lab 1 and Lab 3 print, sums of their fill prices, and the model's arrival probabilities from the conventions. Exemplar A

Official scoring: C1 4 · C2 4 · C3 4 · C4 3 · C5 4. Every criterion is met at level 4 except the assumptions, where the settlement rule is not named as a source of the result.

P&L decomposition

For the submitted log, replay returns a cash flow of \(-9950\) cents, an ending inventory of 1 unit, an inventory mark of 9980 cents and a P&L of 30 cents. The nine fills are at turns 2, 3, 4, 5, 7, 8, 13, 18 and 19 (the fill lines that Lab 1 prints). The purchases by the maker at the bid (turns 2, 3, 4, 8 and 19) cost 49910 cents in total, and the sales at the ask (turns 5, 7, 13 and 18) bring in 39960 cents, so the cash flow is \(39960 - 49910 = -9950\) cents. The inventory after turn 19 is 1 unit, and the mark is \(1 \times 9980 = 9980\) cents.

Evidence from the log

Turn 2 bought at the bid of 9990 cents, a fill at 9990. Turn 5 sold at the ask of 9980 cents, a fill at 9980 with inventory 2 after it. Turn 18 sold at the ask of 10000 cents, a fill at 10000 that leaves the inventory at 0.

Counterfactual

Lab 3 reruns seed 0 with the half-spread widened from 10 cents to 15 cents, and the arrivals are the same. The fills stay at 9, and the P&L rises from 30 cents to 55 cents, a change of \(+25\) cents on this seed. One seed is one sample, so this is a difference on the game of seed 0, not an estimate for other seeds.

Assumptions and limits

The arrival probabilities of 1/4, 1/4 and 1/2 set the thresholds that turn each draw into an arrival. Lab 1 does not vary them, so the printed run does not measure their effect on the fills or the P&L. The inventory limit of 10 units does not bind in this run, whose largest inventory is 3 units (Lab 1 prints it). The model leaves out the queue of resting orders and a trader who learns from the fills (both set aside in Lesson 4), latency, and more than one asset, so it does not describe a real market maker.

Self-review

The identity holds for the submitted log: \(30 = -9950 + 1 \times 9980\), and the identity line of Lab 1 prints True. The cash flow also equals the cash after the last turn, which Lab 1 checks on the same log.
