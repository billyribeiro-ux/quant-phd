This lesson treats a timed coding answer as more than running code. The answer must state what the code costs, why the structure it uses meets that cost, and which small cases it was checked on. The lesson sets out that procedure, counts the work of the simplest method for a sliding-window maximum (Definition 1.3 of this lesson) exactly, and proves that a monotonic deque (Definition 3.1 of this lesson) returns the same answers with at most twice the input length in comparisons. The lesson states what each count measures and does not claim how long any session allows.

1The procedure

Definition 1.1 (timed coding interview)

A timed coding interview is the following procedure, applied to one stated task. The answerer works through six steps in order and keeps a time budget for the whole item, set before the item starts and kept on the answerer's own clock.

  1. Restate the task, and fix the type of each input and of the output.
  2. State the edge cases: the empty input, the smallest and the largest value of each parameter, and any parameter larger than the input.
  3. State the complexity budget, the bound the answer must meet, in big-O notation of the input size \(n\) and of each parameter.
  4. Choose a structure whose operations meet the budget, and state the cost of each operation.
  5. Write the code.
  6. Check the code on small cases with unit tests, comparing it with a slow answer that is correct by inspection.
Remark 1.2 (what the lesson does not supply)

The page has no timer. A budget is a number the answerer sets and keeps, and this lesson does not fix its length. The lesson also makes no claim about how long any examination allows, which tasks it sets, or how answers are judged by any employer. Each of those is outside this lesson.

The rest of the lesson applies steps 2 to 6 to one task, the sliding-window maximum. Its statement is the next definition.

Definition 1.3 (sliding-window maximum)

Let \(x_1,\dots,x_n\) be real numbers, with \(n\ge 1\), and let \(k\) be an integer with \(1\le k\le n\). The sliding-window maximum is the sequence \(y_i=\max\{x_{i-k+1},\dots,x_i\}\) for \(i=k,\dots,n\). It has \(n-k+1\) entries. Its outputs are the window maxima. The code of Lab 1 indexes from 0, while the proofs index from 1.

2The naive scan and its exact cost

The naive method finds each window's maximum by scanning the window. It sets the baseline that the complexity budget of step 3 must beat. Its exact count is a theorem, and the lab prints the count beside the measured value.

Proposition 2.1 (comparisons of the naive scan)

Hypotheses: (H1) \(x_1,\dots,x_n\) are real numbers, \(n\ge 1\); (H2) \(1\le k\le n\); (H3) for each window the scan takes the first value of the window as the running maximum and compares each of the other \(k-1\) values with it, one comparison each. Conclusion: the scan makes exactly \((n-k+1)(k-1)\) comparisons in total.

Proof

By H2 there are \(n-k+1\) windows, one for each \(i=k,\dots,n\), and each window is nonempty. By H3 each window contributes \(k-1\) comparisons, and no comparison is shared between windows, since each comparison is made inside one window. The total is \((n-k+1)(k-1)\). \(\square\)

Remark 2.2 (the cost peaks at the middle window size)

Write \(r=k-1\), so the count is \((n-r)r\). Then \((n-r)r=\tfrac{n^{2}}{4}-\bigl(r-\tfrac n2\bigr)^{2}\), which is at most \(n^{2}/4\), with equality when \(r=n/2\). For even \(n\), the count is largest at \(k=n/2+1\). The expansion checks by multiplying out the right side: \(\tfrac{n^{2}}{4}-r^{2}+nr-\tfrac{n^{2}}{4}=nr-r^{2}\).

3A monotonic deque

The deque method keeps, for the current window, only the indices that can still be a window maximum. Step 4 of Definition 1.1 chooses a structure. The rest of this section proves that the deque meets a total budget, and Remark 3.6 compares it with a hash map and a binary heap.

Definition 3.1 (the deque and its invariant)

Call an index \(j\) surviving at step \(i\) when \(i-k<j\le i\) and \(x_j>x_m\) for every \(m\) with \(j<m\le i\). The deque is a monotonic deque, a double-ended queue of indices. After step \(i\) it holds exactly the surviving indices of step \(i\), kept in increasing order of index from front to back. The front is the smallest index and the back is the largest.

The method processes \(i=1,\dots,n\) in order. Its steps are as follows.

Pseudocode, not run; the runnable version is Lab 1

for i = 1 to n:
    while the deque is not empty and x[back] is at most x[i]:
        remove the back of the deque
    append i to the back of the deque
    if the front of the deque is at most i - k:
        remove the front of the deque
    if i is at least k:
        output x[front]
Proposition 3.2 (correctness of the deque)

Hypotheses: (H1) \(x_1,\dots,x_n\) are real numbers, so any two of them are comparable; (H2) \(1\le k\le n\); (H3) the method of Definition 3.1 and the pseudocode above run for \(i=1,\dots,n\). Conclusion: at each step \(i\ge k\) the output is \(\max\{x_{i-k+1},\dots,x_i\}\), and after each step the deque holds exactly the surviving indices of Definition 3.1.

Proof

Step A: the invariant holds after each step. Before step 1 the deque is empty, and the invariant holds vacuously. Assume it holds after step \(i-1\). Then the deque is decreasing in value from front to back: if \(j<j'\) are both in the deque, then \(x_j>x_{j'}\), because \(j\) survives step \(i-1\) with \(m=j'\). Hence the entries whose value is at most \(x_i\) form a block at the back. The while loop removes exactly this block, since it stops at the first back entry whose value exceeds \(x_i\). Afterwards the deque holds the surviving indices of step \(i-1\) whose values exceed \(x_i\), and then the index \(i\) is appended. Each remaining index \(j\) satisfies \(x_j>x_m\) for all \(m\) with \(j<m\le i\). Indices that the loop removed fail this condition for \(m=i\), so they are rightly absent. Conversely, an index \(j<i\) that survives step \(i\) also survives step \(i-1\), because the condition for \(i-1\) is weaker. So the deque after the append is exactly the set of indices \(j\le i\) that satisfy the condition with \(m\le i\). The expiry step then removes the front when it equals \(i-k\), which is the only index that leaves the window \(\{i-k+1,\dots,i\}\) at this step. Indices increase from front to back, so if index \(i-k\) is in the deque it is the front, and one removal suffices.

Step B: the front is the window maximum. Let \(f\) be the front after step \(i\geq k\). It is in the window, and \(x_f>x_m\) for every \(m\) with \(f<m\le i\). Take any \(p\) in the window. If \(p\ge f\), then either \(p=f\) or \(f<p\le i\), and \(x_f\ge x_p\) holds in both cases. If \(p<f\), let \(M\) be the largest value among \(x_p,\dots,x_i\), and let \(q\) be the largest index in \(\{p,\dots,i\}\) with \(x_q=M\). Then \(x_q>x_m\) for every \(m\) with \(q<m\le i\), so \(q\) survives step \(i\). Since \(f\) is the smallest surviving index, \(f\le q\), and the decreasing order of the deque gives \(x_f\ge x_q=M\ge x_p\). Hence \(x_f\) is the maximum of the window.

Step C. For \(i\ge k\) the window \(\{i-k+1,\dots,i\}\) is complete, and the output \(x_f\) is its maximum by Step B. \(\square\)

Proposition 3.3 (total work of the deque)

Hypotheses: (H1)–(H3) of Proposition 3.2. Conclusion: each index is appended exactly once, so there are \(n\) appends; each index is removed at most once, so there are at most \(n\) removals; and the number of comparisons made by the while-loop tests is at most \(2n\).

Proof

Step \(i\) appends \(i\) once, and no index is appended twice, which gives \(n\) appends. An index leaves the deque at most once, because it is removed from the back or the front and never returns, so the removals are at most \(n\). A while-loop test is either followed by a back removal or is the one failed test that ends the loop, and each step has at most one failed test. So the tests number at most the back removals plus \(n\). The back removals are at most \(n\), so the tests number at most \(2n\). The front-expiry test is an if-test outside the while loop; it runs at most once per step and is not counted in Proposition 3.3. \(\square\)

Remark 3.4 (a single step can be expensive)

One step can remove up to \(k\) entries. Take \(x=(k,k-1,\dots,1,\,k+1)\), with \(n=k+1\) and \(k\ge 1\). After step \(k\) the deque holds indices \(1,\dots,k\) in decreasing value. At step \(k+1\) the value \(k+1\) at index \(k+1\) exceeds all of them, so that step removes all \(k\) of them in one loop. The bound is \(k\): before step \(i\) the deque holds only indices in \(\{i-k,\dots,i-1\}\), which are \(k\) indices, and every removal at step \(i\) removes one of them. So the cost of one step is not bounded by a constant. Proposition 3.3 bounds the total, and it is the total that the budget of step 3 uses.

Example 3.5 (a trace with window 3)

Let \(x=(3,1,4,1,5)\) and \(k=3\). After step 1 the deque is \((1)\). At step 2 the value 1 does not remove the index 1, so the deque is \((1,2)\). At step 3 the value 4 removes indices 2 and 1, the deque becomes \((3)\), and the output is \(x_3=4\). At step 4 the deque is \((3,4)\), and the output is \(x_3=4\), because index 3 is still in the window \(\{2,3,4\}\). At step 5 the value 5 removes indices 4 and 3, so the deque is \((5)\), and the output is \(x_5=5\). The outputs are \((4,4,5)\).

Remark 3.6 (a hash map and a binary heap in Step 4)

A hash map finds a value by its key, but it keeps no order on its values, so a lookup by key does not report the window maximum. This remark does not consider any other use of a hash map.

A binary heap of the window's indices, keyed by value, has its maximum at the root. Its costs are counted in comparisons of stored values. A push sifts up a heap of \(m\) entries, which makes at most \(\lfloor\log_2 m\rfloor\) comparisons, because the deepest position of a heap of \(m\) entries has depth \(\lfloor\log_2 m\rfloor\). A pop sifts down, which makes at most two comparisons on each level it descends, so at most \(2\lfloor\log_2 m\rfloor\). If the heap holds at most \(n\) entries and makes \(n\) pushes and at most \(n\) pops, its total is at most \(3n\lfloor\log_2 n\rfloor\) comparisons, the pushes contributing at most \(n\lfloor\log_2 n\rfloor\) and the pops at most \(2n\lfloor\log_2 n\rfloor\). For \(n=200\) this bound is \(3\cdot 200\cdot 7=4200\), against the bound \(2n=400\) of Proposition 3.3 for the deque. The heap's bound is of order \(n\log n\), so this count does not show that the heap meets a budget of order \(n\). The remark counts the heap's comparisons only and does not prove that a heap of indices reports the window maximum.

Lab 1 · Both methods on one seeded sequence, with operation counts

Before running: the sequence is 200 integers from 0 to 999 drawn from random.Random(5), a generated input and not data. At window size 8 the two methods give equal outputs, the naive count is 1351, which equals \((n-k+1)(k-1)\) of Proposition 2.1, and the deque makes at most \(2n=400\) comparisons, with 200 pushes (appends). Part 1 also runs both methods on the seed-6 sequence at window size 8 and prints its counts. Part 2 expects equal outputs for every window size from 1 to 20 and True for each of the five edge-case checks. Part 3 prints the counts at five window sizes. Standard library only, no network access and no timing.

"""PC3 lab L05: sliding-window maximum by a monotonic deque and by a naive scan, on one seeded sequence.

SEEDED. The sequence is 200 integers in 0 to 999 drawn from random.Random(5). It is a generated test input, not data.
No data file is read and there is no network access. Standard library only.

Every count below is an operation count: comparisons of stored values, and pushes and pops on the deque. No count is a
wall-clock time, and none is a claim about how long an interview allows.

Part 1 runs both methods at window size 8 and prints the operation counts. The naive scan makes k - 1 comparisons per
window, so its count is (n - k + 1)(k - 1), which the lab prints beside the measured count. It then runs both methods
on the seed-6 sequence of the same length at the same window and prints that sequence's counts.

Part 2 compares the two outputs for every window size from 1 to 20, and checks the edge cases: window size 1, a window
equal to the length, a window longer than the sequence, and an empty sequence. A match is a check on this sequence only.
"""

from __future__ import annotations

import random
from collections import deque
from collections.abc import Sequence
from dataclasses import dataclass

SEED = 5
LENGTH = 200
WINDOW = 8
LOW = 0
HIGH = 999


@dataclass
class Ops:
    """Operation counts for one run: comparisons of stored values, and deque pushes and pops."""

    comparisons: int = 0
    pushes: int = 0
    pops: int = 0


def make_sequence(seed: int, length: int) -> list[int]:
    """Integers in LOW..HIGH drawn from random.Random(seed), in order."""
    rng = random.Random(seed)
    return [rng.randint(LOW, HIGH) for _ in range(length)]


def naive_maxima(xs: Sequence[int], k: int) -> tuple[list[int], int]:
    """The maximum of each window of k consecutive values, found by scanning the window. Returns the maxima and the
    number of comparisons, which is k - 1 for each of the n - k + 1 windows."""
    maxima: list[int] = []
    comparisons = 0
    for start in range(len(xs) - k + 1):
        best = xs[start]
        for x in xs[start + 1 : start + k]:
            comparisons += 1
            if x > best:
                best = x
        maxima.append(best)
    return maxima, comparisons


def deque_maxima(xs: Sequence[int], k: int) -> tuple[list[int], Ops]:
    """The maximum of each window of k values, using a deque of indices whose values decrease from front to back.

    The front index is the index of the current window's maximum. Each index is pushed once and popped at most once.
    """
    window: deque[int] = deque()
    maxima: list[int] = []
    ops = Ops()
    for i, x in enumerate(xs):
        while window:
            ops.comparisons += 1
            if xs[window[-1]] > x:
                break
            window.pop()
            ops.pops += 1
        window.append(i)
        ops.pushes += 1
        if window[0] <= i - k:
            window.popleft()
            ops.pops += 1
        if i >= k - 1:
            maxima.append(xs[window[0]])
    return maxima, ops


def part_one() -> None:
    print(f"Part 1 · seeded sequence, seed {SEED}, length {LENGTH}, window {WINDOW}, values {LOW} to {HIGH}")
    xs = make_sequence(SEED, LENGTH)
    print(f"first five values: {xs[:5]}")
    naive, naive_count = naive_maxima(xs, WINDOW)
    fast, ops = deque_maxima(xs, WINDOW)
    windows = LENGTH - WINDOW + 1
    print(f"windows = {windows}")
    print(f"first five maxima by deque: {fast[:5]}")
    print(f"outputs equal: {naive == fast}")
    print(f"naive comparisons = {naive_count}, formula (n - k + 1)(k - 1) = {windows * (WINDOW - 1)}")
    print(f"deque comparisons = {ops.comparisons}, pushes = {ops.pushes}, pops = {ops.pops}")
    print(f"deque comparisons at most 2n = {2 * LENGTH}: {ops.comparisons <= 2 * LENGTH}")
    print(f"each index pushed once: {ops.pushes == LENGTH}")
    seed_six = make_sequence(6, LENGTH)
    naive_six, naive_six_count = naive_maxima(seed_six, WINDOW)
    fast_six, ops_six = deque_maxima(seed_six, WINDOW)
    print(f"seed 6 at window {WINDOW}: outputs equal: {naive_six == fast_six}")
    print(
        f"seed 6: naive comparisons = {naive_six_count}, deque comparisons = {ops_six.comparisons}, "
        f"pushes = {ops_six.pushes}, pops = {ops_six.pops}"
    )


def part_two() -> None:
    print("Part 2 · every window size from 1 to 20, and edge cases, on the same sequence")
    xs = make_sequence(SEED, LENGTH)
    agree = all(naive_maxima(xs, k)[0] == deque_maxima(xs, k)[0] for k in range(1, 21))
    print(f"outputs equal for window sizes 1 to 20: {agree}")
    print(f"window 1 returns the sequence itself: {deque_maxima(xs, 1)[0] == xs}")
    whole, _ = deque_maxima(xs, LENGTH)
    print(f"window equal to the length gives one maximum, equal to max(xs) = {max(xs)}: {whole == [max(xs)]}")
    print(f"window longer than the sequence gives no maxima: {deque_maxima(xs, LENGTH + 1)[0] == []}")
    print(f"empty sequence, window 3, gives no maxima: {deque_maxima([], 3)[0] == []}")
    print(f"naive scan on the empty sequence gives no maxima: {naive_maxima([], 3)[0] == []}")


def part_three() -> None:
    print("Part 3 · operation counts by window size, same sequence")
    xs = make_sequence(SEED, LENGTH)
    print("  k  windows  naive  (n-k+1)(k-1)  deque_comparisons  pops  pushes")
    for k in (1, 2, 8, 32, 200):
        _, naive_count = naive_maxima(xs, k)
        _, ops = deque_maxima(xs, k)
        windows = LENGTH - k + 1
        print(
            f"{k:>3}  {windows:>7}  {naive_count:>5}  {windows * (k - 1):>12}  "
            f"{ops.comparisons:>17}  {ops.pops:>4}  {ops.pushes:>6}"
        )


def main() -> None:
    part_one()
    part_two()
    part_three()

4Where the canon breaks

An operation count is not a run time. The comparisons of Proposition 2.1 and Proposition 3.3 are the work a model counts. Run time depends on the language, the interpreter, the memory access pattern and the machine, none of which this lesson fixes.

Proposition 3.3 counts comparisons, appends and removals, and it assigns no time to any of them. An implementation whose removal at the front costs more than one unit of time, such as a plain list that shifts its elements, makes the same comparisons, but its run time is not bounded by Proposition 3.3 unless that cost is stated.

The total bound is an amortised bound, that is, an average over the run: the average cost per step over the run is at most two comparisons, although a single step can cost of order \(k\), as Remark 3.4 shows. A budget written as a per-step bound of one operation would be false for this method, and a budget written as a total over the run is the one the method meets.

The proof of Proposition 3.2 uses the fact that values are comparable. With values that have no order, or with missing values, Proposition 3.2 does not apply. The lab's convention that a window longer than the sequence gives no output is a choice, and another convention would change the edge case without changing the method.

5Misconceptions

  1. “The deque costs of order \(k\) per step, so the whole scan costs of order \(nk\).”

    A single step can cost of order \(k\), as Remark 3.4 shows. The total is at most \(2n\) comparisons by Proposition 3.3, which is of order \(n\). Lab 1 prints 354 comparisons for \(n=200\) and window 8, within the bound of 400.

  2. “The operation counts in Lab 1 are the run times of the two methods.”

    The lab counts comparisons, pushes and pops. It does not time anything. Run time depends on the implementation and the machine, and Section 4 names what the counts leave out.

  3. “Matching outputs on a few inputs prove that the method is correct.”

    Lab 1, Part 2 matches the outputs for every window size from 1 to 20 on one sequence. That is evidence for that sequence. Proposition 3.2 is the proof for every sequence of real numbers, and the lab's check is not a substitute for it.

6Problem set

Each problem has a full worked solution. Attempt each one before opening it. Empirical problems use the seeded sequences of Lab 1, which are generated inputs and not data.

Mechanics

M1 · The naive count for a short sequence

Find the number of comparisons made by the naive scan for \(n=10\) and \(k=4\).

Solution

By Proposition 2.1, the count is \((n-k+1)(k-1)=(10-4+1)(4-1)=7\cdot 3=21\) comparisons, over 7 windows of 3 comparisons each.

M2 · Trace the deque with window 2

Run the deque method on \(x=(2,5,1,0,3)\) with \(k=2\), recording the deque after each step and the outputs.

Solution

Step 1: the deque is \((1)\). Step 2: the value 5 removes index 1, the deque is \((2)\), and the output is \(x_2=5\). Step 3: the value 1 does not remove index 2, the deque is \((2,3)\), and index 2 is still in the window \(\{2,3\}\), so the output is \(x_2=5\). Step 4: the value 0 gives \((2,3,4)\). The front index 2 is at most \(i-k=2\), so it is removed, the deque is \((3,4)\), and the output is \(x_3=1\). Step 5: the value 3 removes indices 4 and 3, the deque is \((5)\), and the output is \(x_5=3\). The outputs are \((5,5,1,3)\).

M3 · The two extreme window sizes

For an input of length \(n\), state the outputs of the deque method when \(k=1\) and when \(k=n\).

Solution

For \(k=1\), there are \(n\) windows, each a single value, so the output is the input itself. At step \(i\), the deque holds at most the indices \(i-1\) and \(i\) before expiry, and the expiry rule removes \(i-1\) if it is there, so the deque holds only \(i\) and the output is \(x_i\). For \(k=n\), there is one window, \(\{1,\dots,n\}\), and by Proposition 3.2 with \(i=n\) the output is \(\max\{x_1,\dots,x_n\}\). The output list has one entry.

Proof

P1 · The peak of the naive count

Prove that \((n-r)r\le n^{2}/4\) for every real \(r\), and find the integer \(k\) that maximises \((n-k+1)(k-1)\) when \(n\) is even.

Solution

Expanding \((n/2-r)^{2}\geq 0\) gives \(r^{2}-nr+n^{2}/4\geq 0\), so \(nr-r^{2}\le n^{2}/4\). The left side is \((n-r)r\). Equality holds when \(r=n/2\). For even \(n\), \(r=n/2\) is an integer, so \(k=r+1=n/2+1\) gives the largest count, \(n^{2}/4\). For example, \(n=200\) gives \(k=101\) and a count of \(100\cdot 100=10000\).

P2 · The maximum survives in the deque

In Step B of Proposition 3.2, show that the largest index \(q\) in \(\{p,\dots,i\}\) whose value equals the maximum \(M\) of \(x_p,\dots,x_i\) survives step \(i\).

Solution

For any \(m\) with \(q<m\le i\), the index \(m\) is in \(\{p,\dots,i\}\), and by the choice of \(q\) as the largest index with value \(M\), \(x_m\neq M\). Since \(M\) is the maximum, \(x_m<M=x_q\). So \(x_q>x_m\) for every \(m\) with \(q<m\le i\), which is the survival condition of Definition 3.1 for \(q\) at step \(i\). Also \(q\ge p\) is in the window, since \(p\) is in the window and \(q\ge p\).

P3 · An increasing sequence costs n minus 1

Let \(x_1<x_2<\dots<x_n\) with \(1\le k\le n\). Count the comparisons made by the while-loop tests, and show that the count is exactly \(n-1\) for every such \(k\).

Solution

At step 1 the deque is empty, so no test is made, and the deque after step 1 is \((1)\). Suppose that at the start of step \(i\ge 2\) the deque is \((i-1)\). The loop makes one test, whether the back value \(x_{i-1}\) is at most \(x_i\). It is, because \(x_{i-1}<x_i\), so the back index \(i-1\) is removed. The deque is now empty, and the loop ends without a second test. Index \(i\) is appended, and the expiry removes nothing, because the front \(i\) is not at most \(i-k\). So the deque after step \(i\) is \((i)\), which is the supposition for step \(i+1\). Each step \(i\ge 2\) makes exactly one test and step 1 makes none, which gives \(n-1\). The expiry removals involve no comparison of values.

Empirical

E1 · The counts at window 32, seeded

Lab 1, Part 3 prints 5239 naive comparisons and 382 deque comparisons for window 32 on seed 5 with \(n=200\). Check the naive count by formula, and compute the ratio of the naive count to the deque count to one decimal place.

Solution

Proposition 2.1 gives \((200-32+1)(32-1)=169\cdot 31=5239\), which matches the printed count. The ratio is \(5239/382\approx 13.7\). The deque count of 382 is within the bound \(2n=400\) of Proposition 3.3. The ratio is a property of this sequence and this window, not a general constant.

E2 · A different seed, window 8

Run both methods with window 8 on 200 values from random.Random(6), drawn with the same generator as Lab 1 and in the same range. Report whether the outputs agree, and the two comparison counts.

Solution

Running the lab's two functions on the seed-6 sequence gives equal outputs, and the naive count is \((200-8+1)(8-1)=193\cdot 7=1351\), which is the same formula as for seed 5 because the count depends only on \(n\) and \(k\). On this sequence the deque makes 350 comparisons, with 200 pushes (appends) and 197 pops (removals). These are the seed-6 counts that Lab 1, Part 1 prints. The count is within the bound \(2n=400\) of Proposition 3.3.

E3 · The largest deque count in Lab 1

Of the five rows that Lab 1, Part 3 prints, the deque count is largest at window 200, with 387 comparisons. Compare it with the bound of Proposition 3.3 and with the pushes and pops the lab prints for that row.

Solution

The bound is \(2n=400\), and \(387\le 400\). The row prints 200 pushes, which equals \(n\), and 194 pops. The proof of Proposition 3.3 splits the comparisons into those followed by a removal, at most the 194 pops, and the step-ending tests, at most \(n=200\). So the comparisons are at most \(194+200=394\), and 387 is within that split bound.

Research

R1 · A timing protocol that could decide the question

Criterion: state a protocol that could decide, for a given machine and implementation, whether the deque is faster than the naive scan at window size \(k\). List the choices the protocol must fix, and state the result that would decide it.

Solution

The protocol fixes the language and version, the implementation of each method, the machine, the input family and its length \(n\), and the window sizes. It repeats each run a stated number of times, reports a summary of the repeats, and keeps the timer outside the algorithm. The decisive result would be a window size \(k^{*}\) above which the deque's measured time is smaller for every stated input family. The lesson does not run this protocol, so it establishes no timing result. The counts of Lab 1 are measurements of the model. The lesson proves the operation counts of Proposition 2.1, the bound of Remark 2.2 and the bounds of Proposition 3.3, and it proves no timing result.

R2 · A window size that maximises the naive work

Criterion: for \(n=200\), find the window size \(k\) that maximises the naive comparisons, and state the count.

Solution

By Remark 2.2 the count is maximised at \(k-1=n/2=100\), so \(k=101\). The count is \((200-101+1)(101-1)=100\cdot 100=10000\), which equals \(n^{2}/4\). The count is not the same as a time, so this answer is about the model's count only.

R3 · An input that makes every step expensive

Criterion: find an input of length \(n\) and a window size \(k\ge 2\) such that every step \(i\ge k\) removes at least one index from the back. Decide whether that per-step cost forces the total work to be of the order of \(nk\).

Solution

A strictly decreasing sequence removes nothing from the back, since each new value is smaller than the back. Take instead a strictly increasing sequence. At each step \(i\ge 2\) the back value is smaller than \(x_i\), so one back removal occurs, and every step \(i\ge k\) qualifies. By Problem P3 the total is \(n-1\) comparisons for any \(k\). So the per-step removal does not force a total of the order of \(nk\).
