Constrained allocator

You write constrained_allocator.py, which allocates weights across three to five assets under a budget, a bound on each weight, a cap on the total weight in each sector and a turnover limit (a bound on how far the weights may move from the starting portfolio in one period), and returns with each answer its Lagrange multipliers, defined in the Conventions of the specification below, and a certificate that checks its optimality conditions to the stated tolerance. The autograder checks the answer on a SIMULATED problem generated from your workspace seed: a generated case, not market data. The problem is a convex quadratic program, and the certificate is the set of Karush-Kuhn-Tucker (KKT) conditions that the answer must satisfy. There are four: stationarity (the gradient, plus each multiplier times the gradient of its constraint, is zero), primal feasibility (the constraints hold), dual feasibility (the inequality multipliers are non-negative) and complementary slackness (a multiplier is zero unless its constraint holds with equality).

Rungs 1 and 2

Lab 1 · Worked example: a long-only allocation, solved and certified

The problem has three assets, the objective (gamma / 2) w' Sigma w minus mu' w with gamma, the risk aversion, equal to 2, the budget that the weights sum to one, and a long-only bound on each weight. The expected returns are 5.0%, 3.0% and minus 2.0% for the three assets, and the third asset has the lowest. Before running the code, predict which weight the bound should hold at zero. The unconstrained answer should put a negative weight on the third asset, which has the lowest expected return, so the bound on the third weight should bind at the answer. The code prints the budget-only weights in step 1 and the assets held at zero in step 2, so the prediction can be read against them; then it solves the constrained problem exactly, prints the KKT checks in steps 4 to 6, and reports the objective. The data are SIMULATED.

"""Rung 1 worked example: a three-asset allocation with long-only bounds, solved in exact arithmetic step by step.

SIMULATED three-asset problem, not market data. The objective is (gamma / 2) w' Sigma w - mu' w with gamma = 2, so the
quadratic term is w' Sigma w. The constraints are that the weights sum to one and that each weight is at least
zero. The code imposes no upper limit on a weight; the largest weight at the answer is below one, and step 5 prints it.
Every input is an exact decimal read as a Fraction, so the printed values are exact, except the approximation in step 7.
"""

from fractions import Fraction

# SIMULATED three-asset problem, not market data.
GAMMA = Fraction(2)
SIGMA = [
    [Fraction(4, 100), Fraction(1, 100), Fraction(0)],
    [Fraction(1, 100), Fraction(9, 100), Fraction(2, 100)],
    [Fraction(0), Fraction(2, 100), Fraction(16, 100)],
]
MU = [Fraction(5, 100), Fraction(3, 100), Fraction(-2, 100)]
N = 3


def solve(matrix: list[list[Fraction]], rhs: list[Fraction]) -> list[Fraction]:
    """Solve a square linear system by Gauss-Jordan elimination in exact arithmetic."""
    size = len(rhs)
    rows = [[*matrix[i], rhs[i]] for i in range(size)]
    for col in range(size):
        pivot = next(r for r in range(col, size) if rows[r][col] != 0)
        rows[col], rows[pivot] = rows[pivot], rows[col]
        for r in range(size):
            if r != col and rows[r][col] != 0:
                factor = rows[r][col] / rows[col][col]
                rows[r] = [x - factor * y for x, y in zip(rows[r], rows[col], strict=True)]
    return [rows[i][size] / rows[i][i] for i in range(size)]


def kkt_solution(held_at_zero: list[int]) -> tuple[list[Fraction], Fraction, list[Fraction]]:
    """The weights, the budget multiplier and the lower-bound multipliers, with the listed assets held at zero.

    The unknowns are the N weights, the budget multiplier, and one multiplier per held asset. The equations are the
    stationarity of each weight, the budget, and each held weight equal to zero: as many equations as unknowns.
    """
    size = N + 1 + len(held_at_zero)
    matrix = [[Fraction(0)] * size for _ in range(size)]
    rhs = [Fraction(0)] * size
    for i in range(N):
        for j in range(N):
            matrix[i][j] = GAMMA * SIGMA[i][j]
        matrix[i][N] = Fraction(1)
        for c, j in enumerate(held_at_zero):
            if i == j:
                matrix[i][N + 1 + c] = Fraction(-1)
        rhs[i] = MU[i]
    for j in range(N):
        matrix[N][j] = Fraction(1)
    rhs[N] = Fraction(1)
    for c, j in enumerate(held_at_zero):
        matrix[N + 1 + c][j] = Fraction(1)
    solution = solve(matrix, rhs)
    return solution[:N], solution[N], solution[N + 1 :]


def main() -> None:
    # Step 1. Budget only. Why: without the bounds, the answer shows which bound the optimum would break.
    free, _, _ = kkt_solution([])
    print("step 1 budget-only weights:", [str(w) for w in free])

    # Step 2. Active set. Why: a lower bound is active when the budget-only weight below it is negative.
    held = [i for i in range(N) if free[i] < 0]
    print("step 2 assets held at zero:", held)

    # Step 3. Constrained solution. Why: with the held assets at zero, the remaining equations are linear.
    w, nu, lam = kkt_solution(held)
    print("step 3 weights:", [str(x) for x in w])
    print("step 3 budget multiplier nu:", str(nu))
    print("step 3 lower-bound multipliers of the held assets:", [str(x) for x in lam])

    # Step 4. Stationarity. Why: at the optimum, the gradient plus the multipliers is zero in every weight.
    residual = [GAMMA * sum(SIGMA[i][j] * w[j] for j in range(N)) - MU[i] + nu for i in range(N)]
    for c, j in enumerate(held):
        residual[j] -= lam[c]
    print("step 4 stationarity residuals:", [str(r) for r in residual])

    # Step 5. Primal feasibility. Why: the weights must sum to one; the smallest and largest weight are printed.
    print("step 5 budget gap:", str(sum(w) - 1))
    print("step 5 smallest weight:", str(min(w)), "largest weight:", str(max(w)))

    # Step 6. Dual feasibility and complementary slackness. Why: a bound multiplier is non-negative, and it is zero
    # unless its weight sits on the bound.
    signs = [x >= 0 for x in lam]
    dual_feasible = all(signs)
    print("step 6 lower-bound multipliers non-negative:", dual_feasible)
    print("step 6 weight times multiplier, held assets:", [str(w[j] * lam[c]) for c, j in enumerate(held)])

    # Step 7. Objective at the solution. Why: this is the minimized value of the objective at the answer.
    quadratic = sum(SIGMA[i][j] * w[i] * w[j] for i in range(N) for j in range(N))
    objective = GAMMA / 2 * quadratic - sum(MU[i] * w[i] for i in range(N))
    print("step 7 objective (exact):", str(objective), "approximately", f"{float(objective):.6f}")

Rung 3 · Specification

Context
A SIMULATED fund allocates its capital across three to five assets each period. The manager sets an expected return for each asset, a symmetric positive definite matrix Sigma of risk for the assets, a risk-aversion parameter, a starting portfolio, a bound on each weight, a cap on the total weight in each of two sectors, and a limit on how far the portfolio may move from the starting portfolio in one period. The allocator returns the weights that minimize the risk-adjusted cost under those limits, and a certificate that checks the four KKT conditions for the answer to the stated tolerance. This module takes the covariance matrix Sigma as an input and does not estimate it; estimation is outside this module.
Inputs
Write n for the number of assets, which is three, four or five depending on the seed, and Z for the number of sectors, which is two on every seed. One case: a mapping that grader/instance.py returns as JSON under the payload key of make_instance(seed). The grader decodes the payload and passes the mapping to your function, so your code never calls make_instance. The mapping has these fields. gamma: a positive number, the risk aversion. mu: a list of n expected returns for one period. sigma: an n by n symmetric, positive definite matrix. w0: the starting weights, one per asset. lower and upper: the bounds on each weight, one per asset. sector: one integer label per asset, from 0 to Z minus 1, where Z, the number of sectors, is the length of sector_caps. sector_caps: the cap of each sector, a list of Z numbers. turnover_limit: a non-negative number, the limit on the total change from the starting portfolio. The field label says the case is SIMULATED. The weights, returns and limits are numbers for one stated period, with no annualization. No currency amount appears on this page.
Required outputs

A file constrained_allocator.py at the root of your repository, with one function allocate(instance) whose parameter is the decoded case. It returns a dictionary with the three keys weights, multipliers and certificate, and no other keys.

weights is a list of n numbers, the optimal w. multipliers is a dictionary with the seven keys budget, lower, upper, sector, turnover_plus, turnover_minus and turnover_total. budget is a number. lower, upper, turnover_plus and turnover_minus are lists of n numbers, and sector is a list of Z numbers, one per sector cap. turnover_total is a number. certificate is a dictionary with the four keys primal_residual, stationarity_residual, dual_residual and complementary_slackness, each a number that must agree, to 10-9, with the value the suite recomputes from your weights and multipliers by the definitions below.

The starter file is the starter. Its allocate raises NotImplementedError until you replace it, and the suite fails on the starter.

Conventions

Write \(\gamma\) for the risk aversion, \(\mu\) for the expected returns, \(\Sigma\) for the input matrix, \(w_0\) for the starting weights, \(l\) and \(u\) for the bounds, \(c_k\) for the cap of sector \(k\), and \(\tau\) for the turnover limit. The sectors partition the assets: asset \(i\) belongs to sector \(k(i)\), and \(S_k\) is the set of assets in sector \(k\). Write \(d_i = w_i - w_{0,i}\) and \(t_i = |d_i|\).

The problem is to minimize \[ f(w) = \tfrac{\gamma}{2}\, w^{\top}\Sigma w - \mu^{\top} w \] subject to \(\sum_i w_i = 1\), \(l \le w \le u\), \(\sum_{i\in S_k} w_i \le c_k\) for each sector \(k\), and \(\sum_i |w_i - w_{0,i}| \le \tau\).

The turnover constraint is convex but not linear, so the page uses the linearized form. A point \(w\) satisfies \(\sum_i |d_i| \le \tau\) if and only if some \(t\) satisfies \(t_i \ge d_i\), \(t_i \ge -d_i\) and \(\sum_i t_i \le \tau\). For the direction that matters: if \(\sum_i |d_i| \le \tau\), then \(t_i = |d_i|\) satisfies all three. For the converse, \(\sum_i |d_i| \le \sum_i t_i \le \tau\). The variables are \((w, t)\), and every constraint is affine in them.

The multipliers are those of the Lagrangian (defined in Lesson 3) of this linear form, the objective plus each multiplier times its constraint. The budget multiplier is \(\nu\). The lower and upper bound multipliers are \(\lambda^l_i\) and \(\lambda^u_i\). The sector multiplier is \(\eta_k\). The two turnover multipliers are \(\alpha_i\), attached to \(t_i \ge d_i\), and \(\beta_i\), attached to \(t_i \ge -d_i\). The total turnover multiplier is \(\kappa\), attached to \(\sum_i t_i \le \tau\). Each inequality is written as a constraint \(g_j \le 0\): \(l_i - w_i\), \(w_i - u_i\), \(\sum_{i\in S_k} w_i - c_k\), \(d_i - t_i\), \(-d_i - t_i\) and \(\sum_i t_i - \tau\).

At \(t_i = |d_i|\) the residuals are these. The stationarity residual in the weights is \[ r^w_i = \gamma (\Sigma w)_i - \mu_i + \nu - \lambda^l_i + \lambda^u_i + \eta_{k(i)} + \alpha_i - \beta_i, \] and the stationarity residual in the turnover variables is \(r^t_i = \kappa - \alpha_i - \beta_i\). The four certificate fields are defined as follows:

  • primal residual: the largest of 0, \(|\sum_i w_i - 1|\), \(l_i - w_i\), \(w_i - u_i\), \(\sum_{i\in S_k} w_i - c_k\) and \(\sum_i |d_i| - \tau\), over all \(i\) and \(k\);
  • stationarity residual: the largest of \(|r^w_i|\) and \(|r^t_i|\) over all \(i\);
  • dual residual: the larger of 0 and the negative of the smallest inequality multiplier, where the inequality multipliers are the lower, upper, sector, turnover-plus, turnover-minus and turnover-total multipliers;
  • complementary slackness: the largest of \(|\lambda_j g_j|\) over the inequality multipliers, each with its constraint \(g_j\) at \(t_i = |d_i|\).

The floor at zero in the dual residual is not exercised by the reference solution. Its smallest inequality multiplier is zero on each of seeds 0 to 49 (50 of 50, checked for this page against the reference's output), and this is structural: its active set holds the budget row and at most n minus 1 inequality rows, because the working rows must be linearly independent in n unknowns, so at least n plus 1 of the 2n bound multipliers are zero. The floor changes the dual residual only when every inequality multiplier is positive, so no reference output shows the floor, and no mutant of the reference separates it from its absence; the mutation suite does not test it. The agreement check still recomputes the dual residual from your own multipliers, so an answer with every multiplier positive is checked against the floor.

The tolerance on each certificate field is \(10^{-8}\), and the value you report must agree with the value the suite recomputes from your weights and multipliers to \(10^{-9}\). The starting portfolio is checked with a tolerance of \(10^{-9}\): its weights sum to one, lie in their bounds and satisfy the sector caps, each to that tolerance.

The objective is the convex function \(f\) of the weights, and \(\Sigma\) is positive definite, so \(f\) is strictly convex in \(w\). The next statement is the test the certificate uses.

Proposition (sufficiency of the KKT conditions). Let \(f\) be differentiable and convex in \(w\), let the constraints be affine in \((w, t)\), and let \((w, t)\) be feasible. Suppose there are a budget multiplier \(\nu\) of either sign for the equality \(\sum_i w_i = 1\) and a non-negative multiplier for each inequality, such that the stationarity conditions in \(w\) and in \(t\) hold, and each inequality's product with its multiplier is zero. Then \(w\) minimizes \(f\) over the feasible set. If \(f\) is strictly convex in \(w\), the minimizer \(w\) is unique.

Proof. Let \(L(w, t) = f(w) + \sum_j \lambda_j g_j(w, t) + \nu(\sum_i w_i - 1)\), with the sum over the inequalities. Since \(f\) is differentiable and convex and each \(g_j\) is affine and differentiable, \(L\) is differentiable and convex in \((w, t)\). The stationarity conditions say that its gradient vanishes at \((w, t)\), so \((w, t)\) minimizes \(L\). For any feasible \((y, s)\), each \(g_j(y, s) \le 0\) and \(\lambda_j \ge 0\), and the budget term is zero, so \(f(y) \ge L(y, s) \ge L(w, t)\). Complementary slackness gives \(L(w, t) = f(w)\), so \(f(y) \ge f(w)\). If \(f\) is strictly convex in \(w\) and \((w', t')\) is another minimizer with \(w' \ne w\), then the midpoint \(((w + w')/2, (t + t')/2)\) is feasible, because the constraints are affine in \((w, t)\) and so the feasible set is convex. Since \(f(w) = f(w')\) at the minimum, \(f((w + w')/2) < \tfrac12 f(w) + \tfrac12 f(w') = f(w)\), which contradicts minimality, so the minimizer is unique in \(w\). \(\square\)

Hypotheses: \(f\) is differentiable and convex, and strictly convex in \(w\) because \(\gamma\) is positive and \(\Sigma\) is positive definite; the constraints are affine in \((w, t)\), as the linearization shows; the answer is feasible; and the multipliers satisfy the conditions above. Positive definiteness of \(\Sigma\), together with \(\gamma > 0\), is what gives uniqueness: the generated instances have \(\Sigma = (A^{\top}A + I)/1000\) for a matrix \(A\) with integer entries, and \(x^{\top}\Sigma x = (|Ax|^2 + |x|^2)/1000 > 0\) for \(x \ne 0\). Existence of multipliers for every generated instance is not proved on this page. A reference solution was checked on seeds 0 to 49 only: its multipliers pass every check on those seeds, 50 of 50, which is evidence for those seeds only.

A named condition is refused with ValueError, and the refusal carries a message. The conditions are these: the instance is not a mapping; a field is missing; a value is NaN or infinite; the instance has no assets; a list does not have one entry per asset; \(\Sigma\) is not symmetric; \(\Sigma\) is not positive definite (singular, negative, or indefinite with a positive diagonal); \(\gamma\) is not positive; the turnover limit is negative; a lower bound lies above its upper bound; the starting portfolio does not sum to one, lies outside a bound or breaks a sector cap; a sector label lies outside 0 to \(Z-1\); or a sector has no asset (a label that no asset carries, or a cap for such a label). Each condition is also accepted in a valid form. Where the condition has a limit, the valid form sits on the limit or just inside it, and for the starting portfolio the tolerance is \(10^{-9}\); otherwise the valid form is the case the seed generates. Other invalid inputs, such as a boolean, text or nothing where a number belongs, a float where a sector label belongs, or a number where a list belongs, raise an exception that carries a message. A bound equal to the starting weight, a cap equal to the starting sector weight, a turnover limit of zero and a \(\gamma\) of \(10^{-6}\) are valid.

The function is pure. It does not print, does not emit warnings, does not change its argument and returns the same output for the same input. The standard library is the only import you may use.

Constraints
Standard library only. Your file must not import a grader file. Use exact arithmetic, floating-point arithmetic with the stated tolerance, or any method, as long as the returned numbers satisfy the definitions above. The suite does not inspect your method: it inspects the returned weights, multipliers and certificate, and the imports of your file.
Grading
Autograder only. The autograder is grader/test_project.py. It collects 363 checks, the same number for every seed, and runs them with warnings as errors. The checks cover the output's shape and names; the budget, the bounds, the sector caps and the turnover limit on your weights; dual feasibility; stationarity in the weights and in the turnover variables; complementary slackness; agreement of your certificate with the recomputed residuals; the objective against three feasible comparators (points that satisfy every constraint, here the mixes at 0.25, 0.5 and 0.75 of the way from your answer to the starting portfolio); five hand-worked cases with known answers, each weight within 10-8 of its worked value and each with its own certificate check; each named ValueError condition, refused in its invalid form and accepted in a valid form, with the exact boundary values (a bound or a cap equal to the starting weight, and a starting sum inside the tolerance on either side) accepted; the other invalid inputs, refused with an exception that carries a message; a missing field, a non-mapping, a non-finite value (NaN or infinity) in each numeric field, an instance with no assets and a list one entry short or one entry long; and purity and silence. Lab 3 computes the four certificate fields for three candidate answers to the problem of Lab 1. Lab 3 · The certificate for three candidate answers

The first candidate is the answer of Lab 1, for which all four residuals should be zero. The second reverses the sign of the bound multiplier; for it, the dual residual should be positive, and the stationarity residual should change, because the multiplier enters the stationarity equation. The third moves 1/1000 of weight from the second asset to the first, which keeps the budget; for it, the primal residual should stay zero and the stationarity residual should become non-zero. The data are SIMULATED, the same as in Lab 1.

"""Rung 3 check: the certificate of the project, computed for three candidate answers to the worked example of Lab 1.

SIMULATED three-asset problem, not market data. The residuals are the four of the project page, restricted to the
budget and the lower bounds 0 <= w_i of this example, plus the check w_i <= 1 that the budget and
those bounds imply (the example has no sector caps and no turnover constraint). The
primal and dual residuals are the largest violation among the constraints they cover, and the stationarity residual is
the largest absolute stationarity expression. The complementary-slackness residual is not a violation: it is the
largest absolute product of a multiplier and its constraint. So an optimal answer, with its multipliers, has all four
residuals at zero in exact arithmetic. The three candidates are: the answer of Lab 1; the same answer with the sign of
its bound multiplier reversed; and the same answer with a weight moved by 1/1000 between the first two assets, which
keeps the budget.
"""

from fractions import Fraction

# SIMULATED three-asset problem, not market data. The same numbers as Lab 1.
GAMMA = Fraction(2)
SIGMA = [
    [Fraction(4, 100), Fraction(1, 100), Fraction(0)],
    [Fraction(1, 100), Fraction(9, 100), Fraction(2, 100)],
    [Fraction(0), Fraction(2, 100), Fraction(16, 100)],
]
MU = [Fraction(5, 100), Fraction(3, 100), Fraction(-2, 100)]
N = 3


def residuals(w: list[Fraction], budget: Fraction, lower: list[Fraction], upper: list[Fraction]) -> dict[str, Fraction]:
    """Primal, stationarity, dual and complementary-slackness residuals of a weight vector and its multipliers."""
    primal = max([Fraction(0), abs(sum(w, Fraction(0)) - 1), *(-x for x in w), *(x - 1 for x in w)])
    stationarity = [
        GAMMA * sum((SIGMA[i][j] * w[j] for j in range(N)), Fraction(0)) - MU[i] + budget - lower[i] + upper[i]
        for i in range(N)
    ]
    dual = max([Fraction(0), *(-x for x in lower), *(-x for x in upper)])
    slackness = [abs(lower[i] * w[i]) for i in range(N)] + [abs(upper[i] * (w[i] - 1)) for i in range(N)]
    return {
        "primal": primal,
        "stationarity": max(abs(s) for s in stationarity),
        "dual": dual,
        "complementary": max(slackness),
    }


def main() -> None:
    # The Lab 1 answer: weights (9/11, 2/11, 0), budget multiplier -21/1100, and a lower-bound multiplier of 9/1100
    # on the third asset.
    w = [Fraction(9, 11), Fraction(2, 11), Fraction(0)]
    budget = Fraction(-21, 1100)
    lower = [Fraction(0), Fraction(0), Fraction(9, 1100)]
    upper = [Fraction(0), Fraction(0), Fraction(0)]
    zero = [Fraction(0)] * N
    report = residuals(w, budget, lower, upper)
    print("check A, Lab 1 answer:", {k: str(v) for k, v in report.items()})

    # Candidate B: the same weights with the sign of the bound multiplier reversed.
    flipped = [Fraction(0), Fraction(0), -Fraction(9, 1100)]
    report = residuals(w, budget, flipped, zero)
    print("check B, multiplier sign reversed:", {k: str(v) for k, v in report.items()})

    # Candidate C: a weight moved by 1/1000 from the second asset to the first, which keeps the budget.
    moved = [Fraction(9, 11) + Fraction(1, 1000), Fraction(2, 11) - Fraction(1, 1000), Fraction(0)]
    report = residuals(moved, budget, lower, upper)
    print("check C, weights moved by 1/1000:", {k: str(v) for k, v in report.items()})


main()
check A, Lab 1 answer: {'primal': '0', 'stationarity': '0', 'dual': '0', 'complementary': '0'}
check B, multiplier sign reversed: {'primal': '0', 'stationarity': '9/550', 'dual': '9/1100', 'complementary': '0'}
check C, weights moved by 1/1000: {'primal': '0', 'stationarity': '1/6250', 'dual': '0', 'complementary': '0'}

Check A has all four residuals at zero, so the certificate of the answer is exact. Check B reverses the bound multiplier of 9/1100 to −9/1100: the dual residual becomes 9/1100, and the stationarity residual becomes 9/550, which is twice the multiplier, because the reversed multiplier changes the third weight's stationarity by twice its value. Check C keeps the budget, so the primal residual stays zero, but it moves the gradient, and the stationarity residual becomes 1/6250. The lab shows that the dual residual responds to candidate B, and that the stationarity residual responds to candidates B and C. No candidate here makes the primal residual or the complementary-slackness residual non-zero, so the lab does not show that either one responds. It does not show that these three are the only errors an answer can make. The autograder's checks cover the other constraints.

What the suite does not test

The suite runs on the problem your seed generates. It does not test the method your code uses, and it does not test the answer for any problem other than the cases it generates and the hand-worked cases it lists. Under the hypotheses of the proposition, exact multipliers and an exactly feasible answer make the answer the minimizer. A certificate whose four fields are within tolerance shows that the answer satisfies those conditions to within the tolerance, and nothing more. No case reads a file, and every case carries the SIMULATED label, so no case describes a real portfolio.

Rung 4 · Stretch

  • A frontier. Solve the problem for a grid of risk-aversion values, and plot the expected return against the risk of each answer. Then relate the budget multiplier to the derivative of the optimal objective with respect to the budget level. The envelope argument, the envelope theorem, is the tool; state the sign convention you use, and check it numerically on two grid points.
  • A cost of trading. Replace the turnover limit with a proportional cost per unit of trading, add it to the objective, and state the new multipliers. State which constraints and multipliers change.
  • A sector with a second label. Let an asset belong to two sectors. State how the sector multipliers enter the stationarity residual, and say which of the certificate definitions must change.
