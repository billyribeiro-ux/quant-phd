Atlas A15: fundamentals engine

An analyst team needs one library that turns a company's SEC filings into standardized statements and computes the ratios, accruals and scores that the module's lessons use. You will write atlas/fundamentals.py to the A15 contract, and the autograder will test it on a filer generated from your workspace seed, so every answer is yours to compute.

Rungs 1 and 2

Lab 1 · Worked example: the as-of rule and the tag priority

The filer below reports 2021 revenue under Revenues, restates it in a 10-K/A filed on 2023-03-20, and reports 2022 revenue under a second tag. The code keeps annual observations only (a 10-K with fiscal-year duration), picks the latest (filed, accession) per tag and period end, and then the first tag in priority that has a value. Before running it, predict the revenue known on 2023-03-01: the restatement is not yet filed on that date, so the original 2021 figure should be the one known.

from typing import Any

# The A15 tag priority for revenue: the first tag with an annual observation for a period end supplies it.
REVENUE_TAGS = ("Revenues", "RevenueFromContractWithCustomerExcludingAssessedTax", "SalesRevenueNet")


def is_annual(obs: dict[str, str | float], flow: bool) -> bool:
    # Annual: a 10-K for the fiscal year (fp == "FY"), and for a flow item a duration of 350 to 380 days.
    # The 10-Q quarter (fp == "Q1") and any other duration are not annual, so they are ignored.
    if not str(obs["form"]).startswith("10-K") or obs["fp"] != "FY":
        return False
    if not flow:
        return "start" not in obs
    from datetime import date

    days = (date.fromisoformat(str(obs["end"])) - date.fromisoformat(str(obs["start"]))).days
    return 350 <= days <= 380


def revenue_by_period(filer: dict[str, Any], as_of: str | None = None) -> dict[str, float]:
    # Step 1. For each tag, keep the annual observation per period end that is known on as_of (filed <= as_of)
    # and is the latest by (filed, accession number): a later 10-K/A supersedes the original.
    best: dict[str, dict[str, tuple[str, str, float]]] = {}
    for tag in REVENUE_TAGS:
        per_end: dict[str, tuple[str, str, float]] = {}
        for obs in filer["facts"]["us-gaap"].get(tag, {}).get("units", {}).get("USD", []):
            if not is_annual(obs, flow=True):
                continue
            if as_of is not None and obs["filed"] > as_of:
                continue
            key = (str(obs["filed"]), str(obs["accn"]))
            current = per_end.get(str(obs["end"]))
            if current is None or key > (current[0], current[1]):
                per_end[str(obs["end"])] = (key[0], key[1], float(obs["val"]))
        best[tag] = per_end
    # Step 2. Walk the tags in priority order: the first tag with a value for a period end supplies it.
    out: dict[str, float] = {}
    for tag in REVENUE_TAGS:
        for end, (_, _, value) in best[tag].items():
            out.setdefault(end, value)
    return dict(sorted(out.items()))


print("revenue, latest knowledge:", revenue_by_period(FILER))
print("revenue, known on 2023-03-01:", revenue_by_period(FILER, "2023-03-01"))
print("revenue, known on 2022-01-31:", revenue_by_period(FILER, "2022-01-31"))
revenue, latest knowledge: {'2021-12-31': 990.0, '2022-12-31': 1200.0}
revenue, known on 2023-03-01: {'2021-12-31': 1000.0, '2022-12-31': 1200.0}
revenue, known on 2022-01-31: {}

Three answers, three rules. On the latest knowledge the 2021 figure is the restated 990, because Revenues has the later annual observation and ranks first. On 2023-03-01 the amendment is not yet known, so the original 1000 is returned: a later filing cannot leak backwards. On 2022-01-31 nothing has been filed, so the statements are empty, and the 10-Q quarter is never a candidate because its form and fiscal-period tag are not annual. The engine must return the same three answers.

The averages use the previous year end, which is why PREV appears in every average. The identity holds to rounding because roe = net_margin * asset_turnover * leverage is algebra once both sides use the same average assets and equity. Rung 3 · Specification

Context
An analyst team wants one library that every later valuation and screen can call. It takes an SEC company-facts file, standardizes the statements of each filer as of any date, and computes the ratios, the accrual measures and the two scores that this module's lessons define. You implement the library to the Atlas A15 contract, and the tests check that it reads filings the way an analyst does: the latest annual figure known on the as-of date, never a later one, and never a quarter. The curriculum's brief also names ingesting EDGAR XBRL. Live EDGAR retrieval is outside this autograded project: the library takes a parsed company-facts mapping, and the A2 data layer supplies the loader.
Inputs
The autograder's company-facts mapping comes from grader/instance.py, seeded by your workspace ID. Its make_instance(seed) returns a dict with the keys seed, label, latest, prior, prior2 and payload. The payload is a JSON string that holds the filer under facts, in the SEC company-facts shape (facts["facts"]["us-gaap"][tag]["units"][unit] is a list of observations with end, val, filed, form, fp and, for flow items, start), and the cross-section sample of firm-years for the modified Jones model under sample. The grader decodes it; a student does not call make_instance. Every instance is labelled SIMULATED: it is generated, it is not a real company, and nothing in it is a real company's figure. Real EDGAR company-facts files are not embedded in this course, because the SEC's statement on reuse has not been read from an issuer page this course can reach. That is an honest pending state: no real filer's figure appears anywhere in this project.
Required outputs
A package atlas/ with the module atlas/fundamentals.py at its root. It must define, with these names and signatures: ITEMS, TAG_PRIORITY, BENEISH_INTERCEPT, BENEISH_COEFFICIENTS (the starter gives the four tables: define them the same way, and do not import any grader file); standardize(facts, as_of=None); dupont(statements, period_end); roic(statements, period_end, tax_rate); current_ratio(statements, period_end); gross_margin(statements, period_end); debt_to_assets(statements, period_end); days_sales_outstanding(statements, period_end); accruals_cash_flow(statements, period_end); accruals_balance_sheet(statements, period_end); modified_jones(sample); piotroski_f_score(statements, period_end); beneish_m_score(statements, period_end). Return values, read by the suite: dupont returns the keys net_margin, asset_turnover, leverage, roe and roa; piotroski_f_score returns {"signals": (s1, ..., s9), "score": ...}, each signal 0 or 1 and the score their sum; beneish_m_score returns the eight variables DSRI, GMI, AQI, SGI, DEPI, SGAI, LVGI, TATA and m_score; modified_jones returns {"coefficients": (a1, a2, a3), "nondiscretionary": [...], "discretionary": [...]}, the two lists in sample order. The A15 contract in the repository (atlas/A15.contract.md) states the same definitions. Start from the starter file: every function raises NotImplementedError until you replace it, and the suite fails on the starter.
Constraints
NumPy and the Python standard library only. The module must not import instance.py or any other grader file, so it runs on its own. Functions are pure: they validate their inputs, never print or warn, never change their arguments, and return fresh objects. Every named error condition raises ValueError; the grader checks the exception type and not the wording of the message. The conditions are these: a company-facts mapping without facts; an observation without end, val, filed or form; a value that is not a finite number; a date that datetime.date.fromisoformat rejects; a period end that is not an ISO date, or that a function needs and the statements do not contain; an as-of date that is not an ISO date (an as-of date before every filing gives an empty mapping, not an error); a missing item, which is never imputed; a missing previous year, meaning no period end 350 to 380 days earlier; a zero denominator, or a non-finite result; a tax rate outside 0 <= tax_rate < 1; a non-positive average invested capital; a sample with fewer than four firm-years, a lagged-asset value that is not positive, a non-finite value, or a rank-deficient design. Money is in the unit the filing reports; the engine never converts currency or scale.
Grading mode
Autograded in your browser. grader/test_project.py collects 240 checks (counted with pytest --collect-only on the reference, the same count on every seed checked). It runs with warnings as errors and covers: the contract's tables; standardize against the filer's own generated numbers, with as-of cut-offs that exclude a later filing and, on the seeds whose filer draws one, a same-day amendment (a fixed same-day case checks the tie-break on every seed), a tag priority, an absent item, and the money units that are read (USD and shares only); every ratio's value and its scale invariance; the DuPont identity; the accrual signs; the modified Jones least-squares coefficients and the identity of fitted and discretionary parts; the Piotroski signals and the Beneish variables; every named ValueError, namely: a mapping without facts; an observation without end, val, filed or form; a non-finite value; a bad date; a missing item or previous year; a zero or overflowing denominator; a tax rate outside the range; non-positive invested capital; and the modified Jones checks (fewer than four firm-years, a non-positive lag, non-finite values, a rank-deficient design); the return containers (tuples where the contract writes tuples, lists for the residuals); purity, silence and integer and NumPy inputs. The suite is not secret: its integrity comes from the seeded instance, which changes the answers, not only the labels.

Conventions, in brief

  • A period end is an ISO date string. standardize returns {period_end: {item: value}}, period ends ascending, and an item is present only when a tag supplies it. Every value is a float.
  • An annual observation has form beginning 10-K and fp == "FY", and for a flow item a duration start to end of 350 to 380 days; an instant item has no start. Anything else is ignored, including 10-Q quarters and transition periods.
  • Among annual observations for one tag and one period end that were filed on or before the as-of date, take the greatest (filed, accn); with no as-of date there is no cut-off. The as-of cut-off is inclusive.
  • Per period end, the first tag of an item's priority list that has a value supplies it. A period end with no value for an item has no key for it.
  • The previous year is the latest period end 350 to 380 days earlier. An average is (x_t + x_{t-1}) / 2 of year-end balances. ROIC uses NOPAT = operating_income (1 - tax_rate) over average invested capital equity + long_term_debt - cash.
  • Accruals, the Piotroski ratios and the Beneish variables follow the formulas in the module lessons and in the A15 contract. The Piotroski signals use the beginning-of-year assets where the contract says so, and the score is the sum of the nine binary signals.
  • Documented proxies and one simplification. The A15 contract defines three Piotroski inputs as proxies: net_income is the NetIncomeLoss tag; signal 7 uses the change in shares_outstanding, not a test of equity issuance; long_term_debt is LongTermDebtNoncurrent. The suite grades these contract definitions. Invested capital omits short-term borrowings, because the contract has no short_term_debt item; the lessons state the size of that omission. Accruals use current_liabilities as published.
  • Tied observations are an error. If the two best annual observations of one tag and period end tie on (filed, accn) and carry different values, standardize raises ValueError. Equal values are not a conflict.
  • The Beneish constants are unconfirmed. BENEISH_INTERCEPT and BENEISH_COEFFICIENTS are given in the starter and defined in the reference; the suite checks them against the copy in instance.py, and instance.BENEISH_STATUS says what is and is not known. If a value is ever confirmed, it changes in all three places. ONE secondary source, the Wikipedia page "Beneish M-score" (read 2026-10-27), reproduces the values; nothing else could be read. They have not been checked against Beneish (1999), registry key beneish1999detection, so the M-score is graded C at best until a locator into the paper is confirmed. The suite checks your module against the shared values, not against an independent truth.

Lab 3 · Reference numbers for the modified Jones model

Lab 3 · The modified Jones regression on six SIMULATED firm-years

The code below runs the modified Jones estimator of registry key dechow1995detecting (“Detecting Earnings Management”) on six SIMULATED firm-years with NumPy's least squares. You can check your modified_jones against these coefficients and discretionary accruals on the same six rows, to the printed precision. The autograder does not run this sample: it grades your module on its own generated filer. The sample is literal, so the lab needs no data file. Before running it, predict the sign of the discretionary accrual of the fifth firm-year: its total accruals are positive while the other firm-years are negative.

import numpy as np

# SIMULATED firm-years for the modified Jones model (registry key dechow1995detecting,
# 'Detecting Earnings Management'). Currency units. Not real firms.
SAMPLE = [
    {"total_accruals": -4.0e6, "lag_assets": 1.0e8, "d_revenue": 6.0e6, "d_receivables": 1.0e6, "ppe": 3.0e7},
    {"total_accruals": -2.5e6, "lag_assets": 8.0e7, "d_revenue": 3.0e6, "d_receivables": 0.5e6, "ppe": 2.4e7},
    {"total_accruals": -5.2e6, "lag_assets": 1.3e8, "d_revenue": 9.0e6, "d_receivables": 2.0e6, "ppe": 4.5e7},
    {"total_accruals": -1.1e6, "lag_assets": 5.0e7, "d_revenue": 1.5e6, "d_receivables": 0.2e6, "ppe": 1.1e7},
    {"total_accruals": 0.9e6, "lag_assets": 6.0e7, "d_revenue": -0.5e6, "d_receivables": 0.4e6, "ppe": 2.0e7},
    {"total_accruals": -3.3e6, "lag_assets": 9.0e7, "d_revenue": 4.0e6, "d_receivables": 1.2e6, "ppe": 3.2e7},
]

# Total accruals and each regressor are scaled by lagged assets; the model has no intercept.
lag = np.array([row["lag_assets"] for row in SAMPLE])
y = np.array([row["total_accruals"] for row in SAMPLE]) / lag
X = np.column_stack(
    [
        1.0 / lag,
        (np.array([row["d_revenue"] for row in SAMPLE]) - np.array([row["d_receivables"] for row in SAMPLE])) / lag,
        np.array([row["ppe"] for row in SAMPLE]) / lag,
    ]
)
coef = np.linalg.lstsq(X, y, rcond=None)[0]
fitted = X @ coef
print("coefficients (a1, a2, a3):", np.round(coef, 6).tolist())
print("discretionary (scaled):", np.round(y - fitted, 6).tolist())
print("rank of the design:", int(np.linalg.matrix_rank(X)))
coefficients (a1, a2, a3): [25081.462105, -0.821498, -0.006263]
discretionary (scaled): [0.002703, -0.004013, 0.006209, 0.000235, 0.004347, -0.009161]
rank of the design: 3

With six firm-years and three regressors the design has three degrees of freedom left, so the coefficients are estimated with the residual noise of a small sample; treat them as a check of the estimator, not as a finding about any firm. The rank is three: the three regressors are linearly independent, which the contract requires. The fifth firm-year's positive accrual is not explained by its regressors, so its discretionary part is positive, as predicted.
