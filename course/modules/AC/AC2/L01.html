Every ratio, return and score in this module starts from one row per fiscal year. Whether two firms are comparable, and whether a backtest used only what was known on its decision date, is settled here, before any ratio is computed. This lesson specifies the rules that turn a filer's tagged facts into a standardized statement (the A15 engine's input), proves the property that makes point-in-time analysis possible, and marks the places where the rules are conventions that the analyst must check.

1A filing as a set of tagged facts

An XBRL filing attaches a tag, a unit and a period to every number it reports. The tag names the concept, for example NetIncomeLoss. A company's facts across all of its filings form one mapping. The A15 engine reads that mapping as its input. It reads only the us-gaap taxonomy, in unit USD for money and shares for share counts. Each observation carries the keys below. Other keys are ignored.

  • end, the period end, or the instant, as an ISO date.
  • val, a number in the filing's unit.
  • filed, the date the filing was made.
  • form, for example 10-K, 10-K/A or 10-Q, and fp, for example FY, Q1 or Q4.
  • start, present only for flow items, which are measured over a period. An instant such as a balance has no start.
  • accn, an optional filing identifier, used only as a tie-break.

The key list above is the A15 input contract (atlas/A15.contract.md, Input). It is a specification of the file the engine accepts, not a claim about any filer. No registry source documents the EDGAR file format yet, so this lesson makes no sourced claim about it (see the reference request in the module hub).

Definition 1.1 (XBRL standardization)

XBRL standardization is the map from one filer's tagged facts to a table with one row per period end and one value per standardized item (revenue, cogs, total assets, and so on). The map is fixed by three rules: the annual-observation rule (Section 2), the as-of rule (Section 3) and the tag priority per period end (Section 4). Items that the rules cannot supply are absent from the table. They are not filled in.

2The annual-observation rule

Definition 2.1 (annual observation)

An observation is annual when its form starts with 10-K, its fp is FY, and either (flow item) it has a start and 350 ≤ (end − start) ≤ 380 days, or (instant item) it has no start. Every other observation is ignored.

Remark 2.2 (what the window admits)

The window of 350 to 380 days admits a full fiscal year of 365 days and a 52- or 53-week year (364 or 371 days). It rejects a quarter (about 90 days) and a two-year cumulative period (730 days). The window is a convention that encodes "one fiscal year". It is not a fact of accounting, and Problem M1 checks which durations pass.

Validation runs before the ignore step. An observation that lacks a required key raises an error even when the rules would ignore it. A 10-Q observation is therefore checked for its keys and then discarded. The value of this design is that a malformed file fails loudly rather than producing a table with silent holes.

3The as-of rule: what was known on a date

A 10-K repeats its comparatives. The same fiscal year-end can therefore appear in the 10-K for that year and in the 10-K for each later year. A restatement adds a further observation filed later, with a 10-K/A form. For one tag and one period end there can be several annual observations, and they can disagree.

Definition 3.1 (as-of selection)

Let \(c\) be a cut-off date, or \(c = \infty\) when there is none. For a tag and a period end, the as-of selection is the annual observation with the greatest \((\texttt{filed}, \texttt{accn})\) among those with \(\texttt{filed} \le c\). If no annual observation has \(\texttt{filed} \le c\), the period end does not exist for that tag at \(c\).

Proposition 3.2 (the as-of selection never moves backward)

Let \(c_1 \le c_2\). If a period end has an as-of selection at \(c_1\), then it has one at \(c_2\), and the filing date selected at \(c_2\) is no earlier than the filing date selected at \(c_1\).

Proof

Let \(S(c)\) be the set of annual observations for the period end with \(\texttt{filed} \le c\). Then \(S(c_1) \subseteq S(c_2)\), because a filing made by \(c_1\) was also made by \(c_2\). The selection at \(c\) is the maximum of the pairs \((\texttt{filed}, \texttt{accn})\) over \(S(c)\), taken in lexicographic order. A maximum over a set that contains \(S(c_1)\) is at least the maximum over \(S(c_1)\). If \(S(c_1)\) is empty there is nothing to prove for the first claim, and \(S(c_2) \supseteq S(c_1)\) is non-empty whenever \(S(c_1)\) is. The second claim follows because the first component of the maximum is the filing date. \(\blacksquare\)

Corollary 3.3 (a date on which a value was known)

Let \(c^\ast\) be the latest filing date in the file. Then the selection with no cut-off equals the selection at \(c^\ast\). A backtest that calls the standardizer with no cut-off therefore uses filings made after the decision date it is simulating whenever such filings exist.

Proof

Every observation has \(\texttt{filed} \le c^\ast\), so \(S(c^\ast)\) contains every annual observation, and so does \(S(\infty)\). The two selections are maximums over the same set. The second claim is the definition of a cut-off: a filing made after the decision date has \(\texttt{filed} > c\) and is excluded only when a cut-off is given. \(\blacksquare\)

The as-of rule is the device that makes point-in-time work possible. Proposition 3.2 says that a later cut-off never selects an earlier filing for a period end. It does not say that the value is unchanged. Lab 1 shows a restated value replacing the original once the 10-K/A is in the file.

Remark 3.4 (a tie on the best key is a conflict, by contract)

Two annual observations for one tag and period end can tie on \((\texttt{filed}, \texttt{accn or ""})\). The A15 contract decides this case. If the two best observations tie and carry different val, the facts are inconsistent, and standardize raises ValueError naming the tag and the period end. Equal values are not a conflict, so an equal-valued tie returns the value. The choice is the contract's. This lesson does not derive it, and it relies on the rule only to say that a conflict is an error and never a silent pick. Lab 1 implements the rule exactly and prints one conflicting tie that raises and one equal-valued tie that does not.

4Tag priority per period end

Several tags can measure the same item. Revenue, for example, has three tags in the contract, and a filer may switch from one to another. A15 fixes an ordered list of tags for each item. For each period end, the first tag in the list that has an annual observation (after the as-of rule) supplies the value.

Definition 4.1 (tag priority per period end)

For a standardized item with tag list \((t_1, \dots, t_k)\) and a period end \(e\), the value is the value of the as-of selection for the smallest \(j\) such that \(t_j\) has an annual observation for \(e\). If no tag has one, the item has no value at \(e\).

Example 4.2 (the revenue tag switches)

In the SIMULATED filer of Lab 1, FY2021 and earlier 10-Ks report revenue under Revenues, and later 10-Ks under RevenueFromContractWithCustomerExcludingAssessedTax. The FY2022 10-K reports the 2021 year end under the new tag as a comparative, so for 2021 both tags have an annual observation. Priority gives Revenues for 2020 and 2021, and the new tag from 2022. The lab's revenue_tag column prints the tag that supplied each value.

Proposition 4.3 (nothing is imputed)

A standardized table contains an item at a period end if and only if some tag in the item's list has an as-of selection for that period end. An item that is absent is never filled by interpolation, by a neighbouring year, or by zero.

Proof

The table is built by assigning a value to an item only when a winning observation exists for that item and period end (Definition 4.1). No other assignment is made, and the period ends are those that appear in some selection. Both claims follow from that construction. \(\blacksquare\)

Proposition 4.3 says what the standardizer does. It does not say why a value is missing. A missing item can mean the filer did not tag the concept in that year, or that the concept sits in an extension tag that A15 does not read, or that the item was never reported. Those are three different mechanisms, and the standardizer cannot tell them apart. The distinction belongs to the missing-data analysis in S0 (missing-data mechanisms), and the engine's answer is only that the item is absent.

Lab 1 · Standardizing a SIMULATED company-facts mapping

The lab generates one SIMULATED filer from a seeded random number generator. It has five fiscal years, 10-K comparatives, a 10-K/A that restates FY2022 revenue, a Q4 row inside a 10-K, and 10-Q quarters. Predicted from the rules, not from the output: the standardized table has five period ends; the 2020 year end has no long-term debt because the file contains none for that date; as of 2023-06-30 the FY2022 revenue is the value filed in February 2023, and with no cut-off it is the restated value; the 10-Q rows never supply an annual value, and the 10-K/A supplies FY2022 revenue only from its filing date on; malformed input raises ValueError with a message that names the condition, a conflicting tie between the two best observations raises, and an equal-valued tie does not.

"""AC2 lab L01: standardize a company-facts mapping under the A15 rules.

SIMULATED: the filer is generated from a seeded RNG. Its name, CIK and every figure are invented
for this lab and are not a real company's. The rules applied are those of atlas/A15.contract.md:
the annual-observation rule, the as-of rule, the tag priority per period end, and the input checks.
Standard library only; no network; every number printed is computed by the code below.
"""

from __future__ import annotations

import math
import random
from collections.abc import Mapping
from dataclasses import dataclass
from datetime import date
from typing import Any

SEED = 20261027
ITEMS: tuple[str, ...] = (
    "revenue",
    "cogs",
    "sga",
    "depreciation",
    "operating_income",
    "net_income",
    "cfo",
    "total_assets",
    "current_assets",
    "cash",
    "receivables",
    "ppe",
    "total_liabilities",
    "current_liabilities",
    "long_term_debt",
    "equity",
    "shares_outstanding",
)
TAG_PRIORITY: Mapping[str, tuple[str, ...]] = {
    "revenue": ("Revenues", "RevenueFromContractWithCustomerExcludingAssessedTax", "SalesRevenueNet"),
    "cogs": ("CostOfRevenue", "CostOfGoodsAndServicesSold"),
    "sga": ("SellingGeneralAndAdministrativeExpense",),
    "depreciation": ("DepreciationDepletionAndAmortization", "DepreciationAndAmortization", "Depreciation"),
    "operating_income": ("OperatingIncomeLoss",),
    "net_income": ("NetIncomeLoss",),
    "cfo": ("NetCashProvidedByUsedInOperatingActivities",),
    "total_assets": ("Assets",),
    "current_assets": ("AssetsCurrent",),
    "cash": ("CashAndCashEquivalentsAtCarryingValue",),
    "receivables": ("AccountsReceivableNetCurrent",),
    "ppe": ("PropertyPlantAndEquipmentNet",),
    "total_liabilities": ("Liabilities",),
    "current_liabilities": ("LiabilitiesCurrent",),
    "long_term_debt": ("LongTermDebtNoncurrent",),
    "equity": ("StockholdersEquity",),
    "shares_outstanding": ("CommonStockSharesOutstanding",),
}
FLOW_ITEMS: frozenset[str] = frozenset(
    {"revenue", "cogs", "sga", "depreciation", "operating_income", "net_income", "cfo"}
)


@dataclass(frozen=True)
class Observation:
    """One parsed observation. Dates are datetime.date; val is a finite float in the filing's unit."""

    end: date
    val: float
    filed: date
    form: str
    fp: str
    accn: str
    start: date | None


def _date(value: object, where: str) -> date:
    """Parse an ISO date with date.fromisoformat; anything else raises ValueError."""
    if not isinstance(value, str):
        raise ValueError(f"{where} must be an ISO date string, not {type(value).__name__}")
    try:
        return date.fromisoformat(value)
    except ValueError as exc:
        raise ValueError(f"{where} is not an ISO date: {value!r}") from exc


def _observation(raw: object, tag: str, unit: str) -> Observation:
    """Validate one raw observation; a missing or malformed required key raises ValueError."""
    where = f"{tag} [{unit}]"
    if not isinstance(raw, Mapping):
        raise ValueError(f"{where}: an observation must be a mapping")
    for key in ("end", "val", "filed", "form"):
        if key not in raw:
            raise ValueError(f"{where}: observation lacks {key!r}")
    value = raw["val"]
    if isinstance(value, bool) or not isinstance(value, int | float) or not math.isfinite(value):
        raise ValueError(f"{where}: val must be a finite number, not {value!r}")
    form = raw["form"]
    if not isinstance(form, str):
        raise ValueError(f"{where}: form must be a string")
    fp = raw.get("fp", "")
    accn = raw.get("accn", "")
    if not isinstance(fp, str) or not isinstance(accn, str):
        raise ValueError(f"{where}: fp and accn must be strings when present")
    start = _date(raw["start"], f"{where}: start") if "start" in raw else None
    return Observation(
        end=_date(raw["end"], f"{where}: end"),
        val=float(value),
        filed=_date(raw["filed"], f"{where}: filed"),
        form=form,
        fp=fp,
        accn=accn,
        start=start,
    )


def _is_annual(obs: Observation, flow: bool) -> bool:
    """Annual: form 10-K*, fp FY, and a 350-380 day duration (flow) or no start date (instant)."""
    if not obs.form.startswith("10-K") or obs.fp != "FY":
        return False
    if flow:
        return obs.start is not None and 350 <= (obs.end - obs.start).days <= 380
    return obs.start is None


def _us_gaap(facts: Mapping[str, Any]) -> Mapping[str, Any]:
    """Return the us-gaap block; a mapping without 'facts' raises ValueError."""
    if not isinstance(facts, Mapping) or "facts" not in facts:
        raise ValueError("the company-facts mapping lacks 'facts'")
    block = facts["facts"]
    if not isinstance(block, Mapping):
        raise ValueError("'facts' must be a mapping")
    gaap = block.get("us-gaap", {})
    if not isinstance(gaap, Mapping):
        raise ValueError("'facts[us-gaap]' must be a mapping")
    return gaap


def _as_of_pick(
    gaap: Mapping[str, Any], tag: str, unit: str, flow: bool, cutoff: date | None
) -> dict[date, Observation]:
    """For one tag: per period end, the annual observation with the greatest (filed, accn) among filed <= cutoff."""
    block = gaap.get(tag)
    if block is None:
        return {}
    if not isinstance(block, Mapping) or not isinstance(block.get("units", {}), Mapping):
        raise ValueError(f"{tag}: must be a mapping with a 'units' mapping")
    rows = block.get("units", {}).get(unit, [])
    if not isinstance(rows, list):
        raise ValueError(f"{tag} [{unit}]: observations must be a list")
    candidates: dict[date, list[Observation]] = {}
    for raw in rows:
        obs = _observation(raw, tag, unit)
        if not _is_annual(obs, flow):
            continue
        if cutoff is not None and obs.filed > cutoff:
            continue
        candidates.setdefault(obs.end, []).append(obs)
    best: dict[date, Observation] = {}
    for end, group in candidates.items():
        # Rank by (filed, accn or ""), best first. Contract: if the two best tie on that key and carry different
        # val, the facts are inconsistent and standardize raises ValueError. Equal values are not a conflict.
        ranked = sorted(group, key=lambda o: (o.filed, o.accn), reverse=True)
        top = ranked[0]
        if len(ranked) > 1:
            runner = ranked[1]
            if (top.filed, top.accn) == (runner.filed, runner.accn) and top.val != runner.val:
                raise ValueError(
                    f"{tag} at period end {end.isoformat()}: two annual observations tie on "
                    f"(filed {top.filed.isoformat()}, accn {top.accn!r}) with different values "
                    f"{top.val!r} and {runner.val!r}"
                )
        best[end] = top
    return best


def select(facts: Mapping[str, Any], as_of: str | None = None) -> dict[str, dict[date, tuple[str, Observation]]]:
    """Per item and period end, the winning (tag, observation) under the tag priority and the as-of rule."""
    cutoff = None if as_of is None else _date(as_of, "as_of")
    gaap = _us_gaap(facts)
    out: dict[str, dict[date, tuple[str, Observation]]] = {}
    for item in ITEMS:
        flow = item in FLOW_ITEMS
        unit = "shares" if item == "shares_outstanding" else "USD"
        per_tag = {tag: _as_of_pick(gaap, tag, unit, flow, cutoff) for tag in TAG_PRIORITY[item]}
        ends: set[date] = set()
        for picks in per_tag.values():
            ends.update(picks)
        winners: dict[date, tuple[str, Observation]] = {}
        for end in ends:
            for tag in TAG_PRIORITY[item]:
                if end in per_tag[tag]:
                    winners[end] = (tag, per_tag[tag][end])
                    break
        out[item] = winners
    return out


def standardize(facts: Mapping[str, Any], as_of: str | None = None) -> dict[str, dict[str, float]]:
    """{period_end_iso: {item: value}}, period ends ascending; absent items are absent (nothing imputed)."""
    picked = select(facts, as_of)
    table: dict[date, dict[str, float]] = {}
    for item in ITEMS:
        for end, (_tag, obs) in picked[item].items():
            table.setdefault(end, {})[item] = obs.val
    return {end.isoformat(): table[end] for end in sorted(table)}


def make_filer(seed: int = SEED) -> dict[str, Any]:
    """A SIMULATED company-facts mapping: five fiscal years, 10-K comparatives, a restatement, a 10-Q, a Q4 row."""
    rng = random.Random(seed)
    years = (2020, 2021, 2022, 2023, 2024)
    rev = {2020: 1_000_000_000}
    for y in years[1:]:
        rev[y] = round(rev[y - 1] * (1 + rng.uniform(0.04, 0.09)))
    cogs = {y: round(rev[y] * rng.uniform(0.58, 0.64)) for y in years}
    sga = {y: round(rev[y] * rng.uniform(0.18, 0.22)) for y in years}
    noise = {y: round(rev[y] * rng.uniform(-0.03, 0.03)) for y in years}
    dep: dict[int, int] = {2020: 38_000_000}
    ppe: dict[int, int] = {2020: 400_000_000}
    for y in years[1:]:
        dep[y] = round(ppe[y - 1] * 0.10)
        ppe[y] = ppe[y - 1] + round(rev[y] * 0.06) - dep[y]
    oi = {y: rev[y] - cogs[y] - sga[y] - dep[y] for y in years}
    ni = {y: round(oi[y] * 0.75) for y in years}
    cfo = {y: ni[y] + dep[y] + noise[y] for y in years}
    eq: dict[int, int] = {2020: 600_000_000}
    for y in years[1:]:
        eq[y] = eq[y - 1] + ni[y] - round(0.4 * ni[y])
    ltd = {y: 300_000_000 + 10_000_000 * (y - 2020) for y in years}
    cash = {y: round(rev[y] * 0.08) for y in years}
    recv = {y: round(rev[y] * 0.12) for y in years}
    inv = {y: round(cogs[y] * 0.15) for y in years}
    other_ca = {y: round(rev[y] * 0.03) for y in years}
    ca = {y: cash[y] + recv[y] + inv[y] + other_ca[y] for y in years}
    cl = {y: round(cogs[y] * 0.25) for y in years}
    ol = {y: round(rev[y] * 0.05) for y in years}
    tl = {y: cl[y] + ltd[y] + ol[y] for y in years}
    ta = {y: tl[y] + eq[y] for y in years}
    shares = {y: 50_000_000 if y < 2024 else 52_000_000 for y in years}

    def fy_tag(item: str, fy: int) -> str:
        if item == "revenue":
            return "Revenues" if fy <= 2021 else "RevenueFromContractWithCustomerExcludingAssessedTax"
        if item == "cogs":
            return "CostOfRevenue" if fy <= 2022 else "CostOfGoodsAndServicesSold"
        return TAG_PRIORITY[item][0]

    truth: dict[str, dict[int, int]] = {
        "revenue": rev,
        "cogs": cogs,
        "sga": sga,
        "depreciation": dep,
        "operating_income": oi,
        "net_income": ni,
        "cfo": cfo,
        "total_assets": ta,
        "current_assets": ca,
        "cash": cash,
        "receivables": recv,
        "ppe": ppe,
        "total_liabilities": tl,
        "current_liabilities": cl,
        "long_term_debt": ltd,
        "equity": eq,
        "shares_outstanding": shares,
    }
    flows = {"revenue", "cogs", "sga", "depreciation", "operating_income", "net_income", "cfo"}
    gaap: dict[str, dict[str, dict[str, list[dict[str, Any]]]]] = {}

    def add(item: str, fy: int, end_year: int, val: int, form: str, fp: str, accn: str, filed: str) -> None:
        tag = fy_tag(item, fy)
        unit = "shares" if item == "shares_outstanding" else "USD"
        obs: dict[str, Any] = {"end": f"{end_year}-12-31", "val": val, "filed": filed, "form": form, "fp": fp}
        if item in flows:
            obs["start"] = f"{end_year}-01-01"  # a full fiscal year, 365 days
            if fp == "Q1":
                obs["end"] = f"{end_year}-03-31"
            if fp == "Q4":
                obs["start"] = f"{end_year}-10-01"
        obs["accn"] = accn
        units: dict[str, list[dict[str, Any]]] = gaap.setdefault(tag, {"units": {}})["units"]
        units.setdefault(unit, []).append(obs)

    for fy in years:
        filed = f"{fy + 1}-02-15"
        accn = f"SIM-{fy}-K"
        for end_year in (fy, fy - 1):
            if end_year < 2020:
                continue
            for item in truth:
                if item == "long_term_debt" and end_year == 2020:
                    continue  # never published: the 2020 long-term debt is absent from the file
                add(item, fy, end_year, truth[item][end_year], "10-K", "FY", accn, filed)
        if fy == 2023:
            add("revenue", fy, 2023, rev[2023] // 4, "10-K", "Q4", accn, filed)
    # Restatement of FY2022 revenue, filed later as a 10-K/A.
    add("revenue", 2023, 2022, round(rev[2022] * 1.012), "10-K/A", "FY", "SIM-2023-KA", "2024-03-01")
    # Quarterly revenue from 10-Q filings: never annual, so the rules ignore them.
    for fy in years[1:]:
        add("revenue", fy, fy, rev[fy] // 4, "10-Q", "Q1", f"SIM-{fy}-Q1", f"{fy}-05-10")
    return {
        "cik": 1,
        "entityName": "SIMULATED FILER 1 (generated; not a real company)",
        "facts": {"us-gaap": gaap},
    }


def observation_counts(gaap: Mapping[str, Any]) -> dict[str, int]:
    counts: dict[str, int] = {}
    for block in gaap.values():
        for rows in block["units"].values():
            for row in rows:
                counts[row["form"]] = counts.get(row["form"], 0) + 1
    return dict(sorted(counts.items()))


def as_of_monotone(facts: Mapping[str, Any], cutoffs: list[str], item: str) -> bool:
    """Proposition 3.1 in the lesson: a later cutoff never selects an earlier filing for a period end."""
    gaap = _us_gaap(facts)
    tag = TAG_PRIORITY[item][0]
    previous: dict[date, date] = {}
    for cut in cutoffs:
        current = {
            end: obs.filed for end, obs in _as_of_pick(gaap, tag, "USD", item in FLOW_ITEMS, _date(cut, "cut")).items()
        }
        for end, filed in previous.items():
            if end in current and current[end] < filed:
                return False
        previous = current
    return True


def tie_filer(first: float, second: float) -> dict[str, Any]:
    """A SIMULATED one-tag mapping with two annual observations filed the same day under the same accession."""
    row = {"end": "2023-12-31", "filed": "2024-02-15", "form": "10-K", "fp": "FY", "accn": "SIM-2023-K"}
    rows = [{**row, "val": first}, {**row, "val": second}]
    return {"facts": {"us-gaap": {"Assets": {"units": {"USD": rows}}}}}


def millions(value: float) -> str:
    return f"{value / 1e6:,.1f}"


def main() -> None:
    filer = make_filer()
    gaap = _us_gaap(filer)
    counts = observation_counts(gaap)
    print("SIMULATED filer: observations by form", counts)

    table = standardize(filer)
    print("standardize(as_of=None): USD millions; source of revenue in brackets")
    picked = select(filer)
    print("period_end  items  revenue  net_income  total_assets  equity  shares_m  revenue_tag")
    for end_iso, items in table.items():
        end = date.fromisoformat(end_iso)
        tag = picked["revenue"][end][0] if end in picked["revenue"] else "absent"
        print(
            f"{end_iso}  {len(items):5d}  {millions(items.get('revenue', math.nan)):>7}"
            f"  {millions(items.get('net_income', math.nan)):>10}  {millions(items.get('total_assets', math.nan)):>12}"
            f"  {millions(items.get('equity', math.nan)):>6}  {items.get('shares_outstanding', math.nan) / 1e6:>8.1f}"
            f"  {tag}"

5Malformed input fails loudly

A required key missing, a value that is not a finite number, a boolean used as a number, a date that is not an ISO date, or a file without facts each raises ValueError. The message names the observation and the condition. Lab 1 prints four such cases. The contract's tie rule (Remark 3.4) adds one more error of the same kind, for a conflicting tie, and it lets an equal-valued tie pass. The design choice is the one the program's rules require: invalid input fails loudly, and no value is invented to keep a pipeline running.

6Where the canon breaks

The standard treatment treats a filing's statements as a faithful, comparable record of the firm. Four facts in this lesson break that frame in practice.

  • Comparability depends on tags, not on the line label. The engine maps a tag name to an item. Two firms that label a line the same way can use different tags, and two firms that use the same tag can have measured the concept differently. Priority lists reduce this problem but do not remove it. The lab's revenue tag changes in 2022, and comparing 2021 with 2022 assumes that the two tags measure the same concept. In the simulation they do, by construction. In a real filing that is an assumption to test.
  • An extension tag is invisible. A15 reads only us-gaap. A filer that reports a line under its own extension taxonomy gets no value for the matching item. That follows from the contract's rule that only us-gaap is read, and it means the standardized table is a subset of what the filer reported.
  • A restatement is a second fact, not a correction in place. The file keeps the original and the restated observations. Which one the analyst should use depends on the question. The as-of rule makes the choice explicit. A backtest that wants the information of the decision date needs the original. An analysis of the firm's economics today may want the restated value. Lab 1 shows the two values side by side.
  • Mixing states within one row produces numbers that match neither filing. Standardization takes each item from its own winning observation. If one item is restated and a related item is not, a ratio built from both can match neither filing. Lesson 2 shows this for the 2022 receivables ratio in the same simulated filer.

7Misconceptions

  1. “The latest filing gives the best value for each year.”

    For the question “what did the market know on the decision date”, the latest filing is the wrong one. Lab 1 shows FY2022 revenue of 1,131.9 USD m under a cut-off of 2023-06-30 and 1,145.5 USD m with no cut-off. The second value was not in the file on the first date, so using it would leak information from the future. Corollary 3.3 gives the exact condition.

  2. “A missing value in one year means the firm had zero.”

    Proposition 4.3 says the standardizer never fills an absent item. Lab 1 shows long-term debt absent for 2020, not zero. Any ratio that needs that item raises an error (Lesson 2 and Lesson 3 show the error). Treating absence as zero would turn a tagging gap into a claim about the balance sheet.

  3. “Quarterly figures can fill in the annual column.”

    Definition 2.1 excludes 10-Q observations and any row whose fp is not FY. Lab 1's SIMULATED filer contains a Q4 row inside a 10-K, and its value is a quarter of the year, not a year. Both are ignored by the annual rule, because their durations are about 90 days and their fp is not FY.

  4. “When a filer changes the tag for an item, the series stays comparable.”

    The standardizer does not check this. It selects a tag for each period end, and the change of tag in Lab 1's 2021–2022 revenue is visible only in the revenue_tag column. Whether the two tags measure the same concept is a question about the filing, and the table cannot answer it.

8Problem set

Every problem has a full worked solution. Attempt each one before opening it. Problems marked on Lab 1 use the SIMULATED filer it generates.

Mechanics

M1 · Which durations are annual?

Under Definition 2.1, which of these flow observations are annual, given fp = FY and form = 10-K: durations of 91, 364, 371 and 730 days?

Solution

The window is \(350 \le d \le 380\). The 91-day duration is a quarter and fails. The 364-day and 371-day durations are a 52-week and a 53-week year and pass. The 730-day duration is a two-year cumulative period and fails. The annual observations are therefore those of 364 and 371 days, and the quarter and the two-year period are ignored.

M2 · Which FY2022 revenue is selected?

In Lab 1's filer, FY2022 revenue has three annual observations: the FY2022 10-K (filed 2023-02-15), the FY2023 10-K comparative (filed 2024-02-15) and the 10-K/A (filed 2024-03-01). What does the standardizer return for the 2022 year end at each cut-off: 2023-02-14, 2023-02-15, 2024-02-29, and no cut-off? Give USD m to one decimal.

Solution

At 2023-02-14 no observation has filed at or before the cut-off, so the 2022 year end is absent for revenue. At 2023-02-15 the FY2022 10-K qualifies alone, giving 1,131.9. At 2024-02-29 the FY2023 10-K qualifies as well. It has the later filing date, 2024-02-15, and reports the same original value, so the answer is 1,131.9. With no cut-off the 10-K/A qualifies, its filing date 2024-03-01 is the latest, and the answer is the restated 1,145.5. Lab 1 prints the last two values and the 1,131.9 value for 2023-06-30.

M3 · A year end that does not yet exist

In Lab 1's filer the FY2024 10-K was filed on 2025-02-15. What does the standardizer return for the 2024-12-31 year end with a cut-off of 2025-01-31, and with a cut-off of 2025-02-15?

Solution

With a cut-off of 2025-01-31 no annual observation for the 2024 year end has filed at or before the cut-off, so the 2024-12-31 key is absent from the table. With a cut-off of 2025-02-15 the 10-K qualifies, since the rule is filed ≤ as_of, and the year end is present. The two answers differ only through the filing date, which is the point of the as-of rule: a year end exists only from the date its filing exists.

Proof

P1 · The number of changes is bounded

Fix a tag and a period end, and let \(k\) be the number of annual observations for that pair. Show that as the cut-off \(c\) increases, the as-of selection changes at most \(k\) times.

Solution

The selection at \(c\) is the maximum over the observations with \(\texttt{filed} \le c\). Between two consecutive filing dates the set of observations with \(\texttt{filed} \le c\) does not change, so the maximum does not change. The selection can therefore change only at a cut-off equal to the filing date of one of the \(k\) observations. Each observation can cause at most one change, when it first enters the set. Hence there are at most \(k\) changes. The bound is attained when the filing dates are distinct and each later filing has a greater \((\texttt{filed}, \texttt{accn})\) than the one before it.

P2 · No cut-off equals the last filing date

Let \(c^\ast\) be the latest filed date in a file. Prove that the table with no cut-off equals the table with cut-off \(c^\ast\).

Solution

Every observation in the file has \(\texttt{filed} \le c^\ast\), so the set of observations passing the cut-off at \(c^\ast\) is the whole set. The set passing the test with no cut-off is also the whole set, because no test applies. The as-of selection at each period end is the maximum over the same set in both cases, so it is the same observation. Tag priority then acts on identical selections, so the two tables agree item by item. This is the content of Corollary 3.3.

P3 · Absence is not a value

Show that if no tag in an item's list has an annual observation at period end \(e\), then the standardized table has no entry for that item at \(e\), and that no other rule of the contract can create one.

Solution

An entry for an item at \(e\) is created only in the assignment step of the standardizer, which runs over the winning observations of Definition 4.1. The winners for the item are the ends for which some tag has a selection, and the winning tag is one with a selection at that end. If no tag has an annual observation at \(e\) there is no selection at \(e\) for any tag, so \(e\) is not a winner and the table has no entry at \(e\). No other step writes to the table, so no rule can create an entry. Hence the absence is preserved.

Empirical

E1 · Counting what the file contains (SIMULATED)

Lab 1 prints the observations in the SIMULATED filer by form. How many 10-K/A and 10-Q observations does the file contain, and what does the annual rule do with each?

Solution

The first line of Lab 1's output prints the counts by form: 10-K 152, 10-K/A 1 and 10-Q 4. The file therefore holds one 10-K/A and four 10-Q observations. Under Definition 2.1 the 10-K/A is an annual candidate, because its form starts with 10-K and its fp is FY, and it is selected for 2022 once its filing date is in range. The four 10-Q observations are never annual, because their form does not start with 10-K, so they are validated and then discarded.

E2 · How large is the restatement? (SIMULATED)

Using Lab 1's output, compute the difference between FY2022 revenue with no cut-off and with the 2023-06-30 cut-off, in USD m and as a percentage of the value filed in February 2023.

Solution

The lab prints 1,145.5 with no cut-off and 1,131.9 at 2023-06-30. The difference is 13.6 USD m. As a percentage of 1,131.9 it is \(13.6 / 1{,}131.9 = 1.20\%\). The exact value, from the unrounded figures, is 1.2000%, because the generator multiplies the filed value by 1.012. The lab prints only one decimal, so the 1.2% comes from a calculation on the printed values and from the generator's constant, which the lesson states openly. No real restatement is implied.

E3 · The missing item in 2020 (SIMULATED)

Lab 1 prints 16 items for the 2020 year end and 17 for every later year end. Which item is absent in 2020, and what would the standardizer do if a ratio needed it?

Solution

The absent item is long_term_debt. The generator publishes no LongTermDebtNoncurrent observation with a 2020 year end, so the as-of selection has nothing for that date and Proposition 4.3 leaves the key out. A ratio that needs the item, such as debt to assets for 2020 or invested capital for 2020, raises a ValueError naming the item and the period end. Lab 1 prints no ROIC. The same mechanism appears for invested capital in Lab 3, whose ROIC at 2021-12-31 raises the same error, since the average for 2021 needs the 2020 value.

Research

R1 · A point-in-time test for a real filer

You have a real company-facts file for one filer and a list of decision dates. Specify a test that shows whether the standardized table the engine produces on each decision date uses only filings made on or before that date. State what the test checks, what it cannot check, and what would make it fail.

Solution

For each decision date \(d\), run the standardizer with \(c = d\). Then, for each item and period end in the output, check that the winning observation's filed date is at most \(d\). By Definition 3.1 this is automatic when the code is correct, so the test is a regression check on the code, not evidence about the filer. It cannot check whether the filing itself was made on time, or whether the decision date was a date on which the analyst could have traded. It fails if a winning observation has a later filed date, which would show that the cut-off was not applied to one of the items, or if an item was filled from a neighbouring year, which Proposition 4.3 rules out. A second test uses the Lab 1 method: the output with no cut-off and with \(c = d\) must agree on all period ends that have a filing on or before \(d\) and disagree wherever a later amendment changed a value.

R2 · Growth across a tag switch (hypothetical)

Suppose that in the switch year the old tag reports a fraction \(\delta\) less revenue than the new tag for the same economic revenue, so that the prior year's value under the old tag is \((1-\delta)R_{t-1}\), while the current year under the new tag is \(R_t\). The true growth is \(g\), with \(R_t = (1+g) R_{t-1}\). Derive the growth the standardized series shows, and the bias, for \(\delta = 0.02\) and \(g = 0.05\). State the assumption under which the prior-year value is the old tag and not the new one.

Solution

The measured growth is \(\hat g = R_t / ((1-\delta) R_{t-1}) - 1 = (1+g)/(1-\delta) - 1\). The bias is \(\hat g - g = (1+g)/(1-\delta) - (1+g) = (1+g)\,\delta/(1-\delta)\). For \(\delta = 0.02\) and \(g = 0.05\) this is \(1.05 \times 0.02 / 0.98 = 0.02143\), so the measured growth is \(1.05/0.98 - 1 = 7.1\%\) against a true 5.0%. The assumption is that the prior year end is supplied by the old tag. Definition 4.1 takes the first tag in the list that has an observation, not the tag that measures the concept on the same basis. If the list ranks the old tag first, the bias stays. If the prior year end is supplied by a tag on the new basis, it disappears. The problem shows that the priority list decides the answer, not only the arithmetic.

R3 · A backtest's cut-off rule

A strategy trades on the first trading day after each annual filing and holds for twelve months. State the cut-off a backtest should pass to the standardizer for the signal at each rebalance, justify it from Corollary 3.3, and say what the rule costs in data coverage.

Solution

The signal at a rebalance date \(d\) may use only information filed on or before the trading decision, so the cut-off is \(c = d\) (or the last close before the trade, if the trade is executed after that close). Corollary 3.3 shows that passing no cut-off would use the restated values from the 10-K/A, filed after \(d\) in general, and would leak the future into the signal. The cost is coverage: a period end whose filing is after \(d\) is absent at \(d\), so the strategy cannot use the newest year until its filing date. In the Lab 1 filer, the 2024 year end is unavailable on any date before 2025-02-15. A backtest that reports the year-end figure for a date before its filing has overstated what was known. The rule also needs a record of filing dates, which the file supplies through filed.
