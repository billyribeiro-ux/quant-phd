Batch-Auction Counterfactual

Continuous limit order books possess a fundamental market design flaw: when public information updates correlated asset values, high-frequency traders engage in an arms race to snipe stale quotes before liquidity providers can cancel them. This project constructs an empirical simulation engine (counterfactual.py) that replays identical order streams through continuous trading and frequent batch auctions (FBA). You will measure the exact latency-arbitrage rents extracted by fast traders, quantify market maker losses and investor welfare improvements, and author an analytical research memo (report.md) evaluated by rubric.

40 h lessons · 20 h project (33%)

Rung 1 · Worked example

In this worked example, an order stream of 60 events—comprising public price jumps and exogenous investor buys and sells—is evaluated under continuous trading and a 100 ms frequent batch auction.

Lab 1 · Continuous vs Frequent Batch Auction counterfactual

Replaying the identical event stream will demonstrate that: (1) under continuous trading, snipers extract latency-arbitrage rents whenever public jumps exceed the half-spread; (2) under frequent batch auctions, latency-arbitrage rents drop to exactly zero; (3) offsetting investor orders cross directly at the mid-price, yielding substantial spread savings.

"""Lab MS2-project-1: Rung 1 worked example for batch-auction counterfactual.

Simulates an order stream under continuous trading (CLOB) and frequent batch auctions (FBA),
computing latency arbitrage rents, market maker PnL, and investor welfare.
"""

from __future__ import annotations

import math
import random
from typing import Any


def run_worked_example() -> None:
    rng = random.Random(42)
    initial_price = 100.0
    half_spread = 0.05
    mm_latency = 2.5
    sniper_latencies = [0.8, 1.2, 1.5]
    batch_interval = 100.0

    print("Step 1 | Generating order stream: 60 events (jumps and investor orders)")
    events: list[dict[str, Any]] = []
    current_time = 0.0
    for _ in range(60):
        current_time += round(rng.expovariate(0.05) + 0.1, 2)
        u = rng.random()
        if u < 0.25:
            delta = round(rng.choice([-1.0, 1.0]) * rng.uniform(0.10, 0.25), 4)
            events.append({"time": round(current_time, 2), "type": "jump", "price_delta": delta, "size": 1})
        elif u < 0.625:
            events.append({"time": round(current_time, 2), "type": "investor_buy", "price_delta": 0.0, "size": 1})
        else:
            events.append({"time": round(current_time, 2), "type": "investor_sell", "price_delta": 0.0, "size": 1})

    t0 = events[0]["time"]
    t_end = events[-1]["time"]
    print(f"Step 1 | Generated {len(events)} events. First event at t={t0}ms, last at t={t_end}ms")

    # Step 2: Continuous limit order book simulation
    mid_clob = initial_price
    fastest_sniper = min(sniper_latencies)
    clob_rents = 0.0
    clob_snipe_count = 0
    clob_trades = 0
    mm_cash_clob = 0.0
    mm_inv_clob = 0

    for e in events:
        t = e["type"]
        sz = e["size"]
        if t == "jump":
            d = e["price_delta"]
            if fastest_sniper < mm_latency:
                if d > half_spread:
                    p = mid_clob + half_spread
                    new_m = mid_clob + d
                    r = (new_m - p) * sz
                    clob_rents += r
                    clob_snipe_count += 1
                    clob_trades += 1
                    mm_cash_clob += p * sz
                    mm_inv_clob -= sz
                elif d < -half_spread:
                    p = mid_clob - half_spread
                    new_m = mid_clob + d
                    r = (p - new_m) * sz
                    clob_rents += r
                    clob_snipe_count += 1
                    clob_trades += 1
                    mm_cash_clob -= p * sz
                    mm_inv_clob += sz
            mid_clob += d
        elif t == "investor_buy":
            p = mid_clob + half_spread
            mm_cash_clob += p * sz
            mm_inv_clob -= sz
            clob_trades += 1
        elif t == "investor_sell":
            p = mid_clob - half_spread
            mm_cash_clob -= p * sz
            mm_inv_clob += sz
            clob_trades += 1

    mm_pnl_clob = mm_cash_clob + mm_inv_clob * mid_clob

    print("Step 2 | Continuous Trading (CLOB) Results:")
    print(f"       | Total Trades:                {clob_trades:d}")
    print(f"       | Latency Arbitrage Trades:    {clob_snipe_count:d}")
    print(f"       | Latency Arbitrage Rents ($): {clob_rents:.4f}")
    print(f"       | Market Maker PnL ($):        {mm_pnl_clob:.4f}")
    print(f"       | Final Mid-Price ($):         {mid_clob:.4f}")

    # Step 3: Frequent Batch Auction simulation
    mid_fba = initial_price
    fba_trades = 0
    mm_cash_fba = 0.0
    mm_inv_fba = 0
    spread_savings = 0.0

    max_t = max(float(e["time"]) for e in events)
    n_batches = math.ceil(max_t / batch_interval) + 1
    batches: list[list[dict[str, Any]]] = [[] for _ in range(n_batches)]
    for e in events:
        batches[int(float(e["time"]) // batch_interval)].append(e)

    for b in batches:
        if not b:
            continue
        buys = 0
        sells = 0
        for e in b:
            if e["type"] == "jump":
                mid_fba += float(e["price_delta"])
            elif e["type"] == "investor_buy":
                buys += int(e["size"])
            elif e["type"] == "investor_sell":
                sells += int(e["size"])

        cross = min(buys, sells)
        if cross > 0:
            spread_savings += cross * half_spread * 2.0
            fba_trades += 1

        imbalance = buys - sells
        if imbalance > 0:
            p = mid_fba + half_spread
            mm_cash_fba += p * imbalance
            mm_inv_fba -= imbalance
            fba_trades += 1
        elif imbalance < 0:
            p = mid_fba - half_spread
            mm_cash_fba -= p * (-imbalance)
            mm_inv_fba += -imbalance
            fba_trades += 1

    mm_pnl_fba = mm_cash_fba + mm_inv_fba * mid_fba

    print("Step 3 | Frequent Batch Auction (FBA, delta=100ms) Results:")
    print(f"       | Batch Clearing Events:       {fba_trades:d}")
    print("       | Latency Arbitrage Trades:    0")
    print("       | Latency Arbitrage Rents ($): 0.0000")
    print(f"       | Multilateral Spread Savings: ${spread_savings:.4f}")
    print(f"       | Market Maker PnL ($):        {mm_pnl_fba:.4f}")
    print(f"       | Final Mid-Price ($):         {mid_fba:.4f}")

    print("Step 4 | Welfare Comparison:")
    print(f"       | Latency Rent Elimination:    ${clob_rents:.4f}")
    print(f"       | Market Maker PnL Gain:       ${mm_pnl_fba - mm_pnl_clob:.4f}")


def main() -> None:
    run_worked_example()

The theoretical model and counterfactual mechanics

The counterfactual framework formalizes the continuous-time limit order book arms race and frequent batch auction mechanics established by Budish, Cramton & Shim (2015).

Assumptions

  1. A1 · Correlated security and public innovations. At discrete jump times \(\tau_k\), public innovations arrive from a correlated venue, shifting the fundamental efficient mid-price \(V_t\) by \(\Delta V_k \in \R\). Innovations are observable immediately by all market participants.
  2. A2 · Market maker quote provision. A competitive market maker maintains bilateral limit orders at half-spread \(s/2 > 0\) around the mid-price: bid \(B = V_t - s/2\) and ask \(A = V_t + s/2\). Upon observing an innovation \(\Delta V_k\) at time \(\tau_k\), the market maker sends a cancel/replace message that reaches the matching engine at time \(\tau_k + \delta_{\text{MM}}\).
  3. A3 · Latency arbitrageurs. Competing latency arbitrageurs (snipers) observe the innovation and transmit aggressive market orders to pick off stale quotes. The fastest sniper's order reaches the matching engine at time \(\tau_k + \delta_{\text{sniper}}\), where \(\delta_{\text{sniper}} < \delta_{\text{MM}}\).
  4. A4 · Continuous limit order book clearing (CLOB). In continuous trading, orders are processed in serial order of matching engine arrival. If \(\delta_{\text{sniper}} < \delta_{\text{MM}}\) and \(|\Delta V_k| > s/2\), the fastest sniper's order executes against the stale quote before the cancellation request arrives, extracting rent \(R_k = (|\Delta V_k| - s/2) \cdot q\).
  5. A5 · Frequent batch auction clearing (FBA). In frequent batch auctions, continuous time is partitioned into discrete intervals \([m\Delta, (m+1)\Delta)\). All orders and cancellations received during the interval are treated as arriving simultaneously and clear at a uniform auction price at time \((m+1)\Delta\). Because cancellations and snipes are batched together, speed within the interval confers no priority, and stale quote sniping rents are strictly zero.

Theoretical propositions

Proposition 1 · Latency-arbitrage rent extraction in CLOB. Under Assumptions A1–A4, whenever a price innovation satisfies \(|\Delta V_k| > s/2\) and \(\delta_{\text{sniper}} < \delta_{\text{MM}}\), the latency arbitrageur earns positive economic rent: \[R_k = (|\Delta V_k| - s/2) \cdot q_k > 0,\] which is borne entirely as an adverse selection loss by the liquidity-providing market maker.

Proposition 2 · Elimination of latency arbitrage in FBA. Under Assumptions A1–A3 and A5, for any batch auction interval \(\Delta \ge \delta_{\text{MM}}\), all orders and cancellations triggered by innovation \(\Delta V_k \in [m\Delta, (m+1)\Delta)\) are processed in the same uniform-price auction at \((m+1)\Delta\). The latency-arbitrage rent extracted from stale quotes is identically zero: \[R_{\text{FBA}} \equiv 0.\] Furthermore, offsetting investor buy and sell orders within the batch interval cross directly at the uniform clearing price, avoiding the bid–ask spread entirely.

"""Lab MS2-project-3: Rung 3 benchmark parameter grid for research memo.

Evaluates counterfactual continuous trading vs frequent batch auctions
across batch intervals delta in {10.0, 50.0, 100.0, 250.0, 500.0} ms.
Produces the reference output table required for the student report.
"""

from __future__ import annotations

import math
import random
from typing import Any


def simulate_continuous_book(
    events: list[dict[str, Any]],
    initial_price: float,
    half_spread: float,
    mm_latency: float,
    sniper_latencies: list[float],
) -> dict[str, Any]:
    mid_price = float(initial_price)
    fastest_sniper = min(sniper_latencies)

    latency_arbitrage_count = 0
    latency_arbitrage_rents = 0.0
    investor_volume = 0

    mm_cash = 0.0
    mm_inventory = 0

    trades = 0

    for e in events:
        etype = e["type"]
        size = int(e["size"])

        if etype == "jump":
            delta = float(e["price_delta"])
            if fastest_sniper < mm_latency:
                if delta > half_spread:
                    exec_price = mid_price + half_spread
                    new_mid = mid_price + delta
                    rent = (new_mid - exec_price) * size
                    latency_arbitrage_count += 1
                    latency_arbitrage_rents += rent
                    mm_cash += exec_price * size
                    mm_inventory -= size
                    trades += 1
                elif delta < -half_spread:
                    exec_price = mid_price - half_spread
                    new_mid = mid_price + delta
                    rent = (exec_price - new_mid) * size
                    latency_arbitrage_count += 1
                    latency_arbitrage_rents += rent
                    mm_cash -= exec_price * size
                    mm_inventory += size
                    trades += 1
            mid_price += delta

        elif etype == "investor_buy":
            exec_price = mid_price + half_spread
            mm_cash += exec_price * size
            mm_inventory -= size
            investor_volume += size
            trades += 1

        elif etype == "investor_sell":
            exec_price = mid_price - half_spread
            mm_cash -= exec_price * size
            mm_inventory += size
            investor_volume += size
            trades += 1

    mm_pnl = mm_cash + mm_inventory * mid_price

    return {
        "trade_count": trades,
        "latency_arbitrage_count": latency_arbitrage_count,
        "latency_arbitrage_rents": round(latency_arbitrage_rents, 4),
        "mm_pnl": round(mm_pnl, 4),
    }


def simulate_batch_auction(
    events: list[dict[str, Any]],
    initial_price: float,
    half_spread: float,
    batch_interval: float,
) -> dict[str, Any]:
    mid_price = float(initial_price)
    spread_savings = 0.0
    mm_cash = 0.0
    mm_inventory = 0
    trade_count = 0

    max_time = max(float(e["time"]) for e in events)
    num_batches = math.ceil(max_time / batch_interval) + 1
    batches: list[list[dict[str, Any]]] = [[] for _ in range(num_batches)]

    for e in events:
        b_idx = int(float(e["time"]) // batch_interval)
        batches[b_idx].append(e)

    for b_events in batches:
        if not b_events:
            continue

        buy_orders = 0
        sell_orders = 0

        for e in b_events:
            etype = e["type"]
            size = int(e["size"])
            if etype == "jump":
                mid_price += float(e["price_delta"])
            elif etype == "investor_buy":
                buy_orders += size
            elif etype == "investor_sell":
                sell_orders += size

        crossed = min(buy_orders, sell_orders)
        if crossed > 0:
            spread_savings += crossed * half_spread * 2.0
            trade_count += 1

        net = buy_orders - sell_orders
        if net > 0:
            exec_price = mid_price + half_spread
            mm_cash += exec_price * net
            mm_inventory -= net
            trade_count += 1
        elif net < 0:
            exec_price = mid_price - half_spread
            mm_cash -= exec_price * (-net)
            mm_inventory += -net
            trade_count += 1

    mm_pnl = mm_cash + mm_inventory * mid_price

    return {
        "trade_count": trade_count,
        "latency_arbitrage_count": 0,
        "latency_arbitrage_rents": 0.0,
        "spread_savings": round(spread_savings, 4),
        "mm_pnl": round(mm_pnl, 4),
    }


def make_benchmark_instance(seed: int) -> dict[str, Any]:
    rng = random.Random(seed)
    n_events = 120
    initial_price = 100.0
    half_spread = 0.05
    mm_latency = 2.5
    sniper_latencies = [0.8, 1.2, 1.5]
    batch_intervals = [10.0, 50.0, 100.0, 250.0, 500.0]

    events: list[dict[str, Any]] = []
    current_time = 0.0
    for _ in range(n_events):
        current_time += round(rng.expovariate(0.04) + 0.1, 2)
        u = rng.random()
        if u < 0.25:
            delta = round(rng.choice([-1.0, 1.0]) * rng.uniform(0.10, 0.30), 4)
            events.append({"time": round(current_time, 2), "type": "jump", "price_delta": delta, "size": 1})
        elif u < 0.625:
            events.append({"time": round(current_time, 2), "type": "investor_buy", "price_delta": 0.0, "size": 1})
        else:
            events.append({"time": round(current_time, 2), "type": "investor_sell", "price_delta": 0.0, "size": 1})

    return {
        "events": events,
        "initial_price": initial_price,
        "half_spread": half_spread,
        "mm_latency": mm_latency,
        "sniper_latencies": sniper_latencies,
        "batch_intervals": batch_intervals,
    }


def main() -> None:
    inst = make_benchmark_instance(1)

Model specification

We evaluate an electronic financial market under two competing market architectures following Budish, Cramton & Shim (2015). The economy satisfies Assumptions A1–A5: public price jumps \(\Delta V_k\) arrive at discrete times \(\tau_k\); a competitive market maker quotes half-spread \(s/2\) and updates quotes with latency \(\delta_{\text{MM}} = 2.5\) ms; competing snipers observe jumps with latency \(\delta_{\text{sniper}} = 0.8\) ms. In continuous trading (CLOB), orders execute serially, allowing snipers to pick off stale quotes whenever \(\delta_{\text{sniper}} < \delta_{\text{MM}}\). In frequent batch auctions (FBA), continuous time is discretized into intervals \([m\Delta, (m+1)\Delta)\), within which all submissions clear at a uniform double-auction price.

Estimators and identities

The rent extracted on a stale quote snipe is \(R_k = (|\Delta V_k| - s/2) \cdot q_k\) when \(|\Delta V_k| > s/2\) and \(\delta_{\text{sniper}} < \delta_{\text{MM}}\), and zero otherwise (Proposition 1). In frequent batch auctions with \(\Delta \ge \delta_{\text{MM}}\), the market maker's cancellation arrives within the same batch interval as the snipers' orders. Because all orders within the batch clear simultaneously at the uniform price, stale quote sniping rents are identically zero: \(R_{\text{FBA}} \equiv 0.0\) (Proposition 2). Furthermore, offsetting investor buys \(B_m\) and sells \(S_m\) cross directly at the mid-price, yielding spread savings \(2(s/2) \min(B_m, S_m)\). The solver validates seven boundary conditions, raising ValueError on non-positive prices, non-positive spreads, negative latencies, empty logs, or out-of-order timestamps.

Results and counterfactual analysis

The Lab 3 benchmark grid (seed 1, \(N = 120\) events, \(s/2 = 0.05\)) demonstrates the transformative welfare impact of batch auctions. In continuous trading, snipers pick off 27 stale quotes, extracting $4.0048 in latency-arbitrage rents and imposing severe adverse selection on the market maker. Under FBA, latency-arbitrage rents drop to exactly $0.0000 across all batch intervals \(\Delta \in \{10, 50, 100, 250, 500\}\) ms. In addition, as \(\Delta\) expands from 10 ms to 500 ms, trade netting increases: multilateral spread savings grow monotonically from $0.8000 (at 10 ms) to $3.8000 (at 500 ms), as 76 of 93 investor orders cross directly without paying dealer spreads.

Numerical rigour and rounding

All internal computations operate on IEEE 754 64-bit floating-point numbers. Display outputs are rounded to four decimal places. As a manual verification check, consider the first sniped jump in the event log: \(\Delta V_1 = +0.1742\), \(s/2 = 0.0500\), \(q = 1\). Because \(\delta_{\text{sniper}} = 0.8 < 2.5 = \delta_{\text{MM}}\) and \(\Delta V_1 > s/2\), the sniper buys at the stale ask \(P = 100.0000 + 0.0500 = 100.0500\). The new mid-price is \(100.1742\). The exact rent extracted is \(100.1742 - 100.0500 = 0.1242\), matching solver output to machine precision.

Limits and evidence

While frequent batch auctions eliminate latency arbitrage (Budish et al. 2015), three structural limitations warrant caution: (1) Execution delay: Urgent traders with idiosyncratic liquidity needs must wait up to \(\Delta\) for execution; (2) Cross-venue fragmentation: If one exchange adopts batch auctions while others remain continuous, cross-market arbitrageurs can exploit price discrepancies across venues (Brogaard et al. 2014); (3) Inventory volatility: Batching concentrates inventory absorption at discrete points, requiring robust dealer capitalization during market stress (Kirilenko et al. 2017).
