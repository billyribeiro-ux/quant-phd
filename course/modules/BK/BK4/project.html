Clearing-house simulator

In this model, a clearing house takes the other side of each trade its members make, and it holds margin (the collateral each member posts) and default funds (each member's contribution to a pool that covers defaults) against the risk. When a member defaults, a fixed order of layers (a waterfall) pays the loss, by the rule of this simulator. You will write the simulator that pays one default through those layers, shares among the surviving members the loss that the layers leave unpaid (the residual), and sizes the defaulter's margin for a target cover (defined under Conventions). The code is tested against hand-computed fixtures and against the rules on this page, and the memo is graded against the rubric.

Rungs 1 and 2

Both labs use one illustrative clearing house with four members, and all of its amounts are SIMULATED: they are illustrative values, not market data, and no file is read. Every amount is an integer number of cents, and every cover (the share of the scenarios whose loss a margin covers in full, defined under Conventions) is an integer number of basis points (bps, one hundredth of a percentage point), floored (rounded down to a whole number). Member 2 defaults. Its initial margin (the collateral it has posted with the clearing house) is 50000 cents, and its default fund (its contribution to the pool that covers defaults) is 6000 cents. The clearing house's own capital, which this page calls the CCP capital (CCP: central counterparty), is 20000 cents. The surviving members are 1, 3 and 4, with default funds of 4000, 5000 and 3000 cents, so their pool is 12000 cents. The losses for the sizing come from a seeded generator, a set of 40 scenarios, each a simulated loss between 0 and 120000 cents (Lesson 3 defines the term scenario).

Lab 1 · Worked example: one default, step by step

Stated before running. The loss of 80000 cents is paid by the margin (50000), the default fund (6000) and the CCP capital (20000), which leaves a residual (the loss not yet paid by the three layers) of 4000 cents. The residual is below the pool of 12000, so the survivors pay pro rata (in proportion to their default funds): the floored shares are 1333, 1666 and 1000, and one cent is left over. That cent goes to member 1, so the survivors pay 1334, 1666 and 1000 cents, and nothing is left uncovered (the uncovered loss is defined under Conventions). The layers and the survivors' payments add to 80000. For the 40 seeded scenarios, a target of 9550 bps has an exact position of 191/5, which is 38.2 (the target times the count, over 10000), so the index is k = 39 and the margin is the 39th smallest loss, 117088 cents. That margin gives a cover of 9750 bps, which reaches the target, and one cent less gives 9500 bps, which does not.

"""Rung 1 worked example: one default on a four-member clearing house, every step annotated, in integer cents.

Standard library only. The inputs are SIMULATED: illustrative values, not market data. No file is read, and the
scenario losses come from a seeded generator, so every run prints the same lines.
"""

import random
from fractions import Fraction

MARGIN = {1: 30_000, 2: 50_000, 3: 40_000, 4: 20_000}  # initial margin of each member, in cents (SIMULATED)
FUND = {1: 4_000, 2: 6_000, 3: 5_000, 4: 3_000}  # default-fund contribution of each member, in cents (SIMULATED)
CAPITAL = 20_000  # the CCP's own capital, in cents (SIMULATED)
DEFAULTER = 2
LOSS = 80_000  # the loss from this one default, in cents


def main() -> None:
    # Step 1. The three layers, in order. Each layer pays what the loss still needs, up to its own size, so the
    # layers never pay the same cent twice. The defaulter's margin is used before its default fund, and the
    # default fund before the CCP capital.
    from_margin = min(LOSS, MARGIN[DEFAULTER])
    from_fund = min(LOSS - from_margin, FUND[DEFAULTER])
    from_capital = min(LOSS - from_margin - from_fund, CAPITAL)
    residual = LOSS - from_margin - from_fund - from_capital
    print(f"layers: margin {from_margin} | default fund {from_fund} | CCP capital {from_capital} | residual {residual}")
    # Step 2. The surviving members are every member except the defaulter. Their default funds form the pool that
    # pays the residual, and the pool is the sum of their contributions.
    survivors = sorted(m for m in FUND if m != DEFAULTER)
    pool = sum(FUND[m] for m in survivors)
    print(f"survivors {survivors} | default funds {[FUND[m] for m in survivors]} | pool {pool}")
    # Step 3. The residual is below the pool, so each survivor pays its pro rata share. The share is floored to a
    # whole cent, which can leave a few cents unpaid. Those cents are given out one each, to the first survivors in
    # ascending id order that have a positive contribution, so the shares add up to the residual exactly.
    uncovered = 0
    if residual >= pool:
        shares = {m: FUND[m] for m in survivors}
        uncovered = residual - pool
    else:
        shares = {m: residual * FUND[m] // pool for m in survivors}
        leftover = residual - sum(shares.values())
        print(f"floored shares {shares} | leftover cents {leftover}")
        for m in survivors:
            if leftover > 0 and FUND[m] > 0:
                shares[m] += 1
                leftover -= 1
    print(f"survivor payments {shares} | uncovered {uncovered}")
    # Step 4. The conservation check. The layers, the survivors' payments and the uncovered loss add to the loss.
    total = from_margin + from_fund + from_capital + sum(shares.values()) + uncovered
    print(f"conservation: {total} == {LOSS} is {total == LOSS}")
    # Step 5. Sizing. The scenario set is 40 losses drawn from a seeded generator, each between 0 and 120000 cents.
    rng = random.Random(1)
    losses = [rng.randint(0, 120_000) for _ in range(40)]
    count = len(losses)
    target = 9_550  # basis points: the cover we want, 95.50 % of scenarios
    # The exact position of the target in the sorted losses is target * count / 10000, a fraction: here 191/5, which
    # is 38.2. The margin must cover at least that many scenarios, so the position is rounded up: k = 39.
    exact_position = Fraction(target * count, 10_000)
    k = -((-target * count) // 10_000)
    print(f"target {target} bps of {count} scenarios: exact position {exact_position} | k {k}")
    margin = sorted(losses)[k - 1]
    print(f"margin: the {k}th smallest loss = {margin}")
    # Step 6. The cover at the margin, and one cent below it. Both are floored counts in basis points.
    covered = sum(1 for loss in losses if loss <= margin)
    below = sum(1 for loss in losses if loss <= margin - 1)
    cover_at = 10_000 * covered // count
    cover_below = 10_000 * below // count
    print(f"cover at the margin: {cover_at} bps | reaches the target: {cover_at >= target}")
    print(f"cover one cent below: {cover_below} bps | reaches the target: {cover_below >= target}")

Rung 3 · Specification

Context
In this model, a clearing house becomes the counterparty to both sides of each trade it clears, and it holds initial margin and a default fund from its members against the losses from their defaults. When a member defaults, in this simulator its initial margin pays first, then its default fund, then the clearing house's own capital, and only then do the surviving members pay, through their default funds. You write the simulator that pays one default through these layers, shares the residual among the survivors, and sizes the defaulter's margin for a target cover, where the cover of a margin is the share of the scenarios whose loss the margin covers in full. The autograder checks the cent results and the cover values, not the docstring or the imports.
Inputs
No data file. The autograder's case comes from grader/instance.py, seeded by your workspace ID. It holds N members with ids 1 to N, where N is from 4 to 6; for each member, an initial margin and a default-fund contribution in whole cents, with every default fund at least 1 cent; the CCP capital in whole cents; the defaulting member's id; a list of 40 to 80 scenario losses in whole cents; and a target cover of 9000, 9500 or 9750 basis points. All values are SIMULATED. None is market data.
Required outputs
clearing_house.py at the root of your repository, with these names. Waterfall, a frozen dataclass with the fields margin_cents, default_fund_cents and ccp_capital_cents (ints), survivor_cents (a dictionary from each surviving member's id to its cents) and uncovered_cents (an int). waterfall(loss_cents, defaulter_id, initial_margin_cents, default_fund_cents, ccp_capital_cents), which returns a Waterfall. The two dictionaries map each member id to cents, and the member ids are the keys of default_fund_cents. margin_for_cover(losses_cents, target_bps), which returns the least margin in cents whose cover is at least target_bps. cover_bps(losses_cents, margin_cents), which returns the cover in basis points. Start from the starter file, whose names and signatures are complete. The module docstring states the conventions in your own words (the layer order, the sign of every amount, the integer rule and the leftover rule). A reviewer reads the docstring; the autograder does not check it. For the memo, commit memo.md, the rubric memo described in the memo section.
Constraints
Standard library only (not checked by the autograder; a reviewer reads it). Every money value is an int in cents, and every computation is integer arithmetic, so no float appears. A survivor's share and a cover are exact fractions that are floored by integer division, and the sizing index is an exact fraction rounded up, also in integers. The leftover cents are given out as the rule below states. Each named condition below raises ValueError. Any other invalid input may raise any exception or return. On a valid input and on each named refused input, no function prints or warns. No function changes any of its arguments, including the lists and the dictionaries.
  • margin_for_cover: losses_cents is empty. The message says that at least one scenario is needed.
  • margin_for_cover: target_bps is below 1 or above 10000. The message names target_bps.
  • margin_for_cover and cover_bps: a loss is negative. The message says that losses cannot be negative.
  • cover_bps: losses_cents is empty. The message says that at least one scenario is needed.
  • waterfall: the loss, a member's initial margin, a member's default fund, or the CCP capital is negative. The message names that input, for example default_fund_cents.
  • waterfall: defaulter_id is not one of the member ids, whether it is below the lowest member id, above the highest, or between two member ids. The message names defaulter_id.
Grading mode

Its checks cover the conservation invariant (defined under Conventions) on every scenario, the layer order at each loss in the hand-computed fixture table, the remainder rule (the leftover rule under Conventions), each named condition on both sides of its limit, the sizing against the order statistic (defined under Conventions) and against a brute-force search over whole-cent margins, the cover and its floor, monotonicity, the silence of the module (no function prints or warns on a valid input or a named refusal), and its purity (no function changes its arguments). The same file runs in your browser and on your machine. It checks the cent results and the cover values, not the method that computes them. It is not secret: its integrity comes from your seeded case and from a second case, which a fixed answer for the first would also have to match. The memo is graded by rubric, against the five criteria in the rubric, each with four observable levels. You score the memo yourself with the form in the self-assessment section, and you calibrate that score on two annotated exemplars.

Conventions

  • Layer order. A loss L is paid in four steps in this order, three layers and then the surviving members, where IM_d and DF_d are the defaulter's initial margin and default fund, and K is the CCP capital: the margin pays a1 = min(L, IM_d); the default fund pays a2 = min(L - a1, DF_d); the capital pays a3 = min(L - a1 - a2, K); and the residual is R = L - a1 - a2 - a3. A layer is used only after the layer before it is exhausted. The order is a rule of this simulator. It is not a claim about any clearing house.
  • Survivors. Let DF_i be the default fund of surviving member i, and D the sum of the surviving members' default funds. If R >= D, each survivor pays its whole default fund and the uncovered loss is R - D. If R < D, survivor i pays share_i = (R * DF_i) // D, and the leftover R - sum(share_i) goes one cent each to the first survivors, in ascending id order, that have DF_i > 0. A survivor with DF_i = 0 pays zero. The uncovered loss is zero in this case.
  • Conservation. The layers, the survivors' payments and the uncovered loss add to the loss: a1 + a2 + a3 + sum(survivor payments) + uncovered = L.
  • Cover. For a list Λ of S scenario losses L_1 to L_S (capitalised, so that L stays one loss) and a margin M, cover_bps(Λ, M) = (10000 * #{s : L_s <= M}) // S. The cover is an integer in basis points, floored. A loss equal to the margin is covered.
  • Sizing. For a target t in basis points, margin_for_cover(Λ, t) is the k-th smallest of the S losses in Λ (an order statistic of the scenario losses), where k = ceil(t * S / 10000), computed in integers as -((-t * S) // 10000). Lesson 3 defines the cover and states the sizing rule with its proof under its own assumptions; this page states the rule the simulator must implement.
  • Money. Every amount is an int number of cents. The layers, the margin and the uncovered loss are formed from integers by subtraction and minimum, so they are exact integers. A survivor's share and a cover are exact fractions in general, and each is floored to an integer. The sizing index is an exact fraction rounded up to an integer.

"""Rung 3 check: the reference instance of the project page, its waterfall rows and its sizing table.

Standard library only. The inputs are SIMULATED: illustrative values, not market data. Every amount is an int in cents,
and every cover is an int in basis points, floored. The scenario losses are the seeded set of Lab 1. The brute-force
search below is a check on the sizing rule, not a proof of it.
"""

import random

MEMBERS = [1, 2, 3, 4]
MARGIN = {1: 30_000, 2: 50_000, 3: 40_000, 4: 20_000}  # initial margin of each member, in cents (SIMULATED)
FUND = {1: 4_000, 2: 6_000, 3: 5_000, 4: 3_000}  # default-fund contribution of each member, in cents (SIMULATED)
CAPITAL = 20_000  # the CCP's own capital, in cents (SIMULATED)
DEFAULTER = 2
TARGETS = (9_000, 9_500, 9_750)  # basis points


def waterfall(loss: int, margin_d: int) -> tuple[int, int, int, dict[int, int], int]:
    """Pay one loss in cents: the defaulter's margin (margin_d), its default fund, the CCP capital, then survivors."""
    from_margin = min(loss, margin_d)
    from_fund = min(loss - from_margin, FUND[DEFAULTER])
    from_capital = min(loss - from_margin - from_fund, CAPITAL)
    residual = loss - from_margin - from_fund - from_capital
    survivors = [m for m in MEMBERS if m != DEFAULTER]
    pool = sum(FUND[m] for m in survivors)
    if residual >= pool:
        return from_margin, from_fund, from_capital, {m: FUND[m] for m in survivors}, residual - pool
    shares = {m: residual * FUND[m] // pool for m in survivors}
    leftover = residual - sum(shares.values())
    for m in survivors:
        if leftover > 0 and FUND[m] > 0:
            shares[m] += 1
            leftover -= 1
    return from_margin, from_fund, from_capital, shares, 0


def margin_for_target(losses: list[int], target: int) -> int:
    """The k-th smallest loss in cents, with k = ceil(target * count / 10000) in integers."""
    k = -((-target * len(losses)) // 10_000)
    return sorted(losses)[k - 1]


def brute_force_margin(losses: list[int], target: int) -> int:
    """The least whole-cent margin whose floored cover in basis points reaches the target, found by scanning margins."""
    top = max(losses)
    tally = [0] * (top + 1)
    for loss in losses:
        tally[loss] += 1
    covered = 0
    for margin in range(top + 1):
        covered += tally[margin]
        if 10_000 * covered // len(losses) >= target:
            return margin
    return top


def main() -> None:
    # Part A. Five losses on the reference instance, each with its layers, survivor payments and uncovered loss.
    print("part A: the waterfall rows, with the defaulter's margin as set")
    for loss in (20_000, 55_000, 70_000, 80_000, 100_000):
        a1, a2, a3, shares, uncovered = waterfall(loss, MARGIN[DEFAULTER])
        total = a1 + a2 + a3 + sum(shares.values()) + uncovered
        print(
            f"loss {loss} | margin {a1} | fund {a2} | capital {a3} | survivors {shares} | "
            f"uncovered {uncovered} | conservation {total == loss}"
        )
    # Part B. Sizing for three targets on the 40 seeded scenario losses.
    rng = random.Random(1)
    losses = [rng.randint(0, 120_000) for _ in range(40)]
    print(f"part B: {len(losses)} scenarios, largest loss {max(losses)}")
    for target in TARGETS:
        k = -((-target * len(losses)) // 10_000)
        margin = margin_for_target(losses, target)
        cover_at = 10_000 * sum(1 for x in losses if x <= margin) // len(losses)
        cover_below = 10_000 * sum(1 for x in losses if x <= margin - 1) // len(losses)
        brute = brute_force_margin(losses, target)
        print(
            f"target {target} | k {k} | margin {margin} | cover {cover_at} | cover one cent below {cover_below} | "
            f"brute force {brute} | agrees {brute == margin}"
        )
    # Part C. The margin for two targets, taken as the defaulter's initial margin. Each count is the number of
    # scenarios that get past one more layer: past the margin, past the default fund, past the CCP capital (so the
    # surviving members pay), and past the surviving members' total (so a loss is uncovered).
    surviving_fund = sum(FUND[m] for m in MEMBERS if m != DEFAULTER)
    print("part C: the scenarios that get past each layer, for each margin taken as the defaulter's margin")
    for target in (9_500, 9_000):
        margin = margin_for_target(losses, target)
        past_margin = sum(1 for x in losses if x > margin)
        past_fund = sum(1 for x in losses if x > margin + FUND[DEFAULTER])
        past_capital = sum(1 for x in losses if x > margin + FUND[DEFAULTER] + CAPITAL)
        past_survivors = sum(1 for x in losses if x > margin + FUND[DEFAULTER] + CAPITAL + surviving_fund)
        print(
            f"target {target} | margin {margin} | past margin {past_margin} | past default fund {past_fund} | "
            f"past CCP capital {past_capital} | past survivors (uncovered) {past_survivors}"
        )

Rung 3 · The memo

The memo is memo.md, one to two pages, in the repository beside clearing_house.py. It states the layer amounts for one stated scenario, the margin you size for one target cover, the survivors' payments for one stated scenario, and a recommendation between two margins. Each number in the memo is printed by your own run of the simulator on the seeded case, or by Lab 1 or Lab 3 on the reference instance, or is an input of that instance in the lab code, or is a value that the rules on this page give by computation from those inputs, or is a difference or a ratio that you compute from printed numbers or inputs and state with its base, so that you can check each one against a printed line or an input before you write it.

Exemplar A

Official scoring: C1 2 · C2 2 · C3 1 · C4 2 · C5 2. The layers are named in order, but no amount is given for any scenario; the margin is stated with its target but its cover is not checked; the survivors' sharing rule is not stated; the recommendation has no cover; and two limits are named.

Setting

The clearing house has four members, and member 2 defaults. The simulator pays the loss through the margin, the default fund and the capital, and then the survivors pay.

Waterfall

The margin pays first, then the default fund, then the capital, and the survivors pay what is left of the loss.

Sizing

For a target of 9500 bps, the margin is the k-th smallest loss of the scenario set, where k is set by the target and the number of scenarios.

Survivors

The survivors share the rest.

Recommendation

We recommend the margin for 9500 bps.

Limits

The model considers one default at a time and a fixed set of scenarios.

  • Meets C1 level 2: names the layers in order, but gives the cents for no scenario.
  • Meets C2 level 2: states a sizing rule for a stated target, with no check of the cover.
  • Misses C2 level 3: the cover at the chosen margin is not checked, and the value of k is not stated.
  • Meets C3 level 1: names no sharing rule and gives no survivor amount.
  • Meets C4 level 2: recommends a margin with no cover stated.
  • Meets C5 level 2: names two limits.

Exemplar B

Official scoring: C1 4 · C2 4 · C3 4 · C4 4 · C5 4. Every criterion is met at level 4. The memo quotes only the numbers that Lab 1 or Lab 3 prints, or that the instance inputs in the lab code and the rules on this page give by computation, or a difference of two printed numbers, as the memo rule above allows.

Setting

The reference instance has four members, with initial margins of 30000, 50000, 40000 and 20000 cents, default funds of 4000, 6000, 5000 and 3000 cents, and a CCP capital of 20000 cents. Member 2 defaults, so the survivors are members 1, 3 and 4, with a pool of 12000 cents. The scenario set has 40 losses, and the instance is SIMULATED.

Waterfall

For a loss of 80000 cents, the margin pays 50000 cents, the default fund pays 6000 cents and the capital pays 20000 cents. That leaves a residual of 4000 cents, which is below the pool of 12000 cents. Under the layer order, a layer is used only after the one before it is exhausted, so the capital is used before any survivor pays. The survivors share the residual pro rata to their default funds: survivor i pays (R * DF_i) // D, floored, with R the residual and D the pool. That gives 1333, 1666 and 1000 cents, which fall one cent short of the residual. The leftover rule gives the leftover cents one each to the first survivors, in ascending id order, that have a positive default fund, so the one leftover cent goes to member 1, and the survivors pay 1334, 1666 and 1000 cents. The three payments add to 4000 cents, which is the residual: 1334 + 1666 + 1000 = 4000. The sum of the layers and the payments is 80000 cents, which is the loss. The printed line conservation: 80000 == 80000 is True in Lab 1 confirms it.

Sizing

For the target of 9500 bps, the exact position is 38.0, so k is 38. The margin is the 38th smallest loss, 111074 cents, which Lab 3 prints for that target in Part B and in Part C. Part B of Lab 3 prints the cover at that margin as 9500 bps, and one cent below it as 9250 bps, which is below the target. Part B prints the same pair for the targets 9000 and 9750 bps, with margins of 105154 and 117088 cents.

Recommendation

I recommend the margin of 111074 cents for the 9500 bps target, and its cover is 9500 bps. The counts in this paragraph take 111074 cents as the defaulter's initial margin (the Lab 3 Part C convention). The Waterfall paragraph above takes the defaulter's initial margin as 50000 cents, so these counts do not describe that waterfall. Under the 111074 convention, two scenarios are past this margin, and no scenario is past the capital or leaves an uncovered loss, so the count of scenarios that get past the surviving members, and the count with an uncovered loss, are both 0. The alternative is the margin for 9000 bps, 105154 cents, which covers 9000 bps and leaves four scenarios past the margin under the same convention. The difference is 5920 cents of initial margin (111074 less 105154, both printed in Lab 3 Part B) for 500 bps of cover (9500 less 9000, both targets printed in Lab 3 Part B), on this set.

Limits

The model simulates one default at a time, over a fixed set of 40 scenarios, and the margin is sized on that set alone. One default at a time biases the sized margin down and the cover up: if a second default added loss to the same scenarios, those losses would be at least as large, and a larger loss cannot lower the k-th smallest loss, and cannot raise the count of losses at or below a margin. The fixed set is one draw of 40 scenarios, so its error on the sized margin has no known direction. The losses are given, with no close-out period for the defaulter's positions: if the losses grew during a close-out, the sized margin would be biased low and the cover high. The margins are held fixed in stress, so if margins rose in stress the simulated cover would be biased low, and if they fell it would be biased high. The memo makes no claim about any real clearing house, so no claim in it is graded B or C, and it cites no source.

  • Meets C1 level 4: names each layer in order, gives the cents for the stated scenario, and states that a layer is used only after the one before it.
  • Meets C2 level 4: states the target, the value of k and the sorted position, and checks the cover at the margin and one cent below.
  • Meets C3 level 4: states the pro rata rule and the leftover rule, and shows that the survivors' payments sum to the residual of 4000 cents.
  • Meets C4 level 4: recommends one margin with its cover, gives the count of scenarios past the surviving members and with an uncovered loss, and compares one alternative.
  • Meets C5 level 4: names all four limits, states the direction in which each one biases the sized margin or the cover, and states that the memo makes no claim graded B or C and cites no source.

Rung 4 · Stretch

Not graded. Each extension needs a stated rule and a check against a direct computation.

  • A second default. Pay a second default from the same scenario set, after the first default's payments have reduced the surviving pool and the capital. State the reduction rule, and check that the total paid by the two defaults equals the total of their losses.
  • The number of scenarios. For the same target, measure how the sized margin changes as the number of scenarios grows from 40 to 80 on a fixed generator. State which scenario is the one the k-th smallest loss selects, and why it changes.
