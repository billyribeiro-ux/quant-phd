# Atlas A2 — data layer (`atlas.dataset`)

**Delivered in:** CS3 · Data, Databases & SQL
**Status:** proposed by the architect's assistant, architect to confirm (2026-11-09). Frozen once CS3 is released. A breaking
change goes through `CONTRACT_CHANGE_REQUESTS` (BUILDER_RULES §5.5).
**Depends on:** the Python standard library only on the grader path (`sqlite3`, `hashlib`, `csv`, `datetime`, `decimal`).
DuckDB is an optional local engine (see *Engines*). No DuckDB import happens on the grader path.
**Consumed by:** A15 (`atlas.fundamentals`) takes a parsed company-facts mapping and imports nothing from A2 (A15 contract,
lines 6-9). A15 expects "the loader that downloads and stores that JSON" from A2 (A15 contract, lines 8-9). This contract
stores the raw bytes (`ingest_raw`) and does not download anything: grading has no network access. The download step is an
honest gap until the architect decides where it lives.

Every function validates its inputs and raises `ValueError` with a message that names the violated condition. The grader
checks the exception type only where this contract names it. No function prints, warns, reads the network or mutates its
inputs. A lookup that finds nothing returns `None`; it does not raise.

## Units and formats (proposed by the architect's assistant, architect to confirm)

| Quantity | Rule |
|---|---|
| Timestamp (`retrieved`, the `t` argument) | ISO 8601 UTC with a trailing `Z`: `YYYY-MM-DDTHH:MM:SSZ`. Any other form raises `ValueError`. Naive timestamps are rejected. |
| Observation date (`date` column) | `datetime.date.fromisoformat` form `YYYY-MM-DD`. It is read as `YYYY-MM-DDT00:00:00Z`. |
| Values | Stored and returned as the exact text of the payload cell. The store never converts a value to `float`. A caller that sums values uses `decimal.Decimal`. |
| Money | The store holds no money type. A caller that stores an amount of money uses `int` cents (the i64 rule in the project's global instructions, applied in Python). A quoted price is a `Decimal` string with its tick size stated by the caller. |
| Bytes and digests | `sha256` is the lowercase hex SHA-256 of the exact payload bytes. `n_bytes` is `len(payload)`. |

## Sources (closed set)

```python
SOURCES: tuple[str, ...] = ("fred", "french", "shiller", "treasury", "edgar")
```

`source` must be one of these five ids; any other value raises `ValueError` naming the unknown source. The ids name the
issuer families the Atlas A2 row lists (`curriculum/meta.yaml` lines 203-206). **This contract does not define the published
layout of any issuer's file.** Those layouts are not in the registry and were not typed from memory. A student's adapter maps an
issuer's published file to the CSV shape below. The shapes used by the grader are generated fixtures labelled SIMULATED (see
*What is SIMULATED*).

## Input shapes

- **CSV table** (`ingest`): UTF-8, with a header row. The first column is named `date`. Every other column is a series, named
  by its header (non-empty and unique). A header-only file is valid and has zero observations. An empty cell is no observation
  for that series on that date; nothing is imputed. A payload with no header, a first column other than `date`, a duplicate or
  empty series name, or a `date` cell that is not an ISO date raises `ValueError`.
- **Raw payload** (`ingest_raw`): any bytes, stored whole, with `rows = None`. It is used for the EDGAR company-facts JSON, which
  the store keeps byte for byte so that A15's caller can parse it with `json.loads`.

## Interface

```python
@dataclass(frozen=True)
class ManifestRow:
    source: str        # one of SOURCES
    sha256: str        # lowercase hex SHA-256 of the exact payload bytes
    n_bytes: int       # len(payload), >= 0
    rows: int | None   # data rows, header excluded, for a CSV table; None for a raw payload
    retrieved: str     # the retrieval timestamp as given, validated
    licence: str       # as supplied by the caller; never empty
    source_url: str    # as supplied by the caller; never empty

def open_store(path: str, *, engine: str = "sqlite") -> Store
    # Creates or opens the store file at `path`. `path` must be non-empty.
    # engine "sqlite": standard library sqlite3. This is the grader path and the default.
    # engine "duckdb": a DuckDB file, local runs only. ValueError if the `duckdb` package cannot be imported.
    # Any other engine name raises ValueError naming it.

class Store:
    def ingest(self, source: str, payload: bytes, *, retrieved: str, licence: str, source_url: str) -> ManifestRow
        # Parses a CSV table, stores the payload bytes and one observation per non-empty cell, and writes one manifest row.
    def ingest_raw(self, source: str, payload: bytes, *, retrieved: str, licence: str, source_url: str) -> ManifestRow
        # Stores the bytes and writes one manifest row with rows=None. No observations.
    def asof(self, source: str, series: str, t: str) -> dict[str, str] | None
        # The as-of answer for one series at time t (rule below). Returns
        # {"source", "series", "date", "value", "retrieved"} with every value a str, or None when no observation qualifies.
    def manifest(self) -> list[ManifestRow]
        # Every manifest row, in ingestion order.
    def verify(self) -> None
        # Recomputes the SHA-256 of every stored payload. Raises ValueError naming the source and retrieved time of the first
        # payload whose bytes no longer hash to its manifest row.
    def close(self) -> None
```

**Deviation from the CS3 build plan, §7.4.** The plan proposed `asof(key, t)`. This contract adds `source`, because one series id
(for example a column named `DGS10`) can occur in two sources. The architect confirms.

### Ingestion rules

1. The manifest row and the observations of one call are written in one transaction. A call that fails writes nothing.
2. **Idempotence.** Ingesting the same bytes for the same source with the same `retrieved` returns the existing manifest row
   and writes no new observations. The result equals the first call's result.
3. **Conflict.** Ingesting different bytes for the same source with the same `retrieved` raises `ValueError` naming the
   conflict.
4. Ingesting the same bytes at a different `retrieved` writes a new manifest row and new observations.
5. `licence` and `source_url` must be non-empty after stripping whitespace; otherwise `ValueError` names the empty field.

### As-of rule (no look-ahead)

Let `O` be the observations of `(source, series)` with `date <= t` and `retrieved <= t`. Both comparisons are non-strict:
an observation dated or retrieved exactly at `t` is visible at `t`. The answer is the member of `O` with the greatest `date`.
When two members have the same `date`, the one ingested later wins: the later row of the later payload. This is the **tie
rule**. Within one payload, the later row wins. If `O` is empty, the answer is `None`.

Guarantee: no answer has `date > t` or `retrieved > t`. A row retrieved after `t` is not visible at `t` even when its `date` is
earlier. This is the point-in-time property the schema exists to keep.

### Store schema (both engines)

The grader tampers with stored bytes, so the schema is fixed. Column names are part of the contract.

| Table | Columns |
|---|---|
| `manifest` | `seq INTEGER PRIMARY KEY`, `source TEXT`, `sha256 TEXT`, `n_bytes INTEGER`, `rows INTEGER NULL`, `retrieved TEXT`, `licence TEXT`, `source_url TEXT` |
| `payloads` | `seq INTEGER PRIMARY KEY` (the `manifest.seq` it belongs to), `body BLOB` |
| `observations` | `seq INTEGER PRIMARY KEY`, `manifest_seq INTEGER`, `source TEXT`, `series TEXT`, `date TEXT`, `value TEXT`, `retrieved TEXT` |

`seq` is a counter the store assigns in insertion order. Its values need not match the engine's own row ids. The tie rule uses
`observations.seq`.

## Engines

- **`sqlite` (default, grader path).** The reference solution and every grader test use it. It needs no install and is the only
  engine the grader imports. **Unverified:** the repository's Pyodide lock (`course/assets/vendor/LOCK.json`, key
  `pyodide_packages`) lists no `sqlite3` entry. Whether the Pyodide build provides `sqlite3` is not confirmed here. It must be
  confirmed in the browser before the grader runs there.
- **`duckdb` (local deliverable).** The curriculum names "a DuckDB store" (`curriculum/01-foundations.yaml:477`; the
  deliverable is at `:480`). The `duckdb` package is not in `course/assets/vendor/LOCK.json` and is not in the Pyodide package list. Its version is
  not in the curriculum or the registry, so no version is chosen here. The architect pins one in `requirements*.txt`. The
  verifier runs the DuckDB engine locally, outside Pyodide, against the same behavioural tests.

## Behaviour that both engines must match

- `asof` answers equal the as-of rule above on every seed. A DuckDB answer that differs from the sqlite answer on the same
  payloads is a defect.
- `verify` detects a changed byte in any stored payload, including a changed byte in the header line.
- Decimal values come back byte-identical to the payload text (no float rounding of the value text).

## Error behaviour (summary)

| Condition | Result |
|---|---|
| Unknown source, unknown engine name, empty `path`, empty `licence` or `source_url` | `ValueError`, message names the condition |
| Malformed `retrieved` or `t` | `ValueError`, message names the field |
| Malformed CSV (no header, wrong first column, duplicate or empty series, non-ISO `date`) | `ValueError`, message names the property |
| Same source and `retrieved`, different bytes | `ValueError` (conflict) |
| `verify` finds a changed payload | `ValueError`, message names source and `retrieved` |
| `asof` finds no qualifying observation, or the series is unknown | `None` |
| `asof` for an unknown source | `ValueError` |

The grader asserts `ValueError` only for the rows named in this table. For any other invalid input it asserts that some
exception is raised and that its message names the violated property.
