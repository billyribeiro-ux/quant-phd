## Units and conventions

| Quantity | Unit and definition |
|---|---|
| Money (face, price, cash amounts) | `int`, cents. Every money output is rounded once, half up, from an exact value (see below). |
| Coupon rate, yield in the bond functions | `Fraction`, decimal per **coupon period** (0.025 means 2.5 % per period). The contract fixes no coupon frequency; the caller chooses the period and states it. |
| `periods` | `int`, number of coupon periods, `>= 1`. |
| Dates | `datetime.date` objects. ISO strings are not accepted (`TypeError`). |
| Zero rates from `bootstrap_zero_rates` | `float`, decimal per **coupon period**, the same period as the input bonds. |
| Maturity `tau` in the curve functions | `float`, in **years**, `> 0`. |
| Yields in the curve functions | `float`, decimal **per annum** (0.05 = 5 %). |
| Decay parameters `lam`, `lam1`, `lam2` | `float`, in years, `> 0`. |

**Rounding rule (money).** For an exact non-negative value `x` (a `Fraction`), the cents amount is
`floor(x + 1/2)`: one rounding, half up, applied once to the exact value. Intermediate values stay exact. The rule is
stated in the module docstring and on the FI1 project page.

**Exact versus float.** Day counts, the price from a yield and the yield to maturity are exact (`Fraction`) because
their arithmetic is rational. The Nelson–Siegel and Svensson functions and the zero rates involve `exp` and roots, which
are irrational in general, so they return `float`.

## Day counts

```python
DAY_COUNT_CONVENTIONS: tuple[str, ...] = ("ACT/360", "ACT/365", "30/360")

def day_count_fraction(start: date, end: date, convention: str) -> Fraction
    # ACT/360: (end - start).days / 360
    # ACT/365: (end - start).days / 365
    # 30/360 (the variant named here, by its rule only): with d1 = min(start.day, 30) and d2 = min(end.day, 30),
    #         days = 360 * (end.year - start.year) + 30 * (end.month - start.month) + (d2 - d1); fraction = days / 360.
    #         This variant has no end-of-month or February adjustment. The page names it by this rule.
```

- `convention` not in `DAY_COUNT_CONVENTIONS`: `ValueError`; the message lists the allowed names.
- `end < start`: `ValueError`; the message names the date order.
- `end == start`: returns `Fraction(0)`.

## Bond arithmetic

```python
def price_from_yield(face_cents: int, coupon_rate: Fraction, periods: int, yield_per_period: Fraction) -> int
    # Price on a coupon date (the dirty price when no interest has accrued), with c = coupon_rate, y = yield_per_period:
    #   P = sum_{k=1..periods} c * F / (1 + y)^k  +  F / (1 + y)^periods,   F = face_cents (exact)
    # returned as floor(P + 1/2) cents.

def yield_to_maturity(dirty_cents: int, face_cents: int, coupon_rate: Fraction, periods: int) -> Fraction
    # Solves P(y) = dirty_cents for y per period, where P(y) is the unrounded price of price_from_yield.
    # Method: bisection. The bracket is found by doubling from a yield near -1; the search stops when
    # |P(mid) - dirty_cents| < 1/2 (cent), so price_from_yield at the returned yield equals dirty_cents.
    # A fixed cap of 200 bisection steps applies; reaching the cap raises ValueError.
```

- `face_cents <= 0`, `coupon_rate < 0`, or `periods < 1`: `ValueError`. (`periods < 1` is a named condition.)
- `yield_per_period <= -1`: `ValueError` naming the condition. (Named condition.)
- `dirty_cents <= 0`: `ValueError`. For positive cash flows no yield above -1 gives a price at or below zero, so this is
  the only price with no solution. (Named in the page as "a price no yield above -1 can produce".)
- Positive cash flows are assumed (`coupon_rate >= 0`, `face_cents > 0`). The yield is above -1 on every returned value.

## Curve construction

```python
def bootstrap_zero_rates(par_bonds: list[dict[str, object]]) -> dict[int, float]
    # Input: one dict per bond with keys
    #   "periods"     int       maturity in coupon periods, >= 1
    #   "coupon_rate" Fraction  per period
    #   "face_cents"  int       > 0
    #   "price_cents" int       dirty price on a coupon date, > 0
    # The maturities must be exactly 1, 2, ..., N, each present once (a bond for every period).
    # Algorithm: DF_0 = 1; DF_n = (P_n/F - c_n * sum_{k<n} DF_k) / (1 + c_n), with P_n/F exact;
    # zero rate z_n = DF_n ** (-1/n) - 1 as float. Returns {n: z_n} for n = 1..N.
```

- Missing or duplicated period, empty list, `periods < 1`, `price_cents <= 0`, or `DF_n <= 0` (no positive discount
  factor, so the prices are inconsistent): `ValueError` naming the condition.
- Reprice check (the grader's test): with the returned rates, every input bond's price is reproduced to within one cent.

```python
def ns_yield(tau: float, beta0: float, beta1: float, beta2: float, lam: float) -> float
    # Nelson–Siegel yield at maturity tau (years):
    #   x = tau / lam;  g = (1 - exp(-x)) / x
    #   y(tau) = beta0 + beta1 * g + beta2 * (g - exp(-x))
    # tau <= 0 or lam <= 0: ValueError naming the violated condition (named condition).

def svensson_yield(tau: float, beta0: float, beta1: float, beta2: float, beta3: float,
                   lam1: float, lam2: float) -> float
    # Svensson yield: ns_yield(tau, beta0, beta1, beta2, lam1) + beta3 * (g2 - exp(-x2)),
    # with x2 = tau / lam2 and g2 = (1 - exp(-x2)) / x2.
    # tau <= 0, lam1 <= 0 or lam2 <= 0: ValueError naming the violated condition (named condition).
    # With beta3 = 0 the result equals ns_yield with the same beta0..beta2 and lam1 (the nesting check).
```

The formulas above are the definitions the lessons use. Attribution of each formula to a source waits for the builder
to read the locator in the cited paper (`plans/FI1-build-plan.md` §2.1, item 3). Until then they are written as
definitions.

```python
def fit_nelson_siegel(maturities: list[Fraction], yields: list[Fraction]) -> dict[str, float]
    # Returns {"beta0", "beta1", "beta2", "lam"}.
    # Method: a fixed grid of lam values, stated in the module docstring; for each lam the betas solve the linear
    # least-squares problem (numpy.linalg.lstsq, rcond=None); the lam with the smallest sum of squared yield errors

    # Fewer than 4 maturities, unequal lengths, a maturity <= 0, a non-finite value, or a rank-deficient design: ValueError.

def fit_svensson(maturities: list[Fraction], yields: list[Fraction]) -> dict[str, float]
    # Returns {"beta0", "beta1", "beta2", "beta3", "lam1", "lam2"}.
    # Method: a fixed grid over the pair (lam1, lam2) stated in the module docstring; the betas solve the linear
    # least-squares problem for each pair; the pair with the smallest sum of squared yield errors is returned, ties
    # broken by the smaller (lam1, lam2) in lexicographic order.
    # Fewer than 6 maturities, unequal lengths, a maturity <= 0, a non-finite value, or a rank-deficient design: ValueError.
```

## Error behaviour (summary)

| Condition | Exception |
|---|---|
| Unknown day-count convention | `ValueError` (lists allowed names) |
| `end < start` | `ValueError` (names date order) |
| `periods < 1`, `yield_per_period <= -1` | `ValueError` (names the condition) |
| `tau <= 0`, `lam <= 0`, `lam1 <= 0`, `lam2 <= 0` | `ValueError` (names the condition) |
| `dirty_cents <= 0` in `yield_to_maturity` | `ValueError` |
| Malformed `par_bonds`, duplicate or missing period | `ValueError` |
| Too few points, unequal lengths, rank-deficient design | `ValueError` |
| Wrong argument type (for example an ISO string as a date) | `TypeError` |
| Any other invalid input | `ValueError` (the module validates everything; the grader tests only the named conditions) |

## What is SIMULATED

  grader instance is labelled **SIMULATED** in its docstring and on the page (BLUEPRINT §5.3; BUILDER_RULES §1, item 7).
