Sorting and searching a list by key comparisons are the basic operations on ordered data. This lesson fixes two counts. The first is the number of key comparisons that a sort needs in the worst case, and §2 proves a worst-case lower bound for every comparison sort that meets the hypotheses of Proposition 2.1. The second is the number of comparisons that a binary search (Definition 3.1) makes for a key that is not present. Both counts are proved here, and Lab 4 checks them on seeded inputs and, for n up to 7, on every permutation. Nothing in the lesson measures time.
1Comparison sorting and two algorithms
Let \(x_1, \ldots, x_n\) be \(n\) keys drawn from a set with a total order. A sort returns the keys in increasing order. A comparison sort touches the keys only by comparing two of them, and each comparison has two outcomes. Its cost is the number of comparisons. Moves of keys, index arithmetic and reads are not counted, so every count below is a count of comparisons and no time is measured.
Definition 1.1 (insertion sort and merge sort)
Insertion sort keeps a sorted prefix. For each new key, it compares the key with the last element of the prefix, moves larger elements one place right while the key is smaller, and stops at the first element not larger than the key. Merge sort splits a list into a first part of \(\lfloor n/2 \rfloor\) keys and a second part of \(\lceil n/2 \rceil\) keys, sorts each part, and merges the two sorted lists. A merge repeatedly compares the two front keys and outputs the smaller one, until one list is empty; the rest of the other list is then copied without comparison.
Lemma 1.2 (comparisons in one merge)
Assume the following. (1) Two lists of lengths \(a \ge 1\) and \(b \ge 1\) are each sorted in increasing order. (2) The keys are comparable and no two keys are compared except as fronts of the two lists. (3) The merge of Definition 1.1 is used, with ties sent to the left list. Then the merge makes at most \(a + b - 1\) comparisons.
Proof
Each comparison outputs exactly one key, so the number of comparisons equals the number of keys output while both lists are nonempty. A comparison removes one key from one list. Before a comparison both lists are nonempty, so after it at most one list is empty, because only the list that lost its key can have become empty. Therefore, at the moment the loop stops, one list is empty and the other list still holds at least one key. The keys output by comparison are \(a + b\) minus the number left in the nonempty list, which is at most \(a + b - 1\).
Proposition 1.3 (the merge-sort bound)
Assume the following. (1) \(n \ge 1\) is an integer. (2) The keys are comparable. (3) Merge sort splits a list of length \(n \ge 2\) into parts of lengths \(\lfloor n/2 \rfloor\) and \(\lceil n/2 \rceil\), sorts each part by the same method, and merges them by Definition 1.1. Let \(C(n)\) be the largest number of comparisons that merge sort makes on a list of \(n\) keys, over all lists of that length. Then \(C(n) \le n\lceil \log_2 n \rceil\).
Proof
Strong induction on \(n\). For \(n = 1\), no comparison is made, and \(C(1) = 0 = 1 \cdot \lceil \log_2 1 \rceil\). Let \(n \ge 2\) and assume the bound for every length below \(n\). Put \(K = \lceil \log_2 n \rceil\), so \(K \ge 1\) and \(2^{K-1} < n \le 2^{K}\). Let \(a = \lceil n/2 \rceil\) and \(b = \lfloor n/2 \rfloor\). Since \(n \ge 2\), \(1 \le b \le a\). The integer \(2^{K-1}\) is at least \(n/2\), so it is at least \(\lceil n/2 \rceil = a\). Hence \(a \le 2^{K-1} < n\), and \(b \le a\) gives \(b < n\) as well. An integer \(m\) with \(m \le 2^{K-1}\) has \(\lceil \log_2 m \rceil \le K - 1\), so the induction hypothesis gives \(C(a) \le a(K-1)\) and \(C(b) \le b(K-1)\). A list of length \(n\) makes the comparisons of its two parts plus at most \(n - 1\) comparisons in the merge, by Lemma 1.2 with \(a\) and \(b\). Therefore \[ C(n) \le C(a) + C(b) + (n - 1) \le (a + b)(K - 1) + n - 1 = n(K - 1) + n - 1 = nK - 1 \le nK. \] This is the bound.
Remark 1.4 (three extreme inputs)
Three counts follow from the definitions, and each is checked by Lab 4, Part A or Part B. (a) On sorted input of \(n\) keys, insertion sort makes exactly \(n - 1\) comparisons: each key is compared once, with the last element of the prefix, and that element is not larger. (b) On strictly decreasing input, insertion sort makes exactly \(n(n-1)/2\) comparisons: key \(i\) is smaller than all \(i - 1\) keys before it, and each of those keys is compared, with no comparison after the front is reached. (c) On sorted input with \(n = 2^{k}\), merge sort makes exactly \(k \, 2^{k-1}\) comparisons. The two halves of sorted input have every key of the left half not larger than every key of the right half, so a merge of two halves of size \(m\) makes exactly \(m\) comparisons: the left list empties after \(m\) comparisons. The count \(c_k\) satisfies \(c_0 = 0\) and \(c_k = 2c_{k-1} + 2^{k-1}\). Dividing by \(2^k\) gives \(c_k / 2^k = c_{k-1} / 2^{k-1} + 1/2\), so \(c_k = k \, 2^{k-1}\).
2The lower bound for every comparison sort
Proposition 1.3 bounds one algorithm from above. This section bounds from below every comparison sort that meets the hypotheses of Proposition 2.1. The proof uses a comparison tree, the record of a run drawn as a binary tree: an internal node is a comparison and its two children are the two outcomes; a leaf is the output.
Proposition 2.1 (the comparison lower bound)
Assume the following. (1) \(n \ge 2\), and the keys are pairwise distinct and comparable. (2) The algorithm is deterministic, and its only operation on the keys is a comparison of two keys with two outcomes. (3) The algorithm halts on every input of length \(n\). (4) Every one of the \(n!\) orderings of the keys is a possible input. (5) On every input of length \(n\), the algorithm returns the keys in increasing order. (6) On every input of length \(n\), the output also records, for each \(k\), the input position \(\sigma(k)\) of the \(k\)-th smallest key, so that the output is the sorting permutation \(\sigma\) of the input; and the output is determined by the outcomes of the comparisons that the run makes. Then on some input of length \(n\), the algorithm makes at least \(\lceil \log_2 (n!) \rceil\) comparisons.
Proof
Run the algorithm on the orderings and record the tree. By (2) the tree is binary: each internal node is one comparison with two children. By (4) there are \(n!\) inputs, and by (3) each run ends, so the tree has finitely many root-to-leaf paths, each of finite length, and every root-to-leaf path is the sequence of comparisons of one run. The number of comparisons of an input equals the length of the path it follows. By (6), the output at a leaf is the sorting permutation \(\sigma\) of the input, and the output is fixed by the leaf. Distinct orderings of distinct keys have distinct sorting permutations: the input at position \(\sigma(k)\) is the \(k\)-th smallest key, so \(\sigma\) determines the input. Two inputs that end at the same leaf therefore have the same output, hence the same \(\sigma\), hence are the same input. So distinct inputs end at distinct leaves. By (4) there are \(n!\) inputs, so the tree has at least \(n!\) leaves. Let \(h\) be the largest length of a root-to-leaf path. Claim: a binary tree in which every root-to-leaf path has length at most \(h\) has at most \(2^{h}\) leaves. Induct on \(h\). For \(h = 0\) the tree is one node, which is one leaf, and \(2^{0} = 1\). For \(h \ge 1\), the root has at most two subtrees, and each has paths of length at most \(h - 1\), so each has at most \(2^{h-1}\) leaves by induction. Together they have at most \(2^{h}\) leaves. Hence \(n! \le 2^{h}\), so \(h \ge \log_2 (n!)\). Since \(h\) is an integer, \(h \ge \lceil \log_2 (n!) \rceil\). The run that follows a longest path makes \(h\) comparisons.
Corollary 2.2 (the explicit form)
For every integer \(n \ge 2\), \(\log_2 (n!) \ge \tfrac{n}{2} \log_2 \tfrac{n}{2}\). Hence, under the hypotheses of Proposition 2.1 (including hypotheses (5) and (6), which fix the output as the sorting permutation), the worst case is at least \(\tfrac{n}{2} \log_2 \tfrac{n}{2}\) comparisons.
Proof
Among the factors \(1, 2, \ldots, n\) of \(n!\), the factors \(k\) with \(n/2 \le k \le n\) are all at least \(n/2\). There are \(n - \lceil n/2 \rceil + 1 = \lfloor n/2 \rfloor + 1\) of them, and \(\lfloor n/2 \rfloor + 1 \ge n/2\). Each factor is at least \(n/2 \ge 1\), so \[ n! \ge \left(\tfrac{n}{2}\right)^{\lfloor n/2 \rfloor + 1} \ge \left(\tfrac{n}{2}\right)^{n/2}, \] where the second step uses \(n/2 \ge 1\) and \(\lfloor n/2 \rfloor + 1 \ge n/2\). Taking \(\log_2\) gives the claim. The second sentence follows from Proposition 2.1 and the first sentence.
Remark 2.3 (a bound on the worst case, not on each input)
Proposition 2.1 gives a lower bound on the largest count over the inputs. It gives no bound on the count of each input. Lab 4, Part A, prints \(\lceil \log_2 (1024!) \rceil = 8770\) for 1024 keys, and merge sort on sorted input of 1024 keys makes 5120 comparisons, which is less. Both facts hold because the bound is a worst-case bound. Part B checks, for every \(n\) from 2 to 7, that the largest merge count over all permutations is at least \(\lceil \log_2 (n!) \rceil\) and no larger than \(n\lceil \log_2 n \rceil\). Merge sort does not meet hypothesis (6) of Proposition 2.1, so these are numerical checks on merge sort and not instances of Proposition 2.1.
3Binary search and its probe count
Definition 3.1 (binary search)
Let \(x_0 < x_1 < \cdots < x_{n-1}\) be a list stored in an array, and let \(y\) be a key. Binary search keeps a range of positions \(lo \le hi\), starting at \(lo = 0\) and \(hi = n - 1\). A probe is one comparison of \(y\) with \(x_{mid}\), where \(mid = \lfloor (lo + hi)/2 \rfloor\). If \(x_{mid} = y\), the search stops and reports the key. If \(x_{mid} < y\), the search sets \(lo = mid + 1\). If \(x_{mid} > y\), it sets \(hi = mid - 1\). The search also stops when the range is empty, which reports that \(y\) is absent.
A gap of a list of \(n\) keys is one of the \(n + 1\) places where an absent key can lie: before the first key, between two consecutive keys, or after the last key.
Proposition 3.2 (probes for an absent key)
Assume the following. (1) \(n \ge 1\), and the list is strictly increasing. (2) The key \(y\) is absent from the list. (3) The search is that of Definition 3.1, and its probe count is the number of comparisons of \(y\) with elements of the list. Let \(f(n) = \lfloor \log_2 n \rfloor + 1\), which is the number of binary digits of \(n\). Then the search makes at most \(f(n)\) probes for every absent \(y\), and some absent \(y\) makes exactly \(f(n)\) probes.
Proof
Write \(\beta(s)\) for the number of binary digits of \(s\), with \(\beta(0) = 0\). For \(s \ge 1\), \(\beta(s) = \lfloor \log_2 s \rfloor + 1\), and \(\beta(\lfloor s/2 \rfloor) = \beta(s) - 1\) because halving removes the last binary digit. We show by induction on \(s \ge 0\) that a search over a range of \(s\) positions makes at most \(\beta(s)\) probes for every absent key. For \(s = 0\) the range is empty and no probe is made. Let \(s \ge 1\), with the range \(lo\) to \(hi = lo + s - 1\). The first probe is at \(mid = lo + \lfloor (s-1)/2 \rfloor\). The part to the left of \(mid\) has \(\lfloor (s-1)/2 \rfloor\) positions, and the part to the right has \(s - 1 - \lfloor (s-1)/2 \rfloor = \lfloor s/2 \rfloor\) positions. Each part has at most \(\lfloor s/2 \rfloor\) positions, so after the first probe the search continues over a range of at most \(\lfloor s/2 \rfloor\) positions and, by the induction hypothesis, makes at most \(\beta(t)\) further probes, where \(t \le \lfloor s/2 \rfloor\) is its range size. Since \(\beta\) is nondecreasing (a larger integer has at least as many binary digits), \(\beta(t) \le \beta(\lfloor s/2 \rfloor) = \beta(s) - 1\). The total is at most \(\beta(s)\). For equality, take \(y\) larger than every key. Each probe then finds \(x_{mid} < y\) and continues on the right part, which has \(\lfloor s/2 \rfloor\) positions. The range sizes are \(n\), \(\lfloor n/2 \rfloor\), \(\lfloor n/4 \rfloor\), and so on, until the range is empty. The number of halvings needed to reach 0 is \(\beta(n)\), so the search makes exactly \(\beta(n) = f(n)\) probes.
Remark 3.3 (what the proposition does not count)
Proposition 3.2 counts probes for an absent key. It does not state the probe count for a present key, and it does not count the cost of putting the list in order. The proposition also assumes that the list is in array positions, so that the middle position can be read directly. Lab 4, Part D, checks the worst case over every gap of the list with keys \(2i\), \(i = 0, \dots, n - 1\), for each length n from 1 to 1000.

4Where the canon breaks
The comparison model. Proposition 2.1 covers deterministic sorting algorithms that meet its hypotheses (1) to (6); hypothesis (2) makes comparison the only operation on keys. An algorithm that reads a key's value as an array position is outside it, and this page does not state its cost on any input class.
Worst case and a single input. The bound is a bound on the largest count. At 1024 keys, merge sort on sorted input is below the bound (Remark 2.3), so a claim that a sort needs at least the bound on every input is false.
Comparisons are not time. The lab counts comparisons and measures no time. Moves, reads and memory traffic are not counted, so a smaller comparison count does not by itself show a faster sort.
Binary search needs the list in order. Proposition 3.2 counts probes once the list is sorted and in array positions. The cost of putting a list in order, or of keeping it in order under insertions, is not in the count.
5Misconceptions
“Merge sort makes fewer comparisons than insertion sort on every input.”
On sorted input of 1024 keys, insertion sort makes 1023 comparisons and merge sort makes 5120 (Remark 1.4, Lab 4 Part A), so insertion sort is the cheaper one there. Over every permutation of 7 keys, insertion sort's largest count is 21 and merge sort's largest count is 14 (Lab 4 Part B). The two claims concern different inputs, and neither ranks the sorts on every input.
“Binary search on a sorted list of \(n\) keys needs at most \(\lfloor \log_2 n \rfloor\) probes.”
That count undercounts the worst case. For an absent key, Proposition 3.2 gives \(\lfloor \log_2 n \rfloor + 1\) probes at worst. For \(n = 4\) and the list 0, 2, 4, 6 with key 7, the probes are at positions 1, 2 and 3, which is 3 probes, while \(\lfloor \log_2 4 \rfloor = 2\). Lab 4, Part D, prints a worst count of 3 for \(n = 4\).
“A clever enough comparison sort can beat \(\tfrac{n}{2}\log_2 \tfrac{n}{2}\) comparisons in the worst case.”
Corollary 2.2 says that, under the hypotheses of Proposition 2.1, no algorithm that meets them has a worst case below \(\tfrac{n}{2}\log_2 \tfrac{n}{2}\) comparisons. Those hypotheses are the six of Proposition 2.1: \(n \ge 2\) with pairwise distinct keys; deterministic; halting on every input; touching the keys only through two-outcome comparisons; every ordering of the keys a possible input; returning the keys in increasing order, with an output that records the sorting permutation and is determined by the comparison outcomes. The proof counts the leaves of its comparison tree, which must number at least \(n!\), and a binary tree with that many leaves has a path of length at least \(\log_2 (n!)\). The argument does not cover algorithms that read key values as positions, and Section 4 says so.
6Problem set
Every problem has a full worked solution. Attempt each one before opening it.
Mechanics
M1 · Insertion sort on three keys
Run insertion sort on the list 3, 1, 2 and count the comparisons.
Solution
Step 1 compares the key 1 with 3. The comparison is 3 at most 1, which is false, so 3 moves right, and the key 1 is placed first. That is 1 comparison, and the list is 1, 3, 2. Step 2 compares the key 2 with 3, which is false, so 3 moves right. Then it compares 2 with 1, which is true, and the key 2 is placed after 1. That is 2 comparisons. The total is 3 comparisons, and the list is 1, 2, 3.
M2 · Probes for an absent key above every value
A sorted list has 13 keys, and the search is for a key larger than all of them. How many probes does binary search make?
Solution
The ranges have sizes 13, 6, 3, 1, 0. The first probe is at \(\lfloor (0 + 12)/2 \rfloor = 6\), which is below the key, so the range moves right and has \(12 - 6 = 6\) positions. The same rule gives sizes 6, then 3, then 1, then 0. That is 4 probes, which equals \(\lfloor \log_2 13 \rfloor + 1 = 3 + 1\), and \(13\) has 4 binary digits. Proposition 3.2 gives the same value.
M3 · Comparisons in one merge
Merge the sorted lists 1, 4, 6 and 2, 3, 7 and count the comparisons. Compare the count with the bound of Lemma 1.2.
Solution
The fronts compare as follows: 1 with 2 (output 1), 4 with 2 (output 2), 4 with 3 (output 3), 4 with 7 (output 4), and 6 with 7 (output 6). The left list is now empty after five comparisons, and the 7 is copied. The count is 5. The bound of Lemma 1.2 is \(a + b - 1 = 3 + 3 - 1 = 5\), so this merge meets the bound.
Proof
P1 · A merge that meets the bound
Merge the lists 1, 3 and 2, 4 and count the comparisons. Show that the bound \(a + b - 1\) of Lemma 1.2 is met for \(a = b = 2\).
Solution
The fronts compare as follows: 1 with 2 (output 1), 3 with 2 (output 2), 3 with 4 (output 3). The left list is then empty, so the loop stops, and 4 is copied. The count is 3 comparisons. The bound is \(a + b - 1 = 2 + 2 - 1 = 3\), so this input attains the bound of Lemma 1.2 for these lengths.
P2 · Leaves of a shallow binary tree
Prove by induction on \(h \ge 0\) that a binary tree in which every root-to-leaf path has length at most \(h\) has at most \(2^{h}\) leaves.
Solution
For \(h = 0\), the tree has no edges, so it is a single node that is a leaf, and \(2^{0} = 1\). Let \(h \ge 1\) and assume the claim for \(h - 1\). The root has at most two children, and the subtree under each child has every path of length at most \(h - 1\). By the induction hypothesis each subtree has at most \(2^{h-1}\) leaves. A leaf of the whole tree is a leaf of one of these subtrees, so the whole tree has at most \(2 \cdot 2^{h-1} = 2^{h}\) leaves.
P3 · The top gap of a sorted list
Show by induction on \(n \ge 0\) that the search for a key larger than all \(n\) keys makes exactly \(\beta(n)\) probes, where \(\beta(n)\) is the number of binary digits of \(n\), with \(\beta(0) = 0\).
Solution
For \(n = 0\) the range is empty, so there are 0 probes, and \(\beta(0) = 0\). Let \(n \ge 1\). The first probe is at position \(\lfloor (n-1)/2 \rfloor\), which holds a key below the search key, so the search continues over the right part, which has \(\lfloor n/2 \rfloor\) positions and still holds a key larger than the search key. By induction it makes \(\beta(\lfloor n/2 \rfloor)\) probes. For \(n \ge 1\), \(\beta(n) = \beta(\lfloor n/2 \rfloor) + 1\), because halving removes the last binary digit. The total is \(1 + \beta(\lfloor n/2 \rfloor) = \beta(n)\).

E1 · The ratio of the two counts at 1024 keys
Read Lab 4, Part A. What is the ratio of the insertion sort count to the merge sort count for the seeded random permutation of 1024 keys? Give it to two decimal places.
Solution
Part A prints 262431 for insertion sort and 8886 for merge sort. The ratio is \(262431 / 8886\). Since \(8886 \times 29 = 257694\) and \(262431 - 257694 = 4737\), the ratio is \(29 + 4737/8886 = 29.5331\). To two decimal places it is 29.53. The ratio describes this one seeded permutation, and the page states no average.
E2 · Distance from the lower bound at seven keys
Read Lab 4, Part B for \(n = 7\). How far is the largest merge sort count above the lower bound the lab prints, and how far is the largest insertion sort count?
Solution
Part B prints the lower bound 13 and the largest merge count 14, so merge sort's worst case is \(14 - 13 = 1\) comparison above the bound. The largest insertion count is 21, which is \(21 - 13 = 8\) above the bound. The insertion count is 21 because \(7 \cdot 6 / 2 = 21\), as Remark 1.4b gives for strictly decreasing input.
E3 · Sorted input against the bound at 1024 keys

Research
R1 · A different midpoint rule
Replace the midpoint \(\lfloor (lo + hi)/2 \rfloor\) by \(\lfloor (lo + hi + 1)/2 \rfloor\). Show that the worst case for an absent key is still \(\beta(n)\) for every \(n \ge 1\).
Solution
With the new rule, the left part has \(\lfloor s/2 \rfloor\) positions and the right part has \(\lfloor (s-1)/2 \rfloor\) positions, for a range of \(s\). Both are at most \(\lfloor s/2 \rfloor\), so the induction of Proposition 3.2 goes through unchanged, with the nondecreasing \(\beta\) that its proof uses, and the search makes at most \(\beta(s)\) probes. For equality, take a key smaller than every key. Each probe then moves left, into a part of \(\lfloor s/2 \rfloor\) positions, and the same halving count gives \(\beta(n)\) probes. For this rule the worst case is still \(\beta(n)\), by the two parts above.
R2 · Binary search needs an ordered list
Run binary search on the unsorted list 3, 1, 2 for the key 3, which is present. Does it find the key? Say which step of Proposition 3.2 fails for an unsorted list.
Solution
The range is 0 to 2 and the middle position is 1, which holds 1. Since 1 is below 3, the search sets the range to positions 2 to 2. The middle is position 2, which holds 2, below 3, so the range becomes positions 3 to 2, which is empty. The search reports that 3 is absent, although 3 sits at position 0. The step that fails is the rule that a probe below the key means the key lies to the right: that rule needs every key to the left of the probe to be smaller than it, which is the sorted hypothesis of Proposition 3.2.
R3 · Binary search meets the comparison lower bound for absent keys
Among \(n\) sorted keys there are \(n + 1\) gaps, and an absent key lies in one of them. Assume the following. (1) \(n \ge 1\), and the keys are distinct and sorted. (2) The algorithm is deterministic, halts on every input, and touches the keys only by comparisons with two outcomes. (3) For each of the \(n + 1\) gaps, some input has its absent key in that gap, and the algorithm reports that gap. Then on some input the algorithm makes at least \(\lceil \log_2 (n+1) \rceil\) comparisons. Show also that \(\lceil \log_2 (n+1) \rceil = \beta(n)\) for \(n \ge 1\), so binary search meets this bound in the worst case.
Solution
By hypothesis (3) each gap is the reported output for some input, and the leaf that an input reaches fixes its output, so the gaps need different leaves: there are at least \(n + 1\) leaves of the comparison tree. By the leaf-count argument of Proposition 2.1 and problem P2, a tree of height \(h\) has at most \(2^{h}\) leaves, so \(2^{h} \ge n + 1\) and \(h \ge \lceil \log_2 (n+1) \rceil\). For the identity, let \(k = \beta(n)\), so that \(2^{k-1} \le n < 2^{k}\). Then \(2^{k-1} < n + 1 \le 2^{k}\), which gives \(\lceil \log_2 (n+1) \rceil = k\). Binary search makes \(\beta(n)\) probes in the worst case by Proposition 3.2, so it meets the bound.
