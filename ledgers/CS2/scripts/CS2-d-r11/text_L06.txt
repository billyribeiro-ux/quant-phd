21: Some questions about a network reduce to one step: starting from one point, find every point that can be reached, and the order in which they are reached. Which accounts are linked to a given account, and how many links separate two of them, are questions of this form. Two search methods answer them. One finds the fewest links from the starting point to each point that can be reached. The other returns a nested record of when each point is first reached and when its search of that point is finished. This lesson proves both properties. Lab 1 checks the first against exhaustive search, and the second on seeded networks.
22: 1 Graphs, adjacency lists and the two orders
23: A graph here is a finite set of vertices with a set of edges , each edge joining two different vertices. The graph is undirected: an edge joins its two ends in both directions. A path is a sequence of vertices in which each consecutive pair is an edge, and a simple path has no repeated vertex. A walk allows repeated vertices, and its length is its number of edges. The number of edges on a path is its hop count . A graph is stored as adjacency lists : for each vertex, the list of its neighbours. A hash map from vertex labels to these lists stores the graph (L02), and a vertex is looked up by its label. An adjacency matrix is the other storage used here: an \(n \times n\) table, for \(n\) vertices, whose entry in row \(u\) and column \(v\) is 1 when \(u\) and \(v\) are joined by an edge and 0 otherwise. Reading the neighbours of a vertex from a matrix means reading its full row of \(n\) entries.
24: Definition 1.1 (graph traversal)
25: A graph traversal starts at a source vertex \(s\) and visits the vertices reachable from \(s\), each once, by moving along edges from vertices already visited. Breadth-first search (BFS) keeps the discovered vertices in a first-in, first-out queue. It starts with \(s\) in the queue, and repeats: remove the front vertex \(u\), and for each neighbour \(v\) of \(u\) that has not been discovered, mark \(v\) discovered, give it distance \(\mathrm{dist}(u) + 1\), record \(u\) as its parent, and add it to the back of the queue. Depth-first search (DFS) is defined in §3.
26: 2 Breadth-first search finds fewest hops
27: Let \(\delta(v)\) be the fewest edges on a path from \(s\) to \(v\), when \(v\) is reachable from \(s\). BFS is run as in Definition 1.1, with \(\mathrm{dist}(s) = 0\).
28: Lemma 2.1 (the queue is ordered by distance)
29: Assume the following. (1) The graph is finite and undirected. (2) BFS runs as in Definition 1.1, and each discovered vertex has distance equal to its parent's distance plus 1. Then at every moment the distances of the queued vertices are nondecreasing from front to back, and they differ by at most 1. Hence the vertices are removed from the queue in nondecreasing order of distance.
30: Proof
31: Induct on the number of queue operations. At the start the queue holds \(s\) alone. Suppose the queue holds distances in \(\{\ell, \ell+1\}\), nondecreasing from front to back, with front distance \(\ell\). A removal takes out a vertex with distance \(\ell\), so the remaining distances still lie in \(\{\ell, \ell+1\}\) and remain nondecreasing. The vertices added during this step have distance \(\ell + 1\), and they are added at the back, so the sequence stays nondecreasing. Every distance now lies in \(\{\ell', \ell'+1\}\), where \(\ell'\) is the distance of the new front: if a vertex of distance \(\ell\) remains, then \(\ell' = \ell\); otherwise every remaining distance is \(\ell+1\) and \(\ell' = \ell+1\), and the added vertices also have distance \(\ell+1\). In both cases the invariant holds.
32: Proposition 2.2 (BFS gives fewest hops)
33: Assume the hypotheses of Lemma 2.1 and a source \(s\). Then BFS discovers exactly the vertices reachable from \(s\), and for each of them \(\mathrm{dist}(v) = \delta(v)\).
34: Proof
35: Every discovered vertex is reachable, because it is discovered from a discovered vertex by an edge, starting from \(s\). Conversely, a reachable vertex is discovered: induct on \(\delta(v)\). If \(\delta(v) = 0\), then \(v = s\). If \(\delta(v) = k \ge 1\), a shortest path to \(v\) has a vertex \(u\) before \(v\) with \(\delta(u) = k - 1\), which is discovered by induction. BFS removes every discovered vertex, so \(u\) is removed, and when it is, \(v\) is either undiscovered, and becomes discovered, or already discovered.
36: Next, \(\mathrm{dist}(v) \ge \delta(v)\) for every discovered \(v\). The distance of \(v\) is the length of the tree path from \(s\) to \(v\) through parents, which is a walk of that length, so the walk has length at least \(\delta(v)\).
37: Finally, \(\mathrm{dist}(v) \le \delta(v)\), by induction on \(k = \delta(v)\). For \(k = 0\), \(\mathrm{dist}(s) = 0\). For \(k \ge 1\), take \(u\) as above, with \(\mathrm{dist}(u) = \delta(u) = k - 1\) by induction. If \(v\) was discovered before \(u\) was removed, by a vertex \(w\) removed no later than \(u\), then \(\mathrm{dist}(w) \le \mathrm{dist}(u) = k - 1\) by Lemma 2.1, so \(\mathrm{dist}(v) = \mathrm{dist}(w) + 1 \le k\). Otherwise \(v\) is discovered when \(u\) is removed, and \(\mathrm{dist}(v) = k\). Either way \(\mathrm{dist}(v) \le k\).
38: Proposition 2.3 (the operation count of BFS)
39: Assume a graph with \(|V|\) vertices and \(|E|\) edges, stored as adjacency lists. BFS from \(s\) makes at most \(|V|\) enqueue operations, and it inspects at most \(2|E|\) adjacency entries. In the count of Remark 2.4, each enqueue and each adjacency-entry inspection costs one operation.
40: Proof
41: A vertex is enqueued only when it is first discovered, so it is enqueued at most once, which gives at most \(|V|\) enqueues. A vertex is removed once, and when it is removed its adjacency list is scanned once, so the entries inspected are the degrees of the removed vertices. The sum of all degrees is \(2|E|\), since each edge contributes one entry to each of its two ends, so the inspections are at most \(2|E|\).
42: Remark 2.4 (what the count is)
43: Proposition 2.3 counts the operations of one search: enqueues and adjacency-entry inspections. It is a count, not a measured time, and it gives \(O(|V| + |E|)\) in the sense of L01. Lab 1, Part D, prints the count for one graph on 200 vertices, together with the row reads that the same search would make on an adjacency matrix.
44: 3 Depth-first search and the parenthesis property
45: Definition 3.1 (depth-first search)
46: Depth-first search keeps one clock. When a vertex \(v\) is first visited, the clock ticks, and the tick is the discovery time \(d(v)\). Then, for each neighbour \(u\) of \(v\) that has not been discovered, the search visits \(u\) recursively. When every neighbour has been handled, the clock ticks again, and the tick is the finish time \(f(v)\). The whole search runs this procedure from every vertex that has not been discovered, in turn.
47: Proposition 3.2 (the parenthesis property)
48: Assume the following. (1) The graph is finite and undirected. (2) The search is that of Definition 3.1, with one clock that ticks once at each discovery and once at each finish. Then for any two distinct vertices \(u\) and \(v\), the intervals \([d(u), f(u)]\) and \([d(v), f(v)]\) are disjoint, or one lies inside the other.
49: Proof
50: Each vertex is visited by exactly one recursive call, so the calls correspond one to one to the vertices, and the call for \(v\) runs from the tick \(d(v)\) to the tick \(f(v)\). Let the calls form the recursion tree, in which the call for \(u\) is the child of the call that discovered it. A child call starts after its parent's discovery tick, and it finishes before its parent's finish tick. So each child interval lies strictly inside its parent's interval. Two calls that are not in an ancestor relation have a lowest common ancestor \(a\), and they lie in different children's subtrees of \(a\). Within the call of \(a\), the children are visited one after another, and the first child's call finishes before the second begins, because the search is recursive. So their intervals are disjoint. For any two distinct vertices, either one call is an ancestor of the other, which gives nesting, or the two calls have a common ancestor and lie in different subtrees, which gives disjointness.

72: def random_graph(rng: random.Random, n: int, p: float) -> Graph:
73: """An undirected graph on 0..n-1: each pair is an edge with probability p. Adjacency lists are sorted."""
74: adj: Graph = {v: [] for v in range(n)}

83: def bfs(adj: Graph, source: int) -> tuple[dict[int, int], dict[int, int], list[int], int]:
84: """Breadth-first search from source. Returns hop distances, parents, the dequeue order, and the number of
85: adjacency entries inspected. A FIFO queue holds the discovered vertices not yet dequeued."""
86: dist: dict[int, int] = {source: 0}
87: parent: dict[int, int] = {}
88: order: list[int] = []
89: queue: deque[int] = deque([source])
90: inspections = 0
91: while queue:
92: v = queue.popleft()
93: order.append(v)
94: for u in adj[v]:
95: inspections += 1
96: if u not in dist:
97: dist[u] = dist[v] + 1
98: parent[u] = v
99: queue.append(u)
100: return dist, parent, order, inspections
101: def brute_min_hops(adj: Graph, source: int) -> dict[int, int]:
102: """The fewest edges over all simple paths from source to each reachable vertex, by exhaustive search."""
103: best: dict[int, int] = {source: 0}
104: on_path = {source}
105: def extend(v: int, length: int) -> None:
106: for u in adj[v]:
107: if u in on_path:
108: continue
109: if length + 1 < best.get(u, 10**9):
110: best[u] = length + 1
111: on_path.add(u)
112: extend(u, length + 1)
113: on_path.remove(u)
114: extend(source, 0)
115: return best
116: def dfs_times(adj: Graph) -> tuple[dict[int, int], dict[int, int]]:
117: """Recursive depth-first search over all vertices. Returns discovery and finish times on one clock.
118: The clock ticks once when a vertex is discovered and once when it finishes, so the times are 1..2n."""
119: discover: dict[int, int] = {}
120: finish: dict[int, int] = {}
121: clock = [0]
122: def visit(v: int) -> None:
123: clock[0] += 1
124: discover[v] = clock[0]
125: for u in adj[v]:
126: if u not in discover:
127: visit(u)
128: clock[0] += 1
129: finish[v] = clock[0]
130: for v in sorted(adj):
131: if v not in discover:
132: visit(v)
133: return discover, finish
134: def nested_or_disjoint(d: dict[int, int], f: dict[int, int], u: int, v: int) -> bool:
135: """True when the intervals [d[u], f[u]] and [d[v], f[v]] are disjoint or one contains the other."""
136: if f[u] < d[v] or f[v] < d[u]:
137: return True
138: return (d[u] < d[v] and f[v] < f[u]) or (d[v] < d[u] and f[u] < f[v])
139: def weighted_paths(adj: Graph, weight: dict[tuple[int, int], int], source: int) -> dict[int, tuple[int, list[int]]]:
140: """For each reachable vertex, the lightest simple path from source: (total weight, path), by exhaustive search."""
141: best: dict[int, tuple[int, list[int]]] = {source: (0, [source])}
142: on_path = [source]
143: def extend(v: int, total: int) -> None:
144: for u in adj[v]:
145: if u in on_path:
146: continue
147: step = total + weight[(min(v, u), max(v, u))]
148: if u not in best or step < best[u][0]:
149: best[u] = (step, [*on_path, u])
150: on_path.append(u)
151: extend(u, step)
152: on_path.pop()
153: extend(source, 0)
154: return best

254: 4 Where the canon breaks
255: Hops are not weights. Proposition 2.2 is about edges, each counted as one. With edge weights, the fewest-hop path can be the heavier of the two simple paths to vertex c in Part C (weight 11, against weight 3 for the path with 3 hops). This lesson gives no method for weighted shortest paths.
256: DFS paths are not shortest. The path to a vertex through the recursion tree of the proof of Proposition 3.2 can be longer than its hop distance (Misconception 2). The parenthesis property is a statement about nesting of times, not about distances.
257: Directed graphs. The proofs above use undirected edges, and the labs use undirected graphs. The classification of edges in a directed DFS is not covered.
258: Recursion depth. Definition 3.1 is recursive, so one path of recursive calls can be as long as the number of vertices. This page does not measure the stack space that the calls use.
259: 5 Misconceptions
260: “Breadth-first search finds the shortest path when edges have weights.”
261: BFS minimizes the number of edges (Proposition 2.2). On the weighted graph of Lab 1, Part C, the path s to a has 1 hop and weight 10, while s to b to a has 2 hops and weight 2. BFS returns the path with the fewest edges, here the direct edge from s to a.
262: “Depth-first search also finds shortest hop paths, because it reaches every vertex.”
263: Reaching a vertex is not the same as reaching it by the fewest edges. Take the triangle a, b, c with edges a to b, b to c and a to c, and let the neighbour list of a be b then c. The search discovers b from a, then c from b, so its tree path to c is a, b, c with 2 hops. But a and c are adjacent, so the hop distance is 1, which BFS returns.
264: “A traversal costs the same whether the graph is stored as adjacency lists or as an adjacency matrix.”
265: Proposition 2.3 gives at most \(|V| + 2|E|\) operations with lists. With an adjacency matrix, a dequeued vertex reads its full row of \(|V|\) entries, so the row reads are \(|V|\) times the number of dequeued vertices, which is at most \(|V|^{2}\). Lab 1, Part D, prints 1438 operations for lists and 40000 row reads for the matrix on the same 200-vertex graph.

268: Mechanics
269: M1 · BFS distances on a five-vertex graph
270: The undirected edges are 1 to 2, 1 to 3, 2 to 4, 3 to 4 and 4 to 5. Run BFS from 1, with neighbours taken in increasing order. Give the distances and the order in which the vertices are removed from the queue.
271: Solution
272: Start with queue \([1]\), distance 0. Remove 1, and discover its neighbours 2 and 3 with distance 1, so the queue is \([2, 3]\). Remove 2, whose neighbours are 1 (discovered) and 4, which gets distance 2. The queue is \([3, 4]\). Remove 3, whose neighbours 1 and 4 are discovered. Remove 4, which discovers 5 with distance 3. Remove 5. The distances are 1 to 0, 2 and 3 to 1, 4 to 2, and 5 to 3. The removal order is 1, 2, 3, 4, 5.
273: M2 · DFS times on a path
274: The undirected path 1 to 2 to 3 is searched by Definition 3.1 from vertex 1. Give the discovery and finish times of every vertex.
275: Solution
276: The clock starts at 0. Vertex 1 is discovered at tick 1, and the search moves to 2, discovered at tick 2. From 2 it moves to 3, discovered at tick 3. Vertex 3 has no undiscovered neighbour, so it finishes at tick 4. Vertex 2 finishes at tick 5 and vertex 1 at tick 6. So \(d = (1, 2, 3)\) and \(f = (6, 5, 4)\) for vertices 1, 2 and 3. The intervals \([1, 6]\), \([2, 5]\) and \([3, 4]\) are nested, as Proposition 3.2 states.
277: M3 · Adjacency scans on a triangle
278: The triangle on vertices 1, 2 and 3 has three edges. Count the adjacency entries BFS inspects from vertex 1.
279: Solution
280: Each of the three vertices is dequeued once, and each has two neighbours, so the scans are the sum of the degrees, which is \(2 + 2 + 2 = 6\). Proposition 2.3 gives at most \(2|E| = 2 \cdot 3 = 6\). Equality holds here because all three vertices are dequeued, so every adjacency entry is inspected.
281: Proof
282: P1 · One queue step keeps the invariant
283: Let the queue hold distances in \(\{\ell, \ell+1\}\), nondecreasing from front to back. Show that after removing the front vertex and adding its undiscovered neighbours with distance \(\ell+1\), the queue still has distances in \(\{\ell', \ell'+1\}\), where \(\ell'\) is the new front distance.
284: Solution
285: The removed vertex has distance \(\ell\), so the remaining vertices have distances in \(\{\ell, \ell+1\}\). The new vertices have distance \(\ell+1\). If a vertex of distance \(\ell\) remains, the new front is \(\ell' = \ell\), and every distance is in \(\{\ell, \ell+1\}\). If none remains, the new front is \(\ell' = \ell + 1\), and every distance is \(\ell+1\), which lies in \(\{\ell', \ell'+1\}\). The order stays nondecreasing, because the new vertices are added at the back with the largest distance present.
286: P2 · Children nest inside their parent
287: In the recursion tree of Definition 3.1, show that the interval of a child call lies strictly inside the interval of its parent.
288: Solution
289: The child is discovered during the parent's call, when the parent has been discovered and not yet finished, so its discovery tick is after \(d(\text{parent})\). The child finishes before the parent's loop over neighbours ends, which is before the parent's finish tick \(f(\text{parent})\). So \(d(\text{parent}) < d(\text{child}) < f(\text{child}) < f(\text{parent})\).
290: P3 · Each vertex is enqueued once
291: Explain why BFS enqueues each vertex at most once, and deduce the bound \(|V|\) on enqueues.
292: Solution
293: A vertex is enqueued only at the moment it is discovered, and discovery marks it as discovered. Any later neighbour check finds it discovered and does not enqueue it again. So each vertex is enqueued at most once, and the number of enqueues is at most the number of vertices, \(|V|\).

308: R1 · Edges in an undirected DFS tree
309: Let the graph be undirected and searched by Definition 3.1. Prove that for every edge \(\{u, v\}\), one end is an ancestor of the other in the recursion tree.
310: Solution
311: Let \(d(u) < d(v)\). When \(u\) is discovered, \(v\) is either undiscovered or discovered already. If \(v\) is already discovered at \(d(u)\), then \(d(v) < d(u)\), a contradiction. So \(v\) is undiscovered at \(d(u)\). If \(v\) were not discovered before \(f(u)\), the loop over the neighbours of \(u\) would reach \(v\) and discover it during \(u\)'s call, so \(v\) would be a descendant of \(u\). If \(v\) were discovered after \(f(u)\), the edge \(\{u, v\}\) would be scanned from \(u\) before \(f(u)\), which would discover \(v\) during \(u\)'s call. Either way \(v\) is a descendant of \(u\).
312: R2 · BFS reaches exactly the component of the source
313: State what Proposition 2.2 gives for the set of discovered vertices, and identify the set of vertices reachable from \(s\) in the graph.
314: Solution
315: Proposition 2.2 gives that the discovered vertices are exactly the vertices reachable from \(s\). These form the connected component of \(s\), because in an undirected graph reachability from \(s\) is the component containing \(s\). So a traversal from \(s\) discovers that component and no other vertex.
316: R3 · The complete graph
317: For the complete graph on \(n\) vertices, count the BFS scans from one source and compare the count with \(|V| + 2|E|\).
318: Solution
319: The complete graph has \(|E| = n(n-1)/2\) edges, and every vertex has degree \(n - 1\). BFS dequeues all \(n\) vertices, so the scans are \(n(n-1) = 2|E|\). The count \(|V| + 2|E|\) of Proposition 2.3 is \(n + n(n-1) = n^{2}\). So the scans are \(n(n-1)\) and the total operations are \(n^{2}\), which is of order \(n^{2}\), the same order as the adjacency-matrix cost of the same search, which reads \(n\) entries for each of the \(n\) dequeued vertices.
