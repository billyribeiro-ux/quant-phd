21: Some problems ask for the best of exponentially many choices: the fewest coins that make an amount, the longest sequence two strings share, the cheapest way to cut a sequence. The method answers each by writing the answer in terms of answers to smaller questions, and computing each of those smaller answers once. The method is only as good as its rule, and two traps come up. A rule that looks optimal can be wrong, as Example 2.4 shows, and a table can be far larger than the input's size suggests. This lesson proves that the rule is correct for two problems, counts the smaller computations in a lab, and shows where the method stops being efficient.
22: 1 Subproblems, recurrences and the two evaluation strategies
23: A subproblem is a smaller instance of the same question, identified by a short key such as a pair of integers. A recurrence expresses the answer to an instance as a formula in the answers to its subproblems, together with base values that need no further reduction. A recursive call is a call of a function on a smaller instance, made from inside that function.
24: Definition 1.1 (dynamic programming)
25: Dynamic programming solves a problem in three steps. It writes the answer as a recurrence over subproblems. It evaluates each distinct subproblem once and stores its value. It reads the answer from the stored values. There are two standard forms. In memoized recursion , a function calls itself on subproblems, and every call after the first for a given subproblem returns the stored value. In table fill , the values are written into a table in an order where each entry depends only on entries already written.
26: Both forms are meant to store the value of the recurrence at each subproblem they compute. The memoized form is not proved here to do so. Lab 1 checks that the answers of the memoized form agree with the table fill on 60 seeded instances (parts A and B), a grade C result in the key-results table. The two forms can touch different subproblems: on the pair ACGTACG and TGCATGC of Lab 1, Part C (the longest-common-subsequence problem of Section 3), the memoized recursion stores 28 of the 49 cells that the table fills. They can also touch the same ones: for denominations \(\{1\}\) and amount 3, both touch the amounts 0 to 3. The memoized form makes recursive calls, which the table fill does not make. Section 4 counts these differences. The rest of this section fixes the notion of a correct recurrence by proving one for each of two problems.
27: 2 Coin change: the recurrence and the greedy trap
28: Definition 2.1 (representations and the fewest-coin count)
29: Let \(D\) be a finite nonempty set of positive integers, the denominations . A multiset is a collection in which an element may appear several times and order is ignored. A representation of a nonnegative integer \(a\) is a multiset of elements of \(D\), each usable any number of times, whose sum is \(a\). Let \(f(a)\) be the fewest elements in a representation of \(a\), with \(f(a) = \infty\) when no representation exists.
30: Theorem 2.2 (coin-change recurrence)
31: Hypotheses.
32: \(D\) is a finite nonempty set of positive integers.
33: \(a\) is a nonnegative integer, and \(f\) is as in Definition 2.1.
34: The minimum over an empty set is \(\infty\), and \(\infty + 1 = \infty\).
35: Then \(f(0) = 0\), and for every \(a \ge 1\),
36: \[ f(a) = \min\{\, 1 + f(a - c) : c \in D,\ c \le a \,\}. \]
37: Proof
38: Base case. The only multiset of positive integers with sum \(0\) is the empty one, so \(f(0) = 0\).
39: Upper bound. Let \(a \ge 1\), and let \(g(a)\) be the right-hand side. Take any \(c \in D\) with \(c \le a\) and \(f(a - c) < \infty\). A fewest-element representation of \(a - c\) has \(f(a - c)\) elements; adding one element \(c\) gives a representation of \(a\) with \(1 + f(a - c)\) elements. So \(f(a) \le 1 + f(a - c)\) for each such \(c\), and \(f(a) \le g(a)\). If no such \(c\) exists, \(g(a) = \infty\) and the inequality holds.
40: Lower bound. Suppose \(f(a) < \infty\), and let \(S\) be a representation of \(a\) with \(f(a)\) elements. Since \(a \ge 1\), \(S\) is nonempty. Pick any element \(c\) of \(S\). Then \(c \le a\), and \(S\) without that element represents \(a - c\) with \(f(a) - 1\) elements. So \(f(a - c) \le f(a) - 1\), that is \(1 + f(a - c) \le f(a)\), and \(g(a) \le f(a)\).
41: Infinite case. If \(f(a) = \infty\) and \(g(a) < \infty\), some \(c \le a\) has \(f(a - c) < \infty\). Adding \(c\) to a representation of \(a - c\) represents \(a\), so \(f(a) < \infty\), a contradiction. Hence \(f(a) = g(a)\) in every case.
42: The proof uses no induction. Induction enters when the recurrence is turned into a table, which the next corollary states.
43: Corollary 2.3 (table fill computes the fewest-coin counts)
44: Hypotheses.
45: The hypotheses of Theorem 2.2 hold.
46: \(A \ge 0\) is an integer.
47: Write \(\mathrm{dp}[0] = 0\), and for \(a = 1, \ldots, A\) let \(\mathrm{dp}[a] = \min\{1 + \mathrm{dp}[a - c] : c \in D,\ c \le a,\ \mathrm{dp}[a - c] < \infty\}\), with the minimum over an empty set taken as \(\infty\). Then \(\mathrm{dp}[a] = f(a)\) for every \(0 \le a \le A\).
48: Proof
49: By strong induction on \(a\). For \(a = 0\), \(\mathrm{dp}[0] = 0 = f(0)\) by Theorem 2.2. For \(a \ge 1\), assume \(\mathrm{dp}[b] = f(b)\) for all \(b < a\). Each entry \(\mathrm{dp}[a - c]\) that the formula reads has \(a - c < a\), so \(\mathrm{dp}[a - c] = f(a - c)\) by hypothesis. The formula for \(\mathrm{dp}[a]\) is then the right-hand side of Theorem 2.2, so \(\mathrm{dp}[a] = f(a)\).
50: Example 2.4 (denominations 1, 3 and 4)
51: Take \(D = \{1, 3, 4\}\). Theorem 2.2 gives \(f(0), \ldots, f(6) = 0, 1, 2, 1, 1, 2, 2\). For \(a = 6\), the three candidates are \(1 + f(5) = 3\), \(1 + f(3) = 2\) and \(1 + f(2) = 3\), so \(f(6) = 2\), realized by \(3 + 3\). The largest-coin-first rule, which at each step takes the largest denomination that does not exceed the amount left, takes \(4\), then \(1\), then \(1\), which is three coins. The rule is not optimal here.
52: 3 Longest common subsequence (LCS)
53: Definition 3.1 (common subsequence and the prefix length)
54: Let \(x = x_1 x_2 \cdots x_m\) and \(y = y_1 y_2 \cdots y_n\) be finite sequences of symbols. A common subsequence of length \(k\) is given by indices \(p_1 < \cdots < p_k\) in \(x\) and \(q_1 < \cdots < q_k\) in \(y\) with \(x_{p_t} = y_{q_t}\) for every \(t\). Symbols are equal exactly when they are the same symbol. For \(0 \le i \le m\) and \(0 \le j \le n\), let \(\lambda(i, j)\) be the largest length of a common subsequence of the prefixes \(x_1 \cdots x_i\) and \(y_1 \cdots y_j\), with \(\lambda(0, j) = \lambda(i, 0) = 0\) for the empty prefix.
55: Lemma 3.2 (monotonicity, and at most one more per symbol)
56: Hypotheses.
57: \(x\) and \(y\) are finite sequences.
58: \(\lambda\) is as in Definition 3.1.
59: Symbols are compared by exact equality.
60: Under these hypotheses:
61: for \(1 \le i \le m\) and \(0 \le j \le n\), \(\lambda(i - 1, j) \le \lambda(i, j) \le \lambda(i - 1, j) + 1\);
62: for \(0 \le i \le m\) and \(1 \le j \le n\), \(\lambda(i, j - 1) \le \lambda(i, j) \le \lambda(i, j - 1) + 1\).
63: Proof
64: The left inequalities hold because a common subsequence of shorter prefixes is also one of longer prefixes, with the same indices. For the right inequality in (1), let \(Z\) be a longest common subsequence of \(x_1 \cdots x_i\) and \(y_1 \cdots y_j\), with length \(k\). If \(k = 0\) there is nothing to show. If \(p_k < i\), every index of \(Z\) in \(x\) lies in \(1, \ldots, i - 1\), so \(k \le \lambda(i - 1, j)\). If \(p_k = i\), the first \(k - 1\) pairs are a common subsequence of \(x_1 \cdots x_{i-1}\) and \(y_1 \cdots y_j\), so \(k - 1 \le \lambda(i - 1, j)\). In both cases \(k \le \lambda(i - 1, j) + 1\). Part (2) follows by exchanging the roles of \(x\) and \(y\).
65: Theorem 3.3 (longest-common-subsequence recurrence)
66: Hypotheses.
67: \(x\) and \(y\) are finite sequences.
68: Symbols are compared by exact equality.
69: \(\lambda\) is as in Definition 3.1.
70: Let \(1 \le i \le m\) and \(1 \le j \le n\).
71: (a) If \(x_i = y_j\), then \(\lambda(i, j) = \lambda(i - 1, j - 1) + 1\).
72: (b) If \(x_i \ne y_j\), then \(\lambda(i, j) = \max\{\lambda(i - 1, j), \lambda(i, j - 1)\}\).
73: Proof
74: Part (a). Let \(W\) be a longest common subsequence of \(x_1 \cdots x_{i-1}\) and \(y_1 \cdots y_{j-1}\). Since \(x_i = y_j\), adding the pair \(i, j\) after the indices of \(W\) gives a common subsequence of \(x_1 \cdots x_i\) and \(y_1 \cdots y_j\) of length \(\lambda(i - 1, j - 1) + 1\). So \(\lambda(i, j) \ge \lambda(i - 1, j - 1) + 1\).
75: For the converse, let \(Z\) be a longest common subsequence of \(x_1 \cdots x_i\) and \(y_1 \cdots y_j\), with length \(k\) and indices \(p, q\). If \(k = 0\) the claim is clear. Otherwise there are three exhaustive cases. (i) \(p_k = i\) and \(q_k = j\). The first \(k - 1\) pairs form a common subsequence of the prefixes of length \(i - 1\) and \(j - 1\), so \(k - 1 \le \lambda(i - 1, j - 1)\). (ii) \(p_k < i\). Then \(Z\) is a common subsequence of \(x_1 \cdots x_{i-1}\) and \(y_1 \cdots y_j\), so \(k \le \lambda(i - 1, j)\), and Lemma 3.2(2) gives \(\lambda(i - 1, j) \le \lambda(i - 1, j - 1) + 1\). (iii) \(q_k < j\). Symmetrically, \(k \le \lambda(i, j - 1) \le \lambda(i - 1, j - 1) + 1\) by Lemma 3.2(1). In all three cases \(k \le \lambda(i - 1, j - 1) + 1\).
76: Part (b). The inequality \(\lambda(i, j) \ge\) each term of the maximum holds by Lemma 3.2 (left inequalities). Let \(Z\) be a longest common subsequence, with length \(k \ge 1\) (the case \(k = 0\) is clear). If \(p_k = i\) and \(q_k = j\), then \(x_i = z_k = y_j\), which contradicts \(x_i \ne y_j\). So either \(p_k < i\), and \(k \le \lambda(i - 1, j)\), or \(q_k < j\), and \(k \le \lambda(i, j - 1)\). Hence \(\lambda(i, j) \le \max\{\lambda(i - 1, j), \lambda(i, j - 1)\}\).
77: Corollary 3.4 (row-by-row table fill is correct)
78: Hypotheses. The hypotheses of Theorem 3.3 hold.
79: Let \(\mathrm{dp}[i][j] = 0\) when \(i = 0\) or \(j = 0\). For \(1 \le i \le m\) and \(1 \le j \le n\), let \(\mathrm{dp}[i][j] = \mathrm{dp}[i - 1][j - 1] + 1\) if \(x_i = y_j\), and \(\mathrm{dp}[i][j] = \max\{\mathrm{dp}[i - 1][j], \mathrm{dp}[i][j - 1]\}\) otherwise, with the table filled row by row. Then \(\mathrm{dp}[i][j] = \lambda(i, j)\) for all \(0 \le i \le m\) and \(0 \le j \le n\).
80: Proof
81: By induction on \(i + j\), with the hypotheses of Theorem 3.3. Boundary entries are zero, which equals \(\lambda\) by Definition 3.1. Let \(i, j \ge 1\) and assume the claim for all pairs with a smaller sum. The three entries \((i - 1, j - 1)\), \((i - 1, j)\) and \((i, j - 1)\) have smaller sums, so they equal \(\lambda\) there. Theorem 3.3 then gives \(\lambda(i, j) = \mathrm{dp}[i][j]\) in both cases. The row-by-row order writes each of the three entries before \((i, j)\).
82: Proposition 3.5 (cost of the LCS table)
83: Hypotheses.
84: \(m\) and \(n\) are the lengths of the finite sequences \(x\) and \(y\).
85: The table is filled as in Corollary 3.4.
86: Then the table fill of Corollary 3.4 computes exactly \(mn\) entries, uses \((m + 1)(n + 1)\) stored entries, and performs at most \(K\,mn\) elementary operations for a fixed constant \(K\). Its operation count is therefore \(O(mn)\) in the sense of Lesson 1 .
87: Proof
88: The entries with \(1 \le i \le m\) and \(1 \le j \le n\) are the \(mn\) pairs, and each is computed once. Each computation reads at most three stored entries, makes one equality test, and does at most one addition or one comparison of two values, so it costs at most a fixed number \(K\) of elementary operations. Summing over \(mn\) entries gives at most \(K\,mn\) operations. The boundary entries are stored but not computed.
89: 4 Counting subproblems
90: The cost of a dynamic program has two parts, the number of distinct subproblems and the work per subproblem. Memoized recursion touches only the subproblems reached from the answer's subproblem. A table fill touches every entry in its range. Without a memo table, the same recursion recomputes a subproblem each time it is reached, so its number of calls can be far larger than the number of distinct subproblems. Memoized recursion stores its values in a dictionary, a hash map ( Lesson 2 ), keyed by the subproblem.
91: Proposition 4.2 (size of the coin table in the bits of the amount)
92: Hypotheses.
93: \(A \ge 1\) is an integer.
94: \(b\) is the number of binary digits of \(A\), so that \(b = \lfloor \log_2 A \rfloor + 1\).
95: Then the table of Corollary 2.3 has \(A + 1\) entries, and \(2^{b-1} < A + 1 \le 2^{b}\). In particular, \(A = 2^{40}\) has \(41\) bits in binary and a table with more than \(10^{12}\) entries.
96: Proof
97: The table has entries for \(0, 1, \ldots, A\), which is \(A + 1\) entries. Since \(b - 1 = \lfloor \log_2 A \rfloor \le \log_2 A\), we have \(2^{b-1} \le A\), so \(A + 1 > 2^{b-1}\). Since \(b = \lfloor \log_2 A \rfloor + 1 > \log_2 A\), we have \(A < 2^{b}\), so \(A + 1 \le 2^{b}\). For \(A = 2^{40}\), the binary form is a one followed by forty zeros, so \(b = 41\), and \(A + 1 = 2^{40} + 1 > 10^{12}\) because \(2^{40} = 1\,099\,511\,627\,776\).

99: Lab 1 · Memoized recursion, table fill and exhaustive search
100: Expected result: for 30 seeded LCS pairs and 30 seeded coin instances, the memoized recursion, the table fill and an exhaustive search return the same answer. For every LCS pair the table has exactly \(mn\) computed cells. For denominations (1, 3, 4) and amount 6, largest-coin-first uses 3 coins and the optimum uses 2. For the LCS pair ACGTACG and TGCATGC, the table has 49 computed cells, the memoized recursion stores 28 subproblems and makes 47 calls, and the same recursion with no memo table makes 183 calls.
101: """CS2 L07 lab 1: longest common subsequence and minimum-count coin change, three ways.
102: SIMULATED: every instance is generated from a fixed seed by an integer generator; none is market data.
103: Part A: the longest common subsequence (LCS) of 30 seeded string pairs, by memoized recursion, by table fill
104: and by exhaustive search over all subsequences of the first string. Part B: the fewest coins summing to a
105: seeded amount, for 30 seeded coin sets, by the same three methods (exhaustive search over all coin-count
106: vectors), plus the largest-coin-first rule on the coin set (1, 3, 4). Part C: subproblem counts. Each method's
107: recursive calls and stored subproblems are counted, and the table cells filled are counted. The lab counts
108: operations only; it does not time anything. Standard library only, no network access, no randomness other
109: than the seeded generator.
110: """
111: from __future__ import annotations
112: LCG_MULT = 1103515245
113: LCG_INC = 12345
114: LCG_MOD = 2**31
115: SEED = 20261028
116: ALPHABET = "ACGT"
117: LCS_INSTANCES = 30
118: COIN_INSTANCES = 30
119: FIXED_X = "ACGTACG"
120: FIXED_Y = "TGCATGC"
121: FIXED_COINS = (1, 3, 4)
122: FIXED_AMOUNT = 6
123: PART_C_AMOUNT = 20
124: class Lcg:
125: """A linear congruential generator on integers, so every run draws the same numbers."""
126: def __init__(self, seed: int) -> None:
127: self.state = seed % LCG_MOD
128: def below(self, n: int) -> int:
129: """Return an integer k with 0 <= k < n."""
130: if n < 1:
131: raise ValueError("below needs n >= 1")
132: self.state = (LCG_MULT * self.state + LCG_INC) % LCG_MOD
133: return (self.state >> 16) % n
134: def lcs_memo(x: str, y: str) -> tuple[int, int, int]:
135: """LCS length by memoized recursion. Returns (length, distinct subproblems stored, recursive calls)."""
136: cache: dict[tuple[int, int], int] = {}
137: calls = 0
138: def go(i: int, j: int) -> int:
139: nonlocal calls
140: calls += 1
141: if i == 0 or j == 0:
142: return 0
143: if (i, j) in cache:
144: return cache[(i, j)]
145: value = go(i - 1, j - 1) + 1 if x[i - 1] == y[j - 1] else max(go(i - 1, j), go(i, j - 1))
146: cache[(i, j)] = value
147: return value
148: length = go(len(x), len(y))
149: return length, len(cache), calls
150: def lcs_naive_calls(x: str, y: str) -> int:
151: """Recursive calls of the same recursion with no memo table: every call recomputes its subproblem."""
152: calls = 0
153: def go(i: int, j: int) -> int:
154: nonlocal calls
155: calls += 1
156: if i == 0 or j == 0:
157: return 0
158: if x[i - 1] == y[j - 1]:
159: return go(i - 1, j - 1) + 1
160: return max(go(i - 1, j), go(i, j - 1))
161: go(len(x), len(y))
162: return calls
163: def lcs_table(x: str, y: str) -> tuple[int, int]:
164: """LCS length by filling the (m+1) by (n+1) table row by row. Returns (length, cells filled)."""
165: m, n = len(x), len(y)
166: table = [[0] * (n + 1) for _ in range(m + 1)]
167: cells = 0
168: for i in range(1, m + 1):
169: for j in range(1, n + 1):
170: cells += 1
171: if x[i - 1] == y[j - 1]:
172: table[i][j] = table[i - 1][j - 1] + 1
173: else:
174: table[i][j] = max(table[i - 1][j], table[i][j - 1])
175: return table[m][n], cells
176: def is_subsequence(s: str, t: str) -> bool:
177: """True when s can be read off t in order, by deleting symbols of t."""
178: remaining = iter(t)
179: return all(ch in remaining for ch in s)
180: def lcs_exhaustive(x: str, y: str) -> int:
181: """LCS length by trying every subset of positions of x, which gives every subsequence of x."""
182: best = 0
183: for mask in range(1 << len(x)):
184: s = "".join(x[k] for k in range(len(x)) if (mask >> k) & 1)
185: if len(s) > best and is_subsequence(s, y):
186: best = len(s)
187: return best
188: def coins_memo(denoms: tuple[int, ...], amount: int) -> tuple[int | None, int, int]:
189: """Fewest coins summing to amount, by memoized recursion.
190: Returns (fewest coins or None when no combination exists, distinct amounts stored, recursive calls).
191: """
192: cache: dict[int, int | None] = {}
193: calls = 0
194: def best(a: int) -> int | None:
195: nonlocal calls
196: calls += 1
197: if a == 0:
198: return 0
199: if a in cache:
200: return cache[a]
201: found: list[int] = []
202: for c in denoms:
203: if c <= a:
204: sub = best(a - c)
205: if sub is not None:
206: found.append(1 + sub)
207: value = min(found) if found else None
208: cache[a] = value
209: return value
210: answer = best(amount)
211: return answer, len(cache), calls
212: def coins_naive_calls(denoms: tuple[int, ...], amount: int) -> int:
213: """Recursive calls of the same recursion with no memo table."""
214: calls = 0
215: def best(a: int) -> int | None:
216: nonlocal calls
217: calls += 1
218: if a == 0:
219: return 0
220: found: list[int] = []
221: for c in denoms:
222: if c <= a:
223: sub = best(a - c)
224: if sub is not None:
225: found.append(1 + sub)
226: return min(found) if found else None
227: best(amount)
228: return calls
229: def coins_table(denoms: tuple[int, ...], amount: int) -> tuple[int | None, int]:
230: """Fewest coins by filling the table entry for each amount 0..amount. Returns (answer, entries filled)."""
231: table: list[int | None] = [0] + [None] * amount
232: for a in range(1, amount + 1):
233: found: list[int] = []
234: for c in denoms:
235: sub = table[a - c] if c <= a else None
236: if sub is not None:
237: found.append(1 + sub)
238: table[a] = min(found) if found else None
239: return table[amount], amount
240: def coins_exhaustive(denoms: tuple[int, ...], amount: int) -> int | None:
241: """Fewest coins by trying every vector of coin counts (k_1, ..., k_d) with sum k_i * d_i = amount."""
242: best: int | None = None
243: def search(k: int, remaining: int, used: int) -> None:
244: nonlocal best
245: if k == len(denoms):
246: if remaining == 0 and (best is None or used < best):
247: best = used
248: return
249: c = denoms[k]
250: for count in range(remaining // c + 1):
251: search(k + 1, remaining - count * c, used + count)
252: search(0, amount, 0)
253: return best
254: def greedy_count(denoms: tuple[int, ...], amount: int) -> int | None:
255: """Largest-coin-first: repeatedly take the largest coin that fits. Returns the number of coins used."""
256: remaining, used = amount, 0
257: while remaining > 0:
258: fits = [c for c in denoms if c <= remaining]
259: if not fits:
260: return None
261: remaining -= max(fits)
262: used += 1
263: return used

270: y = "".join(ALPHABET[gen.below(len(ALPHABET))] for _ in range(n))
271: pairs.append((x, y))
272: return pairs

346: 5 Where the canon breaks
347: The greedy rule is not an algorithm for every coin set. Example 2.4 and Lab 1, part B show that largest-coin-first uses 3 coins for amount 6 with denominations (1, 3, 4), while the recurrence gives 2. The rule is optimal for denominations \(\{1, c\}\) (Problem R2), so optimality depends on the set, and the recurrence is the tool that settles which case holds.
348: A table over the amount is not polynomial in the input's size. Corollary 2.3 fills a table with one entry per amount. Proposition 4.2 shows that the number of entries grows exponentially in the number of bits that write the amount, which is the input size for the amount. Dynamic programming over values is polynomial in the value, not in the length of its encoding.
349: Memory is part of the cost. The LCS table has \((m + 1)(n + 1)\) entries (Proposition 3.5). Each row depends only on the row above it and on the entries already written to its left, so Problem R3 keeps two rows.
350: 6 Misconceptions
351: “Taking the largest coin first is optimal for any set of denominations.”
352: It is not. For \(D = \{1, 3, 4\}\) and amount 6, the rule uses \(4 + 1 + 1\), three coins, while \(3 + 3\) uses two (Example 2.4). The smallest amount where the rule fails for this set is 6 (Problem P3). Lab 1, part B prints the same pair: 3 coins against 2.
353: “Dynamic programming is polynomial in the size of the input, so the coin table is always cheap.”
354: Polynomial in the value of the amount is not polynomial in its encoding. Proposition 4.2 shows that \(A + 1\) entries is exponential in the \(b\) bits that write \(A\). An amount of \(2^{40}\) needs 41 bits and more than \(10^{12}\) entries.
355: “A recursion makes one call for each subproblem, so the number of calls equals the number of subproblems.”
356: The lab shows 47 calls and 28 stored subproblems for the memoized LCS recursion on the same pair. Calls to a stored subproblem are lookups, and calls with an empty prefix are base cases that are not stored. Without a memo table the same pair makes 183 calls, because subproblems are recomputed.

359: Mechanics
360: M1 · Coin change by the recurrence
361: Find \(f(9)\) for denominations \(\{2, 5\}\), using Theorem 2.2.
362: Solution
363: Theorem 2.2 gives \(f(9) = \min\{1 + f(7), 1 + f(4)\}\), since \(c = 2\) and \(c = 5\) both fit. Next, \(f(4) = 1 + f(2) = 2\) with \(f(2) = 1\). For \(f(7)\), the candidates are \(1 + f(5)\) and \(1 + f(2)\). Here \(f(5) = 1\) and \(f(2) = 1\), so \(f(7) = 2\). Then \(f(9) = \min\{3, 3\} = 3\), realized by \(2 + 2 + 5\).
364: M2 · An LCS table by hand
365: Fill the table \(\lambda(i, j)\) for \(x = \mathrm{AB}\) and \(y = \mathrm{BA}\), and state the answer.
366: Solution
367: Boundary entries are zero. \(\lambda(1,1)\): \(x_1 = \mathrm{A} \ne \mathrm{B} = y_1\), so the maximum of \(\lambda(0,1)\) and \(\lambda(1,0)\) is 0. \(\lambda(1,2)\): \(x_1 = y_2 = \mathrm{A}\), so \(\lambda(1,2) = \lambda(0,1) + 1 = 1\). \(\lambda(2,1)\): \(x_2 = y_1 = \mathrm{B}\), so \(\lambda(2,1) = \lambda(1,0) + 1 = 1\). \(\lambda(2,2)\): \(x_2 = \mathrm{B} \ne \mathrm{A} = y_2\), so the value is \(\max\{\lambda(1,2), \lambda(2,1)\} = 1\). The answer is 1, since \(\mathrm{AB}\) is not a subsequence of \(\mathrm{BA}\).
368: M3 · Cells of an LCS table
369: For \(m = 5\) and \(n = 8\), how many entries does the table have in total, how many are computed, and how many are boundary entries?
370: Solution
371: The table has \((m + 1)(n + 1) = 6 \times 9 = 54\) entries. The computed entries are \(mn = 5 \times 8 = 40\). The boundary entries are \(54 - 40 = 14\): the row \(i = 0\) has 9 entries, the column \(j = 0\) has 6, and the corner \((0, 0)\) is counted in both, so \(9 + 6 - 1 = 14\).
372: Proof
373: P1 · A single denomination
374: Let \(D = \{c\}\) with \(c \ge 1\). Prove that \(f(a) = a/c\) when \(c\) divides \(a\), and \(f(a) = \infty\) otherwise, using Theorem 2.2 and induction on \(a\).
375: Solution
376: Base. For \(a = 0\), \(f(0) = 0 = 0/c\). For \(1 \le a < c\), no element of \(D\) fits, so the minimum over an empty set gives \(f(a) = \infty\), and \(c\) does not divide \(a\). Step. Let \(a \ge c\), and assume the claim for smaller amounts. Theorem 2.2 gives \(f(a) = 1 + f(a - c)\). If \(c\) divides \(a\), then \(c\) divides \(a - c\), and the hypothesis gives \(f(a - c) = (a - c)/c\), so \(f(a) = 1 + (a - c)/c = a/c\). If \(c\) does not divide \(a\), then it does not divide \(a - c\), so \(f(a - c) = \infty\) and \(f(a) = \infty\).
377: P2 · Column-major fill also works
378: Show that Corollary 3.4 remains true if the table is filled column by column, with \(j\) as the outer index, instead of row by row.
379: Solution
380: The induction in the proof of Corollary 3.4 needs only that each entry is written after the three entries it reads. Column-major order writes \((i, j)\) after every entry of column \(j - 1\) and after \((i - 1, j)\) in column \(j\). The entry \((i - 1, j - 1)\) lies in column \(j - 1\), the entry \((i, j - 1)\) lies in column \(j - 1\), and \((i - 1, j)\) comes earlier in column \(j\). So all three are written first, and the same induction on \(i + j\) gives \(\mathrm{dp}[i][j] = \lambda(i, j)\).
381: P3 · The smallest failing amount
382: For \(D = \{1, 3, 4\}\), find the smallest amount \(a \ge 1\) at which largest-coin-first does not use \(f(a)\) coins.
383: Solution
384: For \(a = 1, 2, 3, 4\), the greedy rule takes \(1\), \(1 + 1\), \(3\) and \(4\), which are \(1, 2, 1, 1\) coins, and these equal \(f(a)\) (Example 2.4). For \(a = 5\), the rule takes \(4 + 1\), two coins, and \(f(5) = 2\) by Theorem 2.2. For \(a = 6\), the rule takes \(4 + 1 + 1\), three coins, while \(f(6) = 2\). So the smallest failing amount is 6.
385: Empirical
386: E1 · Stored amounts for the coin recursion
387: Lab 1, part C, reports 20 stored amounts for denominations (1, 3, 4) and amount 20. Explain why the count is exactly 20.
388: Solution
389: The denomination 1 is in \(D\). From amount \(a\), the recursion calls amount \(a - 1\), so starting at 20 it reaches every amount \(19, 18, \ldots, 1\). Each amount from 1 to 20 is stored once, and amount 0 is a base case that is not stored, so 20 amounts are stored. Every stored amount has a representation, so none is an infinite value.
390: E2 · Stored subproblems for the LCS pair
391: For \(x = \mathrm{ACGTACG}\) and \(y = \mathrm{TGCATGC}\), the table has 49 computed cells and the memoized recursion stores 28 subproblems. Explain the difference without rerunning the lab.
392: Solution
393: A table fill computes every pair \((i, j)\) with \(1 \le i \le 7\) and \(1 \le j \le 7\). The memoized recursion computes only the pairs reached from \((7, 7)\), by the rule that a matching pair moves to \((i - 1, j - 1)\) and a mismatch moves to \((i - 1, j)\) and to \((i, j - 1)\). The lab reports that 28 of the 49 pairs are reached, so the recursion stores 28. The table computes all 49, and the lab's output is consistent with both counts.
394: E3 · Calls and stored subproblems
395: For the same LCS pair, the memoized recursion makes 47 calls. Account for the difference between 47 calls and 28 stored subproblems.
396: Solution
397: Each stored subproblem is computed once, and each call that finds a stored value returns it without further recursion. A subproblem can be reached from several parents, so it is called more than once. The calls also include base calls with an empty prefix, where \(i = 0\) or \(j = 0\), which return 0 at once and are not stored. The 47 calls therefore count both repeated lookups and base calls, and the 28 stored subproblems count only the non-base pairs computed once.
398: Research
399: R1 · The coin table for a power of two
400: For denominations \(\{1, 2\}\) and amount \(A = 2^{20}\), show that the table has more than a million entries while the amount has 21 bits.
401: Solution
402: By Proposition 4.2 the table has \(A + 1 = 2^{20} + 1 = 1\,048\,577\) entries. The binary form of \(2^{20}\) is a one followed by twenty zeros, which has 21 bits. The count \(1\,048\,577\) exceeds \(10^6\). The table has one entry per amount, so its size is the value of the amount plus one. By Proposition 4.2 that size lies between \(2^{b-1} + 1\) and \(2^{b}\) for an amount of \(b\) bits: the bound \(2^{b}\) is reached only when \(A = 2^{b} - 1\), and the lower bound only when \(A = 2^{b-1}\).
403: R2 · Largest-coin-first is optimal for \(\{1, c\}\)
404: Let \(D = \{1, c\}\) with an integer \(c \ge 2\). Prove that largest-coin-first uses \(f(a)\) coins for every \(a \ge 0\).
405: Solution
406: Any representation of \(a\) uses \(k\) coins of value \(c\) and \(a - kc\) coins of value 1, with \(0 \le k \le \lfloor a/c \rfloor\). Its number of coins is \(k + (a - kc) = a - k(c - 1)\). Since \(c \ge 2\), this decreases as \(k\) increases, so the fewest coins come from the largest \(k\), which is \(\lfloor a/c \rfloor\). Largest-coin-first takes \(\lfloor a/c \rfloor\) coins of \(c\) (the rule takes \(c\) while it fits, and \(c\) fits exactly \(\lfloor a/c \rfloor\) times), then \(a - c\lfloor a/c \rfloor\) coins of 1. So it is optimal. The hypothesis \(D = \{1, c\}\) is what makes the argument work: \(\{1, 3, 4\}\) has two denominations above 1, and Example 2.4 shows the argument does not extend.
407: R3 · Two rows instead of a table
408: Show that the LCS length can be computed with two rows of \(n + 1\) entries, and state the memory used.
409: Solution
410: Row \(i\) of the table reads only row \(i - 1\) and the entry just left of the current cell in row \(i\) (Corollary 3.4). So a program can keep the previous row and the current row, and write row \(i\) over row \(i - 2\) after it is no longer needed. The memory is \(2(n + 1)\) entries, not \((m + 1)(n + 1)\). The final entry in row \(m\) is \(\lambda(m, n)\), because each row is computed by the same recurrence in the same order.
