21: A rolling minimum or maximum over the last \(w\) values is a common statistic on a stream, such as the lowest price in the last 30 observations. Scanning the window at every new value costs about \(w\) comparisons per value, so a stream of \(n\) values costs about \(nw\). A monotonic deque (Definition 2.1) answers each query from a short list of candidate positions, and its appends and removals over \(n\) values number at most \(2n\) (Theorem 2.4). This lesson defines the deque, proves its invariant by induction, and counts its operations on a seeded series.
22: 1 Windows and the naive scan
23: Definition 1.1 (window, rolling minimum and maximum)
24: Fix an integer \(w \ge 1\), the window size , and a series \(x_0, x_1, \ldots\) of real numbers. For each position \(i \ge 0\), the window at \(i\) is the set of indices \(W_i = \{j : \max(0, i-w+1) \le j \le i\}\). It holds \(\min(w, i+1)\) values. The rolling minimum at \(i\) is \(\min_{j \in W_i} x_j\), and the rolling maximum is \(\max_{j \in W_i} x_j\). Positions \(i < w-1\) use a partial window, which holds the values from the start of the series up to \(i\).
25: The naive method computes the minimum of each window by scanning it. A full window of \(w\) values needs \(w - 1\) comparisons, so scanning every position costs about \(w\) comparisons per value. The monotonic deque of Definition 2.1 answers each query with at most two operations per value on average, whatever the window size (Corollary 2.5(a)).
26: 2 The monotonic deque
27: Definition 2.1 (monotonic deque, minimum version)
28: A monotonic deque for rolling minimum and maximum is a double-ended list of indices: entries can be added and removed at both ends. It is updated at each position \(i\) as follows. (1) While the deque is not empty and the value at its back is at least \(x_i\), remove the back entry. (2) Append \(i\) to the back. (3) While the entry at the front has index at most \(i - w\), remove the front entry. The rolling minimum at \(i\) is the value at the front after step (3). The maximum version replaces "at least" in step (1) by "at most".
29: Each entry is an index, and its value is read from the series. Step (1) removes candidates that a newer value makes useless for the minimum: an older value that is at least as large as a newer one is never needed for the minimum. Whenever the older value is in the window, the newer value is also in the window (it expires later), and it is no larger. Step (3) removes indices that have left the window.
30: Theorem 2.2 (the deque invariant)
31: Hypotheses. (1) \(w \ge 1\) is an integer. (2) The values \(x_0, x_1, \ldots\) are real numbers, so any two can be compared and no value is NaN (a special value that compares false with every number). (3) Comparisons and arithmetic on indices are exact. Let \(D_i\) be the deque after the update at position \(i\). Then, under (1) to (3), \(D_i\) is the set of indices \(j \in W_i\) such that \(x_j < x_l\) for every \(l\) with \(j < l \le i\). Consequently the indices in \(D_i\) increase from front to back, and so do their values, strictly.
32: Proof
33: Write \(S_i\) for the set in the statement. We use induction on \(i\) (M1 Lesson 6). Base case, \(i = 0\). The deque is empty before step (1), so after step (2) it is \(\{0\}\), and step (3) keeps it because \(0 > 0 - w\). Also \(W_0 = \{0\}\), and the condition on \(l\) is vacuous, so \(S_0 = \{0\} = D_0\).
34: Inductive step. Let \(i \ge 1\) and assume \(D_{i-1} = S_{i-1}\). By the description of \(S_{i-1}\), the values of \(D_{i-1}\) strictly increase from front to back, and so do the indices. (a) Because the values increase toward the back, the entries with value at least \(x_i\) form a contiguous block at the back. Step (1) stops at the first back entry with value below \(x_i\), so it removes exactly this block. Call the rest \(R = \{j \in D_{i-1} : x_j < x_i\}\). (b) Step (2) gives \(R \cup \{i\}\). (c) The indices increase toward the back, so the entries with index at most \(i - w\) form a block at the front. Step (3) removes exactly that block, so \(D_i = \{j \in R \cup \{i\} : j \ge i - w + 1\}\).
35: We show \(D_i = S_i\). Take \(j \in D_i\). Then \(j \in W_i\). If \(j = i\), the condition on \(l\) is vacuous, so \(j \in S_i\). If \(j < i\), then \(j \in R \subseteq D_{i-1} = S_{i-1}\), so \(x_j < x_l\) for every \(l\) in \((j, i-1]\), and \(x_j < x_i\) because \(j \in R\). Thus \(j \in S_i\). Conversely, take \(j \in S_i\). If \(j = i\), then \(j \in D_i\). If \(j < i\), then \(j \ge i - w + 1 > i - w\), so \(j \in W_{i-1}\), and the condition on \((j, i-1]\) holds because it is part of the condition on \((j, i]\). So \(j \in S_{i-1} = D_{i-1}\). The condition with \(l = i\) gives \(x_j < x_i\), so \(j \in R\). Then \(j \in R \cup \{i\}\) and \(j \ge i - w + 1\), so \(j \in D_i\). Both inclusions hold. The strict increase of values follows from the description, because for \(j < j'\) both in \(S_i\), the condition with \(l = j'\) gives \(x_j < x_{j'}\).
36: Theorem 2.3 (rolling minimum is the front)
37: Hypotheses. Those of Theorem 2.2. The claim: for every \(i \ge 0\), the value at the front of \(D_i\) is \(\min_{j \in W_i} x_j\). Moreover the front index is the latest position in \(W_i\) that attains this minimum.
38: Proof
39: Let \(m = \min_{j \in W_i} x_j\), and let \(p\) be the largest index in \(W_i\) with \(x_p = m\). For \(l\) in \((p, i]\), the index \(l\) lies in \(W_i\), so \(x_l \ge m\), and \(x_l \ne m\) by the choice of \(p\). Hence \(x_p < x_l\) for every such \(l\), so \(p \in S_i = D_i\) by Theorem 2.2. Let \(f\) be the front of \(D_i\). The values increase from front to back, so \(x_f \le x_p = m\). Since \(f \in D_i \subseteq W_i\), also \(x_f \ge m\). Therefore \(x_f = m\). For the second claim, \(f\) is the smallest index in \(D_i\) and \(p\) is in \(D_i\), so \(f \le p\). If \(f < p\), then \(x_f < x_p\) by Theorem 2.2, which contradicts \(x_f = m = x_p\). So \(f = p\).
40: An amortized cost is an average over a run of insertions. It is not a bound on the cost of each insertion, which Corollary 2.5(c) shows can be as large as \(w\).
41: Theorem 2.4 (total operations)
42: Hypotheses. (1) \(w \ge 1\) is fixed. (2) The series has \(n \ge 1\) values, inserted at positions \(0, \ldots, n-1\). (3) The values are real numbers, and comparisons are exact. The claim: the number of appends and removals, from either end, is at most \(2n\). The number of value comparisons made in the removal loops of step (1) is at most \(2n\).
43: Proof
44: Each insertion appends exactly one entry, so there are \(n\) appends. An entry that is removed never returns, and each entry was appended once, so there are at most \(n\) removals. Hence there are at most \(2n\) operations. For the comparisons, each comparison in a step (1) loop either removes an entry, or it is the single comparison that stops the loop at one insertion. The removals number at most \(n\), and the stopping comparisons number at most one per insertion, so there are at most \(2n\) comparisons.
45: Corollary 2.5 (average cost, deque size, worst single push)
46: Hypotheses. Those of Theorem 2.4. Then (a) the average number of operations per insertion over a run of \(n\) values is at most 2, so the deque has amortized cost \(O(1)\) per value in the average sense defined in Section 2 above, and \(O(1)\) is the big-O notation of Lesson 1; (b) \(D_i\) never holds more than \(w\) indices; (c) a single insertion can remove as many as \(w\) indices, and it does so for the series \(x_0 < x_1 < \cdots < x_{w-1}\) followed by a value below all of them.
47: Proof
48: (a) follows from Theorem 2.4 by dividing \(2n\) by \(n\). For (b), \(D_i \subseteq W_i\) by Theorem 2.2, and \(|W_i| = \min(w, i+1) \le w\). For (c), the new index \(i\) is not removed in its own insertion: step (1) inspects only entries already in the deque, and step (3) removes only indices at most \(i - w < i\). So the removals at insertion \(i\) are entries of \(D_{i-1}\), and at most \(|D_{i-1}| \le w\) of them occur. For the example, the first \(w\) insertions keep all \(w\) indices, since the values increase and step (1) removes nothing, and no index has left the window yet. The next value is below every value in the deque, so step (1) removes all \(w\) entries, and step (3) then finds nothing to remove.
49: Theorem 2.3 says the front is the rolling minimum. The operation count in Theorem 2.4 is a bound on totals, and Corollary 2.5(c) shows that one insertion can cost \(w\) removals. The lab below checks the front against brute force on one series, and prints the operation counts and removal counts that bear on the other two results. Section 3 lists where the amortized count can be misread.
50: Lab 1 · Rolling minimum and maximum against brute force, with operation counts
51: The lab asserts two claims: for a seeded series of 200 integers and the five window sizes 1, 2, 5, 13 and 30, the deque's rolling minimum and maximum equal brute-force values (the minimum or maximum of a scan of each window) at every position, including the partial windows at the start; and no deque holds more indices than the window size. It does not assert the operation bound. It prints the number of operations for each deque, an operation being an append or a removal, beside the bound \(2N = 400\), and it prints the largest number of removals made by a single insertion and the largest deque size.
52: """CS2 L10 lab 1: a monotonic deque for rolling minimum and maximum, checked against brute force.
53: Claim checked: for a seeded integer series of N = 200 values and the five window sizes 1, 2, 5, 13 and 30,
54: the deque's rolling minimum and rolling maximum equal the brute-force minimum and maximum at every position.
55: At position i the window holds the last min(w, i + 1) values, so the first w - 1 positions use partial windows.
56: The total number of deque operations (appends plus removals) for each deque is counted and compared with 2N.
57: The largest number of removals made by a single push is also printed. SIMULATED integer series, seeded.
58: Standard library only. No network access.
59: """
60: from __future__ import annotations
61: import random
62: from collections import deque
63: N = 200
64: SEED = 1010
65: WINDOWS = (1, 2, 5, 13, 30)
66: class MonotonicDeque:
67: """Keeps (index, value) pairs.
68: In min mode the values strictly increase from front to back; in max mode they strictly decrease.
69: """
70: def __init__(self, window: int, is_min: bool) -> None:
71: self.window = window
72: self.is_min = is_min
73: self.items: deque[tuple[int, int]] = deque()
74: self.operations = 0
75: self.largest_single_push_removals = 0
76: self.largest_size = 0
77: def push(self, index: int, x: int) -> None:
78: removals = 0
79: while self.items:
80: back = self.items[-1][1]
81: dominated = back >= x if self.is_min else back <= x
82: if not dominated:
83: break
84: self.items.pop()
85: removals += 1
86: self.items.append((index, x))
87: while self.items[0][0] <= index - self.window:
88: self.items.popleft()
89: removals += 1
90: self.operations += 1 + removals
91: self.largest_single_push_removals = max(self.largest_single_push_removals, removals)
92: self.largest_size = max(self.largest_size, len(self.items))
93: def best(self) -> int:
94: return self.items[0][1]
95: def brute(series: list[int], i: int, window: int, want_min: bool) -> int:
96: """Minimum or maximum of the last min(window, i + 1) values, by scanning the window."""
97: segment = series[max(0, i - window + 1) : i + 1]
98: return min(segment) if want_min else max(segment)
99: def main() -> None:
100: rng = random.Random(SEED)
101: series = [rng.randint(0, 999) for _ in range(N)]
102: for window in WINDOWS:
103: low = MonotonicDeque(window, is_min=True)
104: high = MonotonicDeque(window, is_min=False)
105: for i, x in enumerate(series):
106: low.push(i, x)
107: high.push(i, x)
108: if low.best() != brute(series, i, window, want_min=True):
109: raise AssertionError(f"rolling minimum differs at window {window}, position {i}")
110: if high.best() != brute(series, i, window, want_min=False):
111: raise AssertionError(f"rolling maximum differs at window {window}, position {i}")
112: if low.largest_size > window or high.largest_size > window:
113: raise AssertionError(f"a deque holds more than {window} indices")
114: print(
115: f"window {window:>2}: all {N} positions match brute force; "
116: f"operations min {low.operations}, max {high.operations}, bound 2N = {2 * N}; "
117: f"largest single-push removals {max(low.largest_single_push_removals, high.largest_single_push_removals)}; "
118: f"largest deque size {max(low.largest_size, high.largest_size)}"
119: )
120: main()
121: window 1: all 200 positions match brute force; operations min 399, max 399, bound 2N = 400; largest single-push removals 1; largest deque size 1
122: window 2: all 200 positions match brute force; operations min 398, max 399, bound 2N = 400; largest single-push removals 2; largest deque size 2
123: window 5: all 200 positions match brute force; operations min 398, max 398, bound 2N = 400; largest single-push removals 5; largest deque size 5
124: window 13: all 200 positions match brute force; operations min 397, max 398, bound 2N = 400; largest single-push removals 6; largest deque size 8
125: window 30: all 200 positions match brute force; operations min 396, max 397, bound 2N = 400; largest single-push removals 6; largest deque size 10
126: Each line covers one window size and all 200 positions, for both the minimum deque and the maximum deque. SIMULATED integer series, seeded. The brute-force comparison is exact, because the values are integers, so every mismatch would appear as an error and none did. The operation totals lie between 396 and 399, below the bound of 400 for every window size. The lab shows that the bound holds on this series and these five windows. It does not show that the bound is tight, and it says nothing about time. The largest single-insertion removal count equals the window size for windows 1, 2 and 5, which matches Corollary 2.5(c). For windows 13 and 30 the largest single removal count is 6, below the window size. This series does not reach the worst case of Corollary 2.5(c) for those windows. Corollary 2.5(c) gives a series that does, and the lab does not run it.
127: 3 Where the canon breaks
128: The amortized bound is a bound on totals. Theorem 2.4 bounds the operations over \(n\) insertions. A single insertion can remove \(w\) entries (Corollary 2.5(c)), so the cost of one call is not constant in the worst case. A claim of a constant worst-case operation count per value is false for this structure.
129: One fixed window size. Step (3) removes indices that have left the window of size \(w\), and those entries cannot return. A deque built for one window size cannot answer for a larger one without starting again from the series, because the indices it dropped may be needed. The lab uses a separate deque for each window size for this reason.
130: Ties and NaN. Step (1) removes entries whose value is at least the new value, so with ties the latest position is kept. Theorem 2.2 assumes that values are totally ordered (hypothesis 2). NaN compares false with every number, so the proof does not cover a series that contains NaN, and such a series must be rejected before it reaches the deque.
131: 4 Misconceptions
132: “Each push costs constant time in the worst case, so the deque is constant time per value.”
133: Corollary 2.5(c) shows one push can remove \(w\) entries. The constant is an average over a run (Theorem 2.4). The lab's largest single-push removal count is 5 for window 5, which equals the window size, the largest count Corollary 2.5(c) allows.
134: “The deque holds every value in the window, so it needs the whole window in memory.”
135: The deque holds only candidates for the minimum or maximum. Theorem 2.2 describes which indices stay, and the lab prints the largest deque size: 10 for window 30, which is below the window size of 30.
136: “The most recent value is at the front of the deque.”
137: The back holds the most recent index \(i\), because step (2) appends it there. The front holds the rolling minimum (Theorem 2.3). By Theorem 2.3 the front is the new index \(i\) exactly when \(x_i\) is at most every value still in the window, and otherwise it is an older index.

140: Mechanics
141: M1 · Rolling minimum by hand
142: For the series 3, 1, 4, 1, 5 and window \(w = 3\), give the rolling minimum at positions \(i = 0\) to \(4\).
143: Solution
144: The windows are \(W_0 = \{0\}\), \(W_1 = \{0, 1\}\), \(W_2 = \{0, 1, 2\}\), \(W_3 = \{1, 2, 3\}\) and \(W_4 = \{2, 3, 4\}\). The minima are \(3\) (window \(\{0\}\)); \(\min(3, 1) = 1\); \(\min(3, 1, 4) = 1\); \(\min(1, 4, 1) = 1\); \(\min(4, 1, 5) = 1\). The rolling minimum is 3, 1, 1, 1, 1.
145: M2 · Trace the deque
146: Trace Definition 2.1 (minimum version) on the series 3, 1, 4, 1, 5 with \(w = 3\). After each position, write the deque as (index, value) pairs.
147: Solution
148: \(i = 0\), value 3: \([(0, 3)]\). \(i = 1\), value 1: the back value 3 is at least 1, so it is removed; append: \([(1, 1)]\). \(i = 2\), value 4: the back value 1 is less than 4, so nothing is removed; append: \([(1, 1), (2, 4)]\). \(i = 3\), value 1: the back value 4 is at least 1, removed; the next back value 1 is at least 1, removed; append: \([(3, 1)]\). \(i = 4\), value 5: nothing removed; append: \([(3, 1), (4, 5)]\). The fronts are 3, 1, 1, 1, 1, which agrees with M1.
149: M3 · Count the operations in M2
150: Count the appends and removals for the trace in M2, and compare the total with the bound of Theorem 2.4.
151: Solution
152: There are 5 appends, one per position. Removals: one at \(i = 1\) (index 0), two at \(i = 3\) (indices 2 and 1), and none at the other positions. Expiry removed nothing: the threshold \(i - w\) is \(-3, -2, -1, 0, 1\) at positions 0 to 4, and at each position every index left in the deque is larger than the threshold. The total is \(5 + 3 = 8\), which is at most \(2 \times 5 = 10\).
153: Proof
154: P1 · The deque never exceeds the window
155: Show that \(|D_i| \le w\) for every \(i\), using Theorem 2.2 and no other fact about the deque.
156: Solution
157: By Theorem 2.2, \(D_i\) is a set of indices in \(W_i\). The window \(W_i\) contains \(\min(w, i+1)\) indices, which is at most \(w\). A subset of a set with at most \(w\) elements has at most \(w\) elements, so \(|D_i| \le w\).
158: P2 · Ties and the front
159: Show from Theorem 2.3 that if the minimum of the window occurs at two positions, the front of \(D_i\) is the later one.
160: Solution
161: Theorem 2.3 states that the front is the latest position \(p\) in \(W_i\) that attains the minimum. The statement is the second claim of Theorem 2.3, whose proof shows that the front cannot be an earlier position with the same value, because the values in \(D_i\) strictly increase from front to back. So among two positions with the minimum value, the earlier one is removed in step (1) of the later insertion, and the front is the later one.
162: P3 · The maximum version
163: State the hypotheses and the invariant for the maximum deque, and show that the rolling maximum is its front.
164: Solution
165: Hypotheses. Those of Theorem 2.2. Replace "at least" by "at most" in step (1) of Definition 2.1. The invariant becomes: \(D_i\) is the set of \(j \in W_i\) with \(x_j > x_l\) for every \(l\) in \((j, i]\), and the values strictly decrease from front to back. The proof of Theorem 2.2 carries over with every inequality between values reversed. The front is then the largest value in \(W_i\), by the argument of Theorem 2.3 with signs reversed.
166: Empirical
167: E1 · Why window 1 costs 2n minus 1
168: Lab 1 prints 399 operations for window 1 on 200 values, for both deques. Explain why the count is exactly \(2n - 1\) for every series, and check the formula for \(n = 200\).
169: Solution
170: With \(w = 1\) the window at \(i\) is \(\{i\}\). The first insertion appends one entry. Each later insertion \(i\) appends one entry, and the previous index \(i-1\) is removed exactly once: either step (1) removes it because its value is at least \(x_i\), or step (3) removes it because \(i - 1 \le i - w = i - 1\). Each later insertion therefore costs 2 operations. The total is \(1 + 2(n-1) = 2n - 1\). For \(n = 200\), the total is \(399\), which matches the lab.
171: E2 · Reproduce the worst single push
172: Find a series of length 6 for which the minimum deque with \(w = 5\) makes a single insertion that removes 5 entries, and state which insertion does it.
173: Solution
174: Take 1, 2, 3, 4, 5, 0. The first five insertions append without removals, because each value is larger than the previous one, and the deque holds indices 0 to 4. At \(i = 5\) the value 0 is below every value in the deque, so step (1) removes all five entries. Step (3) then has nothing to remove. The insertion at \(i = 5\) removes 5 entries, which equals the window size.
175: E3 · A decreasing series
176: For a strictly decreasing series of \(n\) values and any window \(w \ge 1\), find the total operations of the minimum deque, and say how the count depends on \(w\).
177: Solution
178: Each later value is smaller than the back, so step (1) removes the back entry, and the deque always holds one entry. The first insertion costs one append. Each later insertion costs one append and one removal, so the total is \(2n - 1\), with no dependence on \(w\). The series is strictly decreasing, so the argument uses only that each value is below its predecessor.
179: Research
180: R1 · Duplicates with a looser rule
181: Suppose step (1) removed back entries only when their value is strictly greater than \(x_i\). Show that the rolling minimum is still the front, and say what the deque then holds.
182: Solution
183: Hypotheses. Those of Theorem 2.2, with the looser rule. With the looser rule the values in the deque are non-decreasing from front to back, and the deque can hold equal values. (After step (1), the back value is at most \(x_i\), because every back entry strictly greater than \(x_i\) has been removed, so appending \(i\) keeps the order.) Let \(m\) be the window minimum and \(p\) the latest position that attains it. Every later position \(l\) in \((p, i]\) has \(x_l > m = x_p\), by the choice of \(p\). So the looser rule never removes \(p\), because it removes a back entry only when its value is strictly greater than the new value, and \(x_p\) is never strictly greater than a later value. Hence \(p\) stays in the deque. The front has the smallest index, so its index is at most \(p\), and its value is at most \(x_p = m\) because the values are non-decreasing. It is in the window, so its value is \(m\). The deque may therefore hold several entries with the value \(m\). The operation bound of Theorem 2.4 still holds, because each entry is still appended once and removed at most once.
184: R2 · Why expiry uses indices
185: Explain why step (3) compares indices with \(i - w\), not the values, and give a series where a rule that expires by value would remove the wrong entry.
186: Solution
187: Two positions can hold the same value, so a value cannot say which entry has left the window. Take the series 4, 1, 4 with \(w = 2\), minimum version. At \(i = 1\), step (1) removes index 0 (its value 4 is at least 1), so the deque is \([(1, 1)]\). At \(i = 2\) the window is \(\{1, 2\}\), so index 0 has expired, but it is already gone. A rule that expires by value, removing every entry whose value equals the value that left the window (here 4), would remove the valid entry \((2, 4)\), which belongs to \(D_2\) by Theorem 2.2, and the deque would no longer hold the candidates of Theorem 2.2. Expiry by index removes nothing at \(i = 2\), and the deque is \([(1, 1), (2, 4)]\), which is correct.
188: R3 · The largest possible expiry count
189: Over \(n\) insertions with window \(w\), what is the largest possible number of entries removed by step (3), and which series attains it?
190: Solution
191: An index \(j\) can be removed by step (3) only at an insertion \(i\) with \(j \le i - w\), so \(j + w \le i \le n - 1\). That means \(j \le n - 1 - w\), which allows at most \(n - w\) indices (for \(n \ge w\)). Each index is removed at most once, so the count is at most \(n - w\). The increasing series \(0, 1, \ldots, n-1\) attains the bound: no value is ever removed by step (1), and each index \(j \le n - 1 - w\) is at the front when insertion \(j + w\) occurs, so step (3) removes it. The count is \(n - w\).
