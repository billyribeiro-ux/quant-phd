21: A program that stores many account identifiers must test membership without scanning every identifier. A table that computes an index from each key can answer that by searching only the entries stored at that index. This lesson defines the chained form of such a table, counts the key comparisons that a search makes (its probes, Definition 1.2), and proves its average cost under a stated model of the hash function. It then shows that the same table has a key set on which an unsuccessful search makes one comparison per stored key. Lab 2 counts the comparisons on seeded keys and on the colliding set, and it prints no time.
22: 1 Buckets, chains and probes
23: Definition 1.1 (chained hash map)
24: A hash map with \(m\) buckets stores a set of distinct keys in a table of \(m\) slots. A hash function \(h\) sends each key to a bucket index \[h(x) \in \{0, \dots, m - 1\}\]. In the chained form, each bucket holds a list of the keys whose hash is that index, called its chain. Inserting a key appends it to the end of its chain, and a key already present is not added twice.
25: Definition 1.2 (probes, load factor)
26: A probe is one comparison of the sought key with a key stored in the chain being searched. A search for a key \(x\) reads only the chain of bucket \(h(x)\). A successful search stops at the matching key, and its probe count is that key's position in the chain. An unsuccessful search compares \(x\) with every key of its chain. With \(n\) stored keys and \(m\) buckets, the load factor is \(\alpha = n / m\).
27: Proposition 1.3 (the worst case of one search)
28: Assume \(n\) distinct keys are stored in a chained table with \(m\) buckets and a fixed hash function. Then every search examines at most \(n\) keys, so its probe count is at most \(n\).
29: Proof
30: A search reads only the chain of one bucket, and that chain holds some of the \(n\) stored keys, no key twice. So at most \(n\) comparisons are made, and every search of Definition 1.2 satisfies the bound. \(\blacksquare\)
31: Proposition 1.4 (a colliding key set)
32: Let \(M = 2654435761\) and let \[h(x) = ((x M) \bmod 2^{32}) \bmod 64\], which is the hash function of Lab 2. For every integer \(j \ge 0\), \(h(64 j) = 0\). Assume a table of 64 buckets with this \(h\) that stores exactly the \(n\) keys \(64, 128, \dots, 64 n\). Then all \(n\) keys lie in bucket 0, and an unsuccessful search for the absent key \(64(n + 1)\) makes \(n\) probes.
33: Proof
34: Write \(jM = q \cdot 2^{26} + r\) with integers \(q \ge 0\) and \(0 \le r < 2^{26}\). Then \(64 j M = q \cdot 2^{32} + 64 r\), and \(0 \le 64 r < 2^{32}\), so \((64 j M) \bmod 2^{32} = 64 r\). This is a multiple of 64, so \(h(64 j) = 0\). The key \(64(n + 1)\) is not among the keys \(64 j\) for \(1 \le j \le n\), and its chain is the chain of all \(n\) keys, so the unsuccessful search makes \(n\) probes. \(\blacksquare\)
35: Remark 1.5 (what the proposition shows)
36: Proposition 1.4 is a fact about one fixed hash function on one family of keys. It does not say that every hash function collides on these keys. It says that this function, which the lab uses, is a poor choice for keys that are multiples of 64, and the count \(n\) is the cost the table pays on that family.
37: 2 Average cost under simple uniform hashing
38: Assumption 2.1 (simple uniform hashing)
39: The \(n\) stored keys are distinct. Each stored key, and the key sought in a search, is assigned to a bucket chosen uniformly from the \(m\) buckets, and the choice for each key is made without regard to the choices for the other keys. Problem P2 shows that the probability that two keys share a bucket is \(1/m\). Averages in this lesson are taken over these assignments.
40: Proposition 2.2 (average probes)
41: Assume Assumption 2.1 and \(n \ge 1\). Then (a) the average probe count of an unsuccessful search is \(n / m = \alpha\); (b) the average probe count of a successful search for the key inserted in position \(i\), where \(1 \le i \le n\), is \(1 + (i - 1)/m\); and (c) the average of the values in (b) over the \(n\) keys is \(1 + (n - 1)/(2m)\).
42: Proof
43: An average over the bucket assignments is a probability-weighted sum over those assignments, so the average of a finite sum of counts is the sum of their averages. (a) An unsuccessful search for \(x\) makes one probe for each stored key whose bucket equals the bucket of \(x\). For a stored key \(k\), the bucket of \(k\) is chosen without regard to that of \(x\), and it equals it with probability \(1/m\). So the average count is \(\sum_{k} 1/m = n/m\). (b) The key in position \(i\) makes one probe itself and one probe for each earlier key in its bucket. Each of the \(i - 1\) earlier keys shares that bucket with probability \(1/m\), so the average probe count is \(1 + (i - 1)/m\). (c) Averaging over \(i\) gives \[\frac{1}{n} \sum_{i=1}^{n} \bigl(1 + \frac{i - 1}{m}\bigr) = 1 + \frac{1}{nm} \sum_{i=0}^{n-1} i\]. By Proposition 1.4 of Lesson 1, the sum is \(n(n - 1)/2\), so the average is \(1 + (n - 1)/(2m)\). \(\blacksquare\)
44: Corollary 2.3 (bounded load gives bounded search cost)
45: Assume Assumption 2.1, and let \(c\) be a constant. For a table with \(n\) keys and \(m\) buckets satisfying \(n \le c\, m\), every average search cost of Proposition 2.2 is at most \(1 + c\). So for a family of tables that satisfies \(n \le c\, m\) at every size \(n \ge 1\), the average cost of a search is in \(O(1)\), with witness \(1 + c\) and threshold 1, in the sense of Definition 1.1 of Lesson 1.
46: Proof
47: By Proposition 2.2(a), an unsuccessful search costs \(\alpha = n/m \le c\). By Proposition 2.2(b), a successful search for the key in position \(i\) costs \(1 + (i - 1)/m \le 1 + (n - 1)/m \le 1 + c\). \(\blacksquare\)
48: Remark 2.4 (what the model does not cover)
49: Corollary 2.3 needs both the uniform assignment and the bound \(n \le c\, m\). A fixed table with \(m = 64\), as in Lab 2, has no such bound: when \(n\) grows, \(\alpha\) grows with it. The lab keeps \(m\) fixed, so \(\alpha = n/m\) grows with \(n\), and the printed averages show that growth. A table that grows its bucket count to keep \(\alpha\) bounded is outside this lesson.
50: Example 2.5 (the lab's hash is not the model)
51: Lab 2 uses the fixed function of Proposition 1.4, not a random one. Assumption 2.1 is a model of random bucket assignments. Proposition 1.4 shows that this function sends all keys \(64 j\) to one bucket. For 50 fixed keys, Assumption 2.1 gives the probability that they all share one bucket as \(64 \cdot (1/64)^{50} = 64^{-49}\). So the measured averages on seeded random keys are compared with the model's values and not identified with them.

57: a multiplicative hash that is fixed in this file. One probe is one key comparison inside a chain. A successful
58: search stops at the matching key, and an unsuccessful search compares the key with every key in its chain.
59: The model values printed next to the measured ones are exact averages over the random bucket assignments
60: of simple uniform hashing, which assumes that each key lands in a bucket chosen uniformly, without regard
61: to the buckets of the other keys. This hash is not that random model, so the measured and model values can
62: differ. The output prints both values.
63: """
64: from __future__ import annotations
65: import random
66: BUCKETS = 64
67: MULTIPLIER = 2654435761
68: def bucket_of(key: int, m: int) -> int:
69: """The bucket of an integer key in a table of m buckets: ((key * MULTIPLIER) mod 2**32) mod m."""
70: if m < 1:
71: raise ValueError(f"bucket_of needs m >= 1, got {m}")
72: return ((key * MULTIPLIER) % 2**32) % m
73: class ChainedHashTable:
74: """A hash table of distinct integer keys in m buckets, each bucket a chain in insertion order."""
75: def __init__(self, m: int) -> None:
76: if m < 1:
77: raise ValueError(f"ChainedHashTable needs m >= 1, got {m}")
78: self.m = m
79: self.chains: list[list[int]] = [[] for _ in range(m)]
80: def insert(self, key: int) -> None:
81: """Append key to the end of its chain. A key already present is not inserted twice."""
82: chain = self.chains[bucket_of(key, self.m)]
83: if key not in chain:
84: chain.append(key)
85: def lookup(self, key: int) -> tuple[bool, int]:
86: """Return (found, probes): the number of key comparisons made in the key's chain."""
87: probes = 0
88: for stored in self.chains[bucket_of(key, self.m)]:
89: probes += 1
90: if stored == key:
91: return True, probes
92: return False, probes
93: def chain_formula(table: ChainedHashTable) -> int:
94: """The total probes of one successful lookup of every stored key: the sum of L(L + 1) / 2 over the chains."""
95: return sum(len(chain) * (len(chain) + 1) // 2 for chain in table.chains)
96: def main() -> None:

113: print(

116: f"(model {alpha:.4f}) longest chain={longest}"
117: )

149: 3 Where the canon breaks
150: The average-case bound rests on a model, and four limits apply to what this lesson establishes.
151: Averages hide the worst key set. Corollary 2.3 bounds the average cost over random bucket assignments. Proposition 1.4 gives a key set on which a fixed function makes an unsuccessful search cost one probe per stored key, so the average is not a guarantee for every input.
152: The model needs uniform choices, made without regard to the other keys. Assumption 2.1 is not a property of a particular function. The lab's multiplicative hash is deterministic, and its measured averages differ from the model values that the output prints beside them.
153: The load must stay bounded. Corollary 2.3 needs \(n \le c\, m\). With \(m\) fixed, as in the lab, the search cost grows with \(n\), and Remark 2.4 explains why this lesson does not resize the table.
154: The table stores keys. The table holds keys and no values, and the lab measures a count of probes and no other cost.
155: 4 Misconceptions
156: “Hashing is \(O(1)\) always.”
157: Corollary 2.3 says the average cost is bounded under Assumption 2.1 and \(n \le c\, m\). It is not a bound for every key set. Proposition 1.4 gives keys on which an unsuccessful search makes \(n\) probes for the 50 keys of Lab 2, and the lab prints 50 probes for the absent key 3264.
158: “An absent key is found quickly, because there is nothing to find.”
159: An unsuccessful search scans its whole chain. Its average count under Assumption 2.1 is \(\alpha\), while a successful search costs \(1 + (n - 1)/(2m)\) on average, which is about \(1 + \alpha/2\) for large \(n\) (Proposition 2.2). At \(n = 256\) Lab 2 prints an unsuccessful average of 4.0280 and a successful average of 3.0156, so at this load the absent keys cost more.
160: “Doubling the number of keys doubles the cost of a successful search.”
161: At fixed \(m\), the average successful cost is \(1 + (n - 1)/(2m)\). Doubling \(n\) to \(2n\) changes it by \(n/(2m)\), so the increase is an amount, not a factor. Lab 2 prints successful averages of 2.0078 at \(n = 128\) and 3.0156 at \(n = 256\), and the exact averages from its integer totals are 257/128 = 2.0078125 and 193/64 = 3.015625. The totals 257 and 772 are the only integers whose quotients by 128 and 256 round to the printed values 2.0078 and 3.0156, the same interval argument as in Exercise E1. The model predicts an increase of \[(256 - 128)/128 = 1\] between those two loads, and the measured increase is \[193/64 - 257/128 = 1.0078125\], which the printed values 3.0156 and 2.0078 show as 1.0078. Either way the average does not double.

164: Mechanics
165: M1 · Load factor
166: A table has \(m = 40\) buckets and \(n = 100\) keys. Find \(\alpha\) and the average unsuccessful probe count under Assumption 2.1.
167: Solution
168: \(\alpha = 100 / 40 = 2.5\). By Proposition 2.2(a) the average unsuccessful probe count is \(\alpha = 2.5\).
169: M2 · Successful cost at a given position
170: Under Assumption 2.1 with \(m = 64\), find the average probe count of a successful search for the key inserted tenth.
171: Solution
172: By Proposition 2.2(b) with \(i = 10\), the cost is \(1 + 9/64 = 73/64\), which is 1.140625 exactly.
173: M3 · A bound on the average cost
174: Under Assumption 2.1, a table has \(m = 50\) buckets and \(n\) keys with \(n \le 100\). Give a bound on every average search cost.
175: Solution
176: Here \(n \le c\, m\) with \(c = 2\). By Corollary 2.3 every average search cost is at most \(1 + 2 = 3\).
177: Proof
178: P1 · Probes of the colliding keys
179: Prove that the successful search for the key \(64 j\) in the colliding set of Proposition 1.4 makes exactly \(j\) probes, and deduce the total of \(n(n + 1)/2\) probes over all \(n\) keys.
180: Solution
181: The keys are inserted in the order \(64 \cdot 1, 64 \cdot 2, \dots\), and each is appended to the same chain. The key \(64 j\) is at position \(j\), so the search compares it with \(j\) keys and stops, making \(j\) probes. Summing over \(j = 1, \dots, n\) gives \[\sum_{j=1}^{n} j = \sum_{j=0}^{n} j = n(n + 1)/2\], by Proposition 1.4 of Lesson 1 with \(n + 1\) in place of \(n\).
182: P2 · The bucket of one key, given another
183: Under Assumption 2.1, show that for distinct stored keys \(k\) and \(k'\), the probability that they share a bucket is \(1/m\).
184: Solution
185: Condition on the bucket of \(k'\), which is some \(b\). The bucket of \(k\) is chosen uniformly from \(m\) buckets and without regard to the bucket of \(k'\), so it equals \(b\) with probability \(1/m\). Summing over the \(m\) values of \(b\), each weighted by its probability \(1/m\), gives \[m \cdot (1/m) \cdot (1/m) = 1/m\].
186: P3 · The unsuccessful probe count is the chain length
187: Show that an unsuccessful search for \(x\) makes exactly \(L\) probes, where \(L\) is the length of the chain of \(h(x)\).
188: Solution
189: The search compares \(x\) with each key of the chain in turn. Since \(x\) is absent, no comparison stops the search early, so every key of the chain is compared once. That is \(L\) comparisons, and each is one probe in Definition 1.2.
190: Empirical
191: E1 · The largest successful deviation from the model
192: Lab 2 prints successful averages and their model values for five loads. At which load is the absolute gap between them largest, and what is that gap exactly?
193: Solution
194: The measured averages here are the exact quotients of the integer totals 16, 37, 97, 257 and 772 by \(n\), which are 1, 37/32, 97/64, 257/128 and 193/64. Each total is the printed four-decimal average times \(n\), and it is the only integer in that interval because \(n \le 256\). The lab prints the averages rounded to four decimals, and the gaps below use the exact quotients. The unsuccessful gaps are exact too. Lab 2 prints 500 absent test keys, so each unsuccessful average is a total over 500, and the only integer whose quotient by 500 rounds to the printed value is the total 134, 270, 548, 1016 or 2014 (at 0.2680, 0.5400, 1.0960, 2.0320 and 4.0280 in order): the interval of width 500 times 0.0001 = 0.05 around each printed value holds one integer. The successful gaps, measured minus model, are \[1.0 - 1.1171875 = -0.1171875\] at \(n = 16\), \[1.15625 - 1.2421875 = -0.0859375\] at \(n = 32\), \[1.515625 - 1.4921875 = 0.0234375\] at \(n = 64\), \[2.0078125 - 1.9921875 = 0.015625\] at \(n = 128\), and \[3.015625 - 2.9921875 = 0.0234375\] at \(n = 256\). The largest absolute gap is \(0.1171875\), at \(n = 16\). The unsuccessful gaps, measured minus model, are \(0.018 = 134/500 - 1/4\), \(0.04 = 270/500 - 1/2\), \(0.096 = 548/500 - 1\), \(0.032 = 1016/500 - 2\) and \(0.028 = 2014/500 - 4\) at the five loads in order, so the largest is \(0.096\) at \(n = 64\), where the lab prints 1.0960 against 1.0000.
195: E2 · The colliding total
196: Lab 2 prints a successful total of 1275 for the 50 colliding keys. Confirm this value from Problem P1 and state the average it gives.
197: Solution
198: By Problem P1 with \(n = 50\), the total is \(50 \cdot 51 / 2 = 1275\), and the average is \(1275 / 50 = 25.5\), the value the lab prints as 25.5000.
199: E3 · The check that stored keys are found
200: Lab 2 prints "every stored key found: True" at every load. What does this check establish, and what does it not establish?
201: Solution
202: It establishes that for each of the five loads, every key inserted into the table is returned by the lookup, so the chains store and search correctly on these keys. It does not establish that the search cost is small, and it says nothing about keys that were not inserted, which the lab tests separately with the 500 absent keys.
203: Research
204: R1 · A table that resizes
205: Suppose the table doubles its bucket count whenever \(\alpha\) exceeds 1. Explain why Corollary 2.3 then applies with a constant \(c\), and say what the proof still assumes.
206: Solution
207: A doubling happens on the insertion that first makes \(\alpha\) exceed 1, which is when \(n = m + 1\). After that doubling \(\alpha = (m + 1)/(2m) = 1/2 + 1/(2m)\), which lies in \((1/2, 1]\), and \(\alpha\) stays at most 1 until the next doubling, so \(n \le m\) at every check and the bound holds with \(c = 1\) between resizings. The proof still assumes that each key is placed uniformly and without regard to the other keys under the new bucket count, which a resize must preserve. Resizing itself has a cost that this lesson does not count, so the claim covers searches and not the total cost of growth.
208: R2 · Why one colliding family does not refute the hash
209: Explain why Proposition 1.4 does not show that the hash of Lab 2 is poor on every key set.
210: Solution
211: Proposition 1.4 concerns the family \(64 j\). The proof uses only that every key of the family is a multiple of 64. The seeded random keys of the lab fall into 64 buckets, with a longest chain of 9 at \(n = 256\), as Lab 2 prints. The statement is about a family of keys, not about every key set.
212: R3 · Why the unsuccessful average exceeds the successful one
213: Under Assumption 2.1, compare \(\alpha\) with \(1 + (n - 1)/(2m)\), and state when the average unsuccessful cost is larger.
214: Solution
215: Write \(\alpha = n/m\). The difference is \[\alpha - 1 - (n - 1)/(2m) = n/m - 1 - (n-1)/(2m) = (2n - 2m - n + 1)/(2m) = (n - 2m + 1)/(2m)\]. For integers \(n\), this is positive exactly when \(n \ge 2m\), that is, when \(\alpha \ge 2\). It is zero at \(n = 2m - 1\) and negative below that. So the average unsuccessful cost is larger exactly when \(\alpha \ge 2\), and for n below \(2m - 1\) the successful cost is the larger of the two on average, and at \(n = 2m - 1\) the two are equal (the difference is zero there).
