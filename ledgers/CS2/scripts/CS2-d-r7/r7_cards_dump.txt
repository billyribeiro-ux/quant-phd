CS2-c001|L01|T|
 F: What does f in O(g) mean?
 B: There are a constant c > 0 and an integer n0 >= 1 with f(n) <= c g(n) for every integer n >= n0, where g(n) > 0 for every n. The definition uses no limit. c is the witness and n0 the threshold (Definition 1.1).
CS2-c002|L01|T|
 F: What is the maximum scan of a list x0, x1, up to x(n-1) with n >= 1?
 B: Set best to x0. For each later element x, make one comparison x > best and replace best by x when it holds. The scan returns best and the number of comparisons made (Definition 1.5).
CS2-c003|L01|T|
 F: Is a count f(n) = a n + b, with a and b non-negative, in O(n)?
 B: Yes. Assume a and b are non-negative reals and n >= 1 is an integer. Then f is in O(n), with witness c = a + b + 1 and threshold n0 = 1 (Proposition 1.2).
CS2-c004|L01|T|
 F: Is n^2 in O(n)?
 B: No. Assume n ranges over the integers n >= 1. No constant c > 0 and integer n0 >= 1 satisfy n^2 <= c n for every n >= n0. The proof is by contradiction, taking N = max(n0, floor(c) + 1) (Proposition 1.3).
CS2-c005|L01|T|
 F: What is the sum of the integers 0 to n-1 for an integer n >= 1?
 B: It is n(n-1)/2 for every integer n >= 1, proved by induction on n (Proposition 1.4).
CS2-c006|L01|T|
 F: What does the maximum scan return?
 B: The largest value of the list. Assume a list of n >= 1 values and the scan of Definition 1.5, where a comparison is the test x > best (Proposition 1.6).
CS2-c007|L01|T|
 F: How many steps does a nested loop over ordered pairs make?
 B: Assume n >= 1, with the outer index i and the inner index j each running over 0 to n-1 and one step per inner iteration. The loop makes n * n = n^2 steps, which is in O(n^2) and not in O(n) by Proposition 1.3 (Proposition 1.7).
CS2-c008|L01|T|
 F: For integers n >= 1, when does 1000 n > n^2 hold?
 B: Exactly when n < 1000. Equality holds at n = 1000, and the inequality fails for n > 1000 (Proposition 2.3). So n^2 <= 1000 n first fails at n = 1001 (Remark 2.2).
CS2-c009|L01|C|Lab 1, counts in the counting model; no time measured
 F: What exact counts does Lab 1 print for n = 2^k with k = 0 to 10?
 B: The maximum scan makes 2^k - 1 comparisons and the nested loop makes 4^k pair steps, so each doubling multiplies the pair steps by 4. The counts are exact in the counting model, and Lab 1 measures no time.
CS2-c010|L01|T|
 F: Does big-O notation measure running time?
 B: No. Big-O bounds a count of operations in a stated model. Lab 1 counts comparisons and steps and prints no time. A bound on time needs a separate model that assigns a time to each counted operation (Section 4, misconception 1).
CS2-c011|L01|T|
 F: Does f in O(g) mean f(n) <= g(n) for every n?
 B: No. Definition 1.1 allows a constant c and a threshold n0. For f(n) = 3n + 7 and g(n) = n, the inequality f(n) <= g(n) fails for every n >= 1, yet f is in O(g) with c = 10 and n0 = 1 (Example 2.1).
CS2-c012|L01|T|
 F: Is a nested loop always quadratic?
 B: No. A loop of n iterations whose inner loop always runs 2 steps makes 2n steps, which is in O(n) by Proposition 1.2 with a = 2 and b = 0. A quadratic count needs an inner loop whose length grows with n (Proposition 1.7).
CS2-c013|L02|T|
 F: What is a chained hash map with m buckets?
 B: A table of m slots storing a set of distinct keys. A hash function h sends each key to a bucket index in the range 0 to m - 1, and each bucket holds a chain of the keys with that hash. Insertion appends a key to its chain, and a key already present is not added twice (Definition 1.1).
CS2-c014|L02|T|
 F: What is a probe?
 B: A probe is one comparison of the sought key with a key stored in the chain being searched. A successful search stops at the matching key. An unsuccessful search compares the key with every key of its chain (Definition 1.2).
CS2-c015|L02|T|
 F: What is simple uniform hashing (Assumption 2.1)?
 B: The n stored keys are distinct. Each stored key and each sought key is assigned to a bucket chosen uniformly from the m buckets, without regard to the choices for the other keys. Problem P2 shows that two keys share a bucket with probability 1/m.
CS2-c016|L02|T|
 F: How many probes can one search make in a chained table holding n distinct keys?
 B: At most n. Assume n distinct keys in a chained table with m buckets and a fixed hash function. A search reads one chain, and that chain holds no key twice (Proposition 1.3).
CS2-c017|L02|T|
 F: With h(x) = ((x M) mod 2^32) mod 64 and M = 2654435761, where do the keys 64 j go?
 B: h(64 j) = 0 for every integer j >= 0. Assume a table of 64 buckets with this h that stores exactly the n keys 64 j for j = 1 to n. Then all n keys lie in bucket 0, and an unsuccessful search for the absent key 64(n + 1) makes n probes (Proposition 1.4).
CS2-c018|L02|T|
 F: Under Assumption 2.1 with n >= 1, what is the average probe count of an unsuccessful search?
 B: It is n / m = alpha (Proposition 2.2(a)).
CS2-c019|L02|T|
 F: Under Assumption 2.1, what is the average probe count of a successful search for the key inserted in position i, for 1 <= i <= n?
 B: It is 1 + (i - 1)/m (Proposition 2.2(b)).
CS2-c020|L02|T|
 F: Under Assumption 2.1, what is the average, over the n keys, of their successful probe counts?
 B: Assume Assumption 2.1 and n >= 1. The average, over the n keys, of their successful probe counts is 1 + (n - 1)/(2m) (Proposition 2.2(c)).
CS2-c021|L02|T|
 F: Under Assumption 2.1, what bounds the average search cost of a family of tables with n <= c m at every size n >= 1?
 B: Assume Assumption 2.1 and a constant c with n <= c m at every size n >= 1. Every average search cost is at most 1 + c, so the average cost is in O(1) with witness 1 + c and threshold 1 (Corollary 2.3).
CS2-c022|L02|C|Lab 2, printed averages for one fixed hash and seeded keys; no time measured

 B: 1.0000, printed to four decimals for one fixed hash and seeded keys.
CS2-c023|L02|T|
 F: Is hashing O(1) always?
 B: No. Corollary 2.3 bounds the average cost only under Assumption 2.1 with n <= c m. Proposition 1.4 gives a key set on which an unsuccessful search makes n probes.
CS2-c024|L02|C|Proposition 2.2 for the average values; Lab 2 for the printed averages
 F: Does an absent key cost less, because there is nothing to find?
 B: Not in general. Under Assumption 2.1 an unsuccessful search scans its whole chain, with average count alpha, while a successful search costs 1 + (n - 1)/(2m) on average (Proposition 2.2). The absent key costs more only when alpha >= 2 (Problem R3). At n = 256, with m = 64, Lab 2 prints an unsuccessful average of 4.0280 and a successful average of 3.0156.
CS2-c025|L02|T|
 F: Does doubling the keys double the cost of a successful search?
 B: No. At fixed m the average successful cost is 1 + (n - 1)/(2m), so doubling n to 2n adds n/(2m) rather than doubling the cost. At m = 64 the model predicts an increase of 1 from n = 128 to n = 256.
CS2-c026|L03|T|
 F: What is a binary min-heap of n keys?
 B: An array a[0], a[1], up to a[n-1] of distinct keys with heap order: for every index i >= 1, the parent a[floor((i-1)/2)] is smaller than a[i]. The children of index i are 2i + 1 and 2i + 2 when they are less than n, and the minimum is a[0] (Definition 1.1).
CS2-c027|L03|T|
 F: What operations does a priority queue offer?
 B: Push a key, and pop the minimum (Definition 1.1).
CS2-c028|L03|T|
 F: What is an event queue?
 B: A priority queue whose keys are pairs (time, sequence number). The sequence number is the order of insertion, so keys are distinct and the order is total: an earlier time comes first, and events at the same time come out in insertion order (Definition 1.4).
CS2-c029|L03|T|
 F: At which depth does index i of a binary heap lie?
 B: Index i lies at depth floor(log2(i + 1)). Level d holds the indices 2^d - 1 through 2^(d+1) - 2. Assume n >= 1 and the array shape of Definition 1.1 (Proposition 1.2, by induction on the level).
CS2-c030|L03|T|
 F: How many comparisons can a push make in a binary min-heap?
 B: Assume distinct keys in the array shape of Definition 1.1 with s keys, and a comparison as one test of two keys. A push that leaves s keys makes at most floor(log2 s) comparisons (Proposition 1.3(a)).
CS2-c031|L03|T|
 F: How many comparisons can a pop make in a binary min-heap?
 B: Assume distinct keys in the array shape of Definition 1.1 with s >= 1 keys, and a comparison as one test of two keys. A pop makes at most 2 floor(log2 s) comparisons (Proposition 1.3(b)).
CS2-c032|L03|T|
 F: In the hold run of Lab 3, what bounds the heap's total comparisons?
 B: Assume N >= 1, the hold run with N initial pushes, N hold steps and N drain pops, and that the heap never holds more than N keys. The heap makes at most 6 N floor(log2 N) comparisons in total (Proposition 1.5).
CS2-c033|L03|T|
 F: In the hold run of Lab 3, what bounds the sorted list's total moves?
 B: Assume the hold run of Lab 3, as in Proposition 1.5, with N >= 1 initial pushes, N hold steps and N drain pops, so that the list never holds more than N keys. The sorted list makes at most 2N(N + 1) moves in total (Proposition 1.6).
CS2-c034|L03|C|Lab 3, pop-order check (one seeded stream per size)
 F: Do the heap and the sorted list pop the same order in Lab 3?
 B: Yes. They pop the same sequence at every size from N = 16 to N = 4096, on one seeded event stream per size, and no time is measured.
CS2-c035|L03|C|Lab 3 (curriculum lab), doubling ratios of counted moves
 F: By what factor does the sorted list's move count change per doubling of N in Lab 3, from N = 64 to N = 4096?
 B: Each doubling multiplies it by between 3.5282 and 4.5050, over the printed doublings from N = 64 to N = 4096. These are ratios of one stream per size.
CS2-c036|L03|T|
 F: Is a heap a sorted array?
 B: No. Only the heap order holds: each parent is smaller than its children. The array [1, 3, 2] is a valid min-heap and is not sorted (Definition 1.1, misconception 1).
CS2-c037|L03|T|
 F: Is a pop O(1) because it removes only one key?
 B: No. Assume distinct keys in the array shape of Definition 1.1 with s >= 1 keys. The pop restores heap order by a sift-down, which makes up to 2 floor(log2 s) comparisons (Proposition 1.3(b)). That bound grows with s, and no constant bound on a pop is proved.

 B: No. In the counting model the sorted list has the smaller total of comparisons and moves at small sizes: 205 against 602 at N = 16. At N = 256 the heap has the smaller total, 19140 against 21405.
CS2-c039|L03|C|Lab 3 (curriculum lab), counted moves

CS2-c040|L04|T|
 F: What is a comparison sort?
 B: A sort that touches the keys only by comparing two of them, and each comparison has two outcomes. Its cost is the number of comparisons. Moves of keys, index arithmetic and reads are not counted (Section 1).
CS2-c041|L04|T|
 F: What does insertion sort do?
 B: It keeps a sorted prefix. For each new key, it compares the key with the last element of the prefix, moves larger elements one place right while the key is smaller, and stops at the first element not larger than the key (Definition 1.1).
CS2-c042|L04|T|
 F: How many comparisons does one merge of two sorted lists make at most?
 B: At most a + b - 1, for sorted lists of lengths a >= 1 and b >= 1. Assume comparable keys, each list sorted increasingly, keys compared only as fronts of the two lists, and ties going to the left list (Lemma 1.2).
CS2-c043|L04|T|
 F: What is the worst-case comparison count of merge sort?
 B: C(n) <= n ceil(log2 n) for every n >= 1, where C(n) is the largest comparison count over lists of n keys. Assume the keys are comparable and each split is into floor(n/2) and ceil(n/2) parts merged by Definition 1.1 (Proposition 1.3, by strong induction).
CS2-c044|L04|T|
 F: How many comparisons does insertion sort make on sorted input of n keys?
 B: Exactly n - 1, since each key is compared once with its left neighbour (Remark 1.4(a)).
CS2-c045|L04|T|
 F: How many comparisons does insertion sort make on strictly decreasing input of n keys?
 B: Exactly n(n-1)/2, since key i is smaller than all i - 1 keys before it (Remark 1.4(b)).
CS2-c046|L04|T|
 F: How many comparisons does merge sort make on sorted input of 2^k keys?
 B: Exactly k 2^(k-1). A merge of two halves of size m makes exactly m comparisons when every key of the left half is not larger than every key of the right half (Remark 1.4(c)).
CS2-c047|L04|T|
 F: How many comparisons must a comparison sort make in the worst case?
 B: At least ceil(log2(n!)) comparisons on some input of length n. Assume n >= 2, distinct comparable keys, a deterministic algorithm whose only key operation is a two-outcome comparison, halting on every input, every one of the n! orderings possible, returning the keys in increasing order on every input, and outputting the sorting permutation, which the comparison outcomes determine (hypotheses (5) and (6)). The proof counts the leaves of the comparison tree (Proposition 2.1).
CS2-c048|L04|T|
 F: Is log2(n!) at least (n/2) log2(n/2) for n >= 2?
 B: Yes, for every integer n >= 2 (Corollary 2.2). The proof bounds n! below by (n/2)^(floor(n/2)+1).
CS2-c049|L04|T|
 F: What is a gap of a sorted list of n keys?
 B: One of the n + 1 places where an absent key can lie: before the first key, between two consecutive keys, or after the last key (Section 3, the paragraph after Definition 3.1).
CS2-c050|L04|T|
 F: What does binary search do on a sorted array?
 B: It keeps a range lo <= hi, starting at 0 and n-1. A probe compares y with x(mid), where mid = floor((lo + hi)/2). A match stops the search; x(mid) < y sets lo = mid + 1; x(mid) > y sets hi = mid - 1. An empty range reports that y is absent (Definition 3.1).
CS2-c051|L04|T|
 F: How many probes can an unsuccessful binary search make on n sorted keys?
 B: At most floor(log2 n) + 1, which is the number of binary digits of n, and some absent key takes exactly that many. Assume n >= 1, a strictly increasing list, an absent key, and probes counted as comparisons of y with list elements (Proposition 3.2).

 B: 21, which is 7 * 6 / 2 (Lab 4, Part B; Remark 1.4(b)).

 B: No. On sorted input of 1024 keys, insertion sort makes 1023 comparisons and merge sort makes 5120 (Lab 4, Part A).
CS2-c054|L04|T|
 F: How many probes does binary search make for the absent key 7 in the sorted list 0, 2, 4, 6, and at which positions?
 B: 3 probes, at positions 1, 2 and 3, one more than floor(log2 4) = 2 (Misconception 2, Proposition 3.2).
CS2-c055|L04|T|
 F: Can a clever comparison sort beat (n/2) log2(n/2) comparisons in the worst case?
 B: No, under the hypotheses of Proposition 2.1: n >= 2, distinct comparable keys, a deterministic algorithm whose only operation on the keys is a comparison with two outcomes, halting on every input, able to produce every one of the n! orderings, returning the keys in increasing order on every input, and recording the sorting permutation, which the comparison outcomes determine (hypotheses (5) and (6)). Corollary 2.2 then gives a worst case of at least (n/2) log2(n/2) comparisons. The argument does not cover algorithms that read a key's value as an array position (Section 4).
CS2-c056|L05|T|
 F: What is the height of a tree, and what is its in-order sequence?
 B: The height is the number of nodes on the longest path from the root down to a leaf, so the empty tree has height 0 and a single node has height 1. The in-order sequence lists the left subtree's keys, then the node's key, then the right subtree's keys (Section 1).
CS2-c057|L05|T|
 F: What is a balanced search tree?
 B: A binary search tree that restructures itself after each change, so that its height stays logarithmic in the number of its keys. This unit uses the AVL variant (Definition 2.1).
CS2-c058|L05|T|
 F: What is the AVL rule?
 B: The balance factor of a node is the height of its left subtree minus the height of its right subtree, with the height of an empty subtree equal to 0. An AVL tree is a binary search tree in which every node has balance factor -1, 0 or 1 (Definition 2.1).
CS2-c059|L05|T|
 F: What is the recurrence N(h) of Definition 2.2?
 B: N(0) = 0 and N(1) = 1, and N(h) = 1 + N(h-1) + N(h-2) for h >= 2 (Definition 2.2).
CS2-c060|L05|T|
 F: Does every AVL tree of height h have at least N(h) nodes?
 B: Yes. Assume an AVL tree of height h >= 0. The proof is by strong induction: the root's subtrees have heights h - 1 and h2 with h - 2 <= h2 <= h - 1, so the tree has at least 1 + N(h-1) + N(h-2) = N(h) nodes (Lemma 2.3).
CS2-c061|L05|T|
 F: What height bound holds for an AVL tree with n nodes?
 B: h <= log_phi(n + 1) = log2(n + 1) / log2(phi), with phi = (1 + sqrt 5)/2. Equivalently phi^h <= n + 1. Assume an AVL tree with n >= 0 nodes and height h (Proposition 2.4).
CS2-c062|L05|T|
 F: Does a rotation keep the in-order sequence of keys?
 B: Assume y has left child x, with subtrees A under x's left side, B under x's right side and C under y's right side, holding keys in that order. The right rotation makes x the root, with left subtree A and right subtree y, where y has left subtree B and right subtree C. The in-order sequence A, x, B, y, C is the same before and after (Proposition 3.1).
CS2-c063|L05|C|Lab 1, Part A (one seeded run of 500 insertions; checked, not proved)
 F: Does a rotation restore the AVL rule after every insertion?
 B: Not proved here. Proposition 3.1 shows only that a rotation keeps the in-order sequence. Lab 1, Part A checks the rule after each of 500 seeded insertions, and that check is the only evidence for it (Remark 3.2).
CS2-c064|L05|T|
 F: What does sorted insertion do to a binary search tree?
 B: It makes a path. Each inserted key is larger than every key present, so it goes to the right of its predecessor, and the tree of n keys has height n (Remark 1.1).
CS2-c065|L05|C|Lab 1, Part B (keys 1 to 64 in increasing order)

 B: A plain binary search tree has height 64, while the AVL tree on the same keys has height 7. The AVL bound is log_phi 65 = 8.6747 (Lab 1, Part B).
CS2-c066|L05|C|Lab 1, Part A (one seeded run of 500 keys)
 F: How many rotation calls, at most, does one insertion make in Lab 1, Part A?
 B: 2. A double rotation is two calls, and no insertion of the 500 seeded keys made more than two (Lab 1, Part A).
CS2-c068|L05|C|Lab 1, Part A (one seeded run)
 F: Does an AVL tree rotate on every insertion?
 B: No. A rotation is made only at a node whose balance factor has reached 2 or -2. In Lab 1, Part A, 272 of 500 seeded insertions needed no rotation.
CS2-c069|L05|T|
 F: Is the height of an AVL tree at most log2 n?
 B: No. The bound is log_phi(n + 1) = 1/log2(phi) * log2(n + 1), and 1/log2(phi) = 1.440420 to six decimal places (Remark 2.5). The two-node AVL tree with root 2 and left child 1 has height 2, and log2 2 = 1.
CS2-c070|L06|T|
 F: What is a graph here, and how is it stored?
 B: A finite set of vertices with a set of edges, each joining two different vertices. The graph is undirected. It is stored as adjacency lists: for each vertex, the list of its neighbours, held in a hash map from vertex labels (Section 1).
CS2-c071|L06|T|
 F: What is the hop count of a path?
 B: The number of edges on the path. A simple path has no repeated vertex, and a walk may repeat vertices, with its length the number of its edges (Section 1).
CS2-c072|L06|T|
 F: What does breadth-first search do?
 B: BFS starts at the source s and keeps the discovered vertices in a first-in, first-out queue. It repeatedly removes the front vertex u and, for each undiscovered neighbour v, marks v discovered with distance dist(u) + 1, records u as its parent, and adds v to the back of the queue (Definition 1.1).
CS2-c073|L06|T|
 F: What does depth-first search record?
 B: One clock. It ticks when a vertex is first visited, giving the discovery time d(v), and again when every neighbour of v has been handled, giving the finish time f(v). The search runs from every undiscovered vertex in turn (Definition 3.1).
CS2-c074|L06|T|
 F: Are the queued BFS distances nondecreasing from front to back?
 B: Yes. Assume the graph is finite and undirected, and BFS runs as in Definition 1.1 with each discovered distance equal to the parent's plus 1. Then the queued distances are nondecreasing and differ by at most 1, so vertices leave the queue in nondecreasing distance (Lemma 2.1).
CS2-c075|L06|C|Lab 1, Part A (SIMULATED seeded graphs, one run)
 F: Does Lab 1, Part A check BFS hop counts against exhaustive search?
 B: Yes, on 40 seeded graphs and every source. The BFS distances equal the fewest hops over all simple paths found by exhaustive search, with 0 mismatches. The check is on these graphs only and is not a proof (Lab 1, Part A).
CS2-c076|L06|T|
 F: Does BFS find the fewest hops from the source?
 B: Yes. Assume a finite undirected graph, BFS run as in Definition 1.1 with each discovered distance equal to its parent's plus 1, and a source s. Then BFS discovers exactly the vertices reachable from s, and each discovered vertex has dist(v) equal to the fewest edges delta(v) on a path from s (Proposition 2.2).
CS2-c077|L06|T|
 F: How many operations does one BFS make?
 B: At most |V| enqueues and at most 2|E| adjacency entries inspected, for a graph with |V| vertices and |E| edges stored as adjacency lists (Proposition 2.3).
CS2-c078|L06|T|
 F: What is the parenthesis property of depth-first search?
 B: Assume a finite undirected graph and the search of Definition 3.1 with one clock. For distinct vertices u and v, the intervals [d(u), f(u)] and [d(v), f(v)] are disjoint, or one lies inside the other (Proposition 3.2).
CS2-c079|L06|C|Lab 1, Part D (one seeded graph on 200 vertices; counts only)
 F: How many edges does the 200-vertex graph of Lab 1, Part D have?
 B: 619 (Lab 1, Part D).
CS2-c080|L06|C|Lab 1, Part C (weighted 4-vertex graph)
 F: Does BFS find the shortest path when edges have weights?
 B: No. BFS minimizes the number of edges (Proposition 2.2). In Lab 1, Part C, the path from s to a has 1 hop and weight 10, while s to b to a has 2 hops and weight 2. BFS returns the path with the fewest edges, the direct edge from s to a.
CS2-c081|L06|T|
 F: Does depth-first search find shortest hop paths, because it reaches every vertex?
 B: No. In the triangle a, b, c, with a's neighbour list in the order b then c, the DFS tree path from a to c is a, b, c with 2 hops. Since a and c are adjacent, the hop distance is 1, which BFS returns.
CS2-c082|L06|T|
 F: Does a traversal cost the same on adjacency lists as on an adjacency matrix?
 B: No. Lists cost at most |V| + 2|E| operations (Proposition 2.3). With an adjacency matrix a dequeued vertex reads its full row of |V| entries, so the row reads are |V| times the number of dequeued vertices, which is at most |V|^2.
CS2-c083|L07|T|
 F: What is a subproblem?
 B: A smaller instance of the same question, identified by a short key such as a pair of integers (Section 1).
CS2-c084|L07|T|
 F: What are the three steps of dynamic programming?
 B: It writes the answer as a recurrence over subproblems, evaluates each distinct subproblem once and stores its value, and reads the answer from the stored values (Definition 1.1).
CS2-c085|L07|T|
 F: What is f(a) for a set D of denominations?
 B: The fewest elements in a representation of a: a multiset of elements of D, each usable any number of times, whose sum is a. f(a) is infinity when no representation exists (Definition 2.1).
CS2-c086|L07|T|
 F: What is a common subsequence of two sequences?
 B: A common subsequence of length k is given by indices p1 < p2 < up to pk in x and q1 < q2 < up to qk in y with x(p_t) = y(q_t) for every t (Definition 3.1).
CS2-c087|L07|T|
 F: What is the coin-change recurrence?
 B: f(0) = 0, and for a >= 1, f(a) = min{1 + f(a - c) : c in D, c <= a}. Assume D is a finite nonempty set of positive integers and a is a nonnegative integer, with the minimum over an empty set taken as infinity (Theorem 2.2).
CS2-c088|L07|T|
 F: Does filling dp[a] = min{1 + dp[a - c]} for a = 1 to A give the fewest-coin counts?
 B: Yes. dp[a] = f(a) for every 0 <= a <= A. Assume D is a finite nonempty set of positive integers and A >= 0 is an integer. Each dp[a] is the minimum of 1 + dp[a - c] over the denominations c <= a with dp[a - c] < infinity, and the minimum over an empty set is infinity. The proof is by strong induction on a (Corollary 2.3).
CS2-c089|L07|T|
 F: For denominations 1, 3 and 4 and amount 6, what is f(6)?
 B: f(6) = 2, realized by 3 + 3 (Example 2.4).
CS2-c090|L07|T|
 F: What is the LCS recurrence?
 B: For 1 <= i <= m and 1 <= j <= n: if x(i) = y(j), then lambda(i, j) = lambda(i - 1, j - 1) + 1; if x(i) differs from y(j), then lambda(i, j) = max{lambda(i - 1, j), lambda(i, j - 1)}. Assume finite sequences compared by exact equality (Theorem 3.3, with Lemma 3.2).

CS2-c117|L09|T|
 F: What are the mean, the sum of squared deviations, and the sample and population variances?
 B: The mean is xbar_n = (1/n) sum x_i and the sum of squared deviations is S_n = sum (x_i - xbar_n)^2. For n >= 2 the sample variance is S_n/(n-1) and the population variance is S_n/n (Definition 1.1).
CS2-c118|L09|T|
 F: What is Welford's recursion?
 B: M_1 = x_1 and S_1 = 0. For n >= 2, M_n = M_{n-1} + (x_n - M_{n-1})/n and S_n = S_{n-1} + (x_n - M_{n-1})(x_n - M_n). The state after n values is the triple (n, M_n, S_n) (Definition 1.2).

CS2-c208|L04|T|
 F: What does merge sort do?
 B: It splits a list into floor(n/2) and ceil(n/2) keys, sorts each part, and merges the two sorted lists by repeatedly comparing the two front keys and outputting the smaller. When one list is empty, the rest of the other is copied without comparison (Definition 1.1).

CS2-c213|L03|T|
 F: Why does the event queue's key include a sequence number?
 B: So that no two keys are equal. Without it, two events at the same time have equal keys, and a heap may pop them in either order, so the result would depend on how the heap arranged them. With it, Definition 1.4 fixes the pop order (Remark 1.5).

 F: Is the sample variance defined when only one value has been added?
