  52: This lesson treats a timed coding answer as more than running code. The answer must state what the code costs, why the structure it uses meets that cost, and which small cases it was checked on. The lesson sets out that procedure, counts the work of the simplest method for a sliding-window maximum exactly, and proves that a monotonic deque returns the same answers with at most twice the input length in comparisons. The lesson states what each count measures and does not claim how long any session allows.
  54: 1The procedure
  57: Definition 1.1 (timed coding interview)
  58: A timed coding interview is the following procedure, applied to one stated task. The answerer works through six steps in order and keeps a time budget for the whole item, set before the item starts and kept on the answerer's own clock.
  60: Restate the task, and fix the type of each input and of the output.
  61: State the edge cases: the empty input, the smallest and the largest value of each parameter, and any parameter larger than the input.
  62: State the complexity budget, the bound the answer must meet, in big-O notation of the input size \(n\) and of each parameter.
  63: Choose a structure whose operations meet the budget, and state the cost of each operation.
  64: Write the code.
  65: Check the code on small cases with unit tests, comparing it with a slow answer that is correct by inspection.
  70: Remark 1.2 (what the lesson does not supply)
  71: The page has no timer. A budget is a number the answerer sets and keeps, and this lesson does not fix its length. The lesson also makes no claim about how long any examination allows, which tasks it sets, or how answers are judged by any employer. Each of those is outside this lesson.
  74: The rest of the lesson applies steps 2 to 6 to one task, the sliding-window maximum. Its statement is the next definition.
  77: Definition 1.3 (sliding-window maximum)
  78: Let \(x_1,\dots,x_n\) be real numbers, with \(n\ge 1\), and let \(k\) be an integer with \(1\le k\le n\). The sliding-window maximum is the sequence \(y_i=\max\{x_{i-k+1},\dots,x_i\}\) for \(i=k,\dots,n\). It has \(n-k+1\) entries. Its outputs are the window maxima. The code of Lab 1 indexes from 0, while the proofs index from 1.
  81: 2The naive scan and its exact cost
  83: The naive method finds each window's maximum by scanning the window. It sets the baseline that the complexity budget of step 3 must beat. Its exact count is a theorem, and the lab prints the count beside the measured value.
  86: Proposition 2.1 (comparisons of the naive scan)
  87: Hypotheses: (H1) \(x_1,\dots,x_n\) are real numbers, \(n\ge 1\); (H2) \(1\le k\le n\); (H3) for each window the scan takes the first value of the window as the running maximum and compares each of the other \(k-1\) values with it, one comparison each. Conclusion: the scan makes exactly \((n-k+1)(k-1)\) comparisons in total.
  91: Proof
  92: By H2 there are \(n-k+1\) windows, one for each \(i=k,\dots,n\), and each window is nonempty. By H3 each window contributes \(k-1\) comparisons, and no comparison is shared between windows, since each comparison is made inside one window. The total is \((n-k+1)(k-1)\). \(\square\)
  96: Remark 2.2 (the cost peaks at the middle window size)
  97: Write \(r=k-1\), so the count is \((n-r)r\). Then \((n-r)r=\tfrac{n^{2}}{4}-\bigl(r-\tfrac n2\bigr)^{2}\), which is at most \(n^{2}/4\), with equality when \(r=n/2\). For even \(n\), the count is largest at \(k=n/2+1\). The expansion checks by multiplying out the right side: \(\tfrac{n^{2}}{4}-r^{2}+nr-\tfrac{n^{2}}{4}=nr-r^{2}\).
 100: 3A monotonic deque
 102: The deque method keeps, for the current window, only the indices that can still be a window maximum. Step 4 of Definition 1.1 chooses a structure. The rest of this section proves that the deque meets a total budget, and Remark 3.6 compares it with a hash map and a binary heap.
 105: Definition 3.1 (the deque and its invariant)
 106: Call an index \(j\) surviving at step \(i\) when \(i-k<j\le i\) and \(x_j>x_m\) for every \(m\) with \(j<m\le i\). The deque is the monotonic deque of the prerequisite module, a double-ended queue of indices. After step \(i\) it holds exactly the surviving indices of step \(i\), kept in increasing order of index from front to back. The front is the smallest index and the back is the largest.
 109: The method processes \(i=1,\dots,n\) in order. Its steps are as follows.
 112: Pseudocode, not run; the runnable version is Lab 1
 113: for i = 1 to n:
 114: while the deque is not empty and x[back] is at most x[i]:
 115: remove the back of the deque
 116: append i to the back of the deque
 117: if the front of the deque is at most i - k:
 118: remove the front of the deque
 119: if i is at least k:
 120: output x[front]
 124: Proposition 3.2 (correctness of the deque)
 125: Hypotheses: (H1) \(x_1,\dots,x_n\) are real numbers, so any two of them are comparable; (H2) \(1\le k\le n\); (H3) the method of Definition 3.1 and the pseudocode above run for \(i=1,\dots,n\). Conclusion: at each step \(i\ge k\) the output is \(\max\{x_{i-k+1},\dots,x_i\}\), and after each step the deque holds exactly the surviving indices of Definition 3.1.
 129: Proof
 130: Step A: the invariant holds after each step. Before step 1 the deque is empty, and the invariant holds vacuously. Assume it holds after step \(i-1\). Then the deque is decreasing in value from front to back: if \(j<j'\) are both in the deque, then \(x_j>x_{j'}\), because \(j\) survives step \(i-1\) with \(m=j'\). Hence the entries whose value is at most \(x_i\) form a block at the back. The while loop removes exactly this block, since it stops at the first back entry whose value exceeds \(x_i\). Afterwards the deque holds the surviving indices of step \(i-1\) whose values exceed \(x_i\), and then the index \(i\) is appended. Each remaining index \(j\) satisfies \(x_j>x_m\) for all \(m\) with \(j<m\le i\). Indices that the loop removed fail this condition for \(m=i\), so they are rightly absent. Conversely, an index \(j<i\) that survives step \(i\) also survives step \(i-1\), because the condition for \(i-1\) is weaker. So the deque after the append is exactly the set of indices \(j\le i\) that satisfy the condition with \(m\le i\). The expiry step then removes the front when it equals \(i-k\), which is the only index that leaves the window \(\{i-k+1,\dots,i\}\) at this step. Indices increase from front to back, so if index \(i-k\) is in the deque it is the front, and one removal suffices.
 131: Step B: the front is the window maximum. Let \(f\) be the front after step \(i\geq k\). It is in the window, and \(x_f>x_m\) for every \(m\) with \(f<m\le i\). Take any \(p\) in the window. If \(p\ge f\), then either \(p=f\) or \(f<p\le i\), and \(x_f\ge x_p\) holds in both cases. If \(p<f\), let \(M\) be the largest value among \(x_p,\dots,x_i\), and let \(q\) be the largest index in \(\{p,\dots,i\}\) with \(x_q=M\). Then \(x_q>x_m\) for every \(m\) with \(q<m\le i\), so \(q\) survives step \(i\). Since \(f\) is the smallest surviving index, \(f\le q\), and the decreasing order of the deque gives \(x_f\ge x_q=M\ge x_p\). Hence \(x_f\) is the maximum of the window.
 132: Step C. For \(i\ge k\) the window \(\{i-k+1,\dots,i\}\) is complete, and the output \(x_f\) is its maximum by Step B. \(\square\)
 136: Proposition 3.3 (total work of the deque)
 137: Hypotheses: (H1)–(H3) of Proposition 3.2. Conclusion: each index is appended exactly once, so there are \(n\) appends; each index is removed at most once, so there are at most \(n\) removals; and the number of comparisons made by the while-loop tests is at most \(2n\).
 141: Proof
 142: Step \(i\) appends \(i\) once, and no index is appended twice, which gives \(n\) appends. An index leaves the deque at most once, because it is removed from the back or the front and never returns, so the removals are at most \(n\). A while-loop test is either followed by a back removal or is the one failed test that ends the loop, and each step has at most one failed test. So the tests number at most the back removals plus \(n\). The back removals are at most \(n\), so the tests number at most \(2n\). Front expiries involve no test. \(\square\)
 146: Remark 3.4 (a single step can be expensive)
 147: One step can remove up to \(k-1\) entries. Take \(x=(k,k-1,\dots,2,\,k+1)\), with \(n=k\) and \(k\ge 2\). At step \(k\) the deque holds indices \(1,\dots,k-1\) in decreasing value, and the value \(k+1\) at index \(k\) exceeds all of them, so it removes all \(k-1\) of them in one loop. So the cost of one step is not bounded by a constant. Proposition 3.3 bounds the total, and it is the total that the budget of step 3 uses.
 151: Example 3.5 (a trace with window 3)
 152: Let \(x=(3,1,4,1,5)\) and \(k=3\). After step 1 the deque is \((1)\). At step 2 the value 1 does not remove the index 1, so the deque is \((1,2)\). At step 3 the value 4 removes indices 2 and 1, the deque becomes \((3)\), and the output is \(x_3=4\). At step 4 the deque is \((3,4)\), and the output is \(x_3=4\), because index 3 is still in the window \(\{2,3,4\}\). At step 5 the value 5 removes indices 4 and 3, so the deque is \((5)\), and the output is \(x_5=5\). The outputs are \((4,4,5)\).
 156: Remark 3.6 (a hash map and a binary heap in Step 4)
 157: A hash map finds a value by its key, but it keeps no order on its values, so a lookup by key does not report the window maximum. This remark does not consider any other use of a hash map.
 158: A binary heap of the window's indices, keyed by value, has its maximum at the root. Its costs are counted in comparisons of stored values. A push sifts up a heap of \(m\) entries, which makes at most \(\lfloor\log_2 m\rfloor\) comparisons, because the deepest position of a heap of \(m\) entries has depth \(\lfloor\log_2 m\rfloor\). A pop sifts down, which makes at most two comparisons on each level it descends, so at most \(2\lfloor\log_2 m\rfloor\). If the heap holds at most \(n\) entries and makes \(n\) pushes and at most \(n\) pops, its total is at most \(3n\lfloor\log_2 n\rfloor\) comparisons, the pushes contributing at most \(n\lfloor\log_2 n\rfloor\) and the pops at most \(2n\lfloor\log_2 n\rfloor\). For \(n=200\) this bound is \(3\cdot 200\cdot 7=4200\), against the bound \(2n=400\) of Proposition 3.3 for the deque. The heap's bound is of order \(n\log n\), so this count does not show that the heap meets a budget of order \(n\). The remark counts the heap's comparisons only and does not prove that a heap of indices reports the window maximum.

 181: import random
 182: from collections import deque
 183: from collections.abc import Sequence
 184: from dataclasses import dataclass

 195: """Operation counts for one run: comparisons of stored values, and deque pushes and pops."""
 197: comparisons: int = 0

 199: pops: int = 0
 202: def make_sequence(seed: int, length: int) -> list[int]:

 208: def naive_maxima(xs: Sequence[int], k: int) -> tuple[list[int], int]:
 209: """The maximum of each window of k consecutive values, found by scanning the window. Returns the maxima and the
 210: number of comparisons, which is k - 1 for each of the n - k + 1 windows."""
 211: maxima: list[int] = []
 212: comparisons = 0
 213: for start in range(len(xs) - k + 1):
 214: best = xs[start]
 215: for x in xs[start + 1 : start + k]:
 216: comparisons += 1
 217: if x > best:
 218: best = x
 219: maxima.append(best)

 223: def deque_maxima(xs: Sequence[int], k: int) -> tuple[list[int], Ops]:
 224: """The maximum of each window of k values, using a deque of indices whose values decrease from front to back.
 226: The front index is the index of the current window's maximum. Each index is pushed once and popped at most once.
 227: """
 228: window: deque[int] = deque()
 229: maxima: list[int] = []
 230: ops = Ops()
 231: for i, x in enumerate(xs):
 232: while window:
 233: ops.comparisons += 1
 234: if xs[window[-1]] > x:

 325: 4Where the canon breaks
 326: An operation count is not a run time. The comparisons of Proposition 2.1 and Proposition 3.3 are the work a model counts. Run time depends on the language, the interpreter, the memory access pattern and the machine, none of which this lesson fixes.
 327: The bound of Proposition 3.3 charges each append and each removal one unit. That is the model. An implementation whose removal at the front costs more than one unit, such as a plain list that shifts its elements, is outside Proposition 3.3 unless its cost is stated.
 328: The total bound is an amortised bound, that is, an average over the run: the average cost per step over the run is at most two comparisons, although a single step can cost of order \(k\), as Remark 3.4 shows. A budget written as a per-step bound of one operation would be false for this method, and a budget written as a total over the run is the one the method meets.
 329: Both proofs use the fact that values are comparable. With values that have no order, or with missing values, Proposition 3.2 does not apply. The lab's convention that a window longer than the sequence gives no output is a choice, and another convention would change the edge case without changing the method.
 333: 5Misconceptions
 336: “The deque costs of order \(k\) per step, so the whole scan costs of order \(nk\).”
 337: A single step can cost of order \(k\), as Remark 3.4 shows. The total is at most \(2n\) comparisons by Proposition 3.3, which is of order \(n\). Lab 1 prints 354 comparisons for \(n=200\) and window 8, within the bound of 400.
 340: “The operation counts in Lab 1 are the run times of the two methods.”
 341: The lab counts comparisons, pushes and pops. It does not time anything. Run time depends on the implementation and the machine, and Section 4 names what the counts leave out.
 344: “Matching outputs on a few inputs prove that the method is correct.”
 345: Lab 1, Part 2 matches the outputs for every window size from 1 to 20 on one sequence. That is evidence for that sequence. Proposition 3.2 is the proof for every sequence of real numbers, and the lab's check is not a substitute for it.

 355: Mechanics
 357: M1 · The naive count for a short sequence
 358: Find the number of comparisons made by the naive scan for \(n=10\) and \(k=4\).
 359: Solution
 360: By Proposition 2.1, the count is \((n-k+1)(k-1)=(10-4+1)(4-1)=7\cdot 3=21\) comparisons, over 7 windows of 3 comparisons each.
 364: M2 · Trace the deque with window 2
 365: Run the deque method on \(x=(2,5,1,0,3)\) with \(k=2\), recording the deque after each step and the outputs.
 366: Solution
 367: Step 1: the deque is \((1)\). Step 2: the value 5 removes index 1, the deque is \((2)\), and the output is \(x_2=5\). Step 3: the value 1 does not remove index 2, the deque is \((2,3)\), and index 2 is still in the window \(\{2,3\}\), so the output is \(x_2=5\). Step 4: the value 0 gives \((2,3,4)\). The front index 2 is at most \(i-k=2\), so it is removed, the deque is \((3,4)\), and the output is \(x_3=1\). Step 5: the value 3 removes indices 4 and 3, the deque is \((5)\), and the output is \(x_5=3\). The outputs are \((5,5,1,3)\).
 371: M3 · The two extreme window sizes
 372: For an input of length \(n\), state the outputs of the deque method when \(k=1\) and when \(k=n\).
 373: Solution
 374: For \(k=1\), there are \(n\) windows, each a single value, so the output is the input itself. At step \(i\), the deque holds at most the indices \(i-1\) and \(i\) before expiry, and the expiry rule removes \(i-1\) if it is there, so the deque holds only \(i\) and the output is \(x_i\). For \(k=n\), there is one window, \(\{1,\dots,n\}\), and by Proposition 3.2 with \(i=n\) the output is \(\max\{x_1,\dots,x_n\}\). The output list has one entry.
 380: Proof
 382: P1 · The peak of the naive count
 383: Prove that \((n-r)r\le n^{2}/4\) for every real \(r\), and find the integer \(k\) that maximises \((n-k+1)(k-1)\) when \(n\) is even.
 384: Solution
 385: Expanding \((n/2-r)^{2}\geq 0\) gives \(r^{2}-nr+n^{2}/4\geq 0\), so \(nr-r^{2}\le n^{2}/4\). The left side is \((n-r)r\). Equality holds when \(r=n/2\). For even \(n\), \(r=n/2\) is an integer, so \(k=r+1=n/2+1\) gives the largest count, \(n^{2}/4\). For example, \(n=200\) gives \(k=101\) and a count of \(100\cdot 100=10000\).
 389: P2 · The maximum survives in the deque
 390: In Step B of Proposition 3.2, show that the largest index \(q\) in \(\{p,\dots,i\}\) whose value equals the maximum \(M\) of \(x_p,\dots,x_i\) survives step \(i\).
 391: Solution
 392: For any \(m\) with \(q<m\le i\), the index \(m\) is in \(\{p,\dots,i\}\), and by the choice of \(q\) as the largest index with value \(M\), \(x_m\neq M\). Since \(M\) is the maximum, \(x_m<M=x_q\). So \(x_q>x_m\) for every \(m\) with \(q<m\le i\), which is the survival condition of Definition 3.1 for \(q\) at step \(i\). Also \(q\ge p\) is in the window, since \(p\) is in the window and \(q\ge p\).
 396: P3 · An increasing sequence costs n minus 1
 397: Let \(x_1<x_2<\dots<x_n\) with \(1\le k\le n\). Count the comparisons made by the while-loop tests, and show that the count is exactly \(n-1\) for every such \(k\).
 398: Solution
 399: At step 1 the deque is empty, so no test is made, and the deque after step 1 is \((1)\). Suppose that at the start of step \(i\ge 2\) the deque is \((i-1)\). The loop makes one test, whether the back value \(x_{i-1}\) is at most \(x_i\). It is, because \(x_{i-1}<x_i\), so the back index \(i-1\) is removed. The deque is now empty, and the loop ends without a second test. Index \(i\) is appended, and the expiry removes nothing, because the front \(i\) is not at most \(i-k\). So the deque after step \(i\) is \((i)\), which is the supposition for step \(i+1\). Each step \(i\ge 2\) makes exactly one test and step 1 makes none, which gives \(n-1\). The expiry removals involve no comparison of values.
 405: Empirical
 407: E1 · The counts at window 32, seeded
 408: Lab 1, Part 3 prints 5239 naive comparisons and 382 deque comparisons for window 32 on seed 5 with \(n=200\). Check the naive count by formula, and compute the ratio of the naive count to the deque count to one decimal place.
 409: Solution

 421: E3 · The largest deque count in Lab 1
 422: The deque count in Lab 1, Part 3 is largest at window 200 with 387 comparisons. Compare it with the bound of Proposition 3.3 and with the pushes and pops the lab prints for that row.
 423: Solution
 424: The bound is \(2n=400\), and \(387\le 400\). The row prints 200 pushes, which equals \(n\), and 194 pops. The proof of Proposition 3.3 splits the comparisons into those followed by a removal, at most the 194 pops, and the step-ending tests, at most \(n=200\). So the comparisons are at most \(194+200=394\), and 387 is within that split bound.

 432: R1 · A timing protocol that could decide the question
 433: Criterion: state a protocol that could decide, for a given machine and implementation, whether the deque is faster than the naive scan at window size \(k\). List the choices the protocol must fix, and state the result that would decide it.
 434: Solution
 435: The protocol fixes the language and version, the implementation of each method, the machine, the input family and its length \(n\), and the window sizes. It repeats each run a stated number of times, reports a summary of the repeats, and keeps the timer outside the algorithm. The decisive result would be a window size \(k^{*}\) above which the deque's measured time is smaller for every stated input family. The lesson does not run this protocol, so it establishes no timing result. The counts of Lab 1 are measurements of the model. The lesson proves the operation counts of Proposition 2.1, the bound of Remark 2.2 and the bounds of Proposition 3.3, and it proves no timing result.
 439: R2 · A window size that maximises the naive work
 440: Criterion: for \(n=200\), find the window size \(k\) that maximises the naive comparisons, and state the count.
 441: Solution
 442: By Remark 2.2 the count is maximised at \(k-1=n/2=100\), so \(k=101\). The count is \((200-101+1)(101-1)=100\cdot 100=10000\), which equals \(n^{2}/4\). The count is not the same as a time, so this answer is about the model's count only.
 446: R3 · An input that makes every step expensive
 447: Criterion: find an input of length \(n\) and a window size \(k\ge 2\) such that every step \(i\ge k\) removes at least one index from the back. Decide whether that per-step cost forces the total work to be of the order of \(nk\).
 448: Solution
 449: A strictly decreasing sequence removes nothing from the back, since each new value is smaller than the back. Take instead a strictly increasing sequence. At each step \(i\ge 2\) the back value is smaller than \(x_i\), so one back removal occurs, and every step \(i\ge k\) qualifies. By Problem P3 the total is \(n-1\) comparisons for any \(k\). So the per-step removal does not force a total of the order of \(nk\).
