## Project ladder and grader (Builder D)

**Rung 1 (worked example):** a fully solved, annotated posting of 10 transactions to the three statements, with a note
on each step. Skippable on a placement pass.

**Rung 2 (completion):** the same posting, with the articulation identity and the cash-flow reconciliation left as `___`
blanks. Graded instantly by `lab-AC1-project-2` (its twin is the completed solution). Skippable on a placement pass.

**Rung 3 (independent project, the curriculum scope):** implement the library to the spec: `post(transactions) -> Ledger`,
`balance_sheet`, `income_statement`, `cash_flow_statement`, `articulation_check`. A 200-transaction seeded ledger.
Graded by the autograder.

**Rung 4 (stretch, open-ended):** a stated hypothesis about how the same 200-transaction set would present under the
other framework (GAAP vs. IFRS presentation differences only, no external data). Not graded by the autograder.

**Autograder (`grading: autograder`, as the curriculum says):**

- `grader/instance.py`: `make_instance(seed: int) -> dict` builds a balanced, valid 200-transaction ledger from a seeded
  RNG. Every entry balances. Seeds 0-49 give materially different ledgers (different amounts, accounts and dates).
- `grader/reference.py`: full solution, must pass the whole suite on seeds 0-49.
- `grader/test_project.py` checks properties and numbers:
  - each period's balance sheet balances (assets = liabilities + equity);
  - net income equals the change in retained earnings net of dividends;
  - the closing cash on the balance sheet equals the cash-flow statement's ending cash;
  - indirect operating cash flow equals net income plus non-cash add-backs plus working-capital changes;
  - unbalanced entries and unknown accounts raise a named error;
  - failure messages name the violated property and never reveal the answer.
- Mutation design (`tools/mutate_graders.py`, at least three, each must fail a test): a sign error on working-capital
  change in CFO; depreciation omitted from the add-backs; dividends not deducted from retained earnings; a cut-off off by
  one period; a hard-coded answer for seed 0.
- Panel attributes: `data-unit="AC1"`, `data-grader="grader/"`, `data-suite="test_project.py"`,
  `data-support="instance.py"`, `data-solution` must be a local module name (proposal `statements.py`, the AP1 pattern;
  this is an open question, see below), `data-starter="starter.py"`, `data-packages=""` (standard library only).
- Time budget table `#hours` components must sum to 30 h, with a rationale per row (check_projects enforces this).

## Tooling assumptions that do not hold for this module type

1. **No Atlas milestone.** `run_graders.py` takes the solution path from the grader panel (`data-solution`). AC1 has no
   `atlas/` contract, so the value must be a local name, not `atlas/<module>.py`. Confirm this is acceptable.
2. **Not a foundations (F) module.** It is tier U with an autograder, so no exemption from grading applies. The autograder
   is the only grading mode the curriculum names, so no rubric, exemplars or question bank are required.
3. **The curriculum's `lab` is a single line, not a lab list.** BUILDER_RULES §6 expects 1-4 labs per lesson. This plan
   gives each lesson one lab plus three project labs. Architect decision.
4. **`sources` are free text.** Only one of the two is a verified key (`ifrsndifrs`). `check_pages` rejects any cited key
   not in the verified registry (`cards.json: cites unknown key`), so builders cannot cite FASB or the standard-specific
   IFRS pages until REFERENCE_REQUESTS are resolved.
5. **Grade for rule-based (non-research) claims.** BLUEPRINT §3 defines grades for findings. A standard's required
   treatment is a rule, not a finding. There is no defined grade for it. Proposal: double-entry and articulation identities
   are T (proved on the page). Standard content is cited to the primary document and graded per the architect's rule.
   Open question.
6. **`check_dag`:** concepts are unique to AC1 in the curriculum (`render_curriculum.py` enforces single introduction). Not
   re-verified by this planner.
